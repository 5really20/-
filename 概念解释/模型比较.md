- **三家都没有 ultra**；DeepSeek 的 ultra 是 max 的别名（官方映射表：`ultra → max`）。

## 9. 两种口径的落差：为什么"DS 打平 Opus 5"和"DS 只有 Fable 5.2 的一半"能同时成立

这是本报告最需要说清楚的一节，因为它直接决定"你该信哪个数"。

### 9.1 两套数字

| 口径 | 方法 | DeepSeek vs Claude Opus 5 | DeepSeek vs GPT-5.6-Sol | DeepSeek vs Fable 5.2 |
|---|---|---|---:|---:|
| **DeepSeek 官方自测**（2026-10-17） | 自家 harness（DeepSeek Harness）+ 自选 11 项任务集 | **0.97×（基本打平）** | **1.13×（DS 更强）** | 未测（当时 Fable 5.2 未发布） |
| **Artificial Analysis**（v5.0.2） | 统一 harness + 统一 token 预算，9 项评测 | **0.55×（II 59.1 vs 32.4）** | —（未收录 5.6 Sol） | **0.50×（II 64.8 vs 32.4）** |

**同一个模型，两套口径下的结论可以差 2 倍。** 这不是谁在撒谎，而是三个结构性差异：

1. **Harness 适配**：DeepSeek 官方明确说 V4.1-Flash-1017 是"专门针对 DeepSeek Harness、腾讯 CodeBuddy/WorkBuddy 优化"的，需要 DSH ≥ 0.2.1-rc.1。**AA 用的是自己的统一 harness，等于让 DeepSeek 在"别人的主场"打球。**
2. **任务集选择**：DeepSeek 的 11 项里有 Automation-Bench、Agents' Last Exam、Apex Bench 这些它明显强的项（1.10–1.33×），而 AA 的 9 项里有 Terminal-Bench-Science（DS 12.9 vs 73）这种它极弱的项。**换一个任务集，几何平均能差 30%。**
3. **Effort 档位**：AA 测 DeepSeek 只测了 Max 和 High 两档（且社区指出"看起来是最差的档"），而 Fable 5.2 测了 5 档、取最好的。**这本身不是偏袒，但会让"上限对上限"的比较偏向对方。**

### 9.2 该信哪个？

**两个都要信，但用于不同问题：**

- **问"这个模型绝对有多强"→ 信 AA。** 它是独立第三方、统一条件、可复现，且不依赖厂商自选任务集。这是本报告的主口径。
- **问"在我自己的 harness 里它能发挥多少"→ 信官方自测 + 你自己的 A/B。** 用户的场景恰恰是"自家模型 + 自身适配 harness"，这意味着 **DeepSeek 的真实表现会比 AA 的数字更好**，而国外模型的真实表现会比 AA 略差（它们没有针对你的 harness 优化）。
- **保守估计**：把 AA 的 0.49–0.50 与官方的 0.97 取中间，**DS 在"适配良好的自建 harness"里大约是 Fable 5.2 的 0.6–0.7、Opus 5.5 的 0.7–0.8**。这个区间比任何单一口径都更接近真相。

### 9.3 AA 的方法学细节（可核验）

- 统一温度：非思考模型 0，思考模型 0.6（除非厂商另有建议）
- 统一输出上限：思考模型用"厂商披露的最大输出 token"（不是固定 16K），非思考模型 16,384
- Agent 任务：250–500 turns，单轮 MCP 工具 60 秒超时，工具输出截断到 24k token（20k 字符头 + 5k 字符尾），图像压到 ~1MP
- 上下文用到 70% 后，要求模型自总结并清历史
- API 失败重试最多 30 次，持续失败的结果不发布

> 这套方法对"长程 agent"是**偏保守**的：它不允许模型"无限续命"，也不给厂商特定的工具优化。对 DeepSeek 这种"越跑越稳"的模型，AA 的数字是下限。

## 11. 给"自家 harness"的选型建议

前提：你的场景是"DeepSeek 自家模型 + 自身适配 harness，发挥最大能力"。这个前提会显著改变结论——**AA 的数字是下限，不是上限**。

### 11.1 按任务类型

| 任务类型 | 推荐 | 理由 |
|---|---|---|
| **大批量、流程明确的工程任务**（重构、迁移、批量修 bug、生成测试） | **DeepSeek Max** | 1/44 的成本 + AutomationBench 只差 1.15×，是"量大管饱"的最优解 |
| **从零构建完整项目**（给定清晰规格） | **DeepSeek Max + 人工评审** | 官方案例与 HN 实证都支持；但必须外挂检索/校验层压幻觉 |
| **长程自主 agent（>30 分钟，多工具）** | **Claude Opus 5.5（Xhigh）或 Fable 5.2（High）** | Fable 5.2 的"不中途停"是官方与 Uber 案例共同强调的；Opus 5.5 是性价比更好的 daily driver |
| **硬推理 / 科研 / 数学** | **Fable 5.2 或 GPT-6.2 Astra（High）** | 3 倍差距，没有替代方案；注意别开 Max（+4.7% 换 2.9 倍成本） |
| **代码审计 / 找深层 bug** | **GPT-6.1 Sol 或 GPT-6.2 Sol** | HN 实测：GPT-6.1 Sol 4.5 分钟找到两个相关 P1，DeepSeek 20 分钟只找到 1 个 |
| **需要"不编造"的场景**（法务、医疗、对外输出） | **Gemini 4 Carbon / Hydrogen** | 非幻觉率 88–92%，断层领先 |
| **对话/陪伴/需要被理解** | **Claude Opus 5.5** | 舒适度 1.44×，温度 84.7 vs DS 的 23.3 |
| **超长上下文（>500K）** | **任意 1M 型号**，但优先 DeepSeek/Gemini | 全部标称 1M；AA 的分上下文 TTFT 显示 100K 输入时 DeepSeek 为 2.0 秒，而 Claude 全家 435–617 秒、GPT-6.2 系列 247–338 秒 |

### 11.2 混合编队（最贴近"发挥最大能力"的做法）

社区已经验证过的最优解不是"选一个模型"，而是**分工**：

```
需求澄清（贵模型，短）  →  Claude Opus 5.5 / Fable 5.2
       ↓
方案评审（中模型，短）  →  GPT-6.2 Sol / Claude Sonnet 5.5
       ↓
批量实施（便宜模型，长）→  DeepSeek V4.1 Flash Max  ← 80% 的 token 在这里
       ↓
交叉审计（不同家，短）  →  GPT-6.1 Sol / Gemini 4 Carbon
```

`clx75` 用这个结构一周做出两个完整项目；`Roark66` 用"Fable/Opus 带 7 个 DeepSeek"把吞吐提了 10 倍。**核心逻辑：把"贵的模型"用在"决定做什么"上，把"便宜的模型"用在"把它做完"上。**

### 11.3 必须做的三件事

1. **外挂检索/校验层**。DeepSeek 非幻觉率 35.9%，长任务里这是主要故障源。用它的 Search/Fetch API（现已不计工具调用费）或自建 RAG。
2. **写死 AGENTS.md / 规格文件**。`clx75` 的原话是 "What it needs: clear instructions"——DeepSeek 对模糊指令的容忍度低于 Claude，但对清晰指令的执行连续性高于 Claude。
3. **别默认开 Max**（对国外模型）。Fable 5.2 / Astra / Neon 的 Max 档是"测上限"用的，日常用 High 即可，能省 2–3 倍成本而只损失 3–5% 能力。

## 13. 最终结论（四句话版）

1. **能力上，DeepSeek-V4.1-Flash 约为当代最强（Claude Fable 5.2）的一半**：综合 0.49×、代码 0.42×、推理 0.32×、Agent 0.73×、对话 0.76×。它不是"准旗舰"，是"上一代旗舰的水平 + 这一代的价格"。**若以"日常主力"的标尺 Claude Opus 5.5 来衡量，差距是 0.56×（1/1.78）——这是更公道的对照系，因为 Opus 5.5 与 DS 同样定位为"天天用"，而 Fable 5.2 定位为"最雄心任务"。**
2. **对 Opus 5.5 的三个精确结论**：① Agent 上 DS 已追平（0.96×，AutomationBench 66.6 vs 69.5）；② 代码与推理仍是 2.2–2.7 倍的硬差距；③ 对话舒适度 Opus 5.5 是全场第二（1.44×），而它的代价是 337.8 秒首字时延——**DS 的"舒适度"输在文字温度，赢在"立刻有回应"**。
3. **效率上，它是无可争议的第一梯队**：每任务成本 1/44（对 Fable 5.2）、1/17（对 Opus 5.5）、首个 token 1.1 秒（首个**答案** token 46 秒，仍快于 Claude 的 189–338 秒）、输出 170 tok/s（第二快）、能力/美元排前五。**在"按 token 付费 + 大批量"的场景里，没有替代品。**
4. **在"自家 harness"这个特定前提下，差距会缩小**：官方自测显示它能在自选任务集上打平 Opus 5、超过 GPT-5.6-Sol；保守估计真实差距是 0.6–0.8×，而不是 AA 的 0.5×。**但无论怎么调 harness，"硬推理"和"不编造"这两项追不上——这两项该外包给 Claude / Gemini。**
