# AI 发展知识手册

> **这份笔记讲什么**：从 2018 年 GPT-1 到 2026 年 11 月的 GPT-6.2，大模型是怎么一步步从「会续写文字」变成「能自己干活」的。原文的六个阶段划分**整体是对的**，我保留了骨架，补齐了时间线上的事实，并改正了 4 处错误（见 [[#九、更正清单：原文哪里错了]]）。
>
> **信息核对时间**：2026-11-18。这个领域三个月就换一代，看到「最新」两个字请先看日期。

## 30 秒速览

1. **一条主线**：模型从「接龙」到「听话」到「会用工具」到「会自己规划」，每次跃迁都解决前一代的一个硬伤——听不懂指令 → 不会查资料 → 不会多步执行 → 执行不稳定。
2. **两次真正的分水岭**：**2022-11 ChatGPT**（对话可用，让普通人第一次用上大模型）和 **2023-06 Function Calling**（模型能调外部工具，从「说」变成「做」）。
3. **2024 是「会想」**（OpenAI o1 把推理过程显式化），**2025 是「会干」**（R1 开源把推理价格打下来，Claude Code 把 Agent 落到终端），**2026 是「出厂即 Agent」**（模型原生适配循环、规划、反思，不用外部框架硬凑）。
4. **Agent 的本质是一个循环**：想 → 做 → 看结果 → 再想，直到完成。区别只在于「这个循环由谁维护」——早期靠 LangGraph/AutoGen 这类外部框架，现在由模型和平台原生提供。
5. **判断一个产品是不是真 Agent，看三件事**：能不能调工具、能不能多步自主执行、出错能不能自己纠正。只调一次工具就结束的，是「函数调用」，不是 Agent。

> **一句话记住**：**大模型的能力边界，是按「它能不能改变外部世界」来分代的**——只能输出文字（阶段 1-2）→ 能触发一次外部动作（阶段 3）→ 能连续触发并自我纠错（阶段 4-6）。

## 一、先看全景：一张时间轴

| 时间 | 事件 | 为什么重要 |
| --- | --- | --- |
| 2018-06 | GPT-1（1.17 亿参数） | 证明「预训练 + 微调」这条路可行 |
| 2019-02 | GPT-2（15 亿参数） | 生成质量吓到 OpenAI 自己，一度选择不公开完整权重 |
| 2020-05 | GPT-3（1750 亿参数）**并开放 API** | 「模型即服务」的起点：不发布模型，只卖接口 |
| 2022-01 | InstructGPT | 用人类反馈调教模型「听懂指令」，对齐范式确立 |
| 2022-11-30 | **ChatGPT 发布** | 第一次让普通人觉得「这东西能用」，两个月破亿用户 |
| 2023-03 | GPT-4 / Claude 1 / 文心一言 / 通义千问 | 多模态与国产模型同时起跑 |
| 2023-06-13 | **OpenAI 发布 Function Calling** | 模型能输出结构化调用指令，真正接上外部世界 |
| 2023-03~04 | AutoGPT、BabyAGI | 第一次把「自主循环」摆到公众面前，也第一次暴露「死循环 + 幻觉」 |
| 2023 下半年 | RAG 成为标配 | 解决知识截止与幻觉：先检索，再回答 |
| 2024-09 | OpenAI o1 | 把「思考过程」变成可训练的对象，推理能力可被显式强化 |
| 2024-11 | MCP（模型上下文协议） | 工具接入有了统一标准，Agent 生态开始收敛 |
| 2025-01 | **DeepSeek-R1 开源** | 推理能力被开源模型追平，价格被打到地板 |
| 2025 上半年 | Claude Code、Codex、各类 CLI Agent | Agent 从 Demo 走进日常开发 |
| 2026 | GPT-6.2、Seed 2.1、DeepSeek-V4、Kimi K3、Qwen3.8-Max、Gemini 4 Argon、Claude Fable 5.2 | 「Agent 能力」成为旗舰模型的第一卖点，而不是附属功能 |

> **看这张表的方法**：不要记型号，记「每一代解决了上一代的什么硬伤」。型号三个月就过时，硬伤是结构性的。

## 二、阶段 1：基础大模型（2018-2020）

**原文的划分**：GPT-1、GPT-2、GPT-3 这一代，特点是「只能 API 调用，不会好好聊天」。

**准确的说法**：

| 模型 | 能不能 API | 能力状态 |
| --- | --- | --- |
| GPT-1（2018） | **不能**（只有论文和权重） | 会续写、会做简单分类，参数太小 |
| GPT-2（2019） | **不能**（OpenAI 分阶段释放，最初只给小模型） | 能写出像样的段落，但经常跑题 |
| GPT-3（2020-06） | **能**（OpenAI 正式开放 API） | 少样本学习惊艳，但仍然只是「高级接龙」 |

> **原文这里要改一处**：GPT-1、GPT-2 时代并没有 API 可调，真正的「API 调用」是从 **GPT-3（2020 年）** 开始的。这一代的核心特征是「**只会续写**」，而不是「只会 API」。

**这一代为什么不能直接用**：

- 它的训练目标是「预测下一个词」，所以它会**顺着你的话往下编**，而不是回答你。
- 你说「帮我写一封邮件」，它可能给你续出一封「别人的邮件」，甚至续出「以下是我为你写的邮件」然后开始胡说。
- 没有对话产品，普通人接触不到，只存在于实验室和 API 调用里。

> **一句话**：这一代是**能力储备期**——证明了「规模上去，能力就会涌现」，但还没找到「怎么让人用」的接口。

## 三、阶段 2：指令对齐，聊天助手诞生（2022）

**关键两步**：

1. **2022-01 InstructGPT**：不再只让模型「续写」，而是用人类标注的「好回答」去训练它「按指令办事」。这是「对齐（alignment）」的起点。
2. **2022-11-30 ChatGPT**：把 InstructGPT 包成一个网页对话框。技术上没有质变，**产品上是大爆炸**。

**这一代能做到什么**：

| 能力 | 有 / 没有 |
| --- | --- |
| 一问一答、听懂指令 | ✅ 有 |
| 多轮对话、记住上下文 | ✅ 有（有限） |
| 知道实时信息 | ❌ 没有，训练截止之后的事完全不知道 |
| 联网搜索 | ❌ 没有 |
| 查资料、算数、操作文件 | ❌ 只能告诉你「步骤」，不能真的执行 |
| 稳定性 | ⚠️ 会一本正经地胡说（幻觉） |

> 原文说「问它天气，它会说没有联网，要你自己去查」——**这个描述在 2022 年底到 2023 年初完全准确**。后来联网搜索变成产品标配（2023 年 Bing Chat / ChatGPT 插件 / 各家「联网模式」），这一条就不成立了。

**为什么这一代仍然是「被动」的**：它只会**输出文字**。它能告诉你怎么做，但不能替你做。所有动作最终都要你自己完成——这就是阶段 3 要解决的问题。

## 四、阶段 3：Function Calling，模型第一次能「动手」（2023）

**时间点**：2023-06-13，OpenAI 在 GPT-3.5/GPT-4 上正式推出 Function Calling。

**流程（原文写得对，这里补上「为什么这样设计」）**：

```
用户提问
   ↓
模型判断：这个问题需不需要调工具？
   ↓ 需要
模型输出一段结构化 JSON（函数名 + 参数）   ← 注意：模型不执行，只是「说要调什么」
   ↓
外部程序真正执行（联网 / 查数据库 / 跑代码）
   ↓
工具结果回填给模型
   ↓
模型整理成人类可读的答案
```

> **关键认知**：**模型自己从来不执行任何东西**。它只是输出「请调用 weather(city="北京")」这样一段结构化文本，真正执行的是你外面那层程序。这也是为什么 Agent 产品永远需要一个「运行时（harness）」——那个负责跑工具、管循环的程序。

**这一代还不是 Agent，原因很具体**：

- 只调用**一次**工具，拿到结果就回答，然后结束。
- 不能根据结果决定「下一步还要不要继续」。
- 不能组合多个工具完成一件复杂的事。

**同一时期还有两项关键技术**：

| 技术 | 解决什么 | 一句话 |
| --- | --- | --- |
| **RAG**（检索增强生成） | 知识截止、幻觉 | 先把你自己的文档检索出来塞进上下文，再让模型答 |
| **向量数据库 / Embedding** | 「按意思找」而不是「按关键词找」 | RAG 的地基 |

> **RAG 的意义**：它让模型能「读你给的资料」，而不是只靠训练记忆。这是企业落地大模型的第一块砖——至今仍是绝大多数「企业知识库问答」的实现方式。

## 五、阶段 4：早期 Agent，会循环但不可靠（2023 下半年）

**代表**：AutoGPT、BabyAGI，以及后来的各类「自主智能体」框架。

**这一代的循环（原文的四步总结得很好）**：

1. 思考：把大目标拆成几步
2. 执行：调一个工具，做一步
3. 反思：看结果，判断「完成了吗 / 错了怎么办」
4. 继续：进入下一步，直到完成

**举个具体例子**（原文的例子很好，保留）：让它「调研国内三家 AI 公司，整理一份对比报告」，它会自己循环：搜 A 公司 → 整理 → 搜 B 公司 → 整理 → 汇总输出报告。

**为什么当时只能做 Demo**：

| 问题 | 表现 | 根因 |
| --- | --- | --- |
| 死循环 | 同一件事反复做，停不下来 | 没有可靠的「终止判断」 |
| 幻觉累积 | 第三步基于第二步的错误继续编，越滚越错 | 错误不会被发现和回滚 |
| 稳定性差 | 同样的任务，今天能做对，明天就崩 | 靠提示词硬凑流程，没有结构化约束 |
| 需要人工返工 | 跑完还得人检查、重跑 | 没有可靠的验证环节 |

> **一句话**：这一代证明了「自主循环这条路走得通」，但也证明了「光靠提示词约束不住模型」。后来的所有进步，本质都是在**把循环做得更可靠**——用更强的模型、更结构化的框架、更好的验证机制。

## 六、阶段 5：原生推理，会「想」了（2024-2025）

> **原文这里有一处年份错误**：原文写「阶段 5：模型原生增强推理（2024）DeepSeek-R1」。**DeepSeek-R1 是 2025 年 1 月发布的**，2024 年的标志性事件是 **OpenAI o1（2024 年 9 月）**。

**这一代解决了什么**：让模型在回答之前**先想一段**（思维链），并且把「想得好不好」变成可以训练的目标（强化学习）。

| 时间 | 模型 | 意义 |
| --- | --- | --- |
| 2024-09 | OpenAI **o1** | 推理过程显式化，难题正确率大幅提升 |
| 2025-01 | **DeepSeek-R1**（开源） | 推理能力被开源模型追平，API 价格被打到地板，直接改变行业定价 |
| 2025 起 | 各家「思考模式」 | o3、Gemini Thinking、Qwen QwQ、GLM-Z、Kimi K 系列等全面跟进 |

**关于「工具调用越来越稳定，但仍依赖外部框架」**（原文判断准确）：

- 这一代模型「想得更好了」，但**循环还得靠 LangGraph、AutoGen、CrewAI 这类框架来跑**。
- 框架负责：状态管理、工具注册、重试、终止条件、人工介入点。
- 所以它是一个**过渡期**：模型变强了，但「怎么把多步任务跑稳」还是工程问题，不是模型问题。

> **一句话**：**推理能力解决「想得对不对」，框架解决「跑得稳不稳」**。这两件事在阶段 5 是分开的，到阶段 6 才开始合并。

## 七、阶段 6：Agent 时代（2025 至今）

**原文的两条判断都成立，这里给它们补上证据**：

| 判断 | 2026 年的证据 |
| --- | --- |
| 模型出厂原生适配 Agent 循环、规划、反思 | Seed 2.1 主打「Agent 长链路任务、自主规划与动态修复」；DeepSeek-V4 在 Agentic Coding 评测上做到开源最佳；Kimi K3 面向「软件工程、知识工作、深度研究」优化 |
| 平台提供 Agent SDK，普通开发者能直接搭 | OpenAI 的 Agent 能力内置进 ChatGPT Work / Codex；Anthropic 有 Claude Agent SDK；Google 有 Vertex AI Agent Builder；国内阿里百炼、腾讯云 ADP、火山方舟都提供 Agent 编排 |

**这一代真正的变化，不是「模型更聪明」，而是三件事**：

1. **循环内置**：模型自己知道「该调工具了」「该验证了」「该停了」，不再完全靠外部框架拼。
2. **长任务可跑**：从「十几步」到「几百步」——混元 Hy3 官方披露可稳定支撑 **495 步**的复杂智能体工作流；Qwen3.8-Max 内部测试自主完成了一个 **16 天**的软件工程项目。
3. **成本可算**：Agent 一次任务要烧很多 token，所以 2026 年的旗舰模型全都在强调「**同等效果下少用 token**」（GPT-6.2 的卖点之一就是输出 token 大幅下降、单任务成本降到上一代的三分之一）。

> **一句话**：阶段 5 是「模型会想，但活还得人来编排」；阶段 6 是「模型会想，也会自己编排，人只给目标和边界」。

## 八、今天（2026-11）能操作本地文件的 Agent 有四种形态

原文这四种形态的划分**很准**，这里补上各自的限制：

| 形态 | 交互方式 | 能访问什么 | 典型代表 | 主要限制 |
| --- | --- | --- | --- | --- |
| **1. CLI 终端** | 纯命令行文字 | **整台机器**（受系统权限约束） | Claude Code、Codex CLI、Gemini CLI、TRAE CLI | 没有图形界面，学习成本高；权限给大了很危险 |
| **2. 桌面独立 App** | 完整 GUI 窗口 | 本机文件 + 操作系统 | WorkBuddy、DSH（DeepSeek Harness）、ZCode、Claude Cowork | 各个 App 权限模型不同，要看清它到底能碰什么 |
| **3. IDE 插件** | 嵌在编辑器里 | **只有当前打开的工作区** | TRAE、Cursor、GitHub Copilot、通义灵码、CodeBuddy | 不能随便读电脑其他位置；跨项目操作受限 |
| **4. 本地 WebUI** | 本机起服务，浏览器打开 | 取决于后端给你的目录权限 | Open WebUI、各类本地部署面板 | 本质是「本地跑的服务」，安全性取决于配置 |

> **原文的个人观察**：「现在国内 agent 最普遍的是第 2 种，有很多 app：workbuddy、dsh、zcode」。这是**截至 2026-11 的合理观察**，保留。需要说明的是：这只是「桌面 App 形态在国内很热」，**覆盖面最广的其实是第 3 种（IDE 插件）**——因为几乎所有写代码的人都在用。

**四种形态怎么选**：

- 要**改整个仓库**、跑测试、git 提交 → CLI 或 IDE 插件
- 要**处理文档、表格、做汇报** → 桌面 App
- 要**长期挂后台、随时在手机上看进度** → 桌面 App + 移动端（Claude Cowork 已支持远程调度）
- 要**把 AI 装进自己的系统** → WebUI / API，而不是用别人的客户端

## 九、更正清单：原文哪里错了

| # | 原文 | 问题 | 正确说法 |
| --- | --- | --- | --- |
| 1 | 阶段 1「只能 API 调用」 | **时代错位** | GPT-1（2018）、GPT-2（2019）**没有对外 API**；API 是 **GPT-3（2020-06）** 才开放的 |
| 2 | 阶段 5「（2024）DeepSeek-R1」 | **年份错** | DeepSeek-R1 是 **2025-01** 发布；2024 年的标志是 **OpenAI o1（2024-09）** |
| 3 | 阶段 2「（2021-2022）」 | 偏早半年 | InstructGPT 是 2022-01，ChatGPT 是 **2022-11-30**；2021 年还没有可用的对话产品 |
| 4 | 「这时还不是 Agent，只会调用一次工具」 | 表述对，但容易误解 | 准确说：**Function Calling 是「一次工具调用」**；Agent 的门槛是「能根据结果决定下一步」，不是「调了几次」 |
| 5 | 阶段 2「不知道实时信息……无法使用联网搜索」 | **已过时** | 这是 2022-2023 年初的状态；2023 年起联网搜索成为产品标配 |
| 6 | 阶段 6「2025-至今」 | 准确 | 保留，但可补充：2026 年的标志是「Agent 能力成为旗舰模型第一卖点」 |

> **为什么这些错误值得记**：不是抠字眼。**把 R1 记成 2024，就会把「推理能力开源化」和「o1 发布」混成一件事**，后面理解行业格局（为什么 2025 年 API 价格集体跳水）就会错位。时间线是理解这个行业的地基。

## 十、把六个阶段串成一句话

```
阶段 1  会接龙        —— 只会预测下一个词
阶段 2  会听话        —— 对齐后能问答，但只会输出文字
阶段 3  会动手        —— 能触发一次外部工具
阶段 4  会循环        —— 能多步执行，但不可靠
阶段 5  会思考        —— 推理显式化，跑得稳靠框架
阶段 6  会干活        —— 循环、规划、反思内置，人只给目标
```

每一代都在补上一代的洞：**听不懂 → 不会查 → 不会做 → 做不稳 → 想不清 → 不用人管**。

> **最后提醒**：这份笔记里的模型版本会很快过时（三个月一代），但**六个阶段的划分和每一代解决的硬伤，短期内不会变**。读的时候记结构，别记型号。
