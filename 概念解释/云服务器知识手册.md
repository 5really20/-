## 30 秒速览

1. **云服务器 = 别人机房里的一台虚拟机**，你租的是"计算 + 存储 + 网络"三件套和一堆托管服务，不是一台物理机；所以"CPU 型号、邻居、宿主机"都不保证。
2. **选型先定场景再定规格**：个人博客/小站上用轻量应用服务器，正经业务上 ECS，重 IO 或合规要求才看裸金属；**先小后大**比一次买足更省钱，云盘和带宽都能后调。
3. **存储和网络的坑比机器本身多**：云盘扩容后必须 `growpart` + 文件系统扩容才生效；公网访问要**安全组 + 系统防火墙 + 服务监听地址**三处都放行；EIP 和固定公网 IP 是两回事。
4. **安全按五层做**：网络（安全组/云防火墙）→ 主机（补丁/SSH 密钥/最小端口）→ 应用（WAF/依赖漏洞）→ 数据（加密/备份）→ 账号（AK 最小权限 + MFA）。**SSH 密码登录不停用，前面全白做。**
5. **可用性靠"备份 + 演练"，不靠"多买一台"**：先想清 RPO/RTO，再选冷/温/热备；没做过恢复演练的备份等于没有备份；停机也计费、欠费 15 天会隔离释放，这两条最容易踩。

> **一句话记住**：**云服务器不是"一台更便宜的电脑"，而是一整套"可租用、可弹性、按秒计费、但责任边界在你这边"的基础设施**——厂商保证的是"硬件可用"，操作系统以上的安全、备份、可用性，全是你的活。

## 一、云服务器是什么

### 1. 一句话定义

**云服务器（Cloud Server）**：相当于在云上租一台电脑。你按配置（  CPU(几核)、内存(几G)、磁盘、带宽(几M)、存储盘大小。一般来说cpu和内存比是1：2   ）和使用时长付费，随时开通、随时释放。你拿到的是一个有 root / 管理员权限的**完整虚拟机**，而不是"网页空间"。

### 2. 你能租到的几种形态

选型之前先看这张表——很多人一上来就买 ECS（阿里云的计算服务），其实轻量应用服务器就够了。

| 形态                        | 是什么                                                | 适合谁                       |
| ------------------------- | -------------------------------------------------- | ------------------------- |
| **虚拟主机（空间）**              | 一台服务器切出很多目录，只给放网站文件，共用 PHP/MySQL，装不了软件、改不了系统       | 纯静态小站、老式建站、极低预算           |
| **VPS（虚拟私人服务器）**          | 物理机用 KVM/OpenVZ 切出来的虚拟机，小厂售卖，root 权限，但不能弹性扩容、无 SLA | 练手、代理、个人小站、临时测试           |
| **轻量应用服务器**               | 云厂商的"套餐机"：实例 + 带宽 + 月流量 + 常用镜像打包，控制台简化、价格便宜        | 新手、个人站长、博客、小程序后端          |
| **云服务器（ECS / CVM / EC2）** | 标准 IaaS 虚拟机，规格族、网络、存储、安全组全部可选可组合                   | 企业业务、集群、对架构有要求的场景         |
| **裸金属服务器**                | 不做虚拟化，直接交付一台物理机，无超分损耗                              | 高性能数据库、HPC、自建虚拟化、有合规要求的业务 |
| **容器 / Serverless**       | 不关心机器，只提交镜像或一段代码，平台负责调度和伸缩                         | 微服务、突发流量、事件驱动任务           |
性能结论：虚拟主机 ≪ VPS ≈ 轻量应用服务器 < ECS
### 3. 典型用途（六类）

#### （1）运行网站和线上业务（最常见）

企业官网、商城、博客、论坛、小程序或 App 的后端；对外提供 HTTP API、微服务集群；结合负载均衡（SLB）、对象存储（OSS）、CDN 组成完整架构，承担高并发访问。

#### （2）运行程序和数据库

自建 MySQL、PostgreSQL、Redis、MongoDB、MQ 等（云数据库底层也跑在云服务器上）；定时任务、爬虫、数据采集、自动化脚本、聊天机器人；视频转码、图片处理、批量计算、AI 推理（这类任务通常选 GPU 实例）。

#### （3）开发和测试环境

临时开发、测试、预发布环境，用完就销毁；CI/CD 构建机、压力测试机、代码托管（GitLab、Gitea）；学习 Linux、学习运维、做实验（新手最常用的场景之一）。

#### （4）存储和备份

私有网盘（Nextcloud、Alist）、图床、文件服务器；数据库异地备份、容灾节点；内网穿透中转、跳板机、堡垒机（运维入口，可审计）。

#### （5）自用或小众服务

个人 VPN、代理节点（注意当地法规）；游戏服务器（Minecraft、联机私服、对战服）；邮件服务器、DNS、监控告警（Prometheus、Zabbix）；家庭 NAS 的替代、下载机、媒体服务器（Jellyfin）。

#### （6）弹性场景

大促、活动、考试报名等流量高峰临时扩容，结束后释放；搭建容器集群（K8s）的节点，用弹性伸缩自动增减机器。

## 二、怎么选：标准云服务器 vs VPS

### 2.1 标准云服务器（ECS / CVM / EC2）

#### 优点

- **弹性**：秒级创建或释放，CPU、内存、磁盘、带宽可在线升降配，配合 Auto Scaling 自动扩缩容。
- **高可用**：多可用区部署、宕机自动迁移、SLA 99.9%~99.99%，云盘三副本不丢数据。
- **快照与镜像**：随时备份、回滚、批量复制出相同机器（几分钟复制出 100 台）。
- **网络与安全**：VPC 隔离、安全组、弹性 IP、负载均衡、DDoS 基础防护。
- **生态完整**：RDS、Redis、对象存储、CDN、日志监控、容器服务一站式对接。
- **免硬件运维**：不用管机房、电源、硬盘坏盘、RAID。
- **API / IaC**：可用 Terraform、Ansible、SDK 做基础设施即代码，适合 CI/CD。
- **全球节点**：按业务就近部署，多地域容灾。
- **合规**：正规发票、备案支持、等保/可信云认证，能过企业审计。

#### 缺点

- **长期运行贵**：一台 4核8G 包年下来往往比同配置独立服务器还贵，"云比物理机便宜"是误解。
- **带宽尤其贵（国内）**：公网带宽按 M 计价，100M 独享月费可能上千。
- **隐藏费用多**：流量费、快照费、公网 IP 闲置费、跨区流量费、磁盘扩容费。
- **有学习成本**：VPC、安全组、子网、路由表对新手不友好。
- **厂商锁定（vendor lock-in）**：用了云厂商专有产品（专有数据库、函数计算）后迁移成本高。
- **责任共担**：平台只保证底层，系统补丁、安全加固、数据备份仍要自己做。
- **账号与合规风险**：违规内容可能被封号停机，数据取回麻烦。
- **跨境延迟**：海外节点访问国内慢，国内节点对外也慢。

### 2.2 VPS（KVM / OpenVZ 小厂产品）

#### 优点

- **便宜**：$3~10/月能拿到 1~2 核 1~2G，学生党友好。
- **开通快**：付款几分钟就能用，支持支付宝、加密货币。
- **自由度高**：root 权限随便折腾，可装任意系统/内核（KVM）。
- **适合非关键用途**：练手、代理、爬虫、个人小站、临时测试。
- **套餐简单**：一般不限流量（限速）或流量很大，不像云厂商按 M 卖带宽。

#### 缺点

- **超卖严重**：一台物理机切几十上百个，晚上邻居跑满就卡。
- **无 SLA、无快照、无备份**：宿主机挂了数据可能一起没。
- **单点故障**：通常只有一个节点，没有迁移能力。
- **不能弹性扩容**：升级只能停机换套餐（部分支持在线升）。
- **商家跑路风险**：小厂说关就关（"跑路"是行业常态），预付多年要谨慎。
- **IP 风险**：IP 可能被墙、被列入黑名单、是 NAT 共享 IP，端口受限。
- **几乎无技术支持**：出问题只能发工单等回复，或自己去论坛问。
- **合规问题**：部分海外商家无正规合同/发票，企业报销和合规审计过不了。

### 2.3 轻量应用服务器（新手最该先了解的）

相当于"云服务器的套餐版"：厂商把 2核2G / 4核8G 的实例、固定带宽（常见 3~6M）、每月流量包、以及 WordPress / 宝塔 / LNMP 等应用镜像打包成一个固定价格的套餐。控制台只保留最常用的几项，防火墙规则比安全组简单。

| 维度     | 说明                                                              |
| ------ | --------------------------------------------------------------- |
| **优点** | 便宜、开箱即用、带宽通常比同价位 ECS 大方    注：如果租的时间大于1年用ecs而不是轻量。               |
| **限制** | 规格不能自由升降配、带宽和流量包固定、无高级网络能力（不能挂多网卡、不能进复杂 VPC 拓扑）、后续迁移到 ECS 需要手动搬 |
| **适合** | 个人博客、企业展示站、小程序的轻量后端、学习练手                                        |

### 2.4 选型决策（一句话版）

> - 只是放个网站、预算几百块/年 → **轻量应用服务器**
> - 要给团队用、要集群、要对接 VPC/负载均衡/数据库 → **ECS**
> - 跑数据库、要独占性能、有等保要求 → **裸金属或高主频实例**
> - 流量忽高忽低、不想管机器 → **容器或 Serverless**
> - 纯练手、要便宜、能接受不稳定 → **便宜 VPS**
> - 只想传 HTML、不会碰命令行 → **虚拟主机**

## 三、这台机器本身

### 3.1 核心概念

| 概念                                | 通俗解释                                                                                           |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| **实例（Instance）/ ECS / CVM / EC2** | 就是那台虚拟机。云厂商里叫法不同，本质都是"虚拟机实例"                                                                   |
| **vCPU**                          | 虚拟出来的 CPU 核。就是"分给你几个核"，和物理核不完全等价（可能超卖）                                                         |
| **内存**                            | 和家里电脑一样，8G、16G、32G。数据库类应用比 CPU 更吃内存                                                            |
| **实例规格族**                         | 按"偏重什么"分的配置包：通用型（均衡）、计算型（算得快）、内存型（内存大）、本地盘型、GPU 型（跑 AI）、高主频型。选错类型事倍功半                          |
| **镜像（Image）**                     | 相当于系统安装包 + 预装环境：CentOS、Ubuntu、Debian、Windows Server、应用镜像（宝塔/WordPress）、你自己做的自定义镜像。机器都是从镜像创建出来的 |
| **快照（Snapshot）**                  | 相当于存档或时间机器备份，保存某个时刻磁盘的状态。升级前打一个，出问题能回滚                                                         |
| **弹性伸缩（Auto Scaling）**            | 相当于自动加派机器：白天流量涨就多开几台，夜里降就关掉几台                                                                  |
| **密钥对 / 密码**                      | 开机第一道门。公钥放机器上、私钥自己留，比密码安全得多                                                                    |
| **用户数据（User Data）**               | 开机时自动执行的脚本，比如装 Nginx、改 SSH 端口、初始化环境                                                            |

### 3.2 生命周期与状态（很多人栽在这里）

- **创建中 → 运行中 → 停止 → 启动 → 重启 → 释放**。释放后数据不可恢复。
- **停止 ≠ 释放**：按量付费实例停止后计算资源可能不收费，但云盘、弹性公网 IP、快照继续计费（详见第九章）。
- **重装系统 / 更换系统盘**：会清空系统盘，数据盘默认保留，操作前先打快照。
- **到期与隔离**：包年包月到期未续费，会先进入"隔离期/停机保留期"（各厂商数天到十几天不等），逾期自动释放且数据销毁。务必设好到期提醒和自动续费。

### 3.3 容易被忽略的规格细节

> **突发性能实例（共享型，如 t5 / t6 一族）**：便宜，但有 **CPU 积分** 机制。基准性能只有 10%~20%，日常跑满会消耗积分，积分耗尽后 CPU 被限制到基准值——网站突然变卡、后台跑批特别慢，往往就是这个原因。长期跑满负载的业务不要选。

- **CPU 型号与主频不保证固定**：同一规格族在不同批次机器上可能是不同代 CPU、不同主频，对性能敏感的业务要选"高主频"或"独享型"规格。
- **超分（overcommit）**：vCPU 是虚拟的，物理机上的核会被多个实例共享；独享型 / 企业型规格才做资源隔离。
- **NUMA 与绑定**：超大规格（几十核）的机器跨 NUMA 节点访存会变慢，数据库类业务关注这一点。
- **本地盘 vs 云盘**：本地盘（NVMe SSD）延迟低、吞吐高，但数据绑在这台物理机上，宿主机故障可能丢数据，只能存缓存/临时数据；云盘是三副本网络盘，可靠但延迟略高。
- **GPU**：分"GPU 直通"和"vGPU 虚拟化"，还有推理卡与训练卡的区别，按业务选。
- **实例元数据服务**：实例内部可以通过 `169.254.169.254` 这个地址查到自己的实例 ID、地域、甚至临时凭证。方便，但如果应用有 SSRF 漏洞，攻击者能借它拿到云账号凭证——生产环境要限制访问。

## 四、存储：数据放在哪里

### 4.1 核心概念

| 概念 | 通俗解释 |
| --- | --- |
| **系统盘与数据盘** | 系统盘相当于 C 盘（装操作系统），数据盘相当于 D 盘（放业务数据）。两者都能单独扩容 |
| **云盘类型（ESSD / SSD / 高效云盘）** | 相当于硬盘档位。ESSD 是固态盘里的高性能档，适合数据库；普通云盘便宜、较慢 |
| **IOPS 与吞吐** | IOPS 是每秒能做多少次读写（零碎小文件场景）；吞吐是每秒能传多少 MB（大文件连续读写场景）。数据库看 IOPS，视频/备份看吞吐 |
| **对象存储（OSS / S3）** | 相当于不限容量的网盘，存图片、视频、备份包。按量计费，通过 HTTP 访问，不是挂在系统盘里的目录 |
| **文件存储（NAS）** | 相当于共享网盘 / 共享文件夹，几台服务器可以同时挂同一个目录，适合多机共享上传目录 |
| **快照与备份策略** | 定期自动存档的策略，比如每天凌晨 2 点自动打一次，保留最近 7 天 |
| **三种存储形态** | **块存储**（云盘）像硬盘，只能一台机器用；**文件存储**（NAS）像共享文件夹，多机同时读写；**对象存储**（OSS）像网盘，通过 HTTP 接口存取，不适合当本地磁盘用 |

### 4.2 云盘的隐藏细节

- **性能预配置**：部分云盘型号允许单独购买 IOPS 和吞吐上限，性能不是"盘越大越快"这么简单，但通常容量越大基线性能越高。
- **加密盘**：可以开启云盘加密（KMS 托管密钥），对上层透明，合规场景常用。
- **共享块存储**：一块盘同时挂到多台机器（需要集群文件系统配合），用得少但存在。
- **扩容后必须扩文件系统**：控制台把云盘从 100G 改成 200G，`df` 里看到的还是 100G——还要在系统里 `growpart` 扩分区 + `resize2fs`（ext4）/ `xfs_growfs`（xfs）扩文件系统。这是新手最常见的"扩容没生效"。
- **新买的数据盘要先分区、格式化、挂载**，并写进 `/etc/fstab`，否则重启后挂载丢失。**fstab 写错会导致机器起不来**（要用 VNC 救）。
- **磁盘满是最常见的线上故障之一**：日志、Docker 镜像、core dump 都能把盘吃满，建议单独给 `/var/log` 做清理策略或挂独立盘。

### 4.3 快照进阶

- **一致性**：普通快照是"崩溃一致性"（类似拔电源后的状态），数据库最好先停写或做应用一致性快照，否则回滚后数据可能不一致。
- **快照是增量存储、按实际占用容量计费**，长期堆积会变成一笔隐性账单；要配保留策略自动清理。
- **快照不能直接跨地域使用**：要异地容灾，需要把快照 / 镜像"复制"到目标地域，或者用跨地域备份功能。
- **快照回滚会覆盖当前磁盘数据**，回滚前先给现状再打一个快照。
- **快照 ≠ 备份的终点**：快照和云盘在同一个账号、同一个地域，账号被盗或被封时一起没。真正的备份要异地、异账号。

### 4.4 备份的 3-2-1 原则

> **3 份数据、2 种不同介质/存储、1 份在异地（或异账号/离线）。**
>
> 云上最容易犯的错是"只开了快照"，这只能防误删和升级失败，防不了账号级事故。

## 五、网络：最容易让人困惑的部分

### 5.1 核心概念

| 概念 | 通俗解释 |
| --- | --- |
| **VPC（专有网络）** | 你自己的小区围墙，机器都在里面，外人不经允许进不来。云上网络的"大容器" |
| **子网 / 交换机** | 小区里的楼栋。同一子网内默认互通，跨子网要走路由 |
| **路由表** | 小区里的路牌，决定"去哪个网段走哪个出口"。配错路由表 = 机器能上网但互相不通，或压根出不去 |
| **私网 IP 与公网 IP** | 私网 IP 是内部房间号（`192.168.x.x`，外网访问不到）；公网 IP 是对外的门牌号 |
| **固定公网 IP 与弹性公网 IP（EIP）** | 固定公网 IP 绑在这台机器上、不能解绑，机器释放就没了；EIP 像一个可以摘下来换到别的机器上的手机号，机器重建后 IP 不变，不影响 DNS 解析 |
| **辅助私网 IP / 弹性网卡（ENI）** | 一块网卡可以挂多个私网 IP；也能给一台机器插多块网卡（分属不同子网），做多网段接入或网络设备场景 |
| **安全组** | 门禁规则或白名单，工作在**实例层面**：只允许 22 端口给公司 IP，80/443 放开给所有人 |
| **网络 ACL** | 楼梯口再加一道门禁，作用于**整个子网**，比安全组更粗粒度、无状态 |
| **云防火墙** | 小区大门的保安，做南北向（公网进出）和东西向（VPC 内部机器之间）流量管控，比安全组更细、可审计 |
| **带宽计费** | 相当于水管粗细。选"固定带宽"是租一根固定粗的水管，费用固定；选"按使用流量"是按用水量付费，瞬时能超上限但账单会涨 |
| **共享带宽包** | 多台机器共用一条带宽池，按总量买比每台单独买便宜，适合机器多但流量不均的场景 |
| **NAT 网关** | 小区的总出口：内部机器都不带公网 IP，统一通过它出网（下软件包、调外部接口），外网无法主动访问这些机器 |
| **负载均衡（SLB / CLB）** | 前台分流：一个域名对应多台机器，统一分配流量，某台挂了自动跳过 |
| **专线 / VPN** | 从公司机房到云上拉一根专属网线，流量不走公网，稳定安全 |
| **对等连接 / 云企业网（CEN）** | 把两个 VPC 拉通（对等连接是两两相连、不传递；CEN 是中心枢纽，多 VPC 一次接好） |
| **DNS 与 CDN** | DNS 是查号台，把域名翻译成 IP；CDN 是把内容提前分发到离用户最近的节点，静态资源不回源 |
| **IPv6** | 新一代地址，国内云厂商基本都支持双栈，但要注意安全组同样要放行 IPv6 流量 |

### 5.2 负载均衡的四层与七层

- **四层（TCP/UDP）**：只看 IP 和端口转发，速度快、协议无关，但无法按域名/URL 分流，也看不到 HTTP 内容。
- **七层（HTTP/HTTPS）**：能按域名、路径、Header 分流，能做 HTTPS 卸载、会话保持（Cookie）、改写，功能多但多一层解析开销。
- **健康检查**：定期探测后端端口或指定路径，失败就摘除。检查路径配错会导致"机器好好的却一直被摘"。
- **会话保持**：把同一用户的请求固定到同一台后端，否则登录态会丢。更好做法是会话外置到 Redis。
- **权重与最小连接数**：按机器性能分配流量。
- **后端不要直接暴露公网**：让 SLB 持公网 IP，后端只开私网。

### 5.3 带宽的真相

- **内网带宽和公网带宽是两条独立通道**：内网（同 VPC 内机器互访）通常免费且很大，公网才是花钱的。
- **公网带宽常按"峰值"或"保底 + 突发"售卖**，被刷流量（盗链、CC 攻击、爬虫）能在几小时内跑出天价账单，务必设"流量告警"和带宽上限。
- **出方向（上行）收费，入方向（下行）通常免费**——所以"下载别人东西"便宜，"给别人传东西"贵。
- **PPS（每秒包数）也是限制**：小包攻击或高频心跳可能先撞 PPS 上限而不是带宽上限。
- **MTU**：默认约 1500，叠加 VXLAN 等隧道后会降到 1450 左右，跨云/专线场景要留意分片问题。

### 5.4 已经过时的概念

> **经典网络（Classic Network）**：早期所有用户共享一个大内网，安全性差，主流厂商已停止新购。看到老教程里"经典网络"直接跳过，一律用 VPC。

## 六、访问与运维

### 6.1 怎么连上它

| 概念                              | 通俗解释                                                         |
| ------------------------------- | ------------------------------------------------------------ |
| **SSH（Secure Shell） 密钥对**       | 登录凭证，相当于一把钥匙。公钥放机器上，私钥自己留着，比密码安全得多 (最常见的)                    |
| **远程连接**                        | Windows 用 RDP（3389），Linux 用 SSH（22）                          |
| **VNC / 远程控制台**                 | 系统起不来、网络断了、SSH 进不去时的唯一救急入口，相当于直接接显示器。fstab 写错、防火墙把自己关外面，都靠它救 |
| **堡垒机 / 跳板机**                   | 唯一的前台入口，所有运维人员先登录它再跳到目标机，便于审计、避免 22 端口直接暴露                   |
| **控制台 / API / CLI / Terraform** | 四种操作方式：点鼠标、调接口、敲命令行、写配置文件。机器一多，手工点必然出错，要转 IaC                |
| **用户数据（User Data）与云助手**         | 开机自动执行的脚本（装 Nginx、初始化环境）；云助手是批量在所有机器上执行命令/定时任务的工具            |

### 6.2 可观测性

- **云监控**：仪表盘 + 警报器，盯 CPU、内存（需装 Agent）、磁盘、带宽、连接数，超阈值发短信/微信/钉钉。
- **日志服务（SLS 类）**：集中收集系统和应用日志，能检索、能配告警，比登机器 `tail -f` 靠谱。
- **进程/端口监控**：云监控只能看到机器层面，"Nginx 挂了但 CPU 正常"它发现不了，要额外做 HTTP 探活或进程监控。
- **NTP 时间同步**：时间漂移会导致 HTTPS 证书校验失败、集群脑裂、日志顺序错乱、数据库主从异常。默认要开 chrony/ntpd。
- **监控 Agent**：内存、磁盘分区、GPU 等指标必须装 Agent 才采得到。

### 6.3 故障排查手册（按顺序查，别乱试）

> 排查原则：**从外到内、从下到上**。先确认网络通不通，再看服务活不活，最后看代码对不对。

#### （1）SSH 连不上

安全组是否放行 22（以及你的来源 IP 是否变了）→ 实例是否运行中 → 私钥是否配对/权限是否 600 → 系统是否启动完成（看 VNC 画面）→ 系统盘是否 100% 满 → sshd 是否在跑（用 VNC 登录后 `systemctl status sshd`）→ 是否被 fail2ban 封了 IP。

#### （2）网站打不开但机器正常

域名解析对不对（`dig` / `nslookup`）→ 安全组 80/443 → 本机 `curl 127.0.0.1` 是否通 → Nginx 配置与端口监听（`ss -lntp`）→ 后端服务是否活着 → 证书是否过期。

#### （3）CPU 100%

`top` 看是哪个进程；是业务峰值就扩容，是挖矿就查异常进程和外联 IP；再看是不是被 CC 攻击（大量来自同一批 IP 的请求）。

#### （4）带宽打满

`iftop` / `nload` 看谁在跑；常见是被人盗链、被刷、备份任务在跑、或程序死循环重试。

#### （5）磁盘满

`df -h` 找分区，`du -sh /*` 找目录；重点查 `/var/log`、Docker 的 `/var/lib/docker`、journald 日志、core 文件。清完记得配 logrotate。

#### （6）内存 OOM

`dmesg | grep -i oom` 确认；看是不是 Java/PHP 进程内存泄漏，或没设 swap、容器没设 limit。

#### （7）机器起不来

VNC 看启动报错，常见是 fstab 写错、内核升级失败、系统盘满、误改 sshd/网络配置。

### 6.4 压测与容量估算

- **工具**：ab、wrk、JMeter、locust。
- **粗算公式**：`带宽 ≈ 并发数 × 单请求大小 ÷ 响应时间`。例如 1000 并发、每请求 100KB、1 秒响应 ≈ 100MB/s ≈ 800Mbps。
- **先压出单机极限**，再决定加机器还是升配置；不要凭感觉买规格。

## 七、安全：最容易忽略，也最致命

### 7.1 先建立层次感

> 网络层（安全组 / ACL / 云防火墙）→ 主机层（系统加固 / 主机安全）→ 应用层（WAF / 代码）→ 数据层（加密 / 备份 / 权限）→ 身份层（账号 / AK / MFA）
>
> **只配安全组，等于只锁了小区大门，家里门还开着。**

### 7.2 各层要点

| 概念 | 通俗解释 |
| --- | --- |
| **主机安全（HSS / 安骑士类）** | 装在机器里的保安：基线检查、漏洞扫描、木马查杀、防勒索、登录审计、异常进程告警。免费版通常够个人用，务必开 |
| **WAF** | 网站专用防火墙，挡 SQL 注入、XSS、CC 攻击、恶意爬虫。它看的是 HTTP 内容，安全组看不懂这些 |
| **DDoS 基础防护 / 高防** | 基础防护免费但有阈值，超过会被"黑洞"（直接封掉公网，业务全断）。被持续攻击要上高防 IP 或 CDN 清洗 |
| **云防火墙** | 统一管控南北向 + 东西向流量，能按域名/情报拦截，比逐个安全组配规则省事 |
| **基线检查** | 检查系统配置是否合规：有没有弱口令、有没有开无用端口、SSH 是否允许 root、补丁是否打全 |
| **漏洞扫描** | 扫系统和中间件的已知 CVE，扫出来要排期修，不是点一下"忽略" |

### 7.3 SSH 加固（五步，成本极低收益极高）

1. **改端口**：`/etc/ssh/sshd_config` 里 `Port` 改成非 22（注意同步改安全组）。
2. **禁 root 直登**：`PermitRootLogin no`，用普通用户 + sudo。
3. **只允许密钥**：`PasswordAuthentication no`，`PubkeyAuthentication yes`。
4. **装 fail2ban**：连续失败几次自动封 IP。
5. **安全组只放行自己的固定 IP**，别写 `0.0.0.0/0`。

### 7.4 端口最小化

只开业务必需的端口。**22、3389、3306（MySQL）、6379（Redis）、27017（MongoDB）、9200（ES）、2375（Docker API）暴露公网都是高危**，Redis/MongoDB 未授权访问是最经典的被入侵入口。数据库一律只走内网，或经跳板机。

### 7.5 账号与凭证

- **主账号只用来开子账号**，日常操作全用子账号（RAM/IAM），按最小权限授权。
- **AccessKey 不要写进代码、不要提交到 Git**；用 STS 临时凭证或角色扮演。
- **开 MFA（多因素认证）**，尤其是主账号。
- **AK 定期轮换**；离职人员立即禁用。
- **开操作审计**（ActionTrail 类），谁动了什么都有记录。

### 7.6 元数据服务与 SSRF

实例内的 `169.254.169.254` 能取到实例信息和临时凭证。如果网站有 SSRF 漏洞，攻击者可以借它拿到云账号权限。生产环境应限制元数据访问（加固模式 / 限制跳数），或干脆关闭。

### 7.7 被入侵后的处置顺序

> 隔离（先改安全组断公网，**别急着重启**，会丢内存证据）→ 取快照留证 → 查异常进程、定时任务、ssh 公钥、登录日志 → 确认入口（弱口令？漏洞？AK 泄漏？）→ 重装系统 + 从干净备份恢复数据 → 修漏洞 → 复盘。

### 7.8 合规

等保 2.0（二级/三级）是国内企业上云的常见要求，涉及日志留存（一般不少于 6 个月）、访问控制、审计、数据备份等；金融、医疗、政务还有行业细则。个人站点至少做到：备案、实名、不存违规内容。

## 八、可用性与容灾

### 8.1 基础概念

| 概念 | 通俗解释 |
| --- | --- |
| **地域（Region）** | 北京、上海、广州、新加坡。机器在哪就离哪的用户近，数据跨地域通常不能随意迁移 |
| **可用区（AZ）** | 同一城市里物理上隔开的几个机房，供电和网络独立。把机器分布到不同可用区，就是"鸡蛋不放一个篮子" |
| **多可用区部署 / 多活** | 同城主备、同城双活、异地灾备。目的是单个机房挂了业务还能活 |
| **SLA** | 服务等级协议，可用性承诺（如 99.95%）以及不达标时的补偿。注意 SLA 保的是"机器可用"，不保你的业务不丢数据 |
| **RPO** | 恢复点目标：最多能接受丢多少数据（比如最多丢 5 分钟）。决定你多久备份一次 |
| **RTO** | 恢复时间目标：出事到恢复要多久（比如 30 分钟）。决定你是冷备还是热备 |
| **冷备 / 温备 / 热备** | 冷备 = 只存了备份，出事再现搭；温备 = 机器在但没流量；热备 = 随时接管流量 |

### 8.2 备份与容灾的层次

1. **第一层：快照** —— 防误删、防升级失败，分钟级回滚。
2. **第二层：定期备份到对象存储 / 异地** —— 防磁盘损坏、防勒索。
3. **第三层：跨地域复制** —— 防地域级故障。
4. **第四层：多活架构** —— 防机房级故障，成本最高。

> **别忘了演练：没演练过的备份等于没有备份。** 定期做一次"从备份恢复"的实操。

### 8.3 高可用常见套路

- **无状态应用 + 多台机器 + 负载均衡**，是最简单有效的方案。
- **数据库主从 + 读写分离**，主库故障手动/自动切换；注意切换后的脑裂问题。
- **会话外置到 Redis**，避免会话保持带来的单点。
- **健康检查 + 自动伸缩 + 告警**，形成闭环。
- **单点排查**：DNS、SLB、NAT 网关、数据库、对象存储、证书、定时任务机器——这些"只有一个"的东西才是真正的单点。

## 九、花钱的几种方式（以及怎么被坑）

### 9.1 计费模式

| 方式 | 通俗解释 | 适合谁 |
| --- | --- | --- |
| **包年包月** | 整租一年，单价最低，但一次付清、退订麻烦 | 长期稳定的业务 |
| **按量付费** | 打车模式，用一小时算一小时（部分厂商按秒计费），随开随关 | 测试、临时任务、流量波动大 |
| **抢占式 / 竞价实例** | 低价票，出价低于市场价时会被收回，通常提前几分钟通知 | 能容忍中断的批处理、渲染、大数据、CI 构建 |
| **预留实例券 / 节省计划** | 充会员，承诺用量换折扣，和具体机器解耦 | 用量大且稳定的企业 |
| **资源包 / 流量包** | 提前买断一定量的流量或存储容量，比按量便宜 | 流量可预测的站点 |

### 9.2 停机到底还收不收费（高频误解）

> **坑点：以为"关机就不花钱"。**

- 按量付费实例开启"**节省停机模式**"后停机：vCPU 和内存不再收费，但**云盘、EIP、快照、带宽包照常收费**。所以"关机省钱"只省一部分。
- 不开节省停机模式的按量实例，停机后计算资源仍计费。
- 包年包月实例停机：钱已经付了，停不停都一样。
- **结论**：想真正省钱要"**释放**"，而不是"停止"；临时不用可以先把 EIP 解绑、把带宽降到最低。

### 9.3 账单里的隐形项目

- 公网流量费（尤其是出方向、跨地域流量）。
- 快照存储费（按实际占用，越积越多）。
- 闲置公网 IP 费（EIP 不绑机器也收费）。
- NAT 网关、负载均衡的实例费和流量处理费。
- 跨可用区 / 跨地域的内网流量费（同地域同可用区通常免费）。
- 磁盘扩容、镜像复制、日志服务存储、API 调用超量。
- Windows 镜像自带 License 费；自带授权（BYOL）可以省，但要合规。

### 9.4 欠费、到期、退订

| 场景 | 后果与时间线 |
| --- | --- |
| **按量付费欠费** | 先停机保留一段时间（各厂商 15 天左右），逾期释放、数据销毁 |
| **包年包月到期** | 进入隔离期（一般 15 天左右），期间不能访问但数据还在，续费可恢复；逾期释放 |
| **退订** | 包年包月通常有"五天无理由"或按剩余价值退款规则，且有次数限制；按量付费随时释放 |

> **一定要配"余额不足提醒"和"到期提醒"**，别让业务因为忘续费下线。

### 9.5 成本管理

- **打标签**（项目/环境/负责人），账单才能按项目拆。
- **设预算告警**，月度超支提前知道。
- **定期清理**：闲置 EIP、未挂载云盘、老快照、没人用的测试机（这是最容易省出钱的地方）。
- **新用户/学生优惠、代金券、免费试用额度**可以先用；但注意"首年便宜、续费翻倍"的定价套路。

## 十、域名、证书与备案

### 10.1 DNS 记录类型

| 记录 | 作用 |
| --- | --- |
| **A** | 域名 → IPv4 地址 |
| **AAAA** | 域名 → IPv6 地址 |
| **CNAME** | 域名 → 另一个域名（CDN、对象存储、SaaS 接入都用它） |
| **MX** | 邮件服务器地址 |
| **TXT** | 文本记录，常用于域名所有权验证、SPF 反垃圾邮件 |
| **NS** | 由哪台 DNS 服务器解析 |
| **TTL** | 这条记录的缓存时间。改解析前先把 TTL 调小（如 60 秒），切换才快 |

- **智能解析**：按运营商/地域返回不同 IP，多线机房和 CDN 常用。
- **CDN 接入 = 加一条 CNAME** 指向 CDN 给的域名。
- **解析生效有延迟**，受 TTL 影响，不要说"刚改完怎么还不对"。

### 10.2 HTTPS

- **免费证书**：厂商免费 DV 证书（一年期，需续）、Let's Encrypt（90 天，可自动续期）。
- **通配符证书**（`*.example.com`）适合多子域。
- 上 HTTPS 后记得 **HTTP 301 跳转、开 HTTP/2、配 HSTS**。
- **证书过期是最常见的"网站突然打不开"原因之一**，务必配到期提醒或自动续期。

### 10.3 备案（中国大陆特有）

> **服务器在中国大陆：域名解析到 80/443 前必须完成 ICP 备案，否则会被拦截。**

1. 买域名并**实名**。
2. 在云厂商备案系统提交（需要服务器实例、幕布拍照/人脸核验）。
3. **管局审核**（通常 7~20 个工作日）。
4. 拿到备案号，**网站底部展示**。

- **公安备案**：ICP 备案通过后 30 日内到全国互联网安全管理服务平台做公安联网备案。
- **经营性网站**还需要 ICP 许可证（增值电信业务经营许可证）。
- **香港/海外节点免备案**，但访问速度和合规性另说。
- **备案信息变更**（换主体、换服务器、加域名）要走变更备案，别直接切走。

## 十一、应用部署与上线

### 11.1 从裸机到能访问

```
买机器 → 选镜像 → 配安全组 → SSH 登录 → 装环境 → 上传代码
       → 配 Nginx → 域名解析 → 备案 → 上证书 → 配快照和监控
```

### 11.2 常用组件

| 概念 | 通俗解释 |
| --- | --- |
| **Nginx / Apache** | Web 服务器 + 反向代理。Nginx 扛并发强，常放在最前面 |
| **反向代理** | 用户访问 Nginx，Nginx 再转发给后面的应用（如 `127.0.0.1:8080`），应用不直接暴露 |
| **动静分离** | 静态文件（图片/CSS/JS）交给 Nginx 或 CDN，动态请求才走后端，省资源 |
| **宝塔 / 1Panel** | 可视化面板，点鼠标装环境、建站、配证书、看监控。新手友好，但会多开端口、多跑服务，生产环境要评估安全 |
| **Docker** | 把应用和依赖打包成镜像，到哪都能跑。"在我机器上是好的"问题的解药 |
| **镜像仓库** | 存 Docker 镜像的地方（ACR / Harbor / Docker Hub），部署时拉取 |
| **进程守护** | systemd / supervisor，保证应用挂了自动拉起 |

### 11.3 发布方式

- **滚动更新**：一批一批换，服务不中断，最常用。
- **蓝绿部署**：两套环境，切流量，回滚快但资源翻倍。
- **灰度 / 金丝雀**：先放 1%~5% 流量到新版本，观察指标再全量。
- **回滚预案**：每次发布前打好快照 / 镜像 tag，出问题能 5 分钟内退回。

### 11.4 上线检查清单

- [ ] 安全组只开了必要端口；数据库不在公网
- [ ] 有 HTTPS，HTTP 自动跳转
- [ ] 有快照策略 + 异地备份
- [ ] 有监控告警（CPU、磁盘、HTTP 探活、证书到期）
- [ ] 有日志，且日志不会撑爆磁盘
- [ ] 有到期 / 余额提醒
- [ ] 备案完成（大陆节点）
- [ ] 备份恢复演练至少做过一次

## 十二、延伸出来的其他服务

| 服务 | 通俗解释 |
| --- | --- |
| **托管数据库（RDS / 云数据库）** | 不用自己装 MySQL，备份、主从复制、故障切换由厂商负责，你只负责建表。贵一些，但省心 |
| **Redis / 消息队列（MQ / Kafka）** | 缓存和异步解耦组件，同样托管化。自建便宜但运维成本高 |
| **容器与 K8s（ACK / TKE）** | 从"管几台机器"升级为"管一堆容器"，资源利用率高、发布标准化。学习曲线陡 |
| **Serverless（函数计算）** | 连机器都不用管，只上传一段代码，被调用时才运行，按调用次数计费。冷启动是主要缺点 |
| **对象存储 + CDN** | 把静态资源和下载内容从服务器剥离，服务器只处理动态请求 |
| **IAM / RAM 子账号** | 给每位同事发不同的门禁卡，只给必要权限，定期轮换密钥 |
| **日志服务 / 应用监控（APM）** | 集中日志、链路追踪、错误聚合 |
| **证书服务 / 密钥管理（KMS）** | 统一管理证书和加密密钥 |
| **弹性容器实例（ECI）** | 不用买机器，直接跑一个容器，按秒计费 |

## 十三、迁移与多云

- **服务器迁移中心（SMC 类）**：把 IDC 物理机、VMware 虚拟机、其他云的机器整机迁移上云，支持增量同步。
- **镜像导入导出**：把本地虚拟机导出成 qcow2/vmdk，转成云厂商自定义镜像；也能把云上镜像导出到本地。
- **数据库迁移（DTS 类）**：结构 + 全量 + 增量同步，可做不停机迁移。
- **对象存储迁移**：跨云搬桶，注意流量费和一致性校验。
- **混合云**：IDC 与云上用专线/VPN 打通，核心数据留本地、弹性业务上云。
- **多云**：避免单一厂商锁定，但会带来运维复杂度和网络成本；中小团队通常不值得，先把一家用好。
- **跨云 / 跨地域的两大坑**：内网不互通（要走公网或专线）、数据出境合规。

## 十四、合规与风险

- **内容合规**：违规内容会被封号停机，数据取回流程麻烦，恢复可能要几天。
- **ICP 备案**：大陆节点强制，未备案的 80/443 会被拦截。
- **等保 2.0**：企业客户常要求，涉及日志留存、访问审计、数据备份。
- **数据出境**：个人信息/重要数据出境有安全评估要求，海外节点不是"随便放"。
- **实名认证**：云账号必须实名，企业认证才能开票。
- **发票与合同**：企业报销、审计需要正规发票；海外小厂 VPS 通常没有。
- **IP 风险**：共享 IP 被墙会连累你；IP 进了黑名单，邮件、爬虫、API 调用都会被拒。
- **账号安全**：主账号被盗 = 全部资产丢失（含快照和备份）。开 MFA、开操作审计、别把 AK 贴网上。

## 十六、全链路串讲：一个网站的完整走法

```text
用户输入 www.example.com
        ↓
DNS 解析到 EIP 或负载均衡的公网地址
        ↓
静态图片走 CDN，不回源站
        ↓
SLB 把请求分到 VPC 内子网里的两台 ECS（分布在不同可用区）
        ↓
安全组只放行 443 端口，WAF 过滤恶意请求
        ↓
机器从镜像启动，云盘存代码，快照每天备份并复制到异地
        ↓
数据读写 RDS（主从 + 自动备份），上传的文件放进 OSS
        ↓
NAT 网关让内网机器能下载依赖，但外网无法主动访问它们
        ↓
云监控盯着 CPU、磁盘和 HTTP 探活，弹性伸缩在流量上涨时自动加机器
        ↓
主机安全（HSS）盯异常登录和木马，操作审计记录每一次配置变更
        ↓
账单按包年包月、按量付费和流量混合结算，标签按项目分摊
```
