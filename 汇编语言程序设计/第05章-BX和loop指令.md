## 5.1 [BX]

**[bx] 表示一个内存单元，它的偏移地址在 BX 中；段地址默认在 DS 中。**

```asm
mov ax, [bx]        ; AX = ((DS) × 16 + (BX)) 处的一个字
```

**举例：**

```asm
mov ax, 2000h
mov ds, ax          ; DS = 2000H
mov bx, 1000h       ; BX = 1000H
mov ax, [bx]        ; 读物理地址 2000H×16 + 1000H = 21000H 处的字
```

**`[bx]` 和 `[0]` 的本质区别：**

| 写法 | 偏移地址来自 | 能不能在循环中变 |
|---|---|---|
| `[0]` | 立即数 0，写死在指令里 | **不能** |
| `[bx]` | BX 寄存器的值 | **能**（改 BX 就能访问不同单元） |

> **重点**：**这就是引入 `[bx]` 的全部理由**——想用循环批量访问内存，偏移地址必须是「可变的」，而立即数偏移写死在机器码里。所以需要一个寄存器来存偏移地址，8086 选定了 `BX`（其实是 4 个：`BX`、`BP`、`SI`、`DI`，第 7 章会讲全套）。

**用 `[bx]` 遍历一段内存的标准写法：**

```asm
    mov ax, 2000h
    mov ds, ax
    mov bx, 0            ; 从偏移 0 开始
    mov cx, 10           ; 循环 10 次
s:  mov al, [bx]         ; 读一个字节
    inc bx               ; 偏移加 1，指向下一个字节
    loop s
```

## 5.2 Loop指令

**格式：**

```asm
loop 标号
```

**执行过程（两步）：**

```
   ① (CX) = (CX) − 1              ; CX 减 1
   ② 若 (CX) ≠ 0，则转到标号处    ; 否则顺序往下执行
```

**注意顺序：先减 1，再判断。** 这一点极其重要：

```
   ┌─────────────────────────────┐
   │  loop 标号                   │
   └──────────────┬──────────────┘
                  ↓
        ┌───────────────────┐
        │  CX = CX − 1      │
        └─────────┬─────────┘
                  ↓
              ┌───────┐
              │ CX=0? │
              └───┬───┘
         否 ┌─────┴─────┐ 是
            ↓           ↓
      转到标号处    顺序执行下一条
```

**「用 CX 控制循环次数」是 8086 的固定约定——`loop` 指令只认 CX，不能换成别的寄存器。**

**循环次数与 CX 初值的关系：**

| CX 初值 | `loop` 后循环体共执行几次 | 说明 |
|---|---|---|
| 0 | **65536 次** | `0 − 1 = FFFFH ≠ 0`，会一直减到 0，共 65536 次（这是个大坑！） |
| 1 | 1 次 | 减到 0，退出 |
| 5 | 5 次 | |
| n（n>0） | n 次 | |

> **重点**：**`(CX) = 0` 时 `loop` 会循环 65536 次，不是 0 次！** 因为 `loop` 是「先减后判」，`0 − 1` 在 16 位无符号数里回绕成 `FFFFH`，不等于 0，于是继续循环，一直到减到 0 为止，共 65536 次。这是必考陷阱。

## 5.3 在Debug中跟踪用loop指令实现的循环程序

**程序：计算 `2^3`（用循环做 3 次相加）。**

```asm
assume cs:code
code segment
    mov ax, 2
    mov cx, 3            ; 循环次数 = 3
s:  add ax, ax           ; AX = AX × 2
    loop s               ; CX 减 1，不为 0 则回到 s
    mov ax, 4c00h
    int 21h
code ends
end
```

**执行过程跟踪：**

| 步骤 | 执行的指令 | CX 变化 | AX 变化 |
|---|---|---|---|
| 初始 | `mov ax,2` | CX = 3 | AX = 2 |
| 第 1 轮 | `add ax,ax` | CX = 3 | AX = 4 |
| | `loop s` | **CX = 2**（≠0，跳转） | AX = 4 |
| 第 2 轮 | `add ax,ax` | CX = 2 | AX = 8 |
| | `loop s` | **CX = 1**（≠0，跳转） | AX = 8 |
| 第 3 轮 | `add ax,ax` | CX = 1 | AX = 16 |
| | `loop s` | **CX = 0**（=0，不跳转） | AX = 16 |

**最终 `AX = 16`。** 验算一下：初值 2，循环体执行 3 次，每次 `add ax,ax`（自己加自己 = ×2），所以 `AX = 2 × 2 × 2 × 2 = 16 = 2^4`。**规律：循环体执行 n 次「自己加自己」，结果是 `初值 × 2^n`**——注意这里的 n 是**循环体执行次数**（= 初始 CX 值），不是 `loop` 的跳转次数（跳转只发生 n−1 次，最后一次 CX 已减到 0、不跳）。

> **重点**：Debug 跟踪 `loop` 时**必须用 `t` 命令**，不能用 `p`。`p` 会把整个循环体一次执行完（因为它把 `loop` 后面的代码当作「子程序」跳过了），看不到中间过程。要「跨过」循环时反而要用 `p`——**`p` 停在 `loop` 后面那条指令上**，等于一次跑完整个循环。

## 5.4 Debug和汇编编译器masm对指令的不同处理

**这是本章最大的坑：同一个 `mov ax, [0]`，在 Debug 和 MASM 里含义完全不同。**

| 环境 | `mov ax, [0]` 的含义 |
|---|---|
| **Debug**（`a` 命令下输入） | `[0]` 被当作**内存单元**，读 `DS:0` 处的字 |
| **MASM**（源程序里写） | `[0]` 被当作**立即数 0**，等价于 `mov ax, 0`！ |

**为什么？** MASM 的语法规定：`[立即数]` 在源程序中会被解释为「常量」，只有 `[寄存器]` 才被解释为内存单元。这是 MASM 为了和高级语言的数组语法兼容而做的设计。

**两种正确写法（让 MASM 知道你要访问内存）：**

**写法一：借助 BX 中转（推荐）**

```asm
    mov bx, 0
    mov ax, [bx]        ; 现在明确是内存单元 DS:0
```

**写法二：显式加上段前缀**

```asm
    mov ax, ds:[0]      ; 明确告诉 MASM：这是 DS 段偏移 0 的内存单元
```

> **重点**：**考试里常考的判断题**——「`mov ax,[0]` 的功能是把 0 送进 AX」。**错**。在 MASM 源程序中它确实等价于 `mov ax,0`；要访问内存必须写 `mov bx,0` + `mov ax,[bx]`，或写 `mov ax,ds:[0]`。

## 5.5 loop和[bx]的联合应用

**问题：计算 `FFFF:0` ~ `FFFF:B` 这 12 个字节的和，结果存入 DX。**

**先想清楚：为什么不能直接把 12 个字节加进 DX？**

- 12 个字节每个最大 `FFH`，12 × 255 = 3060 < 65535，所以可以用一个 16 位寄存器 DX 装下。
- 但 `add dx, [bx]` 取的是**一个字（2 字节）**，会把相邻两个字节一起读进来——**结果错误**（等于把每个字节算了两次，还错位）。
- **正确做法：先把字节取到 8 位寄存器 `AL`，再让 `AH = 0`，这样 `AX` 就是这个字节的无符号值，最后加进 DX。**

```asm
assume cs:code
code segment
    mov ax, 0ffffh
    mov ds, ax           ; DS = FFFFH（要访问的内存段）
    mov bx, 0            ; BX 作为偏移，从 0 开始
    mov dx, 0            ; DX 累加和，清零
    mov cx, 12           ; 循环 12 次
s:  mov al, [bx]         ; 取一个字节到 AL（8 位）
    mov ah, 0            ; AH 清零，使 AX = 该字节的无符号值
    add dx, ax           ; 累加到 DX
    inc bx               ; 指向下一个字节
    loop s               ; CX 减 1，不为 0 就继续
    mov ax, 4c00h
    int 21h
code ends
end
```

**运行结果**：`DX` 中是 `FFFF:0` ~ `FFFF:B` 共 12 个字节的和。

**执行过程（假设这 12 个字节都是 `11H`）：**

| 轮次 | `mov al,[bx]` | `mov ah,0` 后 AX | DX 累加后 | BX | CX |
|---|---|---|---|---|---|
| 1 | AL=11H | 0011H | 0011H | 1 | 11 |
| 2 | AL=11H | 0011H | 0022H | 2 | 10 |
| … | … | … | … | … | … |
| 12 | AL=11H | 0011H | 00CCH | 12 | 0（退出） |

> **重点**：**「字节 → 字」的零扩展套路 `mov al,[bx]` + `mov ah,0` 是必须背下来的。** 反过来「字 → 双字」要在第 8 章用 `div` / `mul` 处理。**如果不写 `mov ah,0`，AH 里残留上一次的值，结果就全错了。**

## 5.6 段前缀

**在 `[bx]` 前面加一个「段前缀」，可以显式指定用哪个段寄存器。**

```asm
mov ax, ds:[bx]     ; 段地址来自 DS（默认，可省略）
mov ax, cs:[bx]     ; 段地址来自 CS
mov ax, ss:[bx]     ; 段地址来自 SS
mov ax, es:[bx]     ; 段地址来自 ES
```

| 段前缀 | 段寄存器 | 典型用途 |
|---|---|---|
| 无（默认） | DS | 访问数据段 |
| `ds:` | DS | 显式写出，避免歧义 |
| `cs:` | CS | 访问代码段内的数据（如代码段中定义的表） |
| `ss:` | SS | 访问栈段 |
| `es:` | ES | **数据复制时作「目的段」**（因为 DS 已被源占用） |

**用法示例（两个段之间复制数据）：**

```asm
    mov ax, 2000h
    mov ds, ax          ; DS = 源段
    mov ax, 3000h
    mov es, ax          ; ES = 目的段
    mov bx, 0
    mov cx, 10
s:  mov al, [bx]        ; 从 DS:BX 读（源）
    mov es:[bx], al     ; 写到 ES:BX（目的），必须加 es: 前缀
    inc bx
    loop s
```

> **重点**：**为什么复制数据要用 ES？** 因为默认段寄存器是 DS，源地址已经占用了 DS，目的地址只能换一个段寄存器——8086 提供了 `ES`（Extra Segment，附加段寄存器）专门干这个。**`es:[bx]` 这种写法在字符串复制题里是标准答案。**

## 5.7 一段安全的空间

**在 DOS 方式下，直接往任意内存写数据是危险的——可能改掉系统数据或别人的程序，导致死机。**

**但有一块公认安全的空间：**

```
   偏移(0 段)   内容
   00000H ┌────────────────────────┐ ← 中断向量表 前 512 字节
          │  DOS 实际使用            │   （0:000 ~ 0:1FF）
   001FFH ├────────────────────────┤
   00200H │  ★ 安全区 256 字节 ★     │ ← 0:200 ~ 0:2FF（本课程约定用这块）
   002FFH ├────────────────────────┤
   00300H │  中断向量表 后 512 字节   │   （DOS 下未使用）
   003FFH ├────────────────────────┤ ← 中断向量表到此结束（共 1KB = 256 个入口）
   00400H │  BIOS 数据区 …          │
          └────────────────────────┘
```

**为什么 `0:200~0:2FF` 安全？**

- 中断向量表占 `0000:0000 ~ 0000:03FF`，共 1024 字节（即 `0:000 ~ 0:3FF`）。
- **`0:200 ~ 0:2FF` 其实落在中断向量表的范围内**（`0:200` = 512，`0:2FF` = 767，都在 0~1023 之内）——所以严格说，它不是「表外空间」。
- 但 **DOS 只用到中断向量表的前 512 字节（`0:000 ~ 0:1FF`）**，后 512 字节（`0:200 ~ 0:3FF`）在 DOS 下没有被使用。
- 因此 **`0:200 ~ 0:2FF`（256 字节）是 DOS 方式下公认的安全空间**，教材和实验都约定用这块地方。

> **重点**：**实验里凡是要「找块地方放数据」，答案就是 `0:200`**。第 12 章安装自己的中断处理程序时也会用到（装在 `0:200`）。

**为什么不能乱写内存？** 因为一块内存可能装的是：

- 系统数据（如 BIOS 数据区、DOS 内部变量）
- 别的程序的代码
- 中断向量表（**改坏了，下一次中断就会跳飞到不知哪里，死机**）

## 5.8 段前缀的使用

**完整例子：把 `FFFF:0` ~ `FFFF:B` 共 12 个字节复制到 `0:200` ~ `0:20B`。**

```asm
assume cs:code
code segment
    mov ax, 0ffffh
    mov ds, ax           ; DS = 源段 FFFFH
    mov ax, 0020h
    mov es, ax           ; ES = 目的段 0020H（因为 0:200 = 0020:0000）
    mov bx, 0            ; BX 同时作源、目的的偏移
    mov cx, 12           ; 复制 12 个字节
s:  mov al, [bx]         ; 从 DS:BX 读一个字节
    mov es:[bx], al      ; 写到 ES:BX（必须加段前缀）
    inc bx               ; 偏移加 1
    loop s               ; 循环
    mov ax, 4c00h
    int 21h
code ends
end
```

**为什么 `ES = 0020H`？** 因为 `0:200` 的物理地址是 `0000H × 16 + 200H = 200H`。要让它等于 `(ES) × 16 + 0`，则 `(ES) × 16 = 200H`，所以 `(ES) = 200H / 10H = 20H = 0020H`。

> **重点**：**「某物理地址 → 段:偏移」的换算是高频计算题。** 规则：`物理地址 = 段地址 × 16 + 偏移`。同一个物理地址可以有很多种「段:偏移」写法（如 `0020:0000`、`0000:0200`、`001F:0010` 都指向 `200H`）。

**用 Debug 验证：**

```dos
-d 0:200 20b          ; 查看 0:200 ~ 0:20B 的内容，应该和 FFFF:0 处一样
-d ffff:0 b           ; 查看源数据
```

## 典型例题

**例 5.1**（题型：loop 循环次数）
下面程序段中，`inc ax` 共执行多少次？`loop` 指令又实际跳转了多少次？
```asm
    mov ax, 0
    mov cx, 0
s:  inc ax
    loop s
```
**解**：
- `CX = 0` 时，`loop` 的执行是：先 `CX = 0 − 1 = FFFFH`（16 位回绕），再判断 `CX ≠ 0`，所以**跳转**。
- 之后每轮 `CX` 减 1，直到 `CX` 从 `0001H` 减到 `0000H` 才不跳转。
- `loop` 一共执行 `10000H = 65536` 次（`CX` 从 `0000H` 一路减到 `0000H`，恰好走完一个 16 位计数周期）。
- 其中**最后一次不跳转**，所以实际跳转次数 = `65536 − 1 = 65535` 次。
- 每执行一次循环体就 `inc ax` 一次，而循环体一共进入 65536 次，所以 `inc ax` 共执行 **65536 次**。
**答案**：`inc ax` 执行 **65536 次**（`AX` 最终为 0，因为 16 位回绕；`CX` 最终为 0）；`loop` 实际**跳转 65535 次**。**注意区分「循环体执行次数」和「跳转次数」——两者差 1，这是最常见的失分点。**

**例 5.2**（题型：Debug 与 MASM 的差异）
下面程序想读取 `DS:0` 处的字，能实现吗？
```asm
assume cs:code
code segment
    mov ax, 2000h
    mov ds, ax
    mov ax, [0]
    mov ax, 4c00h
    int 21h
code ends
end
```
**解**：
- **不能。** 在 MASM 源程序中，`[0]` 被解释为**常量 0**，所以 `mov ax, [0]` 等价于 `mov ax, 0`。
- 汇编器不会报错，但程序行为不符合预期——`AX` 会被赋成 0，而不是 `20000H` 处的字。
- **两种改法**：
```asm
    mov bx, 0
    mov ax, [bx]        ; 改法一：偏移放 BX
```
```asm
    mov ax, ds:[0]      ; 改法二：加段前缀
```
**答案**：不能。必须写成 `mov bx,0` + `mov ax,[bx]`，或 `mov ax, ds:[0]`。

**例 5.3**（题型：手算循环中寄存器变化）
初始 `(AX)=0`、`(DX)=0`、`(CX)=4`、`(BX)=0`，内存 `DS:0~3` 依次为 `01H, 02H, 03H, 04H`。执行下面程序后 AX、BX、CX、DX 各是多少？
```asm
s:  mov al, [bx]     ; 取一个字节
    mov ah, 0        ; ★ 零扩展：保证 AX 是高字节为 0 的字
    add dx, ax       ; 累加到 DX
    inc bx           ; 指针前移
    loop s
```
**解**（按 `add dx, ax`、DX 初值 0 计算）：
| 轮次 | [bx] | AX | DX | BX | CX |
|---|---|---|---|---|---|
| 1 | 01H | 0001H | 0001H | 1 | 3 |
| 2 | 02H | 0002H | 0003H | 2 | 2 |
| 3 | 03H | 0003H | 0006H | 3 | 1 |
| 4 | 04H | 0004H | 000AH | 4 | 0（退出） |
**答案**：`DX = 000AH`（= 1+2+3+4），`BX = 4`，`CX = 0`。**注意 `mov ah,0` 必须在 `mov al,[bx]` 之后，否则 AX 高字节残留会导致累加错误。**

**例 5.4**（题型：字节与字的区分）
用 `add dx, [bx]` 代替 `mov al,[bx]` / `mov ah,0` / `add dx,ax` 三条指令，累加 `0:200` 起的 12 个字节，结果对吗？
**解**：
- **不对。** `add dx, [bx]` 取的是 `DS:BX` 处的**一个字（2 字节）**，不是 1 个字节。
- 循环 12 次、每次 `inc bx` 加 1，读的范围是 `0:200` ~ `0:20B`，但每次读 2 字节且只前进 1 字节，**同一字节被读了两次、还与相邻字节混在一起**。
- 结果等于「相邻字节对的和」，比正确答案大得多。
**答案**：不对。**累加字节必须先用 `mov al,[bx]` + `mov ah,0` 零扩展成字**，不能直接 `add dx,[bx]`。

**例 5.5**（题型：物理地址与段:偏移换算）
把物理地址 `200H` 用三种不同的「段:偏移」形式表示。
**解**：
- 要求 `段地址 × 16 + 偏移 = 200H`。
- 取段地址 `0020H`：`0020H × 16 = 200H`，偏移 = `0000H` → **`0020:0000`**
- 取段地址 `0000H`：偏移 = `200H` → **`0000:0200`**
- 取段地址 `0010H`：`0010H × 16 = 100H`，偏移 = `200H − 100H = 100H` → **`0010:0100`**
**答案**：`0020:0000`、`0000:0200`、`0010:0100`（均可，偏移必须 ≤ `FFFFH`）。

**例 5.6**（题型：编写完整程序）
编写程序，把 `0:200` ~ `0:20B` 这 12 个字节的内容**乘以 2**（每个字节 × 2，只保留低 8 位），写回原处。
**解**：
```asm
assume cs:code
code segment
    mov ax, 0020h
    mov ds, ax           ; DS 指向 0:200 所在段（0020H）
    mov bx, 0            ; 偏移从 0 开始
    mov cx, 12           ; 12 个字节
s:  mov al, [bx]         ; 取一个字节
    add al, al           ; ×2（AL 加自己，8 位运算，超出的位丢弃）
    mov [bx], al         ; 写回原处
    inc bx               ; 下一个字节
    loop s
    mov ax, 4c00h
    int 21h
code ends
end
```
**为什么用 `add al, al` 而不是 `mul`**：8 位乘法 `mul` 要用 `AL × 操作数 → AX`，还要处理 AH，麻烦；`add al,al` 一条指令搞定且自动丢弃溢出位（这正是「只保留低 8 位」的要求）。

**例 5.7**（题型：循环嵌套的外层计数）
需要写一个「外层循环 10 次、内层循环 5 次」的程序，CX 只有一个，怎么办？
**解**：
- `loop` 只认 `CX`，内层循环会把 `CX` 改成 0，导致外层也退出。
- **两种办法**：
  1. **把外层计数存到别的寄存器或内存**：外层用 `DX` 保存，进入内层前 `mov cx, dx`，内层结束后 `mov dx, cx` 存回。
  2. **用栈保存**：内层开始前 `push cx`，内层结束后 `pop cx`。
- 标准写法（用栈）：
```asm
    mov cx, 10           ; 外层 10 次
outer:
    mov dx, cx           ; ★ 先把外层计数备份到 DX
    mov cx, 5            ; 内层 5 次
inner:
    ; ...（内层循环体：真正要重复做的事写在这里）
    loop inner
    mov cx, dx           ; ★ 恢复外层计数
    loop outer
```
**答案**：用 `DX` 或栈备份外层计数，内层循环前后保存/恢复 `CX`。**这是多重循环题目的标准套路。**

## 易错点提醒

1. **错**：以为 `(CX)=0` 时 `loop` 不循环。**对**：`loop` 是**先减后判**，`0 − 1 = FFFFH ≠ 0`，所以 `CX = 0` 时会循环 **65536 次**。设置 CX 时务必确认初值。
2. **错**：在 MASM 源程序里写 `mov ax, [0]` 想访问内存。**对**：MASM 把 `[0]` 当**常量 0**，等价于 `mov ax,0`。要用 `mov bx,0` + `mov ax,[bx]`，或 `mov ax, ds:[0]`。
3. **错**：累加字节时用 `add dx, [bx]`。**对**：那取的是**一个字（2 字节）**。累加字节必须先 `mov al,[bx]` 再 `mov ah,0` 做零扩展。
4. **错**：忘了 `mov ah, 0`，直接 `mov al,[bx]` 后 `add dx,ax`。**对**：**AH 里会残留上一次的值**，导致结果偏大。零扩展是必须步骤。
5. **错**：往任意内存地址写数据。**对**：DOS 下只能往 **`0:200 ~ 0:2FF`** 这 256 字节的安全空间写，否则可能破坏系统数据或中断向量表导致死机。
6. **错**：复制数据时目的地址也用 `[bx]`（不加前缀）。**对**：默认段是 DS，要想访问另一个段必须加 **`es:[bx]`**。这就是要用 ES 的原因。
7. **错**：多重循环里内外层都用 CX。**对**：内层会把 CX 改成 0，外层也只跑一次。**必须用 DX 或栈保存外层计数**。
8. **错**：以为 `inc bx` 可以省掉，靠 `loop` 自动前进。**对**：`loop` 只管 CX，**不会改 BX**。偏移必须自己加。
9. **错**：`mov bx, 0` 后 `mov ax, [bx]` 再 `inc bx`，然后又 `mov ax, [bx]`——但忘了 `bx` 是 16 位、遍历超过 65535 会回绕。**对**：BX 是 16 位，一个段最多 65536 字节；跨段要用 `inc` 段寄存器或重新设 DS。
10. **错**：以为 `loop` 的标号可以离得很远。**对**：`loop` 是**短转移**，位移只有 **1 字节**，范围是 **−128 ~ +127 字节**。循环体太大（超过 127 字节）汇编会报「jump out of range」。

## 本章小结

- **`[bx]` 表示偏移地址在 BX 中的内存单元**，段地址默认在 DS；它是「可变的偏移」，这是引入它的唯一理由。
- **`loop 标号` 的执行过程：`(CX) = (CX) − 1`，若 `(CX) ≠ 0` 则转标号。** 循环次数必须放在 **CX** 中。
- **`(CX) = 0` 时循环 65536 次**（先减后判、回绕），这是必考陷阱。
- **Debug 与 MASM 对 `[立即数]` 的处理不同**：Debug 当内存，MASM 当常量。MASM 中要访问内存必须用 `[bx]` 或加段前缀。
- **累加字节的标准套路**：`mov al,[bx]` + `mov ah,0` + `add dx,ax` + `inc bx` + `loop`。
- **4 种段前缀**：`ds:`（默认）、`cs:`、`ss:`、**`es:`（数据复制的目的段）**。
- **DOS 下安全空间是 `0:200 ~ 0:2FF`（256 字节）**。
- 多重循环必须**用 DX 或栈保存外层 CX**。

> **一句话记住本章**：**`[bx]` 让偏移可变化、`loop` 用 CX 计数且「先减后判」，所以 CX=0 意味着 65536 次；MASM 里 `[立即数]` 是常量不是内存，累加字节必须先零扩展到 AX。**

## 自测题

**1.** `[bx]` 表示什么？它的段地址默认在哪个寄存器？
**答**：表示一个内存单元，偏移地址在 BX 中；段地址默认在 DS。

**2.** 写出 `loop` 指令的执行过程。为什么说它是「先减后判」？
**答**：① `(CX) = (CX) − 1`；② 若 `(CX) ≠ 0` 转到标号处。因为减 1 发生在判断之前，所以是「先减后判」。

**3.** `(CX) = 0` 时执行 `loop s` 会循环多少次？
**答**：65536 次。`0 − 1 = FFFFH ≠ 0`，继续循环直到减到 0。

**4.** 在 MASM 源程序中，`mov ax, [0]` 的含义是什么？怎么才能访问 `DS:0` 处的字？
**答**：MASM 把 `[0]` 当常量 0，所以等价于 `mov ax,0`。要访问内存可写 `mov bx,0` + `mov ax,[bx]`，或 `mov ax, ds:[0]`。

**5.** 为什么累加字节时不能写 `add dx, [bx]`？
**答**：`[bx]` 默认取一个字（2 字节），会把相邻字节一起读进来。应先用 `mov al,[bx]` 取字节、`mov ah,0` 零扩展，再 `add dx,ax`。

**6.** 列出 4 种段前缀及其对应的段寄存器。
**答**：`ds:` → DS；`cs:` → CS；`ss:` → SS；`es:` → ES。不加前缀时默认 DS。

**7.** 复制数据时为什么要用 `es:`？
**答**：默认段是 DS，源地址已经用掉 DS；目的地址必须换一个段寄存器，8086 提供 ES 专门作附加段。写法是 `mov es:[bx], al`。

**8.** DOS 方式下哪块内存是安全可写的？多大？
**答**：物理地址 `0:200 ~ 0:2FF`，共 256 字节。

**9.** 物理地址 `300H` 用「段:偏移」表示，写出两种。
**答**：`0030:0000`、`0000:0300`（或 `0020:0100` 等，只要 `段×16 + 偏移 = 300H`）。

**10.** 多重循环中内层也用 CX 会怎样？怎么解决？
**答**：内层会把 CX 减到 0，外层循环只执行一次就退出。解决办法：外层计数存到 DX 或压栈，内层进入前恢复 CX、内层结束后再存回。

**11.** `loop` 指令的跳转范围是多少？为什么？
**答**：−128 ~ +127 字节。因为 `loop` 是短转移，位移用 1 个字节的有符号数表示。循环体超过 127 字节会报「jump out of range」。

**12.** 下面程序执行后 AX 是多少？
```asm
    mov ax, 0
    mov cx, 3
s:  inc ax
    loop s
```
**答**：循环 3 次，`AX = 3`。
