## 学习目标

1. 能默写一个完整可运行的 8086 汇编源程序骨架（含 `assume`、`段名 segment`/`段名 ends`、`end start`）。
2. 能说清 `assume`、`segment...ends`、`end`、标号这四者的作用，并区分「伪指令」与「汇编指令」。
3. 能完整走一遍「编辑 → masm → link → 执行」流程，并说出每一步的输入输出文件。
4. 能写出程序正常返回 DOS 的两条指令并解释它们为什么是必需的。
5. 能用 Debug 的 `r`、`t`、`u`、`q` 跟踪程序执行，并说出装载后 CS、IP、DS 的值及其来源。
6. 能解释为什么源程序开头总是 `mov ax, xxx` + `mov ds, ax` 这一对。

## 4.1 一个源程序从写出到执行的过程

**一个汇编程序要经历四步才能跑起来：**

```
   ① 编写        ② 编译          ③ 连接          ④ 执行
  ┌────────┐   ┌────────┐    ┌────────┐    ┌────────┐
  │ 1.asm  │──►│ 1.obj  │──► │ 1.exe  │──► │ 内存中运行 │
  └────────┘   └────────┘    └────────┘    └────────┘
   记事本      masm 1.asm    link 1.obj    1（回车）
   文本编辑器   MASM.EXE      LINK.EXE      COMMAND.COM
```

| 步骤 | 输入 | 工具 | 输出 | 干什么 |
|---|---|---|---|---|
| ① 编写 | 无 | 记事本 / MASM 集成环境 | `1.asm` | 用汇编语言写源程序（纯文本） |
| ② 编译 | `1.asm` | `MASM.EXE` | `1.obj` | 把汇编指令翻译成机器码，生成目标文件 |
| ③ 连接 | `1.obj` | `LINK.EXE` | `1.exe` | 合并段、加入库代码、生成可执行格式 |
| ④ 执行 | `1.exe` | DOS 的 `COMMAND.COM` | — | 把程序装入内存并交给 CPU 执行 |

> **重点**：编译和连接是**两个不同的工具**，做的是**两件不同的事**。编译只管「把汇编指令变成机器码」，不管机器码放在哪里；连接才负责「安排这些机器码在内存中的位置」。

## 4.2 源程序

**下面是一个完整的、能直接汇编运行的源程序（教材的第一个程序）：**

```asm
assume cs:codesg              ; 伪指令：告诉汇编器「codesg 这个段和 CS 相关联」

codesg segment                ; 伪指令：定义一个段，名字叫 codesg，从这里开始
                              ;
    mov ax, 0123h             ; 汇编指令：AX = 0123H
    mov bx, 0456h             ; 汇编指令：BX = 0456H
    add ax, bx                ; 汇编指令：AX = AX + BX = 0579H
    add ax, ax                ; 汇编指令：AX = AX + AX = 0AF2H
    add ax, ax                ; 汇编指令：AX = AX + AX = 15E4H
                              ;
    mov ax, 4c00h             ; 汇编指令：AH = 4CH（DOS 的「带返回码结束程序」功能号）
    int 21h                   ; 汇编指令：调用 DOS 功能，程序正常返回
                              ;
codesg ends                   ; 伪指令：段 codesg 到此结束

end                           ; 伪指令：整个源程序结束，后面的内容汇编器不再看
```

**运行结果**：程序执行完毕后 `AX = 15E4H`，然后正常返回 DOS，屏幕上不会显示任何内容。

### 4.2.1 伪指令

**伪指令是给汇编器（MASM）看的，不是给 CPU 看的——它没有对应的机器码。**

本程序里出现的 3 种伪指令：

**（1）`segment` 和 `ends`**

```asm
codesg segment
    ; ...（段内放指令或数据，此处省略）
codesg ends
```

这一对伪指令**定义一个段**。`codesg` 是段名（自己起，合法的标识符即可）。`segment` 说明段的开始，`ends` 说明段的结束（ends 是 end of segment 的缩写）。

**一个源程序中可以有多个段，段名不能重复。**

**（2）`end`**

```asm
end
```

**`end` 是一个汇编源程序的结束标记。** 汇编器在编译时如果遇到了 `end`，就结束对源程序的编译——后面就算有内容也不看。

**（3）`assume`**

```asm
assume cs:codesg
```

**`assume` 的含义是「假设」：假设某个段寄存器（这里是 CS）和程序中某个用 `segment...ends` 定义的段（这里是 codesg）相关联。**

> **重点**：`assume cs:codesg` **不是**「把 codesg 的段地址装入 CS」——**它只是一条给汇编器的声明**，让汇编器知道「后面某些指令中提到的段和寄存器该怎么对应」。真正把段地址装进段寄存器，必须用 `mov` 指令（对 CS 则只能用 `jmp`）。

### 4.2.2 源程序中的「程序」

**源程序 = 汇编指令 + 伪指令 + 标号 + 注释，但「程序」只指其中要被 CPU 执行的那部分。**

```
   源程序文件 1.asm
   ┌────────────────────────────────────────────┐
   │ assume cs:codesg          ← 伪指令（给汇编器）│
   │ codesg segment            ← 伪指令（给汇编器）│
   │ start: mov ax, 0123h      ← 标号 + 汇编指令   │ ← 这部分才是「程序」
   │        mov bx, 0456h      ← 汇编指令          │   （有机器码）
   │        ...                                   │
   │        mov ax, 4c00h      ← 汇编指令          │
   │        int 21h            ← 汇编指令          │
   │ codesg ends               ← 伪指令（给汇编器）│
   │ end                       ← 伪指令（给汇编器）│
   └────────────────────────────────────────────┘
```

| 成分 | 给谁看的 | 有没有机器码 |
|---|---|---|
| 汇编指令（`mov`、`add`、`int`…） | CPU | **有** |
| 伪指令（`assume`、`segment`、`ends`、`end`…） | 汇编器 MASM | 没有 |
| 标号（`start:`、`codesg`） | 汇编器 + 程序员 | 没有 |
| 注释（`;` 后面的内容） | 人 | 没有 |

### 4.2.3 标号

**标号就是一个地址的「名字」。** 比如 `start:` 标记了 `mov ax, 0123h` 这条指令的地址。

```asm
codesg segment
start:                        ; 标号 start，它代表下面那条指令的地址
    mov ax, 0123h
    ; ...（此处省略若干条指令，真正要汇编运行的程序不能写省略号）
codesg ends
end start                     ; ★ 关键：告诉汇编器「程序的入口是 start 这个标号」
```

> **重点**：**`end start` 与 `end` 的区别是本章第一个大坑。**
>
> | 写法 | 含义 | 谁在用它 |
> |---|---|---|
> | `end` | 源程序到此结束，**不指定入口** | **汇编器（masm）**读到这里就收工 |
> | `end start` | 源程序到此结束，**并把「`start` 标号处是程序入口」这个信息写进 `.obj` 文件** | **汇编器**记录 → **链接器（link）**据此在 `.exe` 文件头里填入口地址 |
>
> **★ 说清楚「谁决定入口」**：**`end start` 是写给汇编器的伪指令，但最终把入口地址写进 `.exe` 的是链接器。** 汇编器只是把「入口标号」这个信息存进 `.obj`；**`link` 读取它，并在生成 `.exe` 时把入口填进文件头**——DOS 装载 `.exe` 时就是照文件头里的这个值去设 `CS:IP` 的。**所以「不写 `end start` 会怎样」这个问题，责任在链接阶段**：`link` 找不到入口信息，会警告并自行猜测（通常是段内第一条指令），单段小程序常常猜对、多段程序几乎必错。
>
> 一个源程序**只能有一个** `end`，且**必须写在最后**。写了标号就一定要在 `end` 后面带上它，否则程序可能从错误的位置开始执行。

### 4.2.4 程序返回

**程序结束后必须把控制权交还给调用它的程序（DOS），否则会跑飞。**

```asm
mov ax, 4c00h      ; AH = 4CH 是 DOS 的「程序结束」功能号，AL = 00H 是返回码
int 21h            ; 调用 DOS 的 21H 号中断，执行该功能
```

**为什么是 `4c00h` 而不是 `4ch`？**

- `int 21h` 的功能号放在 **AH** 里，参数放在 AL 里（这里返回码是 0）。
- 所以 `4c00h` 的高字节 `4CH` 进 AH，低字节 `00H` 进 AL——**一条指令同时设好了功能号和返回码**。

等价写法：

```asm
mov ah, 4ch        ; 只设功能号
mov al, 0          ; 单独设返回码
int 21h
```

> **重点**：`mov ax, 4c00h` + `int 21h` 是每个 DOS 汇编程序的**标准结尾**，要背下来。如果忘了写，程序执行完后 CPU 会继续往下执行内存中的垃圾指令，结果通常是死机或乱跑。

## 4.3 编辑源程序

在 MASM for Windows 集成环境（`D:\Netease\masm`）里新建文件，保存为 `1.asm`。

**注意保存时编码用 ANSI（GBK），因为 DOS 环境不认 UTF-8**，中文注释可能显示成乱码。若只想避免麻烦，**注释全写英文/拼音**或用集成环境的默认设置。

## 4.4 编译

在命令行（DOSBox 或 CMD）中：

```dos
masm 1.asm
```

**MASM 会依次问你三个问题：**

```
Object filename [1.OBJ]:        ← 直接回车，用默认 1.obj
Source listing [NUL.LST]:       ← 直接回车，不要列表文件
Cross-reference [NUL.CRF]:      ← 直接回车，不要交叉引用文件
```

**也可以一步写全，跳过提问：**

```dos
masm 1.asm;
```

**分号表示「后面全部用默认值」。**

| 文件 | 作用 | 要不要保留 |
|---|---|---|
| `1.obj` | **目标文件**，编译的产物，连接时要用 | **必须保留** |
| `1.lst` | 列表文件，程序清单 + 机器码 + 偏移地址（调试有用） | 可选 |
| `1.crf` | 交叉引用文件 | 一般不需要 |

**编译失败时**：MASM 会在屏幕上打印错误行号和错误原因，例如

```
1.asm(7): error A2008: syntax error : mov
```

含义是 `1.asm` 第 7 行语法错误。**★ 本机 MASM 6.11 实测：报出的行号就是【准确的出错行】**——例如源程序第 4 行写成 `mov bx`（漏了操作数），报的就是 `e3.asm(4): error A2008: syntax error : in instruction`。**所以看到行号就直接去看那一行，不要去猜上一行。**

**但有两类例外要知道**：① **缺少 `end`** 是汇编到文件末尾才发现的，报的行号是**文件最后一行**（`error A2088: END directive required at end of file`）——这时要检查的是整个文件的结构；② **`error A2074: cannot access label through segment registers`** 这类「标号所属段不明」的错，报错行是**用到该标号的那一行**，但根因在**前面缺了 `assume` 声明**。**总之：行号先信，但如果那一行看起来没错，再往前找「声明/结构」层面的原因。**

## 4.5 连接

```dos
link 1.obj
```

**LINK 会依次提问：**

```
Run File [1.EXE]:               ← 直接回车
List File [NUL.MAP]:            ← 直接回车
Libraries [.LIB]:               ← 直接回车
```

**一步写全：**

```dos
link 1.obj;
```

**连接到底做了什么？** 三件事：

| 作用 | 说明 |
|---|---|
| ① **合并段** | 把多个 `.obj` 中的同名段合并成一个段 |
| ② **补入库代码** | 如果程序用到了库里的子程序（如 `printf`），把对应代码从 `.lib` 中取出并连接进来 |
| ③ **生成可执行格式** | 按 DOS 的 `.exe` 格式组织各段，写好文件头，标出入口地址等信息 |

> **重点**：为什么不能把 `.obj` 直接拿来执行？因为 **`.obj` 里只有「机器码 + 重定位信息」，没有最终的内存布局**。例如源程序里写了「跳到标号 `s` 处」，编译时还不知道 `s` 最终的段地址和偏移，只能记一个「待定标记」；连接时才能算出真正地址并填回去。这个填回过程叫**重定位**。

## 4.6 以简化的方式进行编译和连接

**`ML.EXE` 把编译和连接合成一步：**

```dos
ml 1.asm
```

一条命令直接得到 `1.exe`（中间还会生成 `1.obj`）。如果源程序有错，`ml` 会给出和 `masm` 一样的错误信息。

| 命令 | 等价于 |
|---|---|
| `masm 1.asm;` + `link 1.obj;` | 两步 |
| `ml 1.asm` | 一步（推荐日常使用） |

## 4.7 1.exe的执行

```dos
1
```

（直接敲文件名，不用敲 `.exe`）

**运行结果**：屏幕立刻回到提示符 `C:\>`，**什么也不显示**——因为程序只改了寄存器，没有做任何输出。这是正常的。

**如果程序卡死不返回**，多半是忘了写 `mov ax,4c00h` + `int 21h`，按 `Ctrl+C` 或 `Ctrl+Break` 强制结束。

## 4.8 谁将可执行文件中的程序装载进入内存并使它运行

**是操作系统中的「命令解释器」——DOS 下就是 `COMMAND.COM`。**

流程：

```
   ① 用户在提示符下敲 "1" 并回车
                ↓
   ② COMMAND.COM 找到当前目录下的 1.exe
                ↓
   ③ COMMAND.COM 把 1.exe 装入内存中的某段空闲区域
                ↓
   ④ COMMAND.COM 设置 CS:IP 指向程序的入口（即 end start 指定的位置）
                ↓
   ⑤ CPU 从 CS:IP 处开始执行，程序取得控制权
                ↓
   ⑥ 程序执行 int 21h 的 4CH 功能，把控制权还给 COMMAND.COM
```

> **重点**：**「谁把程序装入内存」这个问题在考试里很爱考。** 答案：**操作系统（DOS）的命令解释器 `COMMAND.COM`**，不是 MASM、不是 LINK、也不是 CPU 自己。

## 4.9 程序执行过程的跟踪

用 `DEBUG.EXE` 单步跟踪程序：

```dos
debug 1.exe
```

进入 Debug 后常用命令：

| 命令 | 全称 | 作用 | 例子 |
|---|---|---|---|
| `r` | register | 显示/修改寄存器 | `r` 看全部；`r ax` 改 AX |
| `d` | dump | 显示内存内容 | `d ds:0`、`d 1000:0 10` |
| `e` | enter | 修改内存内容 | `e ds:0 12 34 56` |
| `u` | unassemble | 反汇编（机器码 → 汇编指令） | `u cs:0`、`u cs:0 20` |
| `a` | assemble | 输入汇编指令（直接写机器码去处） | `a cs:0` |
| `t` | trace | 单步执行（**会进入子程序/中断**） | `t` |
| `p` | proceed | 单步执行（**跳过子程序/中断**） | `p` |
| `g` | go | 连续执行到指定地址 | `g 0012` |
| `q` | quit | 退出 Debug | `q` |

**关键演示：**

```dos
-t
AX=0000  BX=0000  CX=0000  DX=0000  SP=FFEE  BP=0000  SI=0000  DI=0000
DS=075A  ES=075A  SS=075A  CS=076A  IP=0000   NV UP EI PL NZ NA PO NC
076A:0000 B82301        MOV     AX,0123

-t
AX=0123  BX=0000  CX=0000  DX=0000  SP=FFEE  BP=0000  SI=0000  DI=0000
DS=075A  ES=075A  SS=075A  CS=076A  IP=0003   NV UP EI PL NZ NA PO NC
076A:0003 BB5604        MOV     BX,0456
```

**读这段输出要会三件事：**

1. **`076A:0000 B82301 MOV AX,0123`**——`076A:0000` 是当前 `CS:IP`，`B82301` 是这条指令的**机器码**（1 字节操作码 + 2 字节立即数，小端序：`23 01` 就是 `0123H`）。
2. **执行完一条后 `IP` 从 `0000` 变成 `0003`**——因为 `MOV AX,0123` 这条指令占 **3 个字节**，CPU 自动把 IP 加了 3。
3. **装载后 `DS=075A`、`CS=076A`，两者相差 `0010H`（16 字节 = 一个 PSP 段）**——这不是巧合，见下。

### 为什么 CS 与 DS 相差 10H？

**DOS 装载 `.exe` 时，会在程序前面放一个 256 字节（100H 字节 = 10H 个节）的「程序段前缀 PSP（Program Segment Prefix）」。**

```
   ┌──────────────────────┐ ← DS 指向这里（PSP 起点）
   │   PSP（256 字节）      │   075A:0000 ~ 075A:00FF
   │   存放命令行参数、      │
   │   环境变量段地址等      │
   ├──────────────────────┤ ← CS 指向这里（程序入口）
   │   程序代码             │   076A:0000 ~
   │   ...                │
   └──────────────────────┘
```

- `DS` 被 DOS 设为 **PSP 的段地址**（`075AH`）。
- `CS` 被 DOS 设为 **程序代码段的段地址**（`076AH`）。
- 两者相差 `10H` 个段单位 = `10H × 16 = 100H = 256` 字节——正好是 PSP 的大小。

> **重点**：**这就是「为什么很多程序开头要 `mov ax, data` / `mov ds, ax` 重新设置 DS」的原因**——DOS 给的 DS 指向 PSP，不是你的数据段，你必须自己改。

## 典型例题

**例 4.1**（题型：源程序结构辨析）
指出下面源程序中「伪指令」「汇编指令」「标号」各是哪些：
```asm
assume cs:abc
abc segment
start: mov ax, 2
       add ax, ax
       mov ax, 4c00h
       int 21h
abc ends
end start
```
**解**：
- **伪指令**（给汇编器，无机器码）：`assume cs:abc`、`abc segment`、`abc ends`、`end start`。
- **汇编指令**（给 CPU，有机器码）：`mov ax, 2`、`add ax, ax`、`mov ax, 4c00h`、`int 21h`。
- **标号**（地址的名字）：`start`（还有段名 `abc`，段名也是一种标识符）。
**答案**：伪指令 4 条、汇编指令 4 条、标号 1 个（`start`）。

**例 4.2**（题型：end 与 end start）
把例 4.1 中的 `end start` 改成 `end`，程序还能正确运行吗？
**解**：
- `end` 只表示「源程序到此结束」，**不把「入口在哪」写进 `.obj`**。
- 于是**链接器 `link` 拿不到入口信息**，只能按惯例猜（通常是「第一个段的第一条指令」），并给出警告。对于**只有一个段**的简单程序，这个猜测恰好是对的，所以本程序**大多情况下仍能正确运行**。
- 但一旦程序有多个段（第 6 章开始就是），**`link` 无法判断该从哪个段开始执行**，就必须靠 `end 标号` 明确指定。
**答案**：单段程序可能仍能运行（靠 `link` 的默认猜测），但不保险；**正确做法永远是写 `end start`**，由标号明确指定入口。**记住责任链：`end start` 由汇编器记录进 `.obj`，由链接器写进 `.exe` 文件头，最后 DOS 装载时用它设置 `CS:IP`。**

**例 4.3**（题型：程序返回）
下面程序执行后会怎样？
```asm
codesg segment
    mov ax, 0123h
    mov bx, 0456h
codesg ends
end
```
**解**：
- 程序改完 AX、BX 后**没有把控制权还给 DOS**。
- CPU 会继续执行代码段后面的内存内容——那些是 PSP、DOS 数据或未初始化的空间，内容是随机的。
- 后果：可能执行到随机指令而崩溃、死循环，或破坏系统数据。表现为「程序不返回」「屏幕乱跳」。
**答案**：程序会「跑飞」——因为缺少 `mov ax,4c00h` + `int 21h`，没有正常返回 DOS。

**例 4.4**（题型：装载后寄存器的值）
用 Debug 装载 `1.exe` 后，显示 `DS=075A`、`CS=076A`。请说明两者的含义以及为什么相差 `10H`。
**解**：
- `DS = 075AH` 是 **PSP（程序段前缀）的段地址**，DOS 把 DS 指向 PSP 起点。
- `CS = 076AH` 是**程序代码段的段地址**，即程序入口 `start` 所在的段。
- 相差 `076AH − 075AH = 0010H` 个「节」，每节 16 字节，所以相差 `0010H × 16 = 100H = 256` 字节 = **PSP 的大小**。
**答案**：DS 指向 PSP，CS 指向程序代码段，两者相差一个 PSP（256 字节）的长度。

**例 4.5**（题型：机器码与 IP 递增）
`076A:0000` 处的机器码是 `B82301`，对应的汇编指令是什么？执行后 IP 变成多少？
**解**：
- `B8` 是「`MOV AX, 立即数16`」的操作码，后面跟 2 字节立即数（小端序）`23 01`，即 `0123H`。
- 所以指令是 `MOV AX, 0123`。
- 这条指令共 1 + 2 = **3 字节**，执行时 CPU 自动把 IP 加 3。
**答案**：指令是 `MOV AX,0123`；执行后 `IP = 0003H`。

**例 4.6**（题型：编译连接流程）
写出把 `prog.asm` 变成可执行文件的两种命令行做法，并说明各自生成哪些文件。
**解**：
- **两步法**：`masm prog.asm;` 生成 `prog.obj`；再 `link prog.obj;` 生成 `prog.exe`。中间还可能有 `prog.lst`、`prog.map`（这里用分号跳过了）。
- **一步法**：`ml prog.asm`，直接生成 `prog.obj` 和 `prog.exe`。
- 执行时敲 `prog`（不用敲 `.exe`）。
**答案**：`masm prog.asm;` + `link prog.obj;`，或 `ml prog.asm`；产物都是 `prog.obj` 和 `prog.exe`。

**例 4.7**（题型：assume 的作用）
下面代码中 `assume cs:codesg` 执行时会把 `codesg` 的段地址装入 CS 吗？
```asm
assume cs:codesg
codesg segment
    ; ...（此处省略若干条指令）
codesg ends
end
```
**解**：
- **不会。** `assume` 是**伪指令**，只在汇编阶段起作用，**不产生任何机器码**，运行时不会执行任何动作。
- 它告诉汇编器：「假设 CS 和 codesg 段相关联」，这样在汇编时涉及 CS 的寻址就按 codesg 来算。
- 真正设置 CS 只能靠**转移指令 `jmp`**（如 `jmp far ptr 入口`）或由 DOS 装载时设定。
**答案**：不会。`assume` 只是汇编期的声明，不产生机器码，也不能修改 CS。

## 易错点提醒

1. **错**：只写 `end` 不写标号。**对**：**源程序最后必须写 `end 入口标号`**（本课统一写 `end start`）。多段程序里不指定入口会导致从错误的段开始执行。
2. **错**：把 `mov ax, 4c00h` 写成 `mov ax, 4ch`。**对**：**功能号要放在 AH 里**——`4c00h` 的高字节 `4CH` 才会进 AH。写 `mov ax, 4ch` 后 AH = 00H、AL = 4CH，会调用到 DOS 的 0 号功能（程序终止但不等价），行为不符合预期。
3. **错**：忘了写 `int 21h`。**对**：`mov ax,4c00h` 只是「把功能号准备好」，**必须紧跟 `int 21h` 才真正调用 DOS**。
4. **错**：以为 `.obj` 可以直接运行。**对**：`.obj` 里只有机器码和重定位信息，没有最终内存布局，**必须连接成 `.exe`** 才能执行。
5. **错**：以为 `assume` 会真的设置段寄存器。**对**：`assume` 是伪指令，**不产生机器码，运行时什么都不做**。设置 DS/SS 要写 `mov`，设置 CS 只能靠 `jmp`。
6. **错**：以为 `masm` 一步就能得到 `.exe`。**对**：`masm` 只生成 `.obj`，**要 `link` 才生成 `.exe`**；想一步到位用 `ml 1.asm`。
7. **错**：忘记 `mov ax,4c00h` 导致程序「跑飞」。**对**：DOS 汇编程序必须显式返回，**标准结尾是 `mov ax,4c00h` + `int 21h`**。
8. **错**：以为装载后 `DS` 指向自己的数据段。**对**：**DOS 装载时把 DS 设为 PSP 的段地址**（比 CS 小 `10H`），要访问自己的数据段必须重新 `mov ds, ax`。
9. **错**：把注释写成 UTF-8 中文导致 DOS 下乱码。**对**：DOS 环境用 **ANSI（GBK）** 编码保存 `.asm`；不确定就写英文注释。
10. **错**：源程序里写了两个 `end`。**对**：**一个源程序只能有一个 `end`，且必须在最后**。

## 本章小结

- 汇编程序的生命周期：**编写 `.asm` → 编译 `masm` 得 `.obj` → 连接 `link` 得 `.exe` → 由 `COMMAND.COM` 装入内存执行**。
- `assume`、`segment...ends`、`end` 都是**伪指令**（给汇编器，无机器码）；`mov`、`add`、`int` 是**汇编指令**（给 CPU，有机器码）。
- **`end start` 指定程序入口**；一个源程序只能有一个 `end`，且在最后。
- **程序的标准结尾：`mov ax, 4c00h` + `int 21h`**（AH = 功能号 4CH，AL = 返回码）。
- 连接的三件事：**合并段、补入库代码、按可执行格式组织并重定位**。
- **把程序装入内存并让它运行的是 DOS 的命令解释器 `COMMAND.COM`**。
- Debug 跟踪：`r` 看寄存器、`t` 单步、`p` 跨过、`u` 反汇编、`g` 运行到地址、`q` 退出。
- **装载后 DS 指向 PSP，CS 指向程序入口，二者相差 `10H`（256 字节）**。

> **一句话记住本章**：**asm → obj → exe 三步走，伪指令给汇编器、汇编指令给 CPU，程序入口靠 `end 标号`，收尾必写 `mov ax,4c00h` + `int 21h`。**

## 自测题

**1.** 写出汇编程序从源文件到执行的完整流程，标出每一步的工具和产物。
**答**：`1.asm` →（`MASM.EXE` 编译）→ `1.obj` →（`LINK.EXE` 连接）→ `1.exe` →（`COMMAND.COM` 装入）→ 内存执行。

**2.** `assume`、`segment`、`ends`、`end` 各是什么？给谁看的？
**答**：都是伪指令，给汇编器看的，不产生机器码。`segment`/`ends` 定义一个段的起止；`assume` 声明段与段寄存器的关联；`end` 标记源程序结束（`end 标号` 同时指定入口）。

**3.** `end` 和 `end start` 有什么区别？
**答**：`end` 只说源程序结束，不指定入口；`end start` 额外指定 `start` 标号处为程序入口。

**4.** 程序正常返回 DOS 的两条指令是什么？为什么是 `4c00h`？
**答**：`mov ax,4c00h` + `int 21h`。`int 21h` 的功能号在 AH 中，`4c00h` 的高字节 `4CH` 正好是「程序结束」功能号，低字节 `00H` 是返回码。

**5.** 编译和连接各做什么？为什么 `.obj` 不能直接执行？
**答**：编译把汇编指令翻译成机器码生成 `.obj`；连接负责合并段、补入库代码、按可执行格式组织并做重定位。`.obj` 没有最终内存布局，重定位信息未确定，所以不能执行。

**6.** 谁把 `.exe` 装入内存并让它运行？
**答**：DOS 的命令解释器 `COMMAND.COM`。

**7.** Debug 中 `t` 和 `p` 有什么区别？
**答**：都是单步执行；`t` 遇到子程序（`call`）和中断（`int`）会**进入**内部逐条执行，`p` 会**一次执行完**并停在它的下一条指令。

**8.** 装载后 `DS=075A`、`CS=076A`，说明这两个值分别是什么，为什么差 `10H`。
**答**：`DS` 指向 PSP（程序段前缀，256 字节），`CS` 指向程序代码段。相差 `0010H` 节 = `100H` 字节 = 256 字节，正是 PSP 的大小。

**9.** `075A:0000` 处机器码为 `B82301`，这条指令是什么？执行后 IP 是多少（假设执行前 IP = 0000）？
**答**：`MOV AX,0123`（`B8` 是操作码，`23 01` 是小端序的立即数 `0123H`）。指令长 3 字节，执行后 `IP = 0003H`。

**10.** 一个源程序里写了两条 `end`，会怎样？
**答**：非法。一个源程序**只能有一个 `end`，且必须位于最后**。多余或位置错误的 `end` 会导致汇编报错或后面的代码被忽略。

**11.** 为什么很多程序开头要写 `mov ax, data` + `mov ds, ax`？
**答**：因为 DOS 装载程序时把 DS 设成了 PSP 的段地址，而不是程序自己的数据段。要用 `[bx]` 这类以 DS 为默认段寄存器的寻址方式访问自己的数据，必须先把 DS 改成数据段的段地址。
