## 12.1 内中断的产生

**中断：CPU 不再接着向下执行，而是转去处理这个中断信息。**

**中断信息 = 一个「中断类型码」（8 位，取值 0~255），CPU 用它来定位要执行的处理程序。**

**按来源，中断分为两类：**

| 类别 | 来源 | 例子 |
|---|---|---|
| **内中断**（本章） | CPU **内部** | 除法错误、单步执行、`into`、`int n` |
| **外中断**（第 15 章） | CPU **外部** | 键盘输入、时钟、外设请求 |

**8086 内部能产生的中断（必须记住类型码）：**

| 类型码 | 中断源 | 说明 |
|---|---|---|
| **0** | **除法错误** | `div` 指令除数为 0，或商超出范围（如 `1000H ÷ 1`） |
| **1** | **单步执行** | `TF = 1` 时，每执行完一条指令就产生 |
| **3** | **断点中断** | 执行 `int 3`（单字节指令，机器码 `CC`），Debug 的 `g`/`p` 用它设断点 |
| **4** | **溢出中断** | 执行 `into` 指令，若 `OF = 1` 则产生 |
| **n** | **`int n` 指令** | 由程序员显式指定，`n` 就是类型码（0~255） |

> **重点**：**除了除法错误是「被动」产生的，其余都是「程序主动触发」的。** 平时写程序最常用的就是 `int n`——第 13 章的 DOS/BIOS 调用、本章的自定义中断都是它。

## 12.2 中断处理程序

**CPU 收到中断信息后，不能自己去「解决」问题（CPU 只知道一个类型码），它必须转去执行一段事先写好的代码来处理这个中断——这段代码就叫「中断处理程序」。**

**关键问题：CPU 怎么知道处理程序在哪？**

**答案：靠「中断向量表」——一张事先约定好位置的表，里面存着每个类型码对应的处理程序的入口地址。**

## 12.3 中断向量表

**中断向量表（Interrupt Vector Table）存放在内存的最低端：`0000:0000` 开始，共 1024 字节（1KB）。**

**结构：256 个表项，每个表项 4 字节，存放一个中断处理程序的入口地址。**

```
      中断向量表（0000:0000 ~ 0000:03FF，共 1024 字节）
    ┌────────────────────────────────────────┐  0000:0000
    │  0 号表项：偏移(2字节) + 段(2字节)      │  ← 0000:0000 ~ 0000:0003
    ├────────────────────────────────────────┤  0000:0004
    │  1 号表项：偏移(2字节) + 段(2字节)      │  ← 0000:0004 ~ 0000:0007
    ├────────────────────────────────────────┤  0000:0008
    │  2 号表项                               │
    ├────────────────────────────────────────┤
    │  ……                                    │
    ├────────────────────────────────────────┤  0000:0nnn
    │  n 号表项：IP 在 n×4，CS 在 n×4+2       │
    ├────────────────────────────────────────┤
    │  ……                                    │
    ├────────────────────────────────────────┤  0000:03FC
    │ 255 号表项                              │  ← 0000:03FC ~ 0000:03FF
    └────────────────────────────────────────┘
```

**单个表项的 4 个字节（以小端序存放）：**

```
      低地址 ────────────────────────► 高地址
    ┌──────────┬──────────┬──────────┬──────────┐
    │  IP 低字节│  IP 高字节│  CS 低字节│  CS 高字节│
    └──────────┴──────────┴──────────┴──────────┘
      n*4        n*4+1      n*4+2      n*4+3
      └───── 偏移地址 ─────┘└───── 段地址 ─────┘
```

**n 号表项的地址公式（必背）：**

```
   偏移地址 IP 存放在：  0000 : (n × 4)
   段地址   CS 存放在：  0000 : (n × 4 + 2)
```

**验证几个常用中断的向量位置：**

| 中断 | 类型码 n | IP 存放地址 | CS 存放地址 |
|---|---|---|---|
| 除法错误 | 0 | `0000:0000` | `0000:0002` |
| 单步中断 | 1 | `0000:0004` | `0000:0006` |
| 断点 `int 3` | 3 | `0000:000C` | `0000:000E` |
| 溢出 `into` | 4 | `0000:0010` | `0000:0012` |
| 显示 `int 10h` | 16 | `0000:0040` | `0000:0042` |
| 磁盘 `int 13h` | 19 | `0000:004C` | `0000:004E` |
| 键盘 `int 16h` | 22 | `0000:0058` | `0000:005A` |
| DOS 调用 | 33（21H） | `0000:0084` | `0000:0086` |

> **重点**：**中断向量表的位置和大小是硬件固定的（`0000:0000` 起 1KB），不是操作系统随便挑的。** 你在 `0000:0200` 装自己的代码之所以安全，正是因为 `0000:0000~0000:03FF` 是**向量表**（只放 1024 字节的地址），而 `0000:0400` 之后是 BIOS 数据区——**`0000:0200~0000:02FF` 这块 256 字节是向量表内的空闲区**（第 5 章讲过的安全空间）。

**验证练习：`int 21h` 的处理程序入口在哪？**

```
   n = 21H = 33
   IP 在 33 × 4 = 132 = 0084H
   CS 在 33 × 4 + 2 = 134 = 0086H
```

**在 Debug 中查看：**

```
-d 0:84 87
0000:0080                      xx xx xx xx
```

**两条指令读出 21H 号中断的入口地址：**

```asm
mov ax, 0
mov es, ax
mov ax, es:[21h*4]          ; AX = 入口偏移
mov bx, es:[21h*4+2]        ; BX = 入口段地址
```

## 12.4 ★★★ 中断过程 ★★★

**CPU 在执行完当前指令、拿到中断类型码 `n` 之后，硬件自动完成下面 6 个步骤（不需要程序干预）：**

```
   ① 取得中断类型码 N
   ────────────────────────────────────────────
   ② pushf            ; ★ 标志寄存器入栈（保存现场）
   ③ TF = 0, IF = 0   ; ★ 禁止单步、禁止可屏蔽外中断
   ────────────────────────────────────────────
   ④ push CS          ; ★ 当前代码段地址入栈
   ⑤ push IP          ; ★ 当前指令指针入栈（即返回地址）
   ────────────────────────────────────────────
   ⑥ (IP) = (N×4)     ; 从中断向量表取出处理程序入口
      (CS) = (N×4+2)  ; 转去执行中断处理程序
```

**中断过程执行完后栈中的样子：**

```
      栈段 SS:SP
   ┌──────────────┐ ← 原来的栈顶（高地址）
   │    FLAGS     │ ← ② pushf 压入
   ├──────────────┤
   │      CS      │ ← ④ push CS
   ├──────────────┤
   │      IP      │ ← ⑤ push IP ← SP（现在的栈顶）
   └──────────────┘ ← 低地址
```

**与 `call` 的对比（这是理解中断过程的关键）：**

| 对比项 | `call 标号`（近调用） | `call far ptr 标号` | **中断过程** |
|---|---|---|---|
| 压入的内容 | 只压 IP | 先压 CS，再压 IP | **先压 FLAGS，再压 CS，再压 IP** |
| 压入字节数 | 2 | 4 | **6** |
| 接收方怎么返回 | `ret`（弹 IP） | `retf`（弹 IP、弹 CS） | **`iret`（弹 IP、弹 CS、弹 FLAGS）** |
| 是否清 IF/TF | 否 | 否 | **是（TF=0、IF=0）** |
| 触发方式 | 程序主动 | 程序主动 | **硬件自动** |

**记住这条口诀：**

```
   call  →  ret      （压 1 个，弹 1 个）
   call far → retf   （压 2 个，弹 2 个）
   中断   → iret     （压 3 个，弹 3 个）
```

> **重点**：**中断过程会自动清 `TF` 和 `IF`。** 清 `TF` 是为了避免中断处理程序自己又被单步中断打断（无限递归）；清 `IF` 是为了避免可屏蔽外中断打断当前中断处理（第 15 章）。**这两个标志位在 `iret` 时会从栈中恢复。**

## 12.5 中断处理程序

**中断处理程序就是一串代码，但有两个特殊要求：**

**要求一：入口地址必须登记在中断向量表的对应表项里。**

**要求二：必须用 `iret` 返回，而不是 `ret`。**

**`iret` 的功能（等价于三条指令）：**

```asm
iret
; 等价于：
pop ip
pop cs
popf
```

**一个中断处理程序的标准骨架：**

```asm
; ===== 中断处理程序模板 =====
inthandler:
    push ax                 ; ★ 保护现场：保存本程序会用到的寄存器
    push bx
    push cx
    push ds
    push es
    push si
    push di

    ; …… 中断处理的具体代码 ……

    pop di                  ; ★ 恢复现场：与 push 顺序必须相反
    pop si
    pop es
    pop ds
    pop cx
    pop bx
    pop ax

    iret                    ; ★ 用 iret 返回（恢复 IP、CS、FLAGS）
```

> **重点**：**「保护现场」在中断处理程序里比在普通子程序里更重要。** 因为中断是**异步**发生的——你不知道主程序正把什么重要数据放在 `AX` 里。**不保护现场就会造成极难排查的随机错误。**

**`ret` 和 `iret` 用在中断处理程序里的后果对比：**

| 用法 | 栈的变化 | 结果 |
|---|---|---|
| `iret` | 弹 IP、弹 CS、弹 FLAGS（共 6 字节） | **正确返回** |
| `ret` | 只弹 IP（2 字节） | CS 和 FLAGS 留在栈上 → **栈失衡，程序跑飞** |
| `retf` | 弹 IP、弹 CS（4 字节） | FLAGS 留在栈上 → **标志寄存器错乱** |

## 12.6 除法错误中断的处理

**`div` 指令在两种情况下产生 0 号中断（除法错误）：**

```
   ① 除数为 0
   ② 商超出了目的寄存器能表示的范围（除法溢出）
```

**DOS 对 0 号中断的默认处理：**

```
   ① 显示字符串 "Divide overflow"
   ② 返回 DOS（终止当前程序）
```

**触发除法错误的完整程序：**

```asm
assume cs:code
code segment
start:
    mov ax, 1000h           ; 被除数 DX:AX = 0000:1000H
    mov bh, 1               ; 除数 = 1
    div bh                  ; ★ 1000H ÷ 1 = 1000H = 4096
                            ;   但 8 位除法的商只能放 AL（最大 FFH = 255）
                            ;   商 1000H 装不下 → 除法溢出 → 产生 0 号中断

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：屏幕显示

```
Divide overflow
```

**然后程序直接返回 DOS，`mov ax,4c00h` / `int 21h` 根本不会被执行（因为中断处理程序已经终止了程序）。**

**为什么会溢出？——回顾 `div` 的规则：**

| 除数 | 被除数 | 商 | 余数 |
|---|---|---|---|
| 8 位（`r/m8`） | `AX`（16 位） | `AL`（**只能存 0~255**） | `AH` |
| 16 位（`r/m16`） | `DX:AX`（32 位） | `AX`（**只能存 0~65535**） | `DX` |

**`1000H ÷ 1 = 1000H`，但 `AL` 只有 8 位，最大 `FFH`，装不下 `1000H` → 溢出。**

> **重点**：**这就是第 8 章强调「`div` 之前要清除 `DX`」的另一个原因**——如果 `DX` 里残留了垃圾，`DX:AX` 可能非常大，商就会超范围，于是触发除法错误中断。**这个 bug 的典型表现是程序突然打印 "Divide overflow" 并退出。**

## 12.7 编程处理0号中断

**目标：自己写一个 0 号中断处理程序，当发生除法溢出时，在屏幕中间显示 `overflow!`，然后返回 DOS。**

**要做三件事：**

```
   ① 编写中断处理程序 do0
   ② 把 do0 的代码安装到内存中（选 0000:0200 这块安全空间）
   ③ 设置中断向量表的 0 号表项，指向 do0 的入口
```

**为什么用 `0000:0200`？**

```
   0000:0000 ~ 0000:03FF  中断向量表（1KB）——前面 512 字节已被 DOS 等系统使用
   0000:0200 ~ 0000:02FF  向量表内的空闲区，256 字节 ← 装在这里最省事
   0000:0400 ~             BIOS 数据区
```

## 12.8 安装

**「安装」就是把一段代码从当前所在位置复制到目标内存，并让中断向量指向那里。**

**核心程序段：**

```asm
    ; ===== 把 do0 的代码搬到 0:200 处 =====
    mov ax, cs
    mov ds, ax              ; DS:SI → 源（do0 在代码段里的位置）
    mov si, offset do0
    mov ax, 0
    mov es, ax              ; ES:DI → 目的（0000:0200）
    mov di, 200h
    mov cx, offset do0end - offset do0   ; ★ 长度 = 末尾标号 − 起始标号
    cld                     ; ★ DF = 0，正向复制
    rep movsb               ; ★ 串传送（第 11 章）
```

**`mov cx, offset do0end - offset do0` 是怎么工作的？**

```
   offset do0      = do0 在代码段中的偏移
   offset do0end   = do0end 在代码段中的偏移
   两者相减        = do0 这段代码的字节数
```

**这是汇编中的经典技巧：`offset 标号` 是汇编期就能算出的常量，所以「末尾偏移 − 起始偏移」在编译时就被算成了立即数。** 这样即使你修改了 `do0` 的代码（长度变了），`CX` 也会自动跟着变，不用手动改数字。

**注意：`do0` 里包含了数据（字符串），所以 `do0end` 必须放在字符串之后再 `nop` 标记，才能把数据也一起搬过去。**

## 12.9 do0

**`do0` 要做的事：把字符串 `overflow!` 写到屏幕中间的显存位置，然后返回 DOS。**

**显存的基本知识（第 1 章提过，这里要用到具体的计算）：**

```
   显存段地址：B800H（彩色文本模式）
   屏幕：25 行 × 80 列，每个字符占 2 个字节
        ┌──────┬──────┐
        │ ASCII│ 属性 │  ← 2 字节 = 1 个显示位置
        └──────┴──────┘
   
   第 r 行第 c 列的显存偏移 = (r × 80 + c) × 2
   （行、列都从 0 开始编号）
```

**计算屏幕中间位置：**

```
   行号 = 12（屏幕 25 行，中间是第 12 行，0~24）
   列号 = 36（要让 9 个字符居中：(80 − 9) ÷ 2 ≈ 35，取 36 也行）
   
   偏移 = (12 × 80 + 36) × 2 = (960 + 36) × 2 = 996 × 2 = 1992 = 7C8H
   
   教材写法：160 × 12 + 36 × 2 = 1920 + 72 = 1992 ✓
   （160 = 80 列 × 2 字节/列，即一行的字节数）
```

**`do0` 的完整代码：**

```asm
do0:
    jmp short do0start          ; ★ 跳过下面的字符串，共 2 字节
                                ;    （紧接着的 9 字节是数据，不是指令！）
    db "overflow!"              ; ★ 要显示的字符串，9 个字节
                                ;    安装到 0:200 后，它位于 0:202

do0start:
    mov ax, cs                  ; ★ 此时 CS 已被中断过程设为 0
    mov ds, ax                  ;   所以 DS = 0，指向中断向量表所在段
    mov si, 202h                ; ★ DS:SI → 字符串（0:202）
                                ;    为什么是 202H？因为 do0 装在 0:200，
                                ;    jmp short 占 2 字节，字符串从 202H 开始
    mov ax, 0b800h              ; ★ 显存段地址
    mov es, ax
    mov di, 160*12 + 36*2       ; ★ ES:DI → 屏幕第 12 行第 36 列

    mov cx, 9                   ; ★ 字符串长度 = 9 个字符
s:
    mov al, [si]                ; 取一个字符
    mov es:[di], al             ; 写入显存的字符位置
    inc di
    mov byte ptr es:[di], 2     ; ★ 写入属性字节：02H = 黑底绿字
                                ;    必须用 byte ptr 指明是 1 字节
    inc di                      ; DI 前进 2 字节（字符 + 属性）
    inc si
    loop s

    ; ===== 返回 DOS =====
    mov ax, 4c00h
    int 21h

do0end:
    nop                         ; ★ 用 nop 标记结尾，方便算长度
```

**关于属性字节 `02H`：**

```
   属性字节：  bit7 ──────────────── bit0
              闪烁 │ 背景色(3位) │ 高亮 │ 前景色(3位)
   
   02H = 0000 0010B
         闪烁=0，背景=000（黑），高亮=0，前景=010（绿）
   
   → 黑底绿字
```

| 常用属性值 | 效果 |
|---|---|
| `07H` | 黑底白字（DOS 默认） |
| `02H` | 黑底绿字 |
| `04H` | 黑底红字 |
| `1EH` | 蓝底黄字 |
| `70H` | 白底黑字（反白） |
| `8AH` | 闪烁 + 黑底浅绿 |

> **重点**：**`jmp short do0start` 这个技巧叫「数据与代码混排」——CPU 顺着往下执行会撞上字符串，所以必须先跳过去。** 这是第 9 章「`jmp short` 位移跳转」的直接应用。**注意 `db "overflow!"` 里的 9 个字节安装后位于 `0:202`，所以 `si` 要设成 `202h`——这个偏移是「安装位置 200H + 2 字节 jmp」算出来的，写死很容易错，务必理解推导过程。**

## 12.10 设置中断向量

**把 0 号中断向量指向 `0000:0200`：**

```asm
    ; ===== 设置中断向量表的 0 号表项 =====
    mov ax, 0
    mov es, ax                  ; ES = 0（中断向量表所在段）
    mov word ptr es:[0*4], 200h     ; ★ 偏移 IP = 0200H（存到 0000:0000）
    mov word ptr es:[0*4+2], 0      ; ★ 段地址 CS = 0000H（存到 0000:0002）
```

**注意 `word ptr` 不能省——因为目的操作数 `es:[0*4]` 没有寄存器能说明长度。**

**完整程序（可以直接汇编运行）：**

```asm
assume cs:code
code segment
start:
    ; ===== 第一步：把 do0 安装到 0:200 =====
    mov ax, cs
    mov ds, ax
    mov si, offset do0
    mov ax, 0
    mov es, ax
    mov di, 200h
    mov cx, offset do0end - offset do0
    cld
    rep movsb

    ; ===== 第二步：设置中断向量表 0 号表项 → 0:200 =====
    mov ax, 0
    mov es, ax
    mov word ptr es:[0*4], 200h
    mov word ptr es:[0*4+2], 0

    ; ===== 第三步：故意制造除法溢出，验证中断处理程序 =====
    mov ax, 1000h
    mov bh, 1
    div bh                      ; ★ 触发 0 号中断 → 跳到我们的 do0

    mov ax, 4c00h
    int 21h

; ===== 中断处理程序 =====
do0:
    jmp short do0start
    db "overflow!"
do0start:
    mov ax, cs
    mov ds, ax
    mov si, 202h
    mov ax, 0b800h
    mov es, ax
    mov di, 160*12 + 36*2
    mov cx, 9
s:
    mov al, [si]
    mov es:[di], al
    inc di
    mov byte ptr es:[di], 2
    inc di
    inc si
    loop s

    mov ax, 4c00h
    int 21h
do0end:
    nop

code ends
end start
```

**运行结果：**

```
   （程序执行到 div bh 时触发除法溢出）
   （屏幕第 12 行第 36 列出现绿色的 "overflow!"）
   （因为 do0 最后调用了 int 21h 的 4CH 功能，程序直接返回 DOS）
```

**屏幕效果示意：**

```
   第 0 行  C:\MASM>1
   ……
   第 11 行 （空行）
   第 12 行                                    overflow!
   ……
   第 24 行
```

> **重点**：**这就是「拦截系统中断」的完整流程——安装代码 → 改中断向量 → 自己的代码接管。** 这也是计算机病毒最经典的原理（改写 `int 21h` 或 `int 9` 的向量来劫持系统调用）。**注意本程序只在「程序运行期间」有效，程序退出后 `0:200` 的代码还在、向量也还指向它，但这段内存随时可能被别的程序覆盖——所以真正的中断驻留程序（TSR）必须用第 13 章的方法常驻内存。**

## 12.11 单步中断

**`TF`（Trap Flag，陷阱标志）是标志寄存器的 bit8。**

```
   TF = 0  →  正常执行
   TF = 1  →  CPU 每执行完一条指令，就产生一次单步中断（类型码 1）
```

**单步中断的用途：让调试器能「一条一条地执行程序」。**

**Debug 的 `t` 命令原理（关键理解）：**

```
   ① Debug 把 TF 置 1
   ② CPU 执行一条指令
   ③ 执行完后检测到 TF = 1 → 产生 1 号中断
   ④ 1 号中断处理程序（Debug 提供的）把当前所有寄存器的值显示在屏幕上
   ⑤ 中断处理程序返回，程序回到「下一条指令」继续
   ⑥ Debug 等待用户输入下一个命令
```

**中断过程为什么要把 `TF` 清 0？**

**因为如果不清零，进入 1 号中断处理程序后，处理程序里的每一条指令又会触发新的单步中断——无限递归，系统立刻死机。**

**用程序手工体验单步中断（教材实验）：**

```asm
assume cs:code
code segment
start:
    mov ax, 0
    mov bx, 0

    pushf                       ; ★ 取出标志寄存器
    pop ax
    or  ax, 0100h               ; ★ 置 TF = 1（bit8）
    push ax
    popf                        ; ★ 写回标志寄存器，开启单步

    mov ax, 1                   ; ★ 从这里开始，每条指令后都产生单步中断
    mov bx, 2
    mov cx, 3

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：由于 1 号中断处理程序是 DOS/BIOS 提供的，它会按自己的方式处理单步中断——通常表现为程序行为异常或直接回到 DOS 提示符（不同环境下表现不同）。**这个程序的价值在于「看到 `TF=1` 确实会引发中断」这一现象。**

## 12.12 响应中断的特殊情况

**一般情况下，CPU 在执行完当前指令后，如果检测到中断信息，就响应中断。**

**但有一个重要的例外：**

```
   ★ 在执行完「向 SS 寄存器传送数据」的指令之后，
     即使发生中断，CPU 也不响应。
   ★ 这个「不响应」的状态一直持续到下一条指令执行完。
```

**具体例子：**

```asm
    mov ax, 1000h
    mov ss, ax          ; ★ 这条指令执行完后，CPU 不响应任何中断
    mov sp, 0           ; ★ 直到这条指令也执行完，才恢复响应中断
```

**为什么要这样设计？**

**因为 `SS` 和 `SP` 必须成对设置才有意义：**

```
   SS 决定栈段在哪，SP 决定栈顶在哪。
   
   如果 CPU 在 mov ss,ax 之后、mov sp,0 之前响应了中断：
       → 中断过程要 push 6 个字节到栈里
       → 但此时 SP 还是「旧栈段」的栈顶值！
       → 数据被压到了错误的地址（新 SS 配旧 SP）
       → 栈彻底错乱，中断返回时程序崩溃
```

**一句话：这个硬件特性是为了保证「`SS:SP` 要么都是旧值，要么都是新值」，不会出现「新 SS + 旧 SP」的危险中间状态。**

> **重点**：**这也解释了第 6 章强调的「`mov ss,ax` 后面必须紧跟 `mov sp,立即数`」——不仅是编程规范，更是硬件保护机制。** 顺便说，调试时在 `mov ss,ax` 后面用 `t` 单步跟踪，你会看到**这两条指令是被一起执行完的**（单步中断也被推迟），这不是 Debug 的 bug，而是 CPU 的规定。

## 典型例题

**例 12.1**（题型：内中断类型码识别）
指出下面各种情况产生的内中断类型码：
（1）执行 `mov ax,1` / `mov bx,0` / `div bx`
（2）`TF = 1` 时执行完一条 `mov` 指令
（3）执行 `int 21h`
（4）执行 `into` 且 `OF = 1`
**解**：
- （1）除数为 0 → **除法错误 → 类型码 0**。
- （2）`TF = 1` → **单步中断 → 类型码 1**。
- （3）`int n` 指令 → **类型码就是 21H**（即十进制的 33）。
- （4）`into` 指令在 `OF = 1` 时 → **溢出中断 → 类型码 4**。
**答案**：0、1、21H、4。

**例 12.2**（题型：中断向量表地址计算）
已知 `int 8` 的中断处理程序入口地址是 `1234:5678`，写出中断向量表中该表项 4 个字节的内容。
**解**：
- **表项位置**：`n = 8`，所以 IP 在 `0000:0020`，CS 在 `0000:0022`。
- **内容**：`IP = 5678H`（偏移），`CS = 1234H`（段地址）。
- **小端序存放**：低字节在前。

| 地址 | 字节内容 | 含义 |
|---|---|---|
| `0000:0020` | `78H` | IP 低字节 |
| `0000:0021` | `56H` | IP 高字节 |
| `0000:0022` | `34H` | CS 低字节 |
| `0000:0023` | `12H` | CS 高字节 |

**答案**：从低地址到高地址依次为 `78H 56H 34H 12H`，即 `int 8` 的表项内容是字符串 `78 56 34 12`。

**例 12.3**（题型：中断过程与栈分析）
某程序在 `CS = 1000H`、`IP = 0100H`、`SP = FFFEH` 时发生 0 号中断，中断处理程序入口为 `0000:0200`。写出中断过程执行后 CS、IP、SP 的值，以及栈中 3 个字的内容。
**解**：
- **中断过程 6 步**：① 取类型码 `N = 0`；② `pushf`（保存当时的 FLAGS）；③ `TF=0, IF=0`；④ `push CS`；⑤ `push IP`；⑥ 从向量表取入口：`(IP) = (0×4) = 0200H`、`(CS) = (0×4+2) = 0000H`。题中给出的「入口为 `0000:0200`」正说明 0 号表项里存的就是这个地址。

- **压栈过程**（栈向低地址生长）：
  - `pushf`：`SP = FFFEH − 2 = FFFCH`，`[FFFC] = FLAGS`
  - `push CS`：`SP = FFFAH`，`[FFFA] = 1000H`
  - `push IP`：`SP = FFF8H`，`[FFF8] = 0100H`
- **转向**：`IP = 0200H`、`CS = 0000H`。

**答案**：`CS = 0000H`、`IP = 0200H`、`SP = FFF8H`；栈中从高到低为 `FLAGS`（在 FFFCH）、`1000H`（在 FFFAH）、`0100H`（在 FFF8H）。

**栈布局图：**

```
   SS:FFFEH ┌──────────────┐
            │  （原栈内容） │
   SS:FFFCH ├──────────────┤ ← pushf
            │    FLAGS     │
   SS:FFFAH ├──────────────┤ ← push CS
            │    1000H     │
   SS:FFF8H ├──────────────┤ ← push IP ← SP
            │    0100H     │
            └──────────────┘
```

**例 12.4**（题型：中断处理程序的返回）
某中断处理程序中，保护现场时依次 `push ax` / `push bx` / `push cx`，那么恢复现场时应按什么顺序？如果用 `ret` 代替 `iret` 会发生什么？
**解**：
- **恢复顺序必须与保护顺序相反**（栈是后进先出）：`pop cx` / `pop bx` / `pop ax`。
- **用 `ret` 代替 `iret` 的后果**：`ret` 只从栈中弹出 IP（2 字节），而中断过程压入了 `FLAGS`(2) + `CS`(2) + `IP`(2) = 6 字节。所以 `ret` 之后栈上还残留 4 字节（`CS` 和 `FLAGS`），**栈指针错误 → 后续所有 `push`/`pop` 全部错位 → 程序崩溃；同时 `FLAGS` 也没有被恢复**。

**答案**：`pop cx` / `pop bx` / `pop ax`；用 `ret` 会导致栈失衡且 `FLAGS` 未恢复，必须用 `iret`。

**例 12.5**（题型：修改中断向量）
编写程序，把 0 号中断的入口地址改为 `0000:0200`。
**解**：
```asm
assume cs:code
code segment
start:
    mov ax, 0
    mov es, ax                  ; ★ ES = 0，指向中断向量表所在段
    mov word ptr es:[0*4], 200h     ; ★ 偏移 → 0000:0000
    mov word ptr es:[0*4+2], 0      ; ★ 段地址 → 0000:0002

    mov ax, 4c00h
    int 21h
code ends
end start
```
**答案**：见上。**关键**：① `ES` 要设成 0；② `0*4` 是 0 号表项的 IP 位置，`0*4+2` 是 CS 位置；③ 必须用 `word ptr` 指明传送长度。

**例 12.6**（题型：安装中断处理程序）
某中断处理程序从标号 `do0` 开始，到标号 `do0end` 结束（`do0end` 处是一条 `nop`）。写出把它安装到 `0000:0200` 的代码，并说明 `CX` 为什么这样取值。
**解**：
```asm
    mov ax, cs
    mov ds, ax                  ; DS:SI → 源（当前代码段中的 do0）
    mov si, offset do0
    mov ax, 0
    mov es, ax                  ; ES:DI → 目的（0000:0200）
    mov di, 200h
    mov cx, offset do0end - offset do0      ; ★ 长度 = 末尾偏移 − 起始偏移
    cld
    rep movsb
```
**`CX` 这样取值的原因**：`offset 标号` 在汇编期就是常量，两个 `offset` 相减得到的就是 `do0` 这段代码占用的字节数。**用「偏移相减」而不是写死一个数字，好处是修改 `do0` 的代码后长度会自动更新，不需要手动维护。**

**答案**：见上。

**例 12.7**（题型：显存位置计算）
要在屏幕第 5 行第 10 列（行列均从 0 开始编号）显示一个字符及其属性，写出计算显存偏移的过程。
**解**：
- 屏幕每行 80 个字符，每个字符占 2 字节（字符 + 属性），所以**一行占 160 字节**。
- 第 5 行第 10 列之前，共有 `5 × 80 + 10 = 410` 个字符位置。
- 每个位置 2 字节，所以偏移 = `410 × 2 = 820 = 334H`。
- 也可以写成：`160 × 5 + 10 × 2 = 800 + 20 = 820` ✓
**答案**：显存偏移 `820`（`334H`），段地址 `B800H`；即字符写入 `ES:[820]`，属性写入 `ES:[821]`。

## 易错点提醒

1. **错**：以为中断向量表每项 2 字节。**对**：**每项 4 字节**——低 2 字节是偏移 `IP`，高 2 字节是段地址 `CS`（因为入口地址是「段:偏移」形式，共 4 字节）。
2. **错**：把中断向量表的位置记成别的段。**对**：**固定在 `0000:0000` 开始，共 1024 字节（256 项 × 4 字节）**，即 `0000:0000 ~ 0000:03FF`。
3. **错**：算错 `n` 号表项的地址。**对**：**`IP` 在 `n × 4`，`CS` 在 `n × 4 + 2`**。例如 `int 21h`：`n = 21H = 33`，`IP` 在 `132 = 0084H`，`CS` 在 `0086H`。
4. **错**：以为中断过程只压入 `CS` 和 `IP`。**对**：**中断过程压入 3 个字——先 `FLAGS`，再 `CS`，最后 `IP`**（共 6 字节），所以必须用 `iret` 返回。
5. **错**：在中断处理程序里用 `ret` / `retf` 返回。**对**：**必须用 `iret`**。`ret` 只弹 2 字节，会留下 4 字节垃圾在栈上，导致栈失衡。
6. **错**：忘了在中断处理程序开头保护现场。**对**：中断是**异步**的，主程序的寄存器状态未知。**处理程序里用到的每个寄存器都要 `push` 保存、退出前逆序 `pop` 恢复。**
7. **错**：以为 `push`/`pop` 顺序可以随意。**对**：**必须严格逆序**——先进后出。`push ax` / `push bx` / `push cx` 对应 `pop cx` / `pop bx` / `pop ax`。
8. **错**：中断过程里 `TF=0`、`IF=0` 的意义搞不清。**对**：清 `TF` 防止单步中断递归（否则处理程序自己每条指令都被打断）；清 `IF` 暂时屏蔽可屏蔽外中断，保证当前中断处理不被打断。**`iret` 时会从栈中恢复这两个标志。**
9. **错**：写 `mov es:[0*4], 200h` 忘了 `word ptr`。**对**：**目的操作数 `es:[0*4]` 无法指明长度，必须写成 `mov word ptr es:[0*4], 200h`**。**★ 本机 MASM 6.11 实测**：默认模式报 `error A2070: invalid instruction operands`；用 `/Zm`（MASM 5.1 兼容模式，王爽教材就是 5.0）**不报错**，MASM 按**字**处理、静默写坏 2 个字节（机器码 `26: C7 06 0000 …`，`26:` 是 `ES:` 段超越前缀）。**两种模式下都该写 `ptr`——省了它要么报错、要么静默出错。**
10. **错**：安装中断处理程序时把 `si` 写错、或忘了包含数据。**对**：源用 `DS:SI`、目的用 `ES:DI`；**`do0` 里的字符串也是要搬的数据，所以 `do0end` 标号必须放在字符串之后**，否则字符串不会被复制过去。
11. **错**：`do0` 里 `mov si, 202h` 的 `202H` 直接抄下来不理解。**对**：它是**「安装位置 200H + 2 字节的 `jmp short`」**算出来的——字符串紧跟在 `jmp short do0start` 后面。**如果改了结构（比如把 jmp 换成 3 字节的形式），这个偏移就要重算。**
12. **错**：写显存时忘记字符占 2 字节。**对**：**每个显示位置占 2 字节（ASCII 码 + 属性），所以一行 80 列 = 160 字节**；偏移公式为 `(行 × 80 + 列) × 2`，写成 `行 × 160 + 列 × 2` 也一样。
13. **错**：写属性字节时忘了 `byte ptr`。**对**：`mov byte ptr es:[di], 2` ——**这里传的是 1 字节的属性，必须声明 `byte ptr`**，否则会按字写入，把下一个字符也覆盖掉。
14. **错**：以为 `mov ss, ax` 之后中断会立刻响应。**对**：**CPU 在执行完「向 `SS` 传送数据」的指令后不响应中断，直到下一条指令也执行完。** 这是为了保证 `SS:SP` 成对更新，不会出现「新 SS + 旧 SP」的危险状态。
15. **错**：以为安装到 `0:200` 的处理程序会永久有效。**对**：**它只在当前程序运行期间有效。** 程序退出后这块内存随时可能被覆盖，而中断向量仍指向那里——**要让它长期有效必须写成常驻内存程序（TSR，见第 13 章）。**

## 本章小结

- **中断信息就是一个 8 位的「中断类型码」**（0~255）；内中断来自 CPU 内部，外中断来自 CPU 外部。
- **8086 的内部中断源**：除法错误（**0**）、单步执行（**1**）、断点 `int 3`（**3**）、溢出 `into`（**4**）、`int n`（**n**）。
- **中断向量表固定在 `0000:0000`，共 1024 字节 = 256 项 × 4 字节**；每项 = 偏移（2 字节）+ 段地址（2 字节）。
- **`n` 号表项：`IP` 在 `n × 4`，`CS` 在 `n × 4 + 2`。**
- **★★★ 中断过程 6 步：取类型码 → `pushf` → `TF=0, IF=0` → `push CS` → `push IP` → 从向量表取入口跳转。压栈 6 字节，必须用 `iret` 返回。★★★**
- **`iret` ≡ `pop IP` + `pop CS` + `popf`**；对比：`call`→`ret`（2 字节），`call far`→`retf`（4 字节），**中断→`iret`（6 字节）**。
- **中断处理程序三要素**：保护现场（`push` 用到的所有寄存器）、处理逻辑、逆序恢复现场 + `iret`。
- **除法错误两种情形**：除数为 0、商超出目的寄存器范围；DOS 默认显示 `Divide overflow` 并返回。
- **安装中断处理程序三步**：① 写处理程序；② 用 `rep movsb` 把它搬到 `0000:0200`（长度 = `offset 末 − offset 首`）；③ 改中断向量（`mov word ptr es:[n*4], 偏移` / `mov word ptr es:[n*4+2], 段`）。
- **显存 `B800H`，每字符 2 字节，一行 160 字节**，偏移 = `(行 × 80 + 列) × 2`；属性字节 `02H` = 黑底绿字。
- **`TF`（bit8）= 1 时产生单步中断**，Debug 的 `t` 命令就靠它；中断过程清 `TF` 是为了防止递归。
- **`mov ss, ax` 之后的指令执行完之前，CPU 不响应中断**——保证 `SS:SP` 成对更新。

> **一句话记住本章**：**「类型码 → 向量表（`0000:0000` 起，每项 4 字节，`n×4` 存 IP、`n×4+2` 存 CS）→ 中断过程压 6 字节（FLAGS、CS、IP）并清 TF/IF → `iret` 弹 6 字节返回」；自己装中断就是「搬到 `0:200` + 改向量」。**

## 自测题

**1.** 什么是中断？内中断和外中断的区别是什么？
**答**：中断是 CPU 不再接着向下执行，而是转去处理中断信息。**内中断**由 CPU 内部产生（除法错误、单步、`into`、`int n`）；**外中断**由 CPU 外部产生（键盘、时钟等外设）。

**2.** 8086 内部能产生哪几种中断？类型码分别是什么？
**答**：除法错误（**0**）、单步执行（**1**）、断点 `int 3`（**3**）、溢出 `into`（**4**）、`int n`（**n**）。

**3.** 中断向量表在哪里？多大？每个表项多少字节？各部分含义是什么？
**答**：在 **`0000:0000` 开始**处，共 **1024 字节（1KB）**；共 **256 个表项，每项 4 字节**。**低 2 字节是该中断处理程序的偏移地址 `IP`，高 2 字节是段地址 `CS`。**

**4.** 写出 `n` 号中断表项中 IP 和 CS 的存放地址。
**答**：`IP` 在 **`0000:(n × 4)`**，`CS` 在 **`0000:(n × 4 + 2)`**。

**5.** `int 16h` 的中断向量在哪个地址？请算出具体数值。
**解**：`n = 16H = 22`，`IP` 在 `22 × 4 = 88 = 0058H`，`CS` 在 `22 × 4 + 2 = 90 = 005AH`。
**答**：`IP` 在 `0000:0058`，`CS` 在 `0000:005A`。

**6.** 默写中断过程的 6 个步骤。
**答**：**① 取得中断类型码 N；② `pushf`（标志寄存器入栈）；③ `TF = 0`、`IF = 0`；④ `push CS`；⑤ `push IP`；⑥ `(IP) = (N×4)`、`(CS) = (N×4+2)`。**

**7.** 中断过程压入栈的有哪些内容？共几个字节？返回时用什么指令？
**答**：压入 **`FLAGS`、`CS`、`IP`** 共 3 个字 = **6 字节**（顺序是先 FLAGS、再 CS、最后 IP）；返回用 **`iret`**。

**8.** `iret` 等价于哪三条指令？如果在中断处理程序末尾用 `ret` 会怎样？
**答**：`iret` 等价于 **`pop IP` + `pop CS` + `popf`**。用 `ret` 只弹 2 字节，栈上残留 `CS` 和 `FLAGS` 共 4 字节，**导致栈失衡、标志寄存器未恢复，程序会崩溃**。

**9.** 中断过程为什么要清 `TF`？
**答**：防止中断处理程序本身被单步中断打断——**若 `TF` 仍为 1，处理程序里每执行一条指令都会再产生一次单步中断，造成无限递归。**

**10.** 除法错误中断在什么情况下产生？类型码是多少？DOS 默认如何处理？
**答**：在**除数为 0**或**商超出目的寄存器能表示的范围**时产生，类型码为 **0**。DOS 默认**显示字符串 `Divide overflow` 并返回 DOS**。

**11.** 要把一段中断处理程序安装到 `0000:0200`，需要哪几步？写出关键指令。
**答**：三步：① 写好处理程序；② 搬运代码——`mov ax,cs` / `mov ds,ax` / `mov si,offset do0` / `mov ax,0` / `mov es,ax` / `mov di,200h` / `mov cx,offset do0end-offset do0` / `cld` / `rep movsb`；③ 改中断向量——`mov word ptr es:[n*4], 200h` / `mov word ptr es:[n*4+2], 0`。

**12.** 安装中断处理程序时，`mov cx, offset do0end - offset do0` 的作用是什么？为什么不直接写数字？
**答**：它的作用是**计算 `do0` 这段代码的字节数**，作为 `rep movsb` 的重复次数。**因为 `offset 标号` 是汇编期的常量，两数相减得到的长度会随代码修改自动更新，不需要人工维护，避免了「改了代码忘了改长度」的错误。**

**13.** 显存段地址是多少？屏幕第 12 行第 36 列的显存偏移怎么算？
**答**：显存段地址是 **`B800H`**。偏移 = `(12 × 80 + 36) × 2 = 996 × 2 = 1992 = 7C8H`（也可写成 `160 × 12 + 36 × 2`）。

**14.** 显示字符时为什么要写两个字节？属性字节 `02H` 是什么效果？
**答**：因为**每个显示位置占 2 个字节——第一个是字符的 ASCII 码，第二个是属性（颜色）**。`02H = 0000 0010B`，即**闪烁关闭、背景黑色（000）、不高亮、前景绿色（010）→ 黑底绿字**。

**15.** 为什么 CPU 在执行完 `mov ss, ax` 之后不立刻响应中断？
**答**：因为 `SS` 和 `SP` 必须成对设置。**若在 `mov ss,ax` 与 `mov sp,立即数` 之间响应中断，中断过程会把 6 字节压到「新 `SS` + 旧 `SP`」组成的地址上，导致栈错乱。** CPU 因此推迟响应中断直到下一条指令执行完，保证 `SS:SP` 要么都是旧值、要么都是新值。

**16.** Debug 的 `t` 命令为什么能实现单步跟踪？
**答**：因为 `t` 命令**把标志寄存器的 `TF` 位置 1**，CPU 每执行完一条指令就产生 1 号（单步）中断，**1 号中断处理程序把当前寄存器状态显示出来**，然后 `iret` 返回，程序停在「下一条指令」处等待下一个命令。
