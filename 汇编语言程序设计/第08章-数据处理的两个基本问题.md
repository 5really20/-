## 8.1 ★ bx、si、di和bp ★

**8086 的 `[...]` 里能放哪些寄存器？这是有严格限制的。**

**规则一：只有 `bx`、`bp`、`si`、`di` 这 4 个寄存器可以出现在 `[...]` 中。**

```asm
mov ax, [bx]        ; ✓
mov ax, [bp]        ; ✓
mov ax, [si]        ; ✓
mov ax, [di]        ; ✓

mov ax, [ax]        ; ✗ 错误！ax 不能放进 [ ]
mov ax, [cx]        ; ✗ 错误！cx 不能放进 [ ]
mov ax, [dx]        ; ✗ 错误！dx 不能放进 [ ]
mov ax, [sp]        ; ✗ 错误！sp 不能放进 [ ]
```

**规则二：`[...]` 中这 4 个寄存器可以单个出现，也可以按 4 种组合出现。**

**4 种合法组合：**

| 组合 | 名称 | 例 |
|---|---|---|
| `bx + si` | 基址 + 变址 | `mov ax, [bx+si]` |
| `bx + di` | 基址 + 变址 | `mov ax, [bx+di]` |
| `bp + si` | 基址 + 变址 | `mov ax, [bp+si]` |
| `bp + di` | 基址 + 变址 | `mov ax, [bp+di]` |

**非法的组合（最容易被忽略）：**

```asm
mov ax, [bx+bp]     ; ✗ 两个基址寄存器不能相加
mov ax, [si+di]     ; ✗ 两个变址寄存器不能相加
mov ax, [bx+si+di]  ; ✗ 不能有三个寄存器
```

**命名规律：**

| 寄存器 | 角色 | 能不能单独进 `[ ]` |
|---|---|---|
| `bx` | **基址**寄存器 | ✓ |
| `bp` | **基址**寄存器 | ✓ |
| `si` | **变址**寄存器 | ✓ |
| `di` | **变址**寄存器 | ✓ |

> **重点**：**「基址 + 变址」只能各出一个——一个来自 `{bx, bp}`，一个来自 `{si, di}`。** 这就是那句口诀：**「基址变址各取一，bx 配 si 或 di，bp 也是好兄弟，bx+bp 不行、si+di 也不行。」**

**规则三（最容易错的一条）：`[ ]` 中用了 `bp` 且指令里没有显式给出段前缀时，段地址默认在 `SS` 中。**

**默认段寄存器对照表：**

| `[ ]` 中的寄存器 | 默认段寄存器 |
|---|---|
| `[bx]`、`[si]`、`[di]`、`[bx+si]`、`[bx+di]` | **DS** |
| **`[bp]`、`[bp+si]`、`[bp+di]`** | **SS** |
| 只要写明了段前缀（`ds:` 等） | **以写明的为准** |

**举例说明区别：**

```asm
mov ax, [bp]            ; 段地址在 SS 中 → 物理地址 = (SS)×16 + (BP)
mov ax, ds:[bp]         ; ★ 段地址被强制指定为 DS
mov ax, [bx]            ; 段地址在 DS 中 → 物理地址 = (DS)×16 + (BX)
```

**为什么 `bp` 的默认段是 SS？**

因为 `bp` 的设计用途就是**访问栈内的数据**（`bp` 是 Base Pointer，基址指针）。子程序用栈传递参数时，参数就在栈里，用 `[bp+偏移]` 访问最自然。**这是「设计意图决定默认行为」的典型例子。**

> **重点**：**`[bp]` 默认段是 SS 是考试高频陷阱。** 题目常给出 `SS = 2000H`、`DS = 1000H`、`BP = 100H`，问 `mov ax, [bp]` 访问的物理地址是多少——答案是 `2000H×16 + 100H = 20100H`，**不是** `10100H`。

## 8.2 机器指令处理的数据在什么地方

**在机器指令这一层，CPU 能处理的数据只可能在三个地方：**

| 位置 | 说明 | 汇编语言中的表达 |
|---|---|---|
| **CPU 内部** | 寄存器 | `reg`（`ax`、`bx`、`al`…）、`sreg`（`ds`、`cs`…） |
| **内存** | 内存单元 | `mem`（`[bx]`、`[bx+si+8]`…） |
| **端口** | I/O 端口（第 14 章讲） | `in` / `out` 指令的操作数 |

**注意：机器指令本身也带着数据——立即数。** 所以从汇编语言的视角看，数据来源实际上是四类：`reg`（含 `sreg`）、`mem`、`idata`、以及端口。

**举个对比：**

```asm
mov ax, 1           ; 数据是立即数 idata = 1（就在机器码里）
mov ax, bx          ; 数据在寄存器 reg = bx
mov ax, [bx]        ; 数据在内存 mem，偏移在 bx
mov ax, ds:[0]      ; 数据在内存 mem，偏移是常量 0
```

## 8.3 汇编语言中数据位置的表达

**汇编语言用三种方式表达数据的位置：**

### 方式一：立即数（idata）

**直接写在汇编指令里的常量，汇编后成为机器码的一部分。**

```asm
mov ax, 1           ; 数据 1 就在机器码里（B8 01 00）
mov ax, 2000h
add bx, 0ffffh
```

**注意：汇编源程序中「立即数」的书写规则：**

| 写法 | 说明 |
|---|---|
| `2000h` / `2000H` | 十六进制以字母开头时必须补前导 0：`0ffffh`（不能写 `ffffh`） |
| `1000` | 十进制 |
| `1000d` | 十进制（显式） |
| `10000000b` | 二进制 |
| `'a'` / `'abc'` | 字符/字符串，汇编成对应的 ASCII 码 |

### 方式二：寄存器（reg / sreg）

**数据在寄存器里，直接写寄存器名。**

```asm
mov ax, bx          ; 从 bx 取数据送到 ax
mov ds, ax          ; 段寄存器也能作操作数（有限制）
```

### 方式三：内存（mem）

**内存单元的表达需要两样东西：段地址 + 偏移地址。**

```
   物理地址 = 段地址 × 16 + 偏移地址
                ↑              ↑
          放在某个段寄存器中    写在 [ ] 中
```

**段地址的表达方式：**

| 表达方式 | 段地址在哪个寄存器 | 例 |
|---|---|---|
| **默认** | 由 `[ ]` 中的寄存器决定（见 8.1 的表） | `mov ax, [bx]` → DS |
| **段前缀** | 显式指定 | `mov ax, es:[bx]` |

**偏移地址的表达方式：**

| 表达方式 | 例 |
|---|---|
| 直接给出常量 | `mov ax, ds:[200]` |
| 寄存器间接 | `mov ax, [bx]` |
| 寄存器相对 | `mov ax, [bx+8]` |
| 基址变址 | `mov ax, [bx+si]` |
| 相对基址变址 | `mov ax, [bx+si+8]` |

**四种段前缀：**

| 前缀 | 段寄存器 | 例 |
|---|---|---|
| `ds:` | DS | `mov ax, ds:[0]` |
| `ss:` | SS | `mov ax, ss:[0]` |
| `cs:` | CS | `mov ax, cs:[0]` |
| `es:` | ES | `mov ax, es:[0]` |

## 8.4 ★ 寻址方式与合法组合表 ★

### 五种寻址方式速查

| 格式 | 名称 | 例 |
|---|---|---|
| `[idata]` | 直接寻址 | `mov ax, ds:[200]` |
| `[bx]` | 寄存器间接寻址 | `mov ax, [bx]` |
| `[bx+idata]` | 寄存器相对寻址 | `mov ax, [bx+6]` |
| `[bx+si]` | 基址变址寻址 | `mov ax, [bx+si]` |
| `[bx+si+idata]` | 相对基址变址寻址 | `mov ax, [bx+si+8]` |

（详见第 7 章 7.10 的「寻址方式总表」。）

### ★★★ reg、sreg、mem、idata 的合法组合表（必考）★★★

**以 `mov` 为例（`add`、`sub`、`cmp` 规则相同，只是目的操作数不能是 `sreg` 和 `idata`）：**

| 目的 \ 源 | `reg` | `sreg` | `mem` | `idata` |
|---|---|---|---|---|
| **`reg`** | ✓ | ✓ | ✓ | ✓ |
| **`sreg`** | ✓ | ✗ | ✓ | **✗** |
| **`mem`** | ✓ | ✓ | **✗** | ✓ |
| **`idata`** | ✗ | ✗ | ✗ | ✗ |

**逐格说明（为什么）：**

| 组合 | 合法性 | 原因 |
|---|---|---|
| `reg ← reg` | ✓ | `mov ax, bx`，最基本形式 |
| `reg ← sreg` | ✓ | `mov ax, ds`（读段寄存器） |
| `reg ← mem` | ✓ | `mov ax, [bx]` |
| `reg ← idata` | ✓ | `mov ax, 1` |
| `sreg ← reg` | ✓ | `mov ds, ax` |
| `sreg ← sreg` | **✗** | `mov ds, es` 非法——8086 没有段寄存器到段寄存器的传送指令 |
| `sreg ← mem` | ✓ | `mov ds, [bx]`（合法，但考试少见） |
| `sreg ← idata` | **✗** | `mov ds, 1000h` 非法——**8086 无「立即数→段寄存器」编码**，必须经通用寄存器中转 |
| `mem ← reg` | ✓ | `mov [bx], ax` |
| `mem ← sreg` | ✓ | `mov [bx], ds` |
| `mem ← mem` | **✗** | `mov [bx], [si]` 非法——**两个内存单元不能直接传送**，必须经寄存器中转 |
| `mem ← idata` | ✓ | `mov byte ptr [bx], 1`（**必须加 `ptr`**） |
| `idata ← 任意` | **✗** | 立即数不能作目的操作数（它不是「存储位置」） |

**记忆口诀（四条非法规则）：**

> **① 两个内存不能直接传（mem → mem ✗）**
> **② 两个段寄存器不能直接传（sreg → sreg ✗）**
> **③ 立即数不能直接进段寄存器（idata → sreg ✗）**
> **④ 立即数不能当目的（→ idata ✗）**

**再补充几条容易忽略的：**

| 写法 | 合法性 | 说明 |
|---|---|---|
| `mov cs, ax` | **✗** | **CS 不能作 `mov` 的目的**（改 CS 只能用转移指令） |
| `mov ax, cs` | ✓ | 读 CS 是允许的 |
| `pop cs` | **✗** | `pop` 不能操作 CS；但 `push cs` 合法 |
| `mov ss, ax` | ✓ | 改 SS 合法（但后面必须紧跟 `mov sp, ...`，见第 6 章） |

> **重点**：**这张表在考试里通常有两种考法**：① 给出几条指令判断合法性；② 给一个功能要求，让你选正确指令。**记住「四条非法规则 + CS 不能作目的」就能覆盖 95% 的考题。**

## 8.5 ★ 指令要处理的数据有多长 ★

**8086 是 16 位 CPU，指令既可以处理 8 位数据，也可以处理 16 位数据。CPU 怎么知道这条指令处理几位？**

### 方式一：通过寄存器名指明（最常用）

```asm
mov ax, [bx]        ; ax 是 16 位 → 处理一个字（2 字节）
mov al, [bx]        ; al 是 8 位  → 处理一个字节（1 字节）
mov ah, [bx]        ; ah 是 8 位  → 处理一个字节
```

### 方式二：用操作符 `X ptr` 指明

| 操作符 | 含义 | 处理的位数 |
|---|---|---|
| `byte ptr` | 字节指针 | **8 位**（1 字节） |
| `word ptr` | 字指针 | **16 位**（2 字节） |

**什么时候必须用 `ptr`？——当指令里没有寄存器能提供长度信息时。**

| 情形 | 例子 | 为什么必须加 |
|---|---|---|
| **立即数 → 内存** | `mov byte ptr [bx], 1` | 源是立即数（无长度），目的 `[bx]` 也无长度 |
| **只有一个内存操作数的运算** | `inc word ptr [bx]` | 没有寄存器 |
| **立即数与内存运算** | `add word ptr [bx], 2` | 同上 |
| **`div`/`mul` 的内存操作数** | `div word ptr [bx]` | 要区分 8 位除还是 16 位除 |

```asm
mov byte ptr [bx], 1        ; ✓ 明确写 1 个字节
mov word ptr [bx], 1        ; ✓ 明确写 1 个字
mov [bx], 1                 ; ✗ 危险！见下面的实测说明
```

> **★ `mov [bx], 1` 到底会怎样？本机 MASM 6.11 实测（两种模式结果不同，都必须知道）：**
>
> | 模式 | 汇编结果 | 机器码 |
> |---|---|---|
> | **默认模式** | **报错** `error A2070: invalid instruction operands` | 不生成代码 |
> | **`/Zm`（MASM 5.1 兼容模式）** | **不报错！静默按「字」处理，写坏 2 个字节** | `C7 07 0001` |
>
> **结论：不写 `ptr` 最危险的情况是「不报错但写错长度」**——在 `/Zm` 模式下 MASM 默认按**字**处理，你只想写 1 字节，它却写进去 2 字节，**悄悄覆盖掉后面那个字节**。这比直接报错难查得多。**所以立即数写内存时 `byte ptr` / `word ptr` 一个都不能省。**（王爽教材用的是 MASM 5.0，行为与 `/Zm` 一致；本机 MASM 6.11 默认模式则会报 `A2070`。两种说法都对，取决于模式。）

```asm
inc byte ptr [bx]           ; ✓ 把 [bx] 处的字节加 1
inc word ptr [bx]           ; ✓ 把 [bx] 处的字加 1
inc [bx]                    ; ✗ 错误！不知道是字节还是字
```

**注意：`mov al, byte ptr [bx]` 里的 `byte ptr` 是多余的**（`al` 已经指明 8 位），但写了不算错。

### 方式三：其他默认规则

| 情形 | 默认长度 | 例子 |
|---|---|---|
| `push` / `pop` | **16 位**（8086 不支持压 8 位） | `push ax`、`pop [bx]` |
| 段寄存器参与 | **16 位** | `mov ds, ax` |
| 使用 `db`/`dw`/`dd` 定义的**数据标号** | 由定义类型决定 | `dw` 标号 → 字 |

**数据长度判断练习表：**

| 指令 | 处理长度 | 依据 |
|---|---|---|
| `mov ax, 1` | 16 位 | `ax` |
| `mov al, 1` | 8 位 | `al` |
| `mov byte ptr [bx], 1` | 8 位 | `byte ptr` |
| `mov word ptr [bx], 1` | 16 位 | `word ptr` |
| `push ax` | 16 位 | `push` 默认 16 位 |
| `pop [bx]` | 16 位 | `pop` 默认 16 位 |
| `inc word ptr [bx]` | 16 位 | `word ptr` |
| `div byte ptr [bx]` | 8 位除 | `byte ptr` |
| `mul word ptr [bx]` | 16 位乘 | `word ptr` |

> **重点**：**判断口诀：「指令里只要有立即数参与、又不涉及寄存器长度，就必须加 `ptr`」。** 反过来，只要有一个通用寄存器操作数，长度就自动确定了，`ptr` 可省。

## 8.6 ★★★ 寻址方式的综合应用 ★★★

**下面这段数据是教材里最经典的结构化数据例子——它是「实验七」的数据源，也是「用汇编视角理解结构体」的最佳样本。**

```asm
assume cs:code, ds:data, es:table
data segment
    ; ① 21 个年份字符串，每个 4 字节，共 84 字节，起始偏移 0
    db '1975','1976','1977','1978','1979','1980','1981','1982','1983'
    db '1984','1985','1986','1987','1988','1989','1990','1991','1992'
    db '1993','1994','1995'

    ; ② 21 年公司总收入，每个 4 字节（双字），共 84 字节，起始偏移 84
    dd 16,22,382,1356,2390,8000,16000,24486,50065,97479,140417,197514
    dd 345980,590827,803530,1183000,1843000,2759000,3753000,4649000,5937000

    ; ③ 21 年公司雇员人数，每个 2 字节（字），共 42 字节，起始偏移 168
    dw 3,7,9,13,28,38,130,220,476,778,1001,1442,2258,2793,4037,5635,8226
    dw 11542,14430,15257,17800
data ends
```

**这段数据有三个关键特征：**

| 特征 | 说明 |
|---|---|
| **三张表，元素长度不同** | 年份 4 字节、收入 **4 字节（dd）**、人数 **2 字节（dw）** |
| **表内连续、表间相邻** | 年份 偏移 0~83，收入 偏移 84~167，人数 偏移 168~209 |
| **同一下标 i 的三项数据在偏移上不连续** | 第 i 年的年份在 `0 + i×4`，收入在 `84 + i×4`，人数在 `168 + i×2` |

**怎么用寻址方式统一访问这三张表？（这是本章的精髓）**

**核心思路：用 `bx` 作「表基址」，用 `si` 作「变址」，用 `idata` 作「表间偏移」。**

```
   偏移:  0                      84                     168            210
          ┌──────────────────────┬──────────────────────┬──────────────┐
   data:  │  年份表（4×21=84）    │  收入表（4×21=84）    │ 人数表(2×21) │
          └──────────────────────┴──────────────────────┴──────────────┘
             ↑ 表基址 bx = 0        ↑ 表基址 bx = 84       ↑ bx = 168
                    └──── 用 [bx+si] 访问：bx=表基址、si=表内偏移 ────┘
```

**示例程序：把三张表里的第 i 年数据「凑」到一起处理。**

```asm
assume cs:code, ds:data
data segment
    ; 为节省篇幅，这里只用 3 年的数据（结构与上面完全一致）
    db '1975','1976','1977'      ; 年份：偏移 0 ~ 11
    dd 16,22,382                 ; 收入：偏移 12 ~ 23
    dw 3,7,9                     ; 人数：偏移 24 ~ 29
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    ; ===== 访问第 1 年（下标 i=0）的数据 =====
    mov bx, 0                    ; 表基址：年份表在偏移 0
    mov si, 0                    ; 表内偏移：i×4 = 0
    mov ax, [bx+si]              ; 取年份的【前 2 个字节】→ AX = 3931H，即字符 '1''9'
                                 ;    （小端序：偏移 0 存 '1'=31H 作低字节，偏移 1 存 '9'=39H 作高字节）
    mov dx, [bx+si+2]            ; ★ 用 idata 在表内再偏移 2 字节 → DX = 3735H，即字符 '7''5'（演示用）

    ; ===== 访问第 1 年的收入（下标 i=0）=====
    mov bx, 12                   ; 表基址：收入表在偏移 12
    mov ax, [bx+si]              ; 低 16 位
    mov dx, [bx+si+2]            ; 高 16 位 → 现在 DX:AX 是完整的 32 位收入

    ; ===== 访问第 1 年的人数（下标 i=0）=====
    mov bx, 24                   ; 表基址：人数表在偏移 24
    mov si, 0                    ; ★ 人数是 2 字节，偏移要按 ×2 算
    mov cx, [bx+si]              ; CX = 3

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：`AX` 最终为 `4C00H`；在执行到 `int 21h` 前，`DX:AX` 已经取过 `16`（第 1 年的收入），`CX = 3`（第 1 年的人数）。

**「访问第 i 年」的偏移公式（重点记忆）：**

| 数据 | 表基址 | 表内偏移 | 访问表达式 |
|---|---|---|---|
| 年份（4 字节） | `0` | `i × 4` | `[bx+si]`，`bx=0`，`si=i×4` |
| 收入（4 字节 dd） | `84` | `i × 4` | `[bx+si]` 取低字、`[bx+si+2]` 取高字 |
| 人数（2 字节 dw） | `168` | `i × 2` | `[bx+si]`，`bx=168`，`si=i×2` |

**完整写法的经典模板（把第 i 年数据搬到 table 段的第 i 行）：**

```asm
; 目标：table 段每行 12 字节：年份(4) + 收入(4) + 人数(2) + 人均收入(2)
;       行的起始偏移 = i × 12
; 约定：进入本段时 CX = i（第几年，从 0 开始）
        mov ax, cx
        shl ax, 1                     ; AX = i × 2
        shl ax, 1                     ; AX = i × 4
        mov si, ax                    ; ★ si = i × 4（年份表、收入表的步长都是 4）
        mov di, ax
        add di, di                    ; DI = i × 8
        add di, si                    ; ★ di = i × 8 + i × 4 = i × 12（目标行偏移）

        mov bx, 0                     ; 年份表基址 = 0
        mov ax, [bx+si]               ; 年份低字
        mov es:[di], ax               ; 写入目标行
        mov ax, [bx+si+2]             ; 年份高字（★ idata = 字段内偏移）
        mov es:[di+2], ax

        mov bx, 84                    ; 收入表基址 = 84
        mov ax, [bx+si]               ; 收入低字（★ si 不用改：收入表步长也是 4）
        mov es:[di+4], ax
        mov dx, [bx+si+2]             ; 收入高字 → DX:AX 组成完整 32 位收入
        mov es:[di+6], dx

        mov ax, si
        shr ax, 1                     ; ★★ AX = i × 2
        mov si, ax                    ; ★★ 必须重新算 si，不能直接复用 i×4！
                                      ;    因为人数表步长是 2，只有年份表的一半
        mov bx, 168                   ; 人数表基址 = 168
        mov ax, [bx+si]               ; 人数（字）
        mov es:[di+8], ax
```

> **★★ 这个模板里最值得记住的一句：`mov si, ax` 那一行不能省。**
> **三张表的元素长度不一样**（年份 4 字节、收入 4 字节、人数 2 字节），**所以「同一个 `i` 对应的表内偏移也不同」**：年份/收入是 `i × 4`，人数是 `i × 2`。**直接拿 `si = i × 4` 去访问人数表，会读到第 `2i` 个人的数据——错位一倍。**
> **这正是 8086 提供两个变址寄存器 `SI` 和 `DI` 的原因**：本模板里 `si` 管「源表内偏移」、`di` 管「目标行偏移」，两者互不干扰；而当源表步长变化时，就**重新算一次 `si`**。
> **顺带记住一条硬规则**：`[...]` 里能同时出现的寄存器只有四种配对——**`[bx+si]`、`[bx+di]`、`[bp+si]`、`[bp+di]`**。**`[bx+bp]`、`[si+di]`、`[bx+si+di]` 全是非法组合**（第 8 章前面的非法写法表里列过）。所以**不能用 `bp` 来当第二个变址寄存器**。

> **重点**：**「基址寄存器存表基址、变址寄存器存元素下标 × 元素长度、`idata` 存字段内偏移」——这就是汇编语言访问结构化数据的标准三步法。** 高级语言里的 `struct Student a[10]; a[i].score`，编译后生成的正是 `[bx + si + idata]` 形式的指令。**看懂了这一节，你就看懂了「结构体 + 数组」的底层实现。**

**三条实用技巧（务必记住）：**

1. **数据在哪张表，就把该表的起始偏移装进 `bx`。** 表基址永远在 `bx`（或 `bp`）里，不要写死。
2. **是第几个元素，就把它换算成字节偏移装进 `si`（或 `di`）。** 元素长度是 4 就 `i×4`，是 2 就 `i×2`。
3. **访问元素内部第几个字段，用 `idata` 表示。** 如「收入的高 16 位」就是 `+2`，`+2`。
   **公式：`[bx + si + idata]` = 表基址 + 元素偏移 + 字段偏移。**

## 8.7 div指令

**`div` 是除法指令。格式：`div 除数`。**

**关键：`div` 的被除数、商、余数的存放位置是固定的，由除数的位数决定。**

### 情形一：除数是 8 位

```
   被除数：16 位，放在 AX 中
   除数  ：8 位（reg8 或 mem8）
   
   结果：  商   → AL （8 位）
          余数 → AH （8 位）
```

```asm
div bl              ; AX ÷ BL，商在 AL，余数在 AH
div byte ptr [bx]   ; AX ÷ DS:[bx] 处的字节，商在 AL，余数在 AH
```

**⚠ 溢出问题：** 商必须能放进 AL（即商 ≤ 255）。否则触发**除法溢出**（第 12 章会讲 0 号中断）。

### 情形二：除数是 16 位

```
   被除数：32 位，低位在 AX，高位在 DX（即 DX:AX）
   除数  ：16 位（reg16 或 mem16）
   
   结果：  商   → AX （16 位）
          余数 → DX （16 位）
```

```asm
div bx              ; DX:AX ÷ BX，商在 AX，余数在 DX
div word ptr [bx]   ; DX:AX ÷ DS:[bx] 处的字，商在 AX，余数在 DX
```

**注意：做 16 位除法前，必须先把 DX 清 0（如果被除数的高 16 位是 0）。**

```asm
mov dx, 0           ; ★ 必须先清 DX！否则 DX 里是上次运算的残留值
mov ax, 1000h
mov bx, 10h
div bx              ; 商在 AX = 100H，余数在 DX = 0
```

**总结表（必背）：**

| 除数位数 | 被除数位置 | 商存放 | 余数存放 | 溢出条件 |
|---|---|---|---|---|
| 8 位 | **AX**（16 位） | **AL** | **AH** | 商 > 255（> FFH） |
| 16 位 | **DX:AX**（32 位） | **AX** | **DX** | 商 > 65535（> FFFFH） |

> **重点**：**`div` 的三个易错点**：① 忘了清 DX；② 忘了除法溢出；③ 记混「商在 AL/AX、余数在 AH/DX」。**「商在低位寄存器、余数在相邻的高位寄存器」**——记住这个规律就不会错。

**完整例子：求 1000 ÷ 7 的商和余数，存到内存。**

```asm
assume cs:code, ds:data
data segment
    a    dd 1000            ; 双字：被除数（低字在偏移 0，高字在偏移 2）
    b    dw 7               ; 除数（偏移 4）
    quot dw 0               ; 商存放处（偏移 6）
    rem  dw 0               ; 余数存放处（偏移 8）
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    mov ax, word ptr a      ; ★ 被除数的低 16 位 → AX
    mov dx, word ptr a+2    ; ★ 被除数的高 16 位 → DX
    mov bx, b               ; ★ 除数 → BX
    div bx                  ; DX:AX ÷ BX
    mov quot, ax            ; 商存入 quot
    mov rem, dx             ; 余数存入 rem

    mov ax, 4c00h
    int 21h
code ends
end start
```

> **★ 为什么用标号而不是 `mov ax, [0]`？** 因为 **MASM 把 `[数字]` 当成常量**：`mov ax, [0]` 会被汇编成 `mov ax, 0`（静默错误），而 `mov [6], ax` 会直接报 `error A2001: immediate operand not allowed`。**用标号（`a`、`b`、`quot`、`rem`）既正确又可读**，是 MASM 编程的标准做法。若一定要按偏移写，必须加段前缀：`mov ax, ds:[0]`、`mov ds:[6], ax`。

**运行结果**：`1000 ÷ 7 = 142 余 6`，所以偏移 6 处存 `142`（`008EH`），偏移 8 处存 `6`。

## 8.8 伪指令dd

**`dd` 用来定义 32 位（双字，double word）数据。**

**格式：`[名字] dd 数据1, 数据2, ……`**

**`db` / `dw` / `dd` 对照表：**

| 伪指令 | 全称 | 每个数据占 | 能表示的范围 | 例 |
|---|---|---|---|---|
| `db` | define byte | **1 字节** | 0 ~ 255（或 −128 ~ +127） | `db 1, 2, 'a'` |
| `dw` | define word | **2 字节** | 0 ~ 65535 | `dw 1000, 0ffffh` |
| `dd` | define double word | **4 字节** | 0 ~ 4294967295 | `dd 100000, 5937000` |

**`dd` 在内存中的存放顺序（小端序）：**

```asm
data segment
    dd 1000
data ends
```

```
   1000 = 0000 03E8H
   
   偏移:   0      1      2      3
         ┌──────┬──────┬──────┬──────┐
         │  E8  │  03  │  00  │  00  │
         └──────┴──────┴──────┴──────┘
          └─ 低字 03E8H ─┘└─ 高字 0000H ─┘
          ← 低地址存低位（小端序）
```

**用 `dd` 定义的数据怎么读？**

```asm
    mov ax, ds:[0]      ; AX = 03E8H（低 16 位）
    mov dx, ds:[2]      ; DX = 0000H（高 16 位）
    ; 现在 DX:AX 就是完整的 32 位数 1000
```

**`dd` 与「地址」的关系（重要）：**

**一个 `dd` 也可以用来存放一个「段:偏移」形式的远地址或一个 32 位指针。**

```asm
data segment
    fp dd 0         ; 可存放一个 32 位远指针（低字偏移、高字段）
data ends

code segment
assume cs:code, ds:data
start:
    ; 读取一个远指针并跳过去
    jmp dword ptr ds:fp     ; IP ← fp 的低字，CS ← fp 的高字
                            ; ★ 必须带 ds: 前缀（或用 assume ds:data 后再写 jmp fp）
code ends
end start
```

> **★ `jmp dword ptr fp` 少写 `ds:` 会报什么？本机 MASM 6.11 实测**：
> - 只写 `jmp dword ptr fp`（**没有 `assume ds:data`**）→ **`error A2074: cannot access label through segment registers`**（「无法通过段寄存器访问该标号」——因为 MASM 不知道 `fp` 属于哪个段，没法确定用哪个段寄存器去取它）。
> - 加 `assume ds:data` 之后 `jmp dword ptr fp` 能通过；**但最省事的写法是直接写 `jmp dword ptr ds:fp`**，不用依赖 `assume`。本机实测 `jmp dword ptr ds:fp` 与 `jmp fp` **生成的机器码完全相同：`FF 2E 0000 R`**。
>   **怎么读 `FF 2E 0000 R`**：`FF` 是操作码，`/5` 这个扩展号表示「段间间接转移」（把内存里的 4 字节直接装进 `IP` 和 `CS`）；**`2E` 是 ModRM 字节**（拆成 `00 101 110` = mod 00、reg 101 即 `/5`、r/m 110 即「`disp16` 直接寻址」），**它不是一个段超越前缀，别把它当成 `CS:`**；`0000 R` 是 `fp` 的偏移（`R` 表示重定位，链接时才填真实值）。**段寄存器用哪个是「默认规则」决定的（数据标号默认走 `DS`），并不编码在指令里。**
> - 同样地，`jmp dword ptr [0]` 这种裸偏移写法在 MASM 里**根本不能用**：`[0]` 会被当成常量 0，而不是「内存偏移 0 处的双字」。

**注意：`dd` 定义的数据标号，如果用 `mov ax, 标号` 取的是「低 16 位数据」，而不是地址；取地址要用 `offset 标号`。** 这一点在学「数据标号 vs 地址标号」时（第 16 章）会再深入。

> **重点**：**`dd` 常和 `div`/`mul` 配对使用**——因为 16 位除法的被除数是 32 位（正好一个 `dd`），16 位乘法的结果也是 32 位（正好存进一个 `dd`）。**看到 `dd` 就要想到「这里要么是 32 位数值，要么是远指针」。**

## 8.9 dup

**`dup` 是一个操作符，由编译器处理，用来进行数据的重复定义。**

**格式：`db/dw/dd 重复次数 dup (重复的数据)`**

**基本用法：**

```asm
db 3 dup (0)            ; 相当于 db 0, 0, 0                → 3 个字节
db 3 dup (0,1,2)        ; 相当于 db 0,1,2, 0,1,2, 0,1,2     → 9 个字节
db 3 dup ('abc')        ; 相当于 db 'abcabcabc'             → 9 个字节
dw 5 dup (0)            ; 5 个字节？不，是 5 个字 → 10 个字节
dd 2 dup (0)            ; 2 个双字 → 8 个字节
```

**常用场景：**

| 场景 | 写法 | 含义 |
|---|---|---|
| 预留栈空间 | `dw 0,0,0,0,0,0,0,0` 或 `dw 8 dup (0)` | 16 字节的栈空间 |
| 预留缓冲区 | `db 100 dup (0)` | 100 字节的缓冲区 |
| 预留屏幕空间 | `db 16 dup (0)` | 屏幕一行的字符属性 |
| 初始化数组 | `db 5 dup (1)` | 5 个字节，全是 1 |

**`dup` 的嵌套（可以套用）：**

```asm
db 2 dup (1, 2 dup (3, 4))
; 解析：外层重复 2 次，每次的内容是 1, 3,4, 3,4
; 结果：1,3,4,3,4, 1,3,4,3,4   → 10 个字节
```

**完整例子：用 `dup` 预留栈段空间。**

```asm
assume cs:code, ds:data, ss:stack
data segment
    db 8 dup (0)             ; 8 字节数据区
data ends
stack segment
    dw 0,0,0,0,0,0,0,0       ; 等价于 dw 8 dup (0)，16 字节栈空间
stack ends
code segment
start:
    mov ax, stack
    mov ss, ax
    mov sp, 16               ; ★ SP 指向栈空间的「高地址端 + 1」
    mov ax, data
    mov ds, ax

    mov ax, 1234h
    push ax
    pop bx                   ; BX = 1234H

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：`push ax` 后 SP 从 16 变成 14，`1234H` 存到 `SS:000EH`；`pop bx` 后 SP 回到 16，`BX = 1234H`。

> **重点**：**`dup` 的两大用途：① 批量初始化数据（数组）；② 预留空间（缓冲区、栈）。** 它由**编译器**处理，运行时没有 `dup` 这个动作——所以它和 `db`/`dw`/`dd` 一样属于**伪指令**。

## 典型例题

**例 8.1**（题型：`[ ]` 中的寄存器合法性）
判断下列指令是否合法，不合法的说明原因：
```asm
① mov ax, [ax]
② mov ax, [bx+bp]
③ mov ax, [si+di]
④ mov ax, [bx+si+8]
⑤ mov ax, [bp+di]
⑥ mov ax, es:[bx]
```
**解**：
| 序号 | 合法性 | 原因 |
|---|---|---|
| ① | **非法** | `[ ]` 中只能用 `bx`/`bp`/`si`/`di`，`ax` 不能用 |
| ② | **非法** | `bx` 和 `bp` 都是**基址**寄存器，不能相加（只能「基址 + 变址」各一个） |
| ③ | **非法** | `si` 和 `di` 都是**变址**寄存器，不能相加 |
| ④ | **合法** | `bx`（基址）+ `si`（变址）+ 常量偏移，最完整的形式 |
| ⑤ | **合法** | `bp`（基址）+ `di`（变址） |
| ⑥ | **合法** | `es:` 段前缀 + `[bx]` |

**例 8.2**（题型：`bp` 的默认段陷阱）
已知 `(DS) = 1000H`，`(SS) = 2000H`，`(BX) = 0100H`，`(BP) = 0200H`。分别求下面两条指令访问的内存单元物理地址：
```asm
① mov ax, [bx]
② mov ax, [bp]
```
**解**：
- ① `[bx]` 没有 `bp`，默认段是 **DS**：
  `物理地址 = (DS)×16 + (BX) = 1000H×16 + 0100H = 10000H + 0100H = 10100H`
- ② `[bp]` **含 `bp` 且未写段前缀**，默认段是 **SS**：
  `物理地址 = (SS)×16 + (BP) = 2000H×16 + 0200H = 20000H + 0200H = 20200H`
**答案**：① `10100H`；② `20200H`。
**易错**：② 很容易误答成 `10200H`（用 DS 算）。

**例 8.3**（题型：指令合法性判断——合法组合表）
判断下列指令是否合法，不合法的说明原因：
```asm
① mov ds, es
② mov ds, 1000h
③ mov [bx], [si]
④ mov byte ptr [bx], 1
⑤ mov word ptr [bx], ax
⑥ inc [bx]
⑦ mov cs, ax
```
**解**：
| 序号 | 合法性 | 原因 |
|---|---|---|
| ① | **非法** | 两个段寄存器之间不能直接传送 |
| ② | **非法** | 立即数不能直接送段寄存器，必须经通用寄存器中转 |
| ③ | **非法** | 两个内存单元不能直接传送，必须经寄存器中转 |
| ④ | **合法** | 立即数→内存，用 `byte ptr` 指明了长度 |
| ⑤ | **合法**（`word ptr` 冗余） | `ax` 已经指明 16 位 |
| ⑥ | **非法** | 没有长度信息，必须写 `inc byte ptr [bx]` 或 `inc word ptr [bx]` |
| ⑦ | **非法** | **CS 不能作 `mov` 的目的**，改 CS 只能用转移指令 |

**例 8.4**（题型：数据长度判断）
指出下列指令处理的数据长度：
```asm
① mov ax, [bx]
② mov al, [bx]
③ mov byte ptr [bx], 1
④ push bx
⑤ div word ptr [bx]
⑥ pop [bx]
```
**解**：
| 指令 | 长度 | 依据 |
|---|---|---|
| ① | 16 位 | `ax` |
| ② | 8 位 | `al` |
| ③ | 8 位 | `byte ptr` |
| ④ | 16 位 | `push` 默认 16 位 |
| ⑤ | 16 位（16 位除法） | `word ptr`；被除数 DX:AX |
| ⑥ | 16 位 | `pop` 默认 16 位 |

**例 8.5**（题型：div 计算）
执行下面程序后，AL、AH 各是多少？
```asm
mov ax, 0057h
mov bl, 10h
div bl
```
**解**：
- 被除数 `AX = 0057H = 87`；除数 `BL = 10H = 16`。
- 8 位除法：`AX ÷ BL`，商 → AL，余数 → AH。
- `87 ÷ 16 = 5 余 7`。
**答案**：`AL = 05H`，`AH = 07H`。

**例 8.6**（题型：16 位除法与清 DX 的错误分析）
下面程序有什么错误？为什么？
```asm
mov ax, 1000h
mov bx, 10h
div bx
```
**解**：
- `div bx` 是 16 位除法，被除数是 **DX:AX** 组成的 32 位数。
- 程序只设了 `AX`，**没有清 `DX`**。`DX` 里可能是程序启动时的残留值。
- 假设 `DX = 0001H`，则被除数 = `0001:1000H = 11000H = 69632`，商 = `69632 ÷ 16 = 4352 = 1100H`。
- 而程序员期望的是 `1000H ÷ 10H = 100H`。**结果完全错了。**
- 正确写法：
```asm
mov dx, 0           ; ★ 先清高 16 位
mov ax, 1000h
mov bx, 10h
div bx              ; 商 AX = 100H，余数 DX = 0
```
**答案**：缺少 `mov dx, 0`；16 位除法前必须清 DX。

**例 8.7**（题型：结构化数据访问——三张表）
data 段定义如下（只取 3 年数据）。编写程序取出**第 2 年（下标 i=1）** 的年份（前 2 个字符）、收入（完整的 32 位）、人数，分别放到 `AX`、`DX:AX`、`CX` 中。
```asm
data segment
    db '1975','1976','1977'      ; 年份表：偏移 0 ~ 11，每项 4 字节
    dd 16,22,382                 ; 收入表：偏移 12 ~ 23，每项 4 字节
    dw 3,7,9                     ; 人数表：偏移 24 ~ 29，每项 2 字节
data ends
```
**解**：
```asm
assume cs:code, ds:data
data segment
    db '1975','1976','1977'
    dd 16,22,382
    dw 3,7,9
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    ; ① 年份表：表基址 0，第 i 项偏移 = i×4 = 1×4 = 4
    mov bx, 0                   ; 表基址
    mov si, 4                   ; ★ i=1，元素长 4 → 偏移 4
    mov ax, [bx+si]             ; 取 '1976' 的前 2 字节 → AX = '19'

    ; ② 收入表：表基址 12，第 i 项偏移 = i×4 = 4
    mov bx, 12                  ; 表基址
    mov si, 4                   ; ★ 同样是 i×4 = 4
    mov ax, [bx+si]             ; 低 16 位 = 22
    mov dx, [bx+si+2]           ; ★ 用 idata=2 取高 16 位 = 0
    ; 此时 DX:AX = 0000:0016H = 22，即第 2 年的收入

    ; ③ 人数表：表基址 24，第 i 项偏移 = i×2 = 2
    mov bx, 24                  ; 表基址
    mov si, 2                   ; ★ 元素长 2，所以 i×2 = 2（不是 4！）
    mov cx, [bx+si]             ; CX = 7

    mov ax, 4c00h
    int 21h
code ends
end start
```
**答案**：`AX = 16H`（收入低 16 位，即 22）、`DX = 0`（收入高 16 位）、`CX = 0007H`（第 2 年人数）。
**关键**：**三张表的「表基址」不同（`0` / `12` / `24`），「元素长度」也不同（4 / 4 / 2）——所以 `si` 的换算系数必须跟着变（`i×4` / `i×4` / `i×2`）。这是本题唯一的坑。**

## 易错点提醒

1. **错**：`mov ax, [ax]`、`mov ax, [cx]`。**对**：`[ ]` 中**只能用 `bx`、`bp`、`si`、`di`** 这 4 个寄存器，其余（含 `ax`/`cx`/`dx`/`sp`）都不行。
2. **错**：`mov ax, [bx+bp]`、`mov ax, [si+di]`。**对**：**「基址 + 变址」只能各出一个**——`bx`/`bp` 里选一个，`si`/`di` 里选一个。4 种合法组合：`bx+si`、`bx+di`、`bp+si`、`bp+di`。
3. **错**：以为 `[bp]` 的默认段也是 DS。**对**：**`[ ]` 中只要出现 `bp` 且没写段前缀，默认段就是 SS**。这是高频陷阱。
4. **错**：`mov ds, es`。**对**：**两个段寄存器不能直接传送**，必须经通用寄存器中转（`mov ax, es` + `mov ds, ax`）。
5. **错**：`mov ds, 1000h`。**对**：立即数不能直接进段寄存器，必须 `mov ax,1000h` + `mov ds,ax`。
6. **错**：`mov [bx], [si]`。**对**：**两个内存单元不能直接传送**，必须 `mov ax,[si]` + `mov [bx],ax`。
7. **错**：`mov cs, ax`。**对**：**CS 不能作 `mov` 的目的**，也不能 `pop cs`；改 CS 只能用转移指令。`push cs` 和 `mov ax, cs` 是合法的。
8. **错**：`mov [bx], 1` 不写 `ptr`。**对**：立即数→内存时**必须写 `byte ptr` 或 `word ptr`**；只有一个内存操作数的运算（`inc`、`add`、`div`、`mul`）也必须加 `ptr`。**★ 本机 MASM 6.11 实测：默认模式报 `error A2070: invalid instruction operands`；用 `/Zm`（MASM 5.1 兼容模式，王爽教材就是 5.0）则【不报错】，MASM 按「字」处理生成 `C7 07 0001`，静默写坏 2 个字节。** 后一种情况更危险——不报错但结果错。
9. **错**：16 位除法忘了 `mov dx, 0`。**对**：`div r/m16` 的被除数是 **DX:AX**，不清 DX 就会把残留值当高位，结果全错。
10. **错**：记混 `div` 的商和余数位置。**对**：**8 位除：商→AL、余→AH；16 位除：商→AX、余→DX**。规律是「商在低位、余数在相邻高位」。
11. **错**：`div` 时忽略除法溢出。**对**：8 位除要求商 ≤ `FFH`，16 位除要求商 ≤ `FFFFH`；否则触发 0 号中断（第 12 章）。
12. **错**：把 `dd` 定义的数据当成「地址」。**对**：**`dd` 定义的是 32 位数据（或远指针的内容）**；取地址要用 `offset`。读一个 `dd` 要用两个 `mov`（低字 + 高字）。
13. **错**：以为 `dup` 是运行时执行的。**对**：`dup` 是**伪指令/操作符**，由编译器处理，运行时不存在。
14. **错**：多张表用同一个 `si` 换算系数。**对**：`si` 的偏移系数等于**该表的元素长度**——4 字节的表用 `i×4`，2 字节的表用 `i×2`。**换表就要换系数。**

## 本章小结

- **能用进 `[...]` 的只有 `bx`、`bp`、`si`、`di` 四个寄存器**；「基址 + 变址」只能各取一个，合法组合只有 `bx+si`、`bx+di`、`bp+si`、`bp+di`。
- **`[ ]` 中出现 `bp` 且无段前缀时，默认段是 SS**；其余默认 DS。
- **数据处理的两个基本问题**：数据在哪里（`reg`/`sreg`/`mem`/`idata`）、数据有多长（8 位 / 16 位）。
- **数据位置的三种表达**：立即数（`idata`）、寄存器（`reg`/`sreg`）、内存（段地址 + 偏移地址，段地址由默认规则或段前缀决定）。
- **合法组合表的四条非法规则**：**mem→mem ✗、sreg→sreg ✗、idata→sreg ✗、→idata ✗**；另加 **CS 不能作 `mov` 的目的**。
- **指明数据长度的方式**：① 用寄存器名（`ax` 16 位 / `al` 8 位）；② 用 **`byte ptr`** 或 **`word ptr`**；③ `push`/`pop` 默认 16 位。**立即数参与且无寄存器提供长度时，必须加 `ptr`。**
- **★★★ 结构化数据访问三步法：表基址放 `bx`、元素偏移放 `si`（= 下标 × 元素长度）、字段偏移用 `idata`。** 公式 `[bx+si+idata]` = 表基址 + 元素偏移 + 字段偏移。
- **`div`**：8 位除 → `AX ÷ r/m8`，商在 **AL**、余数在 **AH**；16 位除 → `DX:AX ÷ r/m16`，商在 **AX**、余数在 **DX**。**16 位除前必须清 DX，且要防除法溢出。**
- **`dd`** 定义 32 位数据（4 字节，小端序：低字在低地址）；**`dup`** 批量重复定义数据（也是伪指令）。
- **`db` / `dw` / `dd` 分别是 1 / 2 / 4 字节**；`dup` 的格式是 `重复次数 dup (重复内容)`。

> **一句话记住本章**：**「`[ ]` 里只有 bx/bp/si/di，基址变址各取一，见 bp 就用 SS」；「在哪」看寻址方式、「多长」看寄存器或 `ptr`；四条非法组合（mem→mem、sreg→sreg、idata→sreg、→idata）加上 CS 不能作目的；结构化数据访问就是「表基址 bx + 元素偏移 si + 字段偏移 idata」。**

## 自测题

**1.** 哪 4 个寄存器可以出现在 `[...]` 中？写出它们的 4 种合法组合。
**答**：`bx`、`bp`、`si`、`di`。合法组合：`[bx+si]`、`[bx+di]`、`[bp+si]`、`[bp+di]`。

**2.** 判断合法性并说明原因：`mov ax, [ax]` / `mov ax, [bx+bp]` / `mov ax, [bp+di]` / `mov ax, [si+di]`
**答**：① 非法，`ax` 不能放进 `[ ]`；② 非法，两个基址寄存器不能相加；③ **合法**，`bp`（基址）+ `di`（变址）；④ 非法，两个变址寄存器不能相加。

**3.** `(DS)=1000H`、`(SS)=3000H`、`(BP)=0050H`，`mov ax, [bp]` 访问的物理地址是多少？为什么？
**答**：`3000H×16 + 0050H = 30050H`。因为 `[ ]` 中出现 `bp` 且没有段前缀时，**默认段寄存器是 SS**。

**4.** 数据处理的两个基本问题是什么？
**答**：① 处理的数据在什么地方（`reg`/`sreg`/`mem`/`idata`）；② 要处理的数据有多长（8 位还是 16 位）。

**5.** 写出 `mov` 指令的四条「非法组合」规则（再加一条关于 CS 的）。
**答**：① 两个内存单元之间不能直接传送；② 两个段寄存器之间不能直接传送；③ 立即数不能直接送段寄存器；④ 立即数不能作目的操作数。另加：**CS 不能作 `mov` 的目的**。

**6.** 什么时候必须用 `byte ptr` 或 `word ptr`？
**答**：当指令里没有寄存器能提供长度信息时。典型场合：立即数→内存（`mov byte ptr [bx],1`）、只有一个内存操作数的运算（`inc word ptr [bx]`、`div word ptr [bx]`）。

**7.** 写出 `div bl` 和 `div bx` 各自的被除数、商、余数位置。
**答**：`div bl`（8 位除）：被除数在 AX，商在 AL，余数在 AH。`div bx`（16 位除）：被除数在 DX:AX，商在 AX，余数在 DX。

**8.** `div` 的溢出条件是什么？会发生什么？
**答**：商超出了目的寄存器的表示范围——8 位除时商 > 255（FFH），16 位除时商 > 65535（FFFFH）。会触发除法溢出，转去执行 0 号中断处理程序。

**9.** 执行 `mov ax, 100h` / `mov bl, 10h` / `div bl` 后，AL、AH 各是多少？
**解**：`AX = 100H = 256`，`BL = 10H = 16`。`256 ÷ 16 = 16 余 0`。商 `16 = 10H` 放 AL，余数 `0` 放 AH。
**答**：`AL = 10H`，`AH = 00H`。

**10.** `dd 1000` 在内存中占几个字节？各字节内容是什么（从低地址到高地址）？
**答**：占 **4** 字节。`1000 = 000003E8H`，低字是 `03E8H`、高字是 `0000H`；按小端序存放：`E8`、`03`、`00`、`00`。

**11.** `db 2 dup (1, 3 dup (2))` 一共定义了几个字节？内容是什么？
**解**：内层 `3 dup (2)` = `2,2,2`；所以每次重复的内容是 `1,2,2,2`（4 字节）；外层重复 2 次 → 8 字节。
**答**：8 个字节，内容为 `1,2,2,2,1,2,2,2`。

**12.** data 段里有两张表：表 A 每项 4 字节、起始偏移 0；表 B 每项 2 字节、起始偏移 80。要访问下标为 3 的元素，`bx`、`si` 各应设为多少？
**答**：表 A：`bx = 0`、`si = 3 × 4 = 12`。表 B：`bx = 80`、`si = 3 × 2 = 6`。**换表要同时换表基址和偏移系数。**
