## 13.1 int指令

**`int` 指令的格式：`int n`，其中 `n` 是中断类型码（0~255）。**

**`int n` 的执行过程（与第 12 章的中断过程完全一致）：**

```
   ① 取中断类型码 N（N 就是指令中的立即数 n）
   ────────────────────────────────────────────
   ② pushf            ; 标志寄存器入栈
   ③ TF = 0, IF = 0   ; 禁止单步、禁止可屏蔽外中断
   ────────────────────────────────────────────
   ④ push CS          ; 当前代码段地址入栈
   ⑤ push IP          ; 当前指令指针入栈（指向 int 指令的下一条指令）
   ────────────────────────────────────────────
   ⑥ (IP) = (N×4)     ; 从中断向量表取入口
      (CS) = (N×4+2)  ; 转去执行中断处理程序
```

**`int` 指令与 `call` 指令的相似之处：**

```
   call far ptr 标号   →  调用一个「段:偏移」处的子程序，用 retf 返回
   int n               →  调用一个「中断向量表指定」处的例程，用 iret 返回
```

> **重点**：**`int` 指令和 `call` 指令的最终功能相似——都是「调用一段程序，执行完再回来」。** 区别在于三点：① **`int` 多压了一个 `FLAGS`**；② **`int` 会清 `TF` 和 `IF`**；③ **`int` 的目标地址是从中断向量表里查出来的，而不是写在指令里**。

**为什么「`int` 的目标地址从表里查」很重要？**

**因为指令里只写了 `n`（1 字节），处理程序的地址由「当前向量表的内容」决定——这给了程序一个「挂钩子」的机会：只要改写向量表，就能让所有 `int 21h` 都跳到你的代码里。这就是 TSR（常驻内存程序）、系统调用拦截、以及计算机病毒的基本原理。**

**本章术语约定：**

| 术语 | 含义 |
|---|---|
| **中断例程** | 中断处理程序（本章统一叫「中断例程」，与教材一致） |
| **调用者** | 执行 `int n` 的程序 |
| **例程** | 被调用的中断处理代码 |

## 13.2 编写中断例程

**目标：编写 7ch 中断例程，功能是在屏幕中间显示一个 `!`。**

**完整程序：**

```asm
assume cs:code
code segment
start:
    ; ===== 第一步：把 int7c 例程安装到 0:200 =====
    mov ax, cs
    mov ds, ax
    mov si, offset int7c
    mov ax, 0
    mov es, ax
    mov di, 200h
    mov cx, offset int7cend - offset int7c
    cld
    rep movsb

    ; ===== 第二步：设置 7ch 的中断向量 → 0:200 =====
    mov ax, 0
    mov es, ax
    mov word ptr es:[7ch*4], 200h          ; 偏移 = 0200H
    mov word ptr es:[7ch*4+2], 0           ; 段地址 = 0000H

    ; ===== 第三步：测试调用 =====
    mov ax, 1000h
    int 7ch                                ; ★ 调用我们自己写的中断例程

    mov ax, 4c00h
    int 21h

; ===== 7ch 中断例程：在屏幕中间显示 "!" =====
int7c:
    push ax                                ; ★ 保护现场
    push es
    push di

    mov ax, 0b800h                         ; ★ 显存段地址
    mov es, ax
    mov di, 160*12 + 40*2                  ; ★ 第 12 行第 40 列
    mov byte ptr es:[di], '!'              ; 写字符
    mov byte ptr es:[di+1], 2              ; 写属性：黑底绿字

    pop di                                 ; ★ 恢复现场（逆序）
    pop es
    pop ax
    iret                                   ; ★ 用 iret 返回

int7cend:
    nop                                    ; ★ 标记结尾，用于计算长度
code ends
end start
```

**运行结果**：屏幕第 12 行第 40 列出现一个绿色的 `!`，然后程序返回 DOS。

**关键点分析：**

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 安装 | `rep movsb` 把 `int7c` 搬到 `0:200` | 中断向量表内的空闲区，最安全 |
| `CX` | `offset int7cend - offset int7c` | 自动算出例程字节数 |
| 改向量 | `es:[7ch*4]` 存偏移、`es:[7ch*4+2]` 存段 | 7ch 号表项的位置公式 |
| 保护现场 | `push ax` / `push es` / `push di` | 例程用了这些寄存器，调用者可能正在用 |
| 返回 | `iret` | 弹出 IP、CS、FLAGS 三个字 |

> **重点**：**中断例程是「异步被调用的」——调用者不知道例程改动了哪些寄存器。** 所以例程里**用到的每一个寄存器都必须保护**。上例中如果没有 `push es` / `push di`，调用者的 `ES`、`DI` 就被破坏了——而调用者可能正用它们指向某个数据。**这是「写中断例程」与「写普通子程序」最大的纪律差别。**

**中断例程的参数与返回值：**

**中断例程也可以有「入口参数」和「出口参数」，规则和第 10 章的子程序一样：**

| 传递方式 | 例子 |
|---|---|
| 寄存器 | `int 7ch` 前把参数放 `AX`、`BX`、`CX`、`DX`，例程里用；返回时放回寄存器 |
| 内存 | 用约定好的内存地址（如 `0:200` 之后的应用数据区）传参 |

**BIOS 与 DOS 的例程统一用「`AH` 放功能号」的约定**（13.4~13.7 会看到大量这样的例子）。

## 13.3 ★★★ 对int、iret和栈的深入理解 ★★★

**本节是全书最精彩的技巧之一：用中断例程模拟 `loop` 指令的功能。**

**`loop s` 的两个参数：`CX`（循环次数）和「位移」（往哪跳多少字节）。**

**我们的 7ch 例程设计如下：**

```
   ★ 7ch 中断例程的功能：模拟 loop 指令
   ★ 入口参数：
        CX = 循环次数（例程内部会减 1）
        BX = 转移位移（字节数，可正可负）
   ★ 功能：
        CX 减 1；若 CX ≠ 0，则跳到「位移处」；若 CX = 0，则什么都不做
```

**调用者的程序：**

```asm
assume cs:code
code segment
start:
    ; ===== 安装 7ch 例程（略，同 13.2） =====
    ; ……（此处省略安装与设置向量的代码）……

    ; ===== 用 int 7ch 实现循环显示 80 个 "!" =====
    mov ax, 0b800h
    mov es, ax
    mov di, 160*12 + 40*2       ; 从第 12 行第 40 列开始
    mov bx, offset s - offset se    ; ★ 位移 = s 的偏移 − se 的偏移（负数！）
    mov cx, 80                  ; 循环 80 次
s:
    mov byte ptr es:[di], '!'   ; 在当前位置显示 "!"
    add di, 2                   ; 指向下一个显示位置
    int 7ch                     ; ★ 相当于 loop s
se:
    nop

    mov ax, 4c00h
    int 21h
code ends
end start
```

**注意 `mov bx, offset s - offset se` 是个负数：**

```
   标号顺序：  …… → s（先） → …… → int 7ch → se（后）
   所以 offset s < offset se
   offset s - offset se = 负数 → 表示「往回跳」
```

**中断例程的代码（核心中的核心）：**

```asm
; ===== 7ch 中断例程：模拟 loop 指令 =====
; 入口参数：CX = 循环次数，BX = 转移位移
lp:
    push bp                 ; ★ 保护 BP（例程要用它）
    mov bp, sp              ; ★ 让 BP 指向栈顶，便于访问栈中数据

    dec cx                  ; ★ CX 减 1
    jcxz lpret              ; ★ 若 CX = 0，不转移，直接返回
    add [bp+2], bx          ; ★★★ 修改栈中保存的返回地址 IP ★★★

lpret:
    pop bp                  ; ★ 恢复 BP
    iret                    ; ★ 弹出 IP（已被修改）、CS、FLAGS
```

### 为什么 `add [bp+2], bx` 能实现转移？

**进入中断例程时栈中的布局（务必理解）：**

```
      栈段 SS:SP
   ┌──────────────────┐
   │ 调用者的其他数据  │
   ├──────────────────┤
   │     FLAGS        │ ← 中断过程 pushf 压入
   ├──────────────────┤
   │       CS         │ ← 中断过程 push CS
   ├──────────────────┤
   │       IP         │ ← 中断过程 push IP ← SP 指向这里
   └──────────────────┘
```

**执行 `push bp` 和 `mov bp, sp` 之后：**

```
      栈段 SS:SP
   ┌──────────────────┐
   │     FLAGS        │ ← [bp+6]
   ├──────────────────┤
   │       CS         │ ← [bp+4]
   ├──────────────────┤
   │       IP         │ ← [bp+2]  ★ 关键！
   ├──────────────────┤
   │   旧的 BP        │ ← [bp+0] ← BP 和 SP 都指向这里
   └──────────────────┘
```

**所以 `[bp+2]` 恰好就是「栈中保存的返回地址 IP」！**

**`add [bp+2], bx` 做的事：把栈中的 IP 加上位移 `BX`。**

**随后 `iret` 执行：**

```
   pop IP    → IP 变成了「原返回地址 + BX」= se 的偏移 + (s − se) = s 的偏移
   pop CS    → 恢复调用者的代码段
   popf      → 恢复标志寄存器
```

**结果：`iret` 之后程序跳到了 `s` 处——成功模拟了 `loop s`！**

**完整的执行流程示意：**

```
   调用者                                    中断例程 lp
   ─────────────────────────────────────────────────────────
   s: mov byte ptr es:[di], '!'
      add di, 2
      int 7ch          ──压栈 FLAGS/CS/IP──►  push bp
                                              mov bp, sp
                                              dec cx
                                              jcxz lpret
                                              add [bp+2], bx   ← 改的是栈里的 IP！
                                              pop bp
                          ◄──iret 弹出──      iret
      （IP 已变成 s 的偏移）→ 跳回 s 继续
```

> **重点**：**这个技巧的通用名字叫「修改栈中的返回地址」——它让你能从被调用者那里「操纵调用者的流程」。**
>
> **理解要点只有三句话**：
> ① **中断过程把「返回地址 IP」压在了栈上**；
> ② **`push bp` / `mov bp, sp` 之后，`[bp+2]` 就是那个返回地址**；
> ③ **`iret` 会从栈里把它弹出来送进 IP——所以在 `iret` 之前改掉它，就能改变程序的去向。**
>
> **这个技巧的实战价值**：实现「异常处理」「系统调用挂钩」「断点调试」「协程切换」等高级机制。**理解它，你就理解了「函数调用栈是可以被操纵的」这个现代系统编程的核心事实。**

## 13.4 BIOS和DOS所提供的中断例程

**BIOS（Basic Input/Output System，基本输入输出系统）和 DOS 都提供了大量中断例程，供程序员调用。**

**分工原则（非常重要的一句话）：**

```
   ★ BIOS 提供的例程：主要和「硬件」打交道
   ★ DOS  提供的例程：主要和「操作系统功能」打交道，与硬件无关
```

**为什么这样分工？因为 BIOS 是「硬件之上的第一层软件」，它直接操作硬件；而 DOS 是操作系统，它调用 BIOS 来完成底层工作，再向上提供更抽象的功能。**

**常用 BIOS 中断：**

| 中断号 | 功能 | 说明 |
|---|---|---|
| `int 10h` | **显示 I/O** | 设光标、显示字符、滚屏、读写像素 |
| `int 13h` | **磁盘 I/O** | 读/写磁盘扇区（第 17 章） |
| `int 14h` | 串行口 I/O | 串口通信 |
| `int 15h` | 系统服务 | 杂项（内存大小、A20 门等） |
| `int 16h` | **键盘 I/O** | 读键盘缓冲区（第 17 章） |
| `int 17h` | 打印机 I/O | 打印字符 |
| `int 1Ah` | **时钟 I/O** | 读/设系统时钟计数 |

**常用 DOS 中断：**

| 中断号 | 功能 | 说明 |
|---|---|---|
| `int 20h` | 程序正常退出 | 早期写法 |
| `int 21h` | **DOS 系统功能调用** | 最常用！输入输出、文件、内存、时间…… |
| `int 22h` | 终止处理地址 | 系统内部使用 |
| `int 27h` | 驻留并退出 | 写 TSR（常驻程序）用 |

> **重点**：**`int 21h` 是 DOS 程序的「万能入口」。** 它用 `AH` 传递功能号，不同的功能号做不同的事——**这是全书最需要背下来的一张表**（见 13.7）。

**BIOS 与 DOS 例程的调用约定（对 `int 21h` 尤其重要）：**

```
   ① 功能号放 AH
   ② 入口参数放约定的寄存器（如 DS:DX、AL、BX、CX……）
   ③ 执行 int n
   ④ 出口结果在约定的寄存器里（有的功能还会用 CF 表示成功/失败）
```

## 13.5 BIOS和DOS中断例程的安装过程

**一个常见的误解：「BIOS 和 DOS 的中断例程当然是在内存里的」。**

**但真正的情况是：这些例程是「开机后逐步安装到内存里的」，且它们在内存中的位置不固定（取决于当前内存使用情况）。**

**安装过程（开机到 DOS 就绪）：**

```
   ① CPU 加电，初始化：(CS) = FFFFH，(IP) = 0000H
      → CPU 从 FFFF:0000 处开始执行
      → 那里存放的是一条跳转指令，跳到 BIOS 的「硬件检测和初始化程序」

   ② BIOS 的硬件检测和初始化程序：
      · 检测硬件（内存、显卡、键盘……）
      · ★ 建立中断向量表：把自己提供的中断例程的入口地址登记到 0000:0000 起的表中

   ③ 硬件检测和初始化完成后，调用 int 19h 引导操作系统
      → int 19h 把启动盘的第一个扇区（引导扇区）读入内存并执行

   ④ 操作系统（DOS）启动后：
      · ★ 建立自己提供的中断例程的中断向量
      · 完成初始化，显示命令提示符，等待用户输入
```

**开机后内存的典型布局：**

```
   0000:0000 ┌──────────────────┐
             │   中断向量表      │  1KB（256 项 × 4 字节）
   0000:0400 ├──────────────────┤
             │   BIOS 数据区     │  256 字节
   0000:0500 ├──────────────────┤
             │                  │
             │   BIOS 中断例程   │  ← 由 BIOS 在开机时装入
             │                  │
             ├──────────────────┤
             │                  │
             │   DOS 中断例程    │  ← 由 DOS 在启动时装入
             │                  │
   A0000H    ├──────────────────┤
             │   显存（显卡）     │  B8000H 起是彩色文本模式显存
   C0000H    ├──────────────────┤
             │   ROM（BIOS 程序） │  只读，地址越高越靠上
   FFFFFH    └──────────────────┘
```

> **重点**：**「中断向量表由 BIOS 建立」这件事，解释了一个现象：为什么你在程序里改写了某个中断向量，程序退出后系统还能正常工作？** 因为 DOS 在启动程序前会保存这些向量，程序结束后恢复（这也是为什么自制的 TSR 要用特殊手段才能「赖着不走」）。

## 13.6 BIOS中断例程应用

**`int 10h` 是显示服务中断，用 `AH` 指定功能号。常用功能：**

| `AH` | 功能 | 入口参数 | 说明 |
|---|---|---|---|
| `0` | 设置显示模式 | `AL` = 模式号 | `AL=3` 是 80×25 彩色文本 |
| `2` | **设置光标位置** | `BH`=页号，`DH`=行，`DL`=列 | 行列从 0 开始 |
| `3` | 读光标位置 | `BH`=页号 | 返回 `DH`/`DL`/`CX` |
| `6` | 向上滚屏 | `AL`=行数，`BH`=属性，`CH`/`CL`=左上角，`DH`/`DL`=右下角 | `AL=0` 清屏 |
| `9` | **在光标处显示字符** | `AL`=字符，`BH`=页号，`BL`=属性，`CX`=重复次数 | **不移动光标** |
| `0Ah` | 在光标处显示字符 | 同上，但用当前属性 | |
| `0Eh` | 电传方式显示 | `AL`=字符，`BL`=前景色 | **会移动光标** |
| `13h` | 显示字符串 | `ES:BP`=串地址，`CX`=长度，`DH`/`DL`=位置 | |

**例：在屏幕第 5 行第 12 列显示 3 个红底绿字的 `a`。**

```asm
assume cs:code
code segment
start:
    ; ===== 第一步：把光标设到第 5 行第 12 列 =====
    mov ah, 2                   ; ★ 功能号 2：设置光标位置
    mov bh, 0                   ; 第 0 页（通常就用第 0 页）
    mov dh, 5                   ; ★ 行号 5（从 0 开始）
    mov dl, 12                  ; ★ 列号 12（从 0 开始）
    int 10h

    ; ===== 第二步：在光标位置显示字符 =====
    mov ah, 9                   ; ★ 功能号 9：在光标位置显示字符
    mov al, 'a'                 ; 要显示的字符
    mov bl, 11001010b           ; ★ 属性字节
    mov bh, 0                   ; 第 0 页
    mov cx, 3                   ; ★ 重复显示 3 次
    int 10h

    mov ax, 4c00h
    int 21h
code ends
end start
```

**属性字节 `11001010B` 的解读：**

```
   1100 1010B
   │└┬┘│└┬┘
   │ │  │ └── 前景色 010B = 2 → 绿色
   │ │  └──── 高亮位 = 1 → 高亮（亮绿）
   │ └─────── 背景色 100B = 4 → 红色
   └───────── 闪烁位 = 1 → 字符闪烁
   
   → 闪烁 + 红底 + 亮绿字
```

**颜色编码表（3 位，配合高亮位可扩展）：**

| 值 | 颜色 | 值 | 颜色 |
|---|---|---|---|
| `000B` | 黑 | `100B` | 红 |
| `001B` | 蓝 | `101B` | 紫（洋红） |
| `010B` | 绿 | `110B` | 棕（黄） |
| `011B` | 青 | `111B` | 白 |

**`int 10h` 的 9 号功能 vs 我们自己写显存（第 12 章）的对比：**

| 对比项 | 用 `int 10h` 9 号功能 | 直接写显存 `B800H` |
|---|---|---|
| 代码量 | 少（只需设几个寄存器） | 多（要自己算偏移、写属性） |
| 光标 | **不移动**（9 号功能不移动光标） | 完全不管光标 |
| 可移植性 | 好（不同显示模式有 BIOS 兼容） | 差（只适用 `B800H` 文本模式） |
| 灵活性 | 受 BIOS 限制 | 完全自由 |
| 速度 | 慢（要通过中断调用） | 快（直接内存操作） |

> **重点**：**考试中如果题目要求「在屏幕某位置显示字符」，两种方法都可以——但用 `int 10h` 的代码短得多，推荐优先用它。** 不过要注意 **9 号功能不移动光标**，连续显示多个字符要自己管理位置（或用 2 号功能重设光标）。

## 13.7 DOS中断例程应用

**`int 21h` 是 DOS 系统功能调用中断，用 `AH` 指定功能号。**

**最常用的功能号（必须记住）：**

| `AH` | 功能 | 入口参数 | 出口 |
|---|---|---|---|
| `01h` | **输入一个字符** | 无 | `AL` = 字符（**会回显**） |
| `02h` | **输出一个字符** | `DL` = 字符 | 无 |
| `07h` | 输入一个字符（**不回显**） | 无 | `AL` = 字符 |
| `08h` | 输入一个字符（不回显，检查 Ctrl+C） | 无 | `AL` = 字符 |
| `09h` | **显示字符串** | `DS:DX` = 串地址 | 无 |
| `0Ah` | **输入字符串到缓冲区** | `DS:DX` = 缓冲区地址 | 缓冲区被填充 |
| `2Ah` | 取系统日期 | 无 | `CX`=年，`DH`=月，`DL`=日 |
| `2Ch` | 取系统时间 | 无 | `CH`=时，`CL`=分，`DH`=秒 |
| `3Ch` | 创建文件 | `DS:DX`=文件名，`CX`=属性 | `AX`=文件句柄 |
| `3Dh` | 打开文件 | `DS:DX`=文件名，`AL`=方式 | `AX`=文件句柄 |
| `3Eh` | **关闭文件** | `BX`=文件句柄 | `CF`=0 成功 |
| `3Fh` | **读文件** | `BX`=句柄，`CX`=字节数，`DS:DX`=缓冲区 | `AX`=实际读到的字节数 |
| `40h` | **写文件** | `BX`=句柄，`CX`=字节数，`DS:DX`=缓冲区 | `AX`=实际写入的字节数 |
| `4Ch` | **结束程序** | `AL` = 返回码 | 返回 DOS |

**例一：用 9 号功能显示字符串。**

```asm
assume cs:code, ds:data
data segment
    db 'Welcome to masm', '$'      ; ★ 必须以 '$' 结尾！
data ends
code segment
start:
    mov ax, data
    mov ds, ax                     ; ★ DS 必须指向字符串所在段
    mov dx, 0                      ; ★ DS:DX → 字符串首地址（偏移 0）
    mov ah, 9                      ; ★ 功能号 9：显示字符串
    int 21h                        ; 从 DS:DX 开始显示，直到遇到 '$'

    mov ax, 4c00h                  ; ★ 4CH 功能：结束程序
    int 21h
code ends
end start
```

**运行结果**：屏幕显示

```
Welcome to masm
```

**注意：`'$'` 本身不会被显示出来——它是「字符串结束标记」。**

**例二：用 `int 21h` + `int 10h` 在屏幕中间显示多行字符串。**

```asm
assume cs:code, ds:data
data segment
    db 'Welcome to masm!', '$'
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    ; ===== 把光标设到第 12 行第 32 列（屏幕中间） =====
    mov ah, 2
    mov bh, 0
    mov dh, 12                     ; 第 12 行
    mov dl, 32                     ; 第 32 列
    int 10h

    ; ===== 显示字符串 =====
    mov dx, 0                      ; DS:DX → 字符串
    mov ah, 9
    int 21h

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：`Welcome to masm!` 出现在屏幕第 12 行第 32 列处。

> **重点**：**`int 21h` 的 9 号功能有两个必须记住的坑：** ① **字符串必须以 `'$'`（`24H`）结尾**，否则 DOS 会一直往后打印直到内存里碰巧出现一个 `24H`——表现为「打印出一堆乱码」；② **`DS:DX` 必须正确指向字符串**，`DS` 没设对就会打印出完全无关的内存垃圾。

**例三：综合使用——用 2 号功能逐个输出字符。**

```asm
assume cs:code, ds:data
data segment
    db 'Hello, Assembly!', 0
data ends
code segment
start:
    mov ax, data
    mov ds, ax
    mov si, 0

s:
    mov dl, [si]                   ; 取一个字符到 DL
    cmp dl, 0                      ; 是不是结束标记？
    je  ok                         ; 是 → 结束
    mov ah, 2                      ; ★ 2 号功能：输出一个字符
    int 21h
    inc si
    jmp short s

ok:
    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：屏幕显示 `Hello, Assembly!`。

**`int 21h` 与「程序返回」的关系（贯穿全书的收尾）：**

```asm
    mov ax, 4c00h       ; AH = 4CH（功能号），AL = 00H（返回码）
    int 21h             ; 结束程序，把 AL 作为返回码交给 DOS
```

**为什么写 `mov ax,4c00h` 而不是两条 `mov`？**

```
   4C00H 的高字节 = 4CH → 进 AH（功能号）
   4C00H 的低字节 = 00H → 进 AL（返回码）
   
   一条 mov 搞定两个寄存器的赋值——这是汇编里常见的「打包」写法。
```

| 返回码 `AL` | 含义 |
|---|---|
| `00H` | 正常结束 |
| 非 0 | 出错（可在批处理中用 `ERRORLEVEL` 检测） |

## 典型例题

**例 13.1**（题型：int 指令的执行过程）
写出 `int 20h` 的执行过程（含栈的变化），并说明它和 `call far ptr` 的区别。
**解**：
- **`int 20h` 的执行过程**：① 取类型码 `N = 20H`；② `pushf`（`SP = SP−2`，写入 `FLAGS`）；③ `TF = 0`、`IF = 0`；④ `push CS`（`SP = SP−2`）；⑤ `push IP`（`SP = SP−2`）；⑥ `(IP) = (20H×4) = 80H 处的内容`，`(CS) = (20H×4+2) = 82H 处的内容`。
- **共压栈 6 字节**。

**区别对照：**

| 对比项 | `int 20h` | `call far ptr 标号` |
|---|---|---|
| 目标地址来源 | **从 `0000:0080` 处的中断向量读出** | 指令中直接给出（立即数） |
| 压栈内容 | `FLAGS` + `CS` + `IP`（6 字节） | `CS` + `IP`（4 字节） |
| 是否清 `TF`/`IF` | **清** | 不清 |
| 返回指令 | **`iret`** | `retf` |

**答案**：见上。

**例 13.2**（题型：编写中断例程）
编写一个 7ch 中断例程，功能是把 `AL` 中的字符以黑底白字显示在屏幕第 10 行第 20 列（覆盖原内容）。写出例程代码和安装代码。
**解**：

**例程代码：**
```asm
int7c:
    push ax                     ; ★ 保护现场（AX 里是入口参数，不能不保存就用）
    push bx
    push es
    push di

    mov bx, 0b800h              ; ★ 显存段地址（用 BX 中转，不能直接 mov es,立即数）
    mov es, bx
    mov di, 160*10 + 20*2       ; ★ 第 10 行第 20 列
    mov byte ptr es:[di], al    ; 写字符（AL 是入口参数）
    mov byte ptr es:[di+1], 07h ; 写属性：黑底白字

    pop di                      ; ★ 恢复现场（逆序）
    pop es
    pop bx
    pop ax
    iret
int7cend:
    nop
```

**安装代码：**
```asm
    mov ax, cs
    mov ds, ax
    mov si, offset int7c
    mov ax, 0
    mov es, ax
    mov di, 200h
    mov cx, offset int7cend - offset int7c
    cld
    rep movsb

    mov ax, 0
    mov es, ax
    mov word ptr es:[7ch*4], 200h
    mov word ptr es:[7ch*4+2], 0
```

**答案**：见上。**关键**：① 例程里必须保护所有用到的寄存器；② `mov es, 0b800h` 非法，必须经通用寄存器中转；③ 属性 `07H` = 黑底白字。

**例 13.3**（题型：栈中返回地址的修改）
7ch 中断例程如下，请说明它的功能，并画出执行 `mov bp,sp` 之后栈的布局。
```asm
lp:
    push bp
    mov bp, sp
    dec cx
    jcxz lpret
    add [bp+2], bx
lpret:
    pop bp
    iret
```
**解**：
- **功能**：**模拟 `loop` 指令**。入口参数 `CX` = 循环次数、`BX` = 位移。若 `CX−1 ≠ 0`，则修改栈中保存的返回地址 IP（加位移），实现跳转；否则直接返回。
- **栈布局**（`mov bp, sp` 之后，`BP` 和 `SP` 都指向旧的 `BP`）：

```
   SS:SP ┌──────────────┐
         │    FLAGS     │ ← [bp+6]
         ├──────────────┤
         │      CS      │ ← [bp+4]
         ├──────────────┤
         │      IP      │ ← [bp+2]  ★ 返回地址，被 add 修改
         ├──────────────┤
         │   旧的 BP     │ ← [bp+0]  ← BP = SP 指向这里
         └──────────────┘
```

**答案**：功能是模拟 `loop`；`[bp+2]` 正是栈中保存的返回地址 IP。
**关键**：**`iret` 会把 `[bp+2]` 处的值弹出送进 `IP`——所以在 `iret` 之前修改它，就能改变程序的去向。**

**例 13.4**（题型：BIOS 中断调用）
用 `int 10h` 把光标设到第 8 行第 30 列，并显示 5 个属性为白底黑字（`70H`）的 `*`。
**解**：
```asm
    ; ===== 设置光标 =====
    mov ah, 2
    mov bh, 0               ; 第 0 页
    mov dh, 8               ; 第 8 行
    mov dl, 30              ; 第 30 列
    int 10h

    ; ===== 显示字符 =====
    mov ah, 9               ; 9 号功能：在光标位置显示字符
    mov al, '*'             ; 字符
    mov bh, 0               ; 第 0 页
    mov bl, 70h             ; ★ 属性：白底黑字（bit7=0 不闪，背景 111=白，高亮 0，前景 000=黑）
    mov cx, 5               ; ★ 重复 5 次
    int 10h
```
**答案**：见上。**关键**：① 设光标用 `AH=2`，`DH` 是行、`DL` 是列（**不是 `DH` 列 `DL` 行**！）；② 显示字符用 `AH=9`，**该功能不移动光标**，靠 `CX` 重复显示同一个字符。

**例 13.5**（题型：DOS 中断调用）

**例 13.6**（题型：中断向量位置计算）
写出 7ch 号中断表项在内存中的位置，以及把入口设为 `0000:0200` 的代码。
**解**：

**例 13.7**（题型：综合编程）
编写程序：安装 7ch 例程，使其把 `DS:SI` 处的一个以 `0` 结尾的字符串显示在屏幕第 12 行第 32 列（用显存直接写，属性为黑底绿字），然后测试它。
**解**：
```asm

data ends
code segment

    ; ===== 安装 =====
    mov ax, cs
    mov ds, ax
    mov si, offset int7c
    mov ax, 0
    mov es, ax
    mov di, 200h
    mov cx, offset int7cend - offset int7c

    rep movsb

    mov ax, 0
    mov es, ax
    mov word ptr es:[7ch*4], 200h
    mov word ptr es:[7ch*4+2], 0

    ; ===== 测试：DS:SI 指向字符串，调用 7ch =====
    mov ax, data
    mov ds, ax
    mov si, 0
    int 7ch

    mov ax, 4c00h
    int 21h

; ===== 7ch 例程：显示 DS:SI 处的 0 结尾字符串 =====

    push bx
    push cx
    push si
    push di
    push es

    mov es, ax
```

## 易错点提醒

1. **错**：以为 `int n` 的执行过程和普通 `call` 一样。**对**：**`int n` 会多压一个 `FLAGS`（共压 6 字节），并且会清 `TF` 和 `IF`**；返回必须用 `iret`。
2. **错**：以为 `int n` 的目标地址写在指令里。**对**：**指令里只有类型码 `n`，目标地址是从中断向量表 `0000:(n×4)` 处查出来的。** 这正是「改写向量就能挂钩」的原理。
3. **错**：中断例程里不保护现场、或只在开头保护忘了恢复。**对**：**例程用到的每个寄存器都必须 `push` 保存、退出前逆序 `pop` 恢复。** 中断是异步调用，调用者的寄存器状态未知。
4. **错**：中断例程末尾用 `ret` / `retf`。**对**：**必须用 `iret`**（弹 `IP`、`CS`、`FLAGS` 三个字）。
5. **错**：安装例程时 `CX` 写死一个数字。**对**：**用 `mov cx, offset 末尾标号 - offset 起始标号`**，让长度随代码自动更新。**`do0end`/`int7cend` 这类结尾标号必须放在所有数据之后。**
6. **错**：`mov es, 0b800h` 这样写。**对**：**立即数不能直接送段寄存器**，必须经通用寄存器中转：`mov bx,0b800h` / `mov es,bx`。
7. **错**：把 `int 10h` 设光标的 `DH`/`DL` 记反。**对**：**`DH` 是行号、`DL` 是列号，都从 0 开始。** 而 `AH=9` 显示字符时用的是 `AL`（字符）、`BL`（属性）、`CX`（次数）。
8. **错**：以为 `int 10h` 的 9 号功能会移动光标。**对**：**9 号功能不移动光标**——它只把字符写到光标位置。连续显示多个不同字符要自己重设光标或用 `0Eh`（电传方式，会移动光标）。
9. **错**：用 `int 21h` 9 号功能时字符串忘了 `'$'` 结尾。**对**：**9 号功能以 `'$'`（`24H`）作为结束标记**，没有它就会一直打印后面的内存内容（显示一堆乱码）。
10. **错**：用 `int 21h` 9 号功能时 `DS` 没设对。**对**：**9 号功能用 `DS:DX` 定位字符串**，`DS` 必须指向字符串所在段。**`DX` 是偏移、`DS` 是段——缺一不可。**
11. **错**：以为 `add [bp+2], bx` 是在改数据。**对**：**`[bp+2]` 在中断例程的栈帧里就是「栈中保存的返回地址 IP」**，改它等于改程序的去向——`iret` 会把这个值弹进 `IP`。
12. **错**：忘了 `int 21h` 的 4CH 功能，程序执行完「穿透」到别处。**对**：**程序末尾必须写 `mov ax,4c00h` / `int 21h` 正常返回 DOS**；否则 CPU 会继续往后执行内存里的垃圾指令，可能死机或乱打印。
13. **错**：以为改写了中断向量会影响系统全局。**对**：**改向量只影响「当前程序运行期间」**；DOS 在程序启动前保存向量、结束后恢复。**要让修改长期生效必须写成 TSR（用 `int 27h` 或 `int 21h` 的 31H 功能驻留）。**
14. **错**：把「中断例程」当成「BIOS 里固化的、不能改的」。**对**：**BIOS/DOS 只提供了默认的例程；任何中断向量都可以被程序改写**——这正是第 15 章「安装新的 `int 9` 键盘中断」的前提。

## 本章小结

- **`int n` 的执行过程 = 中断过程**：① 取类型码 `N`；② `pushf`；③ `TF=0, IF=0`；④ `push CS`；⑤ `push IP`；⑥ `(IP)=(N×4)`、`(CS)=(N×4+2)`。
- **`int` 与 `call` 的关系**：功能相似（调用一段程序再返回），区别是 **`int` 多压 `FLAGS`、清 `TF`/`IF`、目标地址从向量表查**，返回用 **`iret`**。
- **编写中断例程的三步**：① 写例程（保护现场 → 处理 → 逆序恢复 → `iret`）；② `rep movsb` 搬到 `0000:0200`（长度用 `offset 末 − offset 首`）；③ 改中断向量（`es:[n*4]` 存偏移、`es:[n*4+2]` 存段）。
- **★★★ 中断例程的栈布局：`[bp+2]` = 返回地址 IP、`[bp+4]` = CS、`[bp+6]` = FLAGS**（在 `push bp` / `mov bp,sp` 之后）。**`add [bp+2], bx` 就能改变 `iret` 的去向——用它可以模拟 `loop`、实现环回跳转。★★★**
- **BIOS 管硬件、DOS 管系统功能**：BIOS 提供 `int 10h`（显示）、`int 13h`（磁盘）、`int 16h`（键盘）、`int 1Ah`（时钟）；DOS 提供 `int 21h`（系统功能调用）、`int 20h`（退出）、`int 27h`（驻留）。
- **BIOS/DOS 例程的安装过程**：CPU 从 `FFFF:0000` 开始执行 → BIOS 检测硬件并建立中断向量表 → `int 19h` 引导操作系统 → DOS 建立自己的中断向量。
- **`int 10h` 常用功能**：`AH=2` 设光标（`DH` 行、`DL` 列）；`AH=9` 在光标处显示字符（`AL` 字符、`BL` 属性、`CX` 次数，**不移动光标**）；`AH=6` 滚屏/清屏。
- **`int 21h` 常用功能**：`AH=01h` 输入字符、`AH=02h` 输出字符（`DL`）、**`AH=09h` 显示字符串（`DS:DX` 指向，必须以 `'$'` 结尾）**、`AH=0Ah` 输入字符串、**`AH=4Ch` 结束程序（`AL` 为返回码）**。
- **`mov ax,4c00h` 的巧妙之处**：一条指令把功能号 `4CH` 送 `AH`、返回码 `00H` 送 `AL`。

> **一句话记住本章**：**`int n` 就是「从向量表查地址的 call + 多压一个 FLAGS」；写例程要「保护现场 → 干活 → 逆序恢复 → `iret`」；理解 `[bp+2]` 是返回地址，就掌握了「从被调用者操纵调用者流程」的关键；日常编程靠 `int 21h`（`AH` 送功能号）和 `int 10h`（显示）。**

## 自测题

**1.** `int n` 的执行过程有哪几步？压栈共几个字节？
**答**：① 取中断类型码 `N`；② `pushf`；③ `TF=0`、`IF=0`；④ `push CS`；⑤ `push IP`；⑥ `(IP)=(N×4)`、`(CS)=(N×4+2)`。**共压栈 6 字节**（`FLAGS`、`CS`、`IP` 各 2 字节）。

**2.** `int n` 与 `call far ptr 标号` 有哪些区别？
**答**：① **目标地址来源**：`int` 从中断向量表 `0000:(n×4)` 读，`call far` 由指令直接给出；② **压栈内容**：`int` 压 `FLAGS`+`CS`+`IP`（6 字节），`call far` 压 `CS`+`IP`（4 字节）；③ **标志位**：`int` 会清 `TF` 和 `IF`，`call far` 不会；④ **返回指令**：`int` 用 `iret`，`call far` 用 `retf`。

**3.** 编写中断例程时，为什么必须保护现场？和普通子程序相比有什么不同？
**答**：因为**中断是异步发生的，调用者不知道例程修改了哪些寄存器**，若例程不保护它用到的寄存器，就可能破坏调用者正在使用的重要数据。普通子程序是同步调用、接口已知，而中断例程的调用时机不确定、影响面更大，**所以保护现场更加必要，且要求更严格（用到什么就必须保护什么）**。

**4.** 安装中断例程时，`mov cx, offset int7cend - offset int7c` 的作用是什么？
**答**：**计算例程代码的字节数**，作为 `rep movsb` 的重复次数。用「偏移相减」的好处是**长度随代码修改自动更新，不需要人工维护**，避免漏改。**因此结尾标号必须放在所有代码和数据（如内嵌字符串）之后。**

**5.** 在 7ch 例程中，`push bp` / `mov bp, sp` 之后，`[bp+2]`、`[bp+4]`、`[bp+6]` 分别是什么？
**答**：**`[bp+2]` 是栈中保存的返回地址 `IP`；`[bp+4]` 是 `CS`；`[bp+6]` 是 `FLAGS`。**

**6.** `add [bp+2], bx` 为什么能实现跳转？
**答**：因为它**修改了栈中保存的返回地址 `IP`**。随后执行的 `iret` 会 `pop IP` 把这个值送入 `IP`，于是程序跳到了「原返回地址 + BX」处。**只要 `BX` 设成「目标标号偏移 − 返回地址偏移」，就实现了转移——这正是模拟 `loop` 的原理。**

**7.** BIOS 和 DOS 提供的例程在功能上如何分工？
**答**：**BIOS 的例程主要与硬件打交道**（显示 `int 10h`、磁盘 `int 13h`、键盘 `int 16h`、时钟 `int 1Ah`）；**DOS 的例程主要提供与硬件无关的操作系统功能**（`int 21h` 系统功能调用、`int 20h`/`int 27h`）。

**8.** 简述开机后 BIOS 和 DOS 中断例程的安装过程。
**答**：① CPU 加电后 `(CS)=FFFFH`、`(IP)=0000H`，从 `FFFF:0000` 开始执行（那里是一条跳转指令）；② 跳到 BIOS 的硬件检测和初始化程序，**该程序建立中断向量表**，登记 BIOS 中断例程的入口；③ 初始化完成后调用 **`int 19h` 引导操作系统**；④ **DOS 启动后建立自己提供的中断例程的中断向量**。

**9.** 用 `int 10h` 把光标设到第 6 行第 25 列，写出代码。
**答**：
```asm
mov ah, 2
mov bh, 0       ; 页号 0
mov dh, 6       ; 行号（DH 是行！）
mov dl, 25      ; 列号
int 10h
```

**10.** 用 `int 10h` 的 9 号功能显示 3 个蓝底白字的 `#`，写出代码。
**答**：
```asm
mov ah, 9
mov al, '#'             ; 字符
mov bh, 0               ; 页号
mov bl, 00011111b       ; 属性：蓝底(001)白字(111)，不闪、不高亮
mov cx, 3               ; 重复 3 次
int 10h
```
（属性 `00011111B = 1FH`：闪烁 0、背景 001 蓝、高亮 0、前景 111 白。）

**11.** 用 `int 21h` 的 9 号功能显示字符串，字符串必须以什么结尾？为什么？
**答**：必须以 **`'$'`（`24H`）** 结尾。**9 号功能用 `'$'` 作为字符串结束标记**，遇到它才停止显示。**忘了加 `'$'` 会导致 DOS 继续打印后面的内存内容，屏幕出现一堆乱码。**

**12.** `mov ax, 4c00h` / `int 21h` 的含义是什么？为什么写成一条 `mov`？
**答**：**调用 `int 21h` 的 `4CH` 功能结束程序**，`AL` 中的值是返回给 DOS 的返回码。写成一条 `mov` 是因为 **`4C00H` 的高字节 `4CH` 正好进 `AH`（功能号）、低字节 `00H` 正好进 `AL`（返回码）**，一条指令完成两个寄存器的赋值。

**13.** 写出下面各 DOS 功能号的作用：`01h`、`02h`、`09h`、`0Ah`、`4Ch`。
**答**：`01h` 输入一个字符（回显，结果在 `AL`）；`02h` 输出一个字符（字符在 `DL`）；`09h` 显示字符串（`DS:DX` 指向，以 `'$'` 结尾）；`0Ah` 输入字符串到缓冲区（`DS:DX` 指向缓冲区）；`4Ch` 结束程序（`AL` = 返回码）。

**14.** 为什么 `mov es, 0b800h` 是非法指令？应该怎么写？
**答**：因为 **8086 不允许立即数直接传送到段寄存器**。应写成：
```asm
mov bx, 0b800h
mov es, bx
```

**15.** 为什么在中断例程里加「显示字符数不超过 80」这样的上限检查是好习惯？
**答**：因为例程的入口参数（如 `DS:SI` 指向的字符串）由调用者提供，**如果字符串缺少结束标记，例程会一直往后读写，冲掉整屏甚至覆盖别的数据**。加上限检查是一种**防御性编程**，能让错误的影响范围可控，而不是造成全屏混乱或崩溃。
