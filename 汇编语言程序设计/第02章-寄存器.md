## 2.1 通用寄存器

**8086 有 14 个 16 位寄存器，其中 AX、BX、CX、DX 是 4 个通用寄存器（General Register），每个都可以拆成两个独立的 8 位寄存器使用。**

```
                  AX（16 位）
        ┌──────────────┬──────────────┐
        │   AH（高 8 位）│   AL（低 8 位）│
        └──────────────┴──────────────┘
               bit15 ... bit8   bit7 ... bit0
```

四个通用寄存器都可拆：

| 16 位 | 高 8 位 | 低 8 位 | 主要用途（约定俗成，不是强制） |
|---|---|---|---|
| AX | AH | AL | 累加器（Accumulator），乘除、I/O 首选 |
| BX | BH | BL | 基址寄存器（Base），**早期最常用来做 `[...]` 里的地址寄存器**（其实 `SI`/`DI`/`BP` 也能放进 `[]`，见第 7、8 章） |
| CX | CH | CL | 计数器（Count），**`loop` 和移位次数必须用它** |
| DX | DH | DL | 数据寄存器（Data），**乘除的高位、端口地址 >255 时用它** |

> **重点**：8086 的 **14 个 16 位寄存器完整清单**——
> **通用寄存器 4 个**：AX、BX、CX、DX
> **指针与变址寄存器 4 个**：SP（栈指针）、BP（基址指针）、SI（源变址）、DI（目的变址）
> **段寄存器 4 个**：CS（代码段）、DS（数据段）、SS（栈段）、ES（附加段）
> **控制寄存器 2 个**：IP（指令指针）、FLAGS/PSW（标志寄存器）
> 4 + 4 + 4 + 2 = **14 个**。

## 2.2 字在寄存器中的存储

**一个字（Word）= 16 位 = 2 字节。存入寄存器时，高字节放高位、低字节放低位。**

例：把 `20000` 存入 AX。

- `20000 = 4E20H`
- 所以 `AH = 4EH`（高字节），`AL = 20H`（低字节）。

```
        AX = 4E20H
   ┌───────────┬───────────┐
   │  AH = 4EH │  AL = 20H │
   └───────────┴───────────┘
      高字节        低字节
```

> **重点**：这种「低地址/低位存低字节」的约定叫**小端序（Little Endian）**。8086 是典型的小端机。写 `mov ax, 4E20H` 后，`AH` 一定是 `4EH`、`AL` 一定是 `20H`——**不要记反**。

## 2.3 几条汇编指令

**8086 里最基础的三条指令：`mov`（传送）、`add`（加）、`sub`（减）。**

### mov

格式：`mov 目的操作数, 源操作数`，功能：把源操作数送进目的操作数。

```asm
mov ax, 18       ; AX = 0012H，把【十进制】18 送进 AX（18 = 12H）
mov ah, 78       ; AH = 4EH，同样是十进制（78 = 4EH），不要看成 78H
mov al, 20h      ; AL = 20H，带 h 才是十六进制
mov ax, bx       ; AX = BX，寄存器之间传送
mov al, bl       ; AL = BL（8 位对 8 位）
```

> **重点**：**MASM 里不带后缀的数字一律是十进制**——`18` 是十进制的 18（= `12H`），`78` 是十进制的 78（= `4EH`）。要写十六进制必须带 `h` 后缀，而且**以字母开头时要补前导 0**（写 `0abh`，不能写 `abh`，否则被当成标号）。上面两行故意把「十进制 18」「十进制 78」和「十六进制 20h」混在一起，就是为了提醒你别看错。

### add / sub

```asm
add ax, 8        ; AX = AX + 8
sub ax, 8        ; AX = AX − 8
add al, 93h      ; AL = AL + 93H
```

### 8 位运算的截断（考点）

**8 位寄存器的运算结果只能保留 8 位，超出的部分被丢掉。**

```asm
mov al, 0FFH     ; AL = FFH = 255
add al, 1        ; AL = (255 + 1) mod 256 = 0，进位被丢弃
                 ; 结果：AL = 00H
```

```asm
mov al, 0FFH
add al, 02H      ; 255 + 2 = 257，257 mod 256 = 1
                 ; 结果：AL = 01H
```

> **重点**：8 位寄存器里发生的运算，结果**自动对 256 取模**。这个「丢掉进位」的行为到第 11 章会变成 **CF 标志位**——CPU 其实没丢，它把进位记到 CF 里了。

### 指令格式的两条硬规矩

1. **两个操作数的位数必须一致**：`mov ax, bl` 是错的（16 位 ← 8 位）；`mov al, bx` 也是错的。
2. **`mov` 不允许两个内存单元之间直接传送**（第 3 章讲），也不允许立即数直接送段寄存器（第 3 章讲）。

## 2.4 物理地址

**物理地址（Physical Address）是内存单元的「唯一身份证」，8086 的物理地址是 20 位。**

1MB 内存有 `1048576` 个单元，需要 `2^20` 个编号，所以物理地址必须用 **20 位二进制**表示，写作 5 位十六进制，如 `20000H`、`FFFFFH`。

从 `00000H` 到 `FFFFFH`，每个单元有且只有一个物理地址——这是 CPU 访问内存的**最终依据**。

## 2.5 16 位结构的 CPU

**8086 是「16 位结构」的 CPU：它内部能一次处理、传输、暂存的地址是 16 位。**

80286 之前，运算器一次最多处理 16 位数据，寄存器最大宽度 16 位，寄存器和运算器之间的通路也是 16 位。

**于是出现矛盾**：

| 需求 | 能力 | 结果 |
|---|---|---|
| 物理地址需要 **20 位** | 内部只能表示 **16 位** | 无法在一条指令里直接给出 20 位地址 |

16 位最多表示 `2^16 = 65536 = 64KB` 的地址。可 8086 明明要寻址 1MB。怎么解决？

## 2.6 8086CPU 给出物理地址的方法

**8086 用「两个 16 位地址合成一个 20 位物理地址」：段地址 × 16 + 偏移地址。**

```
   物理地址 = 段地址 × 16 + 偏移地址
```

- **段地址（Segment Address, SA）**：放在段寄存器（CS/DS/SS/ES）里，16 位。
- **偏移地址（Effective Address, EA）**：也叫有效地址，16 位。

计算过程：

```
   段地址 2000H ─┐
                 ├──→ 2000H × 16 = 20000H
                 │    +    0010H = 0010H
   偏移地址 0010H ┘    ────────────────────
                        物理地址 = 20010H
```

### 「×16」的三种等价说法（都要会）

| 说法 | 操作 | 例子 |
|---|---|---|
| 数学 | 乘以 16 | `2000H × 16 = 20000H` |
| 二进制 | 左移 4 位，低位补 4 个 0 | `0010 0000 0000 0000 → 0010 0000 0000 0000 0000` |
| 十六进制 | 末尾补 1 个 0 | `2000H → 20000H` |

> **重点**：考试中算物理地址，最快的做法就是「**段地址后面添一个 0，再加上偏移地址**」。

### 完整算例

**例：`(DS) = 1000H`，`(BX) = 0010H`，访问的是什么物理地址？**

```
   1000H × 16 = 10000H
   + 0010H   = 0010H
   ───────────────────
   物理地址   = 10010H
```

### 一个物理地址可以有多个「段地址:偏移地址」组合

因为偏移地址只有 16 位（最大 `FFFFH`），所以对同一个物理地址，段地址可以在一定范围内变化：

**物理地址 `20010H` 可以由以下任意一组给出**：

| 段地址 | 偏移地址 | 验算 |
|---|---|---|
| `2000H` | `0010H` | `20000H + 0010H = 20010H` |
| `2001H` | `0000H` | `20010H + 0000H = 20010H` |
| `1FFF0H`? | × | 段地址也是 16 位，最大 `FFFFH` |
| `1FF0H` | `0110H` | `1FF00H + 0110H = 20010H` |
| `1000H` | `10010H`? | × 偏移地址超过 `FFFFH`，非法 |

> **重点**：同一个物理地址，**段地址和偏移地址的组合不唯一**。反过来，给定 `SA` 和 `EA`，物理地址是唯一的。

## 2.7 “段地址×16+偏移地址=物理地址”的本质含义

**这个公式的本质是：CPU 用「基础地址 + 偏移量」的方式定位内存单元。**

- **段地址 × 16** 就是一个**基础地址（基地址）**，它一定是 16 的倍数。
- **偏移地址**是相对于这个基础地址的**偏移量**。

生活类比：**一栋楼的楼层编号**。

- 段地址 = 楼号（比如 3 号楼），乘 16 相当于「把楼的编号放大到以 16 个房间为粒度」；
- 偏移地址 = 楼内的门牌号；
- 物理地址 = 「3 号楼 010 室」这样的绝对位置。

换一种说法：如果全班 100 人排成一队，段地址是「第几排的排头」，偏移地址是「从排头往右数第几个」。排头可以挪（换段地址），但只要你告诉我「排头 + 偏移」，位置就唯一确定了。

**为什么段地址要 ×16，而不是 ×1？**
因为如果直接相加（段地址 + 偏移地址），基础地址就只能以 1 为粒度，很多地址会重复且无法覆盖 1MB。乘 16 后：

- 段地址的范围 `0000H`~`FFFFH`，乘 16 后是 `00000H`~`FFFF0H`，覆盖了 1MB 空间内所有 16 字节对齐的地址；
- 偏移地址 `0000H`~`FFFFH` 补齐了这 16 字节的「缝」，于是整个 1MB 都能被覆盖到。

```
   段地址 FFFFH × 16 = FFFF0H
   + 偏移地址 FFFFH =    FFFFH
   ─────────────────────────────
   最大物理地址     = 10FFEFH  ← 略超 1MB（8086 会回绕到 0FFEFH）
```

> **重点**：`FFFF:FFFF` 算出来是 `10FFEFH`，超出了 20 位。8086 只有 20 根地址线，高位被截掉，实际访问 `0FFEFH`。这叫作**地址回绕（Wrap-around）**，80286 之后的 CPU 上可以通过 A20 门控制，是《操作系统》里「HMA 高端内存区」的由来。

## 2.8 段的概念

**「段」是逻辑上的划分，内存本身并没有被真正切成一段一段。**

这是初学者最大的误解：内存并没有被硬件「分段」，段只是 CPU 在**寻址时**用的一种计算方式。

事实是：

- 我们可以**任意**指定段地址和偏移地址；
- 同一个物理地址可以被不同的段地址 + 偏移地址得到；
- 段的划分完全由编程者决定，**段与段可以重叠**。

**一个段的最大长度是 64KB**：因为偏移地址是 16 位，`2^16 = 65536 = 64KB`。

```
   内存（没有真正的分界线）
   ┌────────────────────────────┐ 00000H
   │  ←「数据段」其实只是 DS 指向这里
   ├────────────────────────────┤ 10000H
   │  ←「代码段」其实只是 CS:IP 指向这里
   ├────────────────────────────┤
   │  ← 段可以重叠！
   ├────────────────────────────┤ 20000H
   │  ←「栈段」其实只是 SS:SP 指向这里
   └────────────────────────────┘ FFFFFH
```

> **重点**：所谓「数据段」「代码段」「栈段」，**只是我们让 DS、CS、SS 分别指向了那块内存而已**。内存本身不知道自己被叫什么。

## 2.9 段寄存器

**8086 有 4 个段寄存器，专门用来存放段地址。**

| 段寄存器 | 全称 | 配套使用的偏移地址寄存器 | 用途 |
|---|---|---|---|
| **CS** | Code Segment | IP | 代码段，`(CS)×16+(IP)` 指向下一条指令 |
| **DS** | Data Segment | BX、SI、DI、直接地址 | 数据段，`[address]` 默认用 DS |
| **SS** | Stack Segment | SP、BP | 栈段，`(SS)×16+(SP)` 是栈顶 |
| **ES** | Extra Segment | DI | 附加段，串操作的目的段 |

**段寄存器是 16 位的**，里面存的是**段地址**，不是物理地址。CPU 访问内存时自动拿它 ×16。

## 2.10 CS和IP

**`(CS)×16 + (IP)` 指向 CPU 将要执行的下一条指令的物理地址——这是整个 8086 运行机制的核心。**

```
        CS（代码段地址）     IP（指令指针/偏移）
        ┌──────────┐        ┌──────────┐
        │  2000H   │        │  0003H   │
        └────┬─────┘        └─────┬────┘
             │  ×16               │
             ▼                    │
          20000H ────────────────►+◄── 0003H
                                  │
                                  ▼
                          20003H = 下一条指令的地址
```

**CPU 的工作循环（每一步都做这件事）**：

```
   ① 从 CS:IP 指向的内存单元读取指令（机器码）
   ② IP = IP + 所读指令的字节数（指向下一条指令）
   ③ 执行刚读入的指令，然后回到 ①
```

> **重点**：**IP 的自动增加发生在「读取指令之后、执行指令之前」**。所以 `jmp`、`call`、`loop` 这类转移指令的本质就是「修改 IP（或 CS:IP）的值」，覆盖掉那个自动增加的 IP。

**Debug 中查看 CS:IP**：

```
-r
AX=0000  BX=0000  CX=0000  DX=0000  SP=FFEE  BP=0000  SI=0000  DI=0000
DS=1B1C  ES=1B1C  SS=1B1C  CS=1B1C  IP=0100   NV UP EI PL NZ NA PO NC
1B1C:0100 B8004C        MOV     AX,4C00
```

最后一行 `1B1C:0100` 就是 `CS:IP`，`B8004C` 是这条指令的机器码（3 字节），所以执行完这条指令后 IP 会变成 `0103H`。

## 2.11 修改CS、IP的指令

**`mov` 指令不能修改 CS 和 IP，只能用 `jmp`（转移指令）来改。**

```asm
mov cs, ax       ; ×  非法！8086 不允许用 mov 修改 CS
mov ip, ax       ; ×  非法！IP 不能作为 mov 的目的操作数
```

**为什么**：CS 和 IP 是 CPU 的「方向盘」，8086 规定只能通过专门的转移指令来改，避免随意修改导致程序跑飞。

**修改方法**：

| 指令 | 效果 | 例子 |
|---|---|---|
| `jmp 段地址:偏移地址` | **同时修改 CS 和 IP** | `jmp 2AE3:3` → `CS=2AE3H, IP=0003H`，CPU 从 `2AE33H` 处取指令 |
| `jmp 16位寄存器` | **只修改 IP**，CS 不变 | `jmp ax` → `IP = AX` 的值 |

```asm
jmp 2AE3:3       ; CS = 2AE3H，IP = 0003H
jmp ax           ; IP = (AX)，CS 不变（段内转移）
```

> **⚠ 重要：上面这两条是 DEBUG 的语法，不是 MASM 源程序语法！**
>
> | 环境 | 写 `jmp 2AE3:3` |
> |---|---|
> | **DEBUG**（`a` 命令下） | ✓ 合法，`CS=2AE3H`、`IP=0003H` |
> | **MASM**（`.asm` 源程序） | ✗ 报错 **`error A2096: segment, group, or segment register expected`** |
>
> **原因**：MASM 要求冒号**左边必须是「段名 / 组名 / 段寄存器」**，不接受裸数字。实测 `jmp 2AE3:3`、`jmp 2AE3h:3`、`jmp 123Bh:0` **全部报 A2096**。
>
> **MASM 里要跨段跳转，有这三种合法写法**：
>
> ```asm
> jmp far ptr 标号      ; ✓ 跳到本程序里的另一个段的标号（MASM 自动填段和偏移）
> jmp dword ptr [bx]    ; ✓ 间接：从内存取 4 字节（低字→IP，高字→CS）
> push 段地址           ; ✓ 借 retf：先压段、再压偏移，retf 会先 pop IP 再 pop CS
> push 偏移地址
> retf
> ```
>
> **王爽教材大量在 DEBUG 下演示，那里 `jmp 2AE3:3` 完全正确**；但作业要写 `.asm` 文件，必须换成上面的写法。**这是「DEBUG 语法 vs MASM 语法」的第二处差异**（第一处是 `[0]`，见第 3 章 3.2 节）。

> **重点**：`jmp 段地址:偏移地址` 用的是**冒号**，冒号左边是段地址、右边是偏移地址。这与第 7 章的 `[bx+si]` 完全无关，不要混。

> **★ 顺带记住十六进制后缀**：MASM 里 **`B` 是二进制后缀**，所以 `mov ax, 123B` 会报 **`error A2048: nondigit in number`**（MASM 把 `123B` 当成二进制数 `123`，而 2、3 不是二进制数字）。**十六进制必须以 `H` 结尾**：`123BH`、`2AE3H`。同理 `D` 是十进制后缀、`Q`/`O` 是八进制后缀。**十六进制数若以 A~F 开头，前面还要补一个 0**（如 `0F000H`），否则会被当成标识符。

## 2.12 代码段

**把一段长度为 N（N ≤ 64KB）、连续、起始地址为 16 的倍数的内存，当作代码段使用——只要让 CS:IP 指向它的第一条指令。**

「当作代码段」不是物理动作，而是**逻辑约定**：我们告诉 CPU「从这里开始取指令执行」。

```asm
; 举例：让 CPU 从 123B0H 开始执行
; 方式一：直接 jmp（★ 注意这是 DEBUG 语法，MASM 会报 A2096）
jmp 123B:0        ; CS=123BH, IP=0000H，物理地址 123B0H
                  ; 且 123B 这种写法在 MASM 里还会报 A2048（B 是二进制后缀），
                  ; 必须写 123Bh

; 方式二：用寄存器绕（不能 mov cs/ip）
mov ax, 123BH
mov cs, ax        ; × 非法！CS 不能用 mov 改
```

正确的做法只能用 `jmp`（或在 MASM 里用下面这种「借 `retf`」的写法）：

```asm
mov ax, 123BH
push ax           ; 把段地址压栈
mov ax, 0
push ax           ; 把偏移地址压栈
retf              ; retf 会 pop IP 再 pop CS → 跳到 123B:0
```

这段「借 `retf` 修改 CS:IP」的写法第 10 章会讲透，现在是让你看到：**只要能让 CS:IP 变成目标值，就把那段内存变成「代码段」了。**

## 典型例题

**例 2.1**（题型：物理地址计算）
已知 `(DS) = 2000H`，`(BX) = 1000H`，求 `DS:[BX]` 指向的物理地址。
**解**：
```
   物理地址 = 段地址 × 16 + 偏移地址
            = 2000H × 16 + 1000H      ; 段地址后面添一个 0
            = 20000H + 1000H
            = 21000H
```
**答案**：`21000H`。

**例 2.2**（题型：由物理地址反推段地址）
物理地址 `21000H` 处的数据，用段地址 `2000H` 访问时偏移地址是多少？如果改用段地址 `2010H` 呢？
**解**：
- `21000H − 2000H × 16 = 21000H − 20000H = 1000H`。
- `21000H − 2010H × 16 = 21000H − 20100H = 0F00H`。
- 为什么两种都可以：段地址和偏移地址的组合不唯一，只要 `段地址 × 16 + 偏移地址` 相等即可。
**答案**：分别是 `1000H` 和 `0F00H`。

**例 2.3**（题型：寄存器拆分与运算）
执行下面的指令后，AX、AH、AL 各是多少？
```asm
mov ax, 4E20H
mov al, 0FFH
add al, 2
```
**解**：
1. `mov ax, 4E20H` → `AX = 4E20H`，即 `AH = 4EH`、`AL = 20H`。
2. `mov al, 0FFH` → 只改低 8 位，`AL = FFH`，`AH` 不变还是 `4EH`，所以 `AX = 4EFFH`。
3. `add al, 2` → `AL = FFH + 2 = 101H`，8 位装不下，**只保留低 8 位** → `AL = 01H`。`AH` 不变，仍是 `4EH`。
**答案**：`AX = 4E01H`，`AH = 4EH`，`AL = 01H`。关键：对 `AL` 的运算**只影响 AL**，不会进位到 `AH`。

**例 2.4**（题型：CS:IP 与指令长度）
在 Debug 中看到：
```
1B1C:0100 B8004C        MOV  AX,4C00
1B1C:0103 CD21          INT  21
```
问：`INT 21` 这条指令的起始物理地址是多少？执行完 `MOV AX,4C00` 后 IP 是多少？
**解**：
1. `CS = 1B1CH`，`IP = 0103H`，所以 `INT 21` 的物理地址 = `1B1CH × 16 + 0103H = 1B1C0H + 0103H = 1B2C3H`。
2. `MOV AX,4C00` 的机器码是 `B8 00 4C`，共 **3 字节**。所以读入后 `IP = 0100H + 3 = 0103H`。
**答案**：`1B2C3H`；执行后 `IP = 0103H`。注意 `B8004C` 只是显示顺序，实际字节是 `B8, 00, 4C`（低字节在前）。

**例 2.5**（题型：段的最大长度）
为什么一个段的最大长度是 64KB？如果偏移地址用 16 位，能不能设计成 32 位？
**解**：
- 偏移地址是 16 位寄存器里放的值，范围 `0000H`~`FFFFH`，共 `2^16 = 65536` 个不同的值，所以最多能寻址 65536 个字节 = 64KB。
- 理论上可以设计成 32 位偏移地址，但 8086 的寄存器只有 16 位，无法直接表示。后续的 IA-32 就把偏移地址扩展到 32 位，一段最大 4GB（第 18 章讲）。
**答案**：因为偏移地址只有 16 位，`2^16 = 65536 = 64KB`。

**例 2.6**（题型：地址回绕）
计算 `FFFFH:FFFFH` 对应的物理地址，并说明实际会访问哪里。
**解**：
```
   段地址 × 16 = FFFFH × 16 = FFFF0H
   + 偏移地址  =             FFFFH
   ───────────────────────────────
   结果        = 10FFEFH
```
`10FFEFH` 需要 21 位二进制。8086 只有 20 根地址总线，第 21 位（最高位）被自然丢弃，实际访问 `0FFEFH`。
**答案**：算出来是 `10FFEFH`，实际访问 `0FFEFH`（地址回绕）。

**例 2.7**（题型：寻址范围）
段地址为 `1000H`，偏移地址的取值范围是什么？这个段覆盖的物理地址范围是多少？
**解**：
- 偏移地址是 16 位，范围 `0000H` ~ `FFFFH`。
- 物理地址范围：最小 `10000H + 0000H = 10000H`；最大 `10000H + FFFFH = 1FFFFH`。
- 段长 = `1FFFFH − 10000H + 1 = 10000H` = 65536 字节 = **64KB**。
**答案**：偏移地址 `0000H`~`FFFFH`；物理地址 `10000H`~`1FFFFH`，共 64KB。

## 易错点提醒

1. **错**：写 `mov cs, ax` 或 `mov ip, 1000h`。**对**：CS 和 IP **不能用 mov 修改**，只能用 `jmp 段地址:偏移地址` 或 `jmp 寄存器`。用 `retf` 或中断返回也能间接修改。
2. **错**：记成「低字节放高位」。**对**：**高字节放高位、低字节放低位**。`mov ax, 4E20H` 后 `AH=4EH`、`AL=20H`。
3. **错**：认为对 `AL` 做加法会进位到 `AH`。**对**：`AL` 和 `AH` 是**独立的 8 位寄存器**，对 `AL` 的运算只影响 `AL` 的低 8 位，进位被丢弃（记入 CF）。
4. **错**：认为内存被真的分成了「数据段」「代码段」「栈段」三块。**对**：段是**逻辑划分**，内存本身没有任何标记；段与段可以重叠，同一个物理地址可以由不同组合表示。
5. **错**：把段地址当成物理地址。**对**：段寄存器里存的是 16 位的**段地址**，必须 `×16` 才是基础地址。
6. **错**：认为 `1MB` 内存里段地址最大能到 `FFFFH`，所以最大物理地址就是 `FFFF0H`。**对**：加上偏移地址后最大可以算到 `10FFEFH`（有回绕）。`FFFF0H` 只是「偏移为 0」时的值。
7. **错**：认为 `jmp ax` 会同时改 CS。**对**：`jmp 16位寄存器` **只改 IP**，是段内转移；要改 CS:IP 必须用 `jmp 段地址:偏移地址`。
8. **错**：把 `mov ax, 4E20H` 的机器码写成 `B8 4E 20`（高字节在前）。**对**：8086 是小端机，机器码中**低字节在前**，实际是 `B8 20 4E`。

## 本章小结

- 8086 有 **14 个 16 位寄存器**：通用 4（AX/BX/CX/DX）、指针变址 4（SP/BP/SI/DI）、段 4（CS/DS/SS/ES）、IP、FLAGS。
- AX/BX/CX/DX 每个可拆成 H/L 两个 **独立** 的 8 位寄存器；字存入时**高字节在高位**。
- 8 位运算结果对 256 取模，进位被 CPU 记入 CF（第 11 章）。
- 8086 内部只有 16 位，却要寻址 20 位 = 1MB，于是用 **`物理地址 = 段地址 × 16 + 偏移地址`** 合成。
- 「×16」= 左移 4 位 = 十六进制末尾补一个 0。
- 同一个物理地址可以有**多种**段地址:偏移地址组合；段的划分是**逻辑的**，一段最大 **64KB**。
- **`(CS)×16 + (IP)`** 指向下一条要执行的指令；CPU 每读一条指令就自动把 IP 加上指令长度。
- 修改 CS/IP 只能用 **`jmp`**，`mov` 不行。
- 让 CS:IP 指向一段内存，那段内存就成了「代码段」。

> **一句话记住本章**：**CPU 手里只有 16 位的段寄存器和 IP，靠「段地址 × 16 + 偏移地址」合成 20 位物理地址——这就是 8086 寻址的全部秘密。**

## 自测题

**1.** 写出 8086 全部 14 个 16 位寄存器的名字，并按功能分组。
**答**：通用 AX、BX、CX、DX；指针与变址 SP、BP、SI、DI；段 CS、DS、SS、ES；控制 IP、FLAGS（PSW）。

**2.** `mov ax, 1234H` 之后，AH 和 AL 分别是多少？
**答**：`AH = 12H`，`AL = 34H`。

**3.** 计算 `(DS)=3000H`、`(SI)=0A00H` 时的物理地址。
**答**：`3000H × 16 + 0A00H = 30000H + 0A00H = 30A00H`。

**4.** 一个段最多能有多长？为什么？
**答**：64KB。因为偏移地址是 16 位，`2^16 = 65536 = 64KB`。

**5.** 判断：`jmp ax` 会把 CS 也改成 AX 的值。
**答**：错。`jmp 16位寄存器` 只修改 IP（段内转移），CS 不变。

**6.** 为什么 8086 不能直接用一个 20 位的数表示物理地址？
**答**：因为 8086 内部结构和寄存器都是 16 位的，一次只能处理 16 位数据，无法在指令或寄存器里直接表示 20 位数。

**7.** 物理地址 `1F000H`，如果段地址是 `1E00H`，偏移地址是多少？如果段地址是 `1000H` 呢？
**答**：`1F000H − 1E000H = 1000H`；`1F000H − 10000H = F000H`。

**8.** CPU 执行完一条 3 字节的指令后，IP 一定增加 3 吗？为什么？
**答**：不一定。对于**顺序执行**的指令，IP 增加 3（读指令时自动完成）；但如果指令是 `jmp`、`call`、`loop`、`ret` 等**转移指令**，执行时会重新给 IP 赋值，覆盖掉那个自动增加的值。

**9.** 8086 中 `FFFFH:FFFFH` 算出的物理地址是多少？实际访问哪里？
**答**：`FFFF0H + FFFFH = 10FFEFH`；20 位地址总线截掉最高位，实际访问 `0FFEFH`。

**10.** 下面三条指令哪几条合法？不合法的说明原因。
```
① mov ax, bx
② mov cs, ax
③ mov al, 1000
```
**答**：① 合法。② 非法，CS 不能用 `mov` 修改。③ 非法（也无法正确汇编），`1000` 超过 8 位（最大 255），`AL` 装不下。
