## 1.1 机器语言

**机器语言（Machine Language）是 CPU 唯一能直接识别和执行的语言，它就是一串二进制数。**

CPU 是硬件，它内部只有通断两种状态。给它 `10110000 00000011`，它知道这是「把 3 送进 AL 寄存器」；换成任何别的符号（哪怕是 `mov al,3`），它都不认识。

机器语言的特征：

| 特征 | 说明 |
|---|---|
| 形式 | 纯二进制，如 `10110000 00000011`（即 `B0 03`） |
| 优点 | CPU 可直接执行，速度最快，不需要翻译 |
| 缺点 | 人几乎无法阅读、记忆、纠错；不同 CPU 的机器语言互不通用 |
| 长度 | 一条指令 1~6 字节不等（8086） |

> **重点**：机器语言是唯一「不需要翻译」的语言。所有其它语言最终都必须变成机器语言。

## 1.2 汇编语言的产生

**汇编语言（Assembly Language）用助记符代替二进制机器码，与机器语言一一对应。**

程序员写 `mov al, 3`，汇编器（Assembler）把它翻译成 `B0 03`。好处是人能读了，代价是必须多一道「汇编」工序。

```
   程序员写        汇编器翻译          CPU 执行
  mov al, 3   ──────────────→   B0 03   ──────────→   AL = 3
  (汇编指令)      (MASM.EXE)     (机器码)
```

汇编语言与机器语言的对应关系是**一对一**的：一条汇编指令对应一条机器指令。这一点与高级语言根本不同——C 语言的一行 `for` 循环可能变成几十条机器指令。

| 对比项 | 机器语言 | 汇编语言 | 高级语言（C） |
|---|---|---|---|
| 形式 | `B0 03` | `mov al,3` | `a = 3;` |
| 与机器指令的关系 | 就是机器指令 | **一对一** | 一对多 |
| 可移植性 | 无（绑死 CPU） | 差（绑死 CPU 家族） | 好（编译器负责） |
| 执行效率 | 最高 | 高 | 取决于编译器优化 |
| 开发效率 | 极低 | 低 | 高 |

## 1.3 汇编语言的组成

**汇编语言由三类内容组成，只有第一类会被翻译成机器码。**

| 类别 | 作用 | 会被翻译成机器码吗 | 例子 |
|---|---|---|---|
| **汇编指令** | 有对应机器码的指令，CPU 真正执行的东西 | ✅ 会 | `mov ax, 4c00h`、`add bx, 1`、`loop s` |
| **伪指令** | 给汇编器看的「说明」，没有机器码 | ❌ 不会 | `assume`、`segment`、`ends`、`end`、`db`、`dw` |
| **其它符号** | 由汇编器识别的符号 | ❌ 不会 | `+`、`−`、`*`、`/`、标号、`offset` |

> **重点**：一条汇编指令对应一条机器指令；**伪指令不产生任何机器码**，它只是告诉汇编器「该怎么组织这段程序」。这是初学者最容易混的点——`assume cs:code` 写完，内存里一个字节都没多。

**先睹为快：一个能真正运行的最小汇编程序。**

下面这个程序现在不用看懂，把它抄进 `t1.asm`、用 MASM 汇编连接后运行，它会立刻返回 DOS 提示符——什么也不显示，但**它确实是一个完整、合法的程序**。第 4 章会逐行讲清每一句。

```asm
assume cs:code          ; 伪指令：告诉汇编器 code 段要用 CS 来定位（不产生机器码）

code segment            ; 伪指令：定义一个名为 code 的段（不产生机器码）
    mov ax, 4c00h       ; 汇编指令：把 4C00H 送进 AX
                        ;   4C 是 DOS 的「带返回码结束程序」功能号，00 是返回码
    int 21h             ; 汇编指令：调用 DOS 的 21H 号中断（真正执行上面那个功能）
code ends               ; 伪指令：code 段结束

end                     ; 伪指令：整个源程序结束
```

**这段程序里，只有两条是「真指令」：**

| 汇编指令 | 对应的机器码 | 字节数 | 说明 |
|---|---|---|---|
| `mov ax, 4c00h` | `B8 00 4C` | 3 | `B8` 是 `mov ax, 立即数` 的操作码，后面跟 2 字节立即数（**低字节在前**：`00 4C`） |
| `int 21h` | `CD 21` | 2 | `CD` 是 `int n` 的操作码，后面跟 1 字节中断类型码 |

**所以这个程序在内存里只占 5 个字节**：`B8 00 4C CD 21`。其余的 `assume`、`code segment`、`code ends`、`end` 一个字都没有留下——这就是「伪指令不产生机器码」最直观的证据。

> **注意**：用 `Ml.exe /Fl` 生成的列表文件里，这一行显示成 `B8 4C00`——那是**把 2 字节立即数当一个「字」显示**（便于阅读），而内存里真正的字节顺序仍然是**低字节在前**的 `00 4C`。列表文件末尾的 `code ... 16 Bit 0005` 就是在告诉你：这个段**长度 5 字节**。

> **重点**：源程序（`.asm`）是给人看的，可执行程序（`.exe`）里的机器码才是给 CPU 看的。**从源程序到机器码，中间隔着「汇编（masm）」和「连接（link）」两步**，第 4 章会走一遍完整流程。

## 1.4 存储器

**存储器（Memory，这里特指内存/主存）存放 CPU 执行时用到的指令和数据。**

CPU 需要数据时，从内存取；算出结果后，再放回内存。CPU 本身只能存极少量数据（寄存器），所以程序和数据平时都躺在内存里。

生活类比：内存像一张巨大的**带门牌号的储物柜**，CPU 像一个只拿着一张小纸条（寄存器）的人。要拿东西，必须先知道门牌号。

## 1.5 指令和数据

**指令和数据在内存里都是二进制，形式上没有任何区别，区别只在于 CPU「怎么用它」。**

内存 `20000H` 处有一串字节 `B0 03`：

- 如果 CPU 把 `CS:IP` 指向它，就把它当**指令**：执行「把 3 送进 AL」（`B0` 是 `mov al, idata` 的操作码，`03` 是立即数）。
- 如果一条 `mov` 指令指向它，就把它当**数据**：
  - 按**字节**读：`mov al, [20000H]` → `AL = B0H`（读到的是 `20000H` 这一个字节）；
  - 按**字**读：`mov ax, [20000H]` → `AX = 03B0H`（低地址 `20000H` 存低字节 `B0H`、高地址 `20001H` 存高字节 `03H`——**小端序**，第 3 章详细讲）。

> **★ 注意**：**同一串字节 `B0 03`，当指令是「把 3 送进 AL」，当数据按字读却是 `03B0H`——两个结果完全不同。** 这正好说明「指令和数据没有形式区别，只在于 CPU 怎么用它」。**千万不要把「`B0 03` 这条指令的语义」和「`B0 03` 这两个字节当数据时的值」混为一谈。**

> **重点**：**CPU 靠「来源」区分指令和数据**——从 `CS:IP` 指向的地址取出来的是指令，从别处取出来的是数据。这就是第 2 章要讲的 CS:IP 的意义。

## 1.6 存储单元

**存储器被划分成若干个存储单元，每个存储单元占 1 字节（Byte）= 8 位（bit），从 0 开始编号。**

| 单位 | 换算 |
|---|---|
| 1 Byte（字节） | 8 bit |
| 1 Word（字，8086 中） | 2 Byte = 16 bit |
| 1 KB | 1024 B = 2^10 B |
| 1 MB | 1024 KB = 2^20 B = 1048576 B |
| 1 GB | 1024 MB = 2^30 B |

**门牌号 = 地址（Address）**，从 `0` 开始，逐个递增。一个地址对应一个字节，所以「地址」也叫「字节地址」。

## 1.7 CPU 对存储器的读写

**CPU 要从内存读写数据，必须提供三个信息：地址（找哪个单元）、数据（传什么）、控制（是读还是写）。**

这三类信息分别通过三组总线（Bus）传输：

```
        ┌───────────────────────────┐
        │            CPU            │
        └──┬─────────┬──────────┬───┘
    地址总线│   数据总线│   控制总线│
           │         │          │
        ┌──▼─────────▼──────────▼───┐
        │          存储器            │
        └───────────────────────────┘
```

**读操作例子**：CPU 想读内存 `20000H` 单元的 1 个字节：

1. CPU 通过**地址总线**把 `20000H` 送出去；
2. CPU 通过**控制总线**发出「读」信号；
3. 存储器把 `20000H` 单元里的 1 个字节通过**数据总线**送回 CPU。

**写操作例子**：CPU 想把 `1800H` 写入内存 `20001H` 单元（2 个字节）：

1. 地址总线上送 `20001H`；
2. 控制总线上发「写」信号；
3. 数据总线上送 `1800H`。

| 总线 | 传输什么 | 方向 | 决定什么 |
|---|---|---|---|
| 地址总线（Address Bus） | 地址 | 单向（CPU 发出） | **能寻址多大空间** |
| 数据总线（Data Bus） | 数据 / 指令 | 双向 | **一次能传多少位** |
| 控制总线（Control Bus） | 读/写等控制信号 | 双向 | **怎么操作** |

## 1.8 地址总线

**地址总线的宽度决定了 CPU 的寻址能力。地址总线有 N 根，最多能寻址 2^N 个存储单元。**

| 地址总线宽度 | 寻址能力 |
|---|---|
| 10 根 | 2^10 = 1 KB |
| 16 根 | 2^16 = 64 KB |
| 20 根（**8086**） | 2^20 = **1 MB = 1048576 B** |
| 24 根 | 2^24 = 16 MB |
| 32 根 | 2^32 = 4 GB |

> **重点**：8086 有 **20 根地址总线**，所以最大寻址 **1MB**。但 8086 内部的寄存器只有 16 位，最多表示 64KB——这个矛盾正是「段地址 × 16 + 偏移地址」这个设计的由来（见第 2 章）。

**为什么是 2^N**：每根地址线只有 0/1 两种状态，N 根线组合出 2^N 种不同编码，每种编码对应一个存储单元。

## 1.9 数据总线

**数据总线的宽度决定了 CPU 一次能传输的数据量，也决定了一次能处理的位数。**

| 数据总线宽度 | 一次传输 | 举例 |
|---|---|---|
| 8 根 | 1 字节 | 8088 读 2 字节要读 2 次 |
| 16 根（**8086**） | **2 字节** | 8086 读 2 字节只需 1 次 |

> **重点**：8086 是**16 位数据总线**，所以「一个字 = 16 位 = 2 字节」；8088 是 8 位数据总线，是 8086 的简化版。

数据总线是**双向**的：既能把内存/端口的数据读进 CPU，也能把 CPU 的数据写到内存/端口。

## 1.10 控制总线

**控制总线是「怎么操作」的信号线，宽度决定 CPU 对外部器件的控制能力。**

控制总线传输的是单个控制信号，例如：

| 信号 | 含义 |
|---|---|
| 读信号 | 从内存 / 端口读数据 |
| 写信号 | 向内存 / 端口写数据 |
| 中断信号 | 外部设备请求 CPU 处理 |

控制总线是**双向**的：CPU 能发出控制信号（读/写），也能接收外部信号（中断请求）。

## 1.11 内存地址空间（概述）

**CPU 把连接在总线上的各种存储器、接口卡上的存储器，统统看成一个逻辑上的大数组，这个数组就是内存地址空间。**

从 CPU 的视角看，它不关心数据到底在内存条上还是在显卡上——只要能通过地址总线找到就行。所以「内存地址空间」是**逻辑概念**，不等于物理的内存条。

## 1.12 主板

**主板（Motherboard）上有 CPU 插槽、内存插槽、总线扩展插槽和芯片组，这些器件用总线连起来。**

```
        ┌──────────────────────────────────────────────┐
        │                  主  板                       │
        │  ┌────────┐   ┌──────────┐   ┌────────────┐  │
        │  │  CPU   │───│  芯片组   │───│ 内存插槽    │  │
        │  └────────┘   └────┬─────┘   └────────────┘  │
        │                    │                          │
        │              ┌─────▼──────┐                   │
        │              │ 扩展插槽    │ ← 插显卡/网卡      │
        │              └────────────┘                   │
        └──────────────────────────────────────────────┘
```

## 1.13 接口卡

**接口卡（Interface Card）插在扩展插槽上，负责 CPU 与外部设备之间的数据转换，卡上也有存储器。**

CPU 不能直接控制显示器、硬盘、键盘。它通过接口卡这个「翻译中转站」说话。

| 接口卡 | 连接的外设 | 卡上的存储器 |
|---|---|---|
| 显卡 | 显示器 | 显存（VRAM），典型 `B8000H` 起的就是文本显存 |
| 网卡 | 网络 | 收发缓冲区 |
| 声卡 | 音箱/麦克风 | 采样缓冲区 |

> **重点**：显卡上的显存被映射到内存地址空间里（如彩色文本模式下的 `B8000H`）。所以我们用 `mov` 往某个内存地址写字符，屏幕上真的会出现字符——这就是第 4 章之后显示输出经常会用的技巧。

## 1.14 各类存储器芯片

| 类型 | 断电后 | 典型用途 | CPU 能写吗 |
|---|---|---|---|
| **随机存储器 RAM** | 数据丢失 | 主存（内存条）、显存 | ✅ 能读能写 |
| **只读存储器 ROM** | 数据保留 | 主板上的 BIOS（基本输入输出系统） | ❌ 只能读 |
| **CMOS RAM** | 靠电池保留 | 保存系统时间、日期、硬件配置 | ✅ 能读能写（通过端口，见第14章） |

在 PC 机中：

- **内存条**：主存，存放运行中的程序和数据。
- **BIOS ROM**：主板上，存放开机自检和 I/O 中断例程（第13章讲）。
- **接口卡上的 RAM**：如显存。

## 1.15 内存地址空间

**PC 机中各类存储器在物理上是独立的器件，但在 CPU 看来，它们共用同一个逻辑地址空间。**

8086 的内存地址空间总大小 **1MB**（`00000H` ~ `FFFFFH`），典型分配：

```
   地址范围              大小      用途
 FFFFFH ┌──────────────┐
        │              │
        │  系统 BIOS    │  64 KB    主板 ROM，含 BIOS 中断例程
 F0000H ├──────────────┤
        │              │
        │  其它接口卡   │           网卡、声卡等的 ROM/RAM
 C0000H ├──────────────┤
        │              │
        │  显存 VRAM    │  128 KB   显卡上的存储器
 A0000H ├──────────────┤
        │              │
        │   ……         │
        │              │
 00000H └──────────────┘
```

> **重点**：**8086 的内存地址空间是 1MB（`00000H`~`FFFFFH`）**。其中 `A0000H` 以下是主存（内存条），往上是显存和 ROM。所以真正留给用户程序的内存是从 `00000H` 到 `9FFFFH`。

## 典型例题

**例 1.1**（题型：寻址空间计算）
某 CPU 的地址总线有 24 根，数据总线有 32 根。求它的最大寻址空间是多少字节？一次最多能传输几个字节？
**解**：
- 寻址空间由**地址总线**决定：24 根 → `2^24 = 16777216` 字节 = 16 MB。
- 一次传输量由**数据总线**决定：32 根 → 32 bit = 4 字节。
- 为什么这样做：地址总线每一根提供 1 位地址编码，N 根就有 2^N 个编码；数据总线每一根传 1 位数据，N 根一次传 N 位。
**答案**：16 MB；4 字节。

**例 1.2**（题型：总线要素分析）
CPU 要从内存 `20000H` 单元读出 2 个字节，请说明三种总线各自传了什么。
**解**：
1. **地址总线**传 `20000H`（20 位，需要全部 20 根地址线）。
2. **控制总线**发「读」信号。
3. **数据总线**把 `20000H` 和 `20001H` 两个单元的 16 位数据送回 CPU。为什么是两个单元：1 个地址对应 1 字节，2 字节就需要连续的两个地址。
**答案**：地址总线送 `20000H`，控制总线发读信号，数据总线返回 16 位数据。

**例 1.3**（题型：概念辨析）
判断正误：「在内存中，`B0 03` 这段二进制既可能是指令也可能是数据。」
**解**：正确。CPU 唯一区分指令和数据的依据是**来源**：如果这串字节在 `CS:IP` 指向的位置，就是指令；如果被 `mov` 之类的指令当作操作数读取，就是数据。同一个字节 `03` 两个身份都能扮演。
**答案**：正确。

**例 1.4**（题型：汇编语言组成）
下面 6 行中，哪些是汇编指令？哪些是伪指令？哪些不产生机器码？
```
① mov ax, 4c00h
② assume cs:code
③ code segment
④ add bx, 1
⑤ end start
⑥ loop s
```
**解**：判断标准是「有没有对应的机器码」。
- 汇编指令（有机器码）：① `mov`、④ `add`、⑥ `loop`。
- 伪指令（无机器码）：② `assume`、③ `segment`、⑤ `end`。
- 这三条伪指令只在汇编阶段起作用，既不对应机器码，也不占用运行时内存。
**答案**：汇编指令 ①④⑥；伪指令 ②③⑤；伪指令不产生机器码。

**例 1.5**（题型：存储单元换算）
8086 的内存地址空间里，地址从 `00000H` 到 `9FFFFH` 的部分是主存。这段主存有多大？
**解**：
- 地址个数 = 末地址 − 首地址 + 1 = `9FFFFH − 00000H + 1 = A0000H`。
- `A0000H = 10 × 16^4 = 10 × 65536 = 655360` 字节。
- 也等于 `640 KB`（因为 `640 × 1024 = 655360`）。
**答案**：`A0000H` = 655360 字节 = 640 KB。

**例 1.6**（题型：综合应用）
计算机中为什么需要「总线」这种结构，而不是让 CPU 直接给每个器件连一堆线？
**解**：如果 CPU 和每个器件都单独连线，n 个器件需要 O(n) 组线，且 CPU 引脚数量有限（8086 只有 40 个引脚），根本连不下。总线让所有器件**共享同一组线**，通过地址来区分「这次跟谁说话」，把连线复杂度从 O(n) 降到 O(1)。代价是同一时刻总线上只能有一个传输，需要仲裁——这是《计算机组成原理》的内容。
**答案**：为了用有限的引脚连接大量器件，靠「地址」来选通目标，共享一组线。

## 易错点提醒

1. **错**：把「存储器」理解成只有内存条。**对**：本课程中「存储器」泛指 CPU 能通过总线访问的所有存储器件，包括内存条、显存、BIOS ROM、CMOS RAM。
2. **错**：认为伪指令也会被执行。**对**：`assume`、`segment`、`end` 这些伪指令只在汇编阶段起作用，**不产生任何机器码**，CPU 根本看不到它们。
3. **错**：把「数据总线宽度」当成寻址能力。**对**：寻址能力看**地址总线**（N 根 → 2^N 字节）；传输速度看**数据总线**（N 根 → N 位/次）。
4. **错**：认为 8086 最大内存是 64KB（因为寄存器是 16 位）。**对**：8086 有 **20 根地址总线，最大 1MB**。64KB 只是「一个段」的最大长度。这正是第 2 章「段地址×16+偏移地址」要解决的问题。
5. **错**：说「内存里第 5 个字节存的是指令」。**对**：内存里只有二进制，是**指令还是数据取决于 CPU 从哪里取、怎么用**。只有 `CS:IP` 指向的才是指令。
6. **错**：把 1MB 算成 1000000 字节。**对**：`1MB = 2^20 B = 1048576 B`；换算用 1024 而不是 1000。
7. **错**：认为 ROM 里的内容可以被程序随便改写。**对**：ROM 只能读，不能写（CMOS RAM 例外，但它要通过端口 70h/71h 访问，且**单元地址不是内存地址**）。

## 本章小结

- 机器语言是 CPU 唯一能直接执行的语言；汇编语言是它的助记符版本，**一一对应**。
- 汇编语言由**汇编指令**（有机器码）、**伪指令**（无机器码）、**其它符号**三部分组成。
- 存储器按字节划分单元，每个单元有唯一地址；指令和数据在内存中都是二进制，靠来源区分。
- CPU 读写内存需要三个信息，分别走**地址总线、数据总线、控制总线**。
- **地址总线宽度决定寻址空间**：8086 有 20 根 → 1MB = 2^20 B = 1048576 B。
- **数据总线宽度决定一次传输量**：8086 是 16 位 → 一次 2 字节，所以「字 = 16 位」。
- PC 机中内存、显存、BIOS ROM 在 CPU 看来是**同一个逻辑地址空间**。
- 8086 的 1MB 地址空间中，`00000H`~`9FFFFH` 是主存（640KB），`A0000H` 往上是显存和 ROM。

> **一句话记住本章**：**CPU 眼里只有 1MB 的地址空间和三种总线；指令和数据长得一样，区别只在 CPU 从哪儿取。**

## 自测题

**1.** 8086 的地址总线是多少位？最大寻址空间是多少字节？
**答**：20 位；`2^20 = 1048576` 字节 = 1MB。

**2.** 汇编语言的三类组成是什么？哪一类不产生机器码？
**答**：汇编指令、伪指令、其它符号。伪指令和其它符号不产生机器码。

**3.** 判断：`assume cs:code` 这条语句会在程序运行时把 code 段的段地址装入 CS。
**答**：错。`assume` 是伪指令，只在汇编阶段告诉汇编器「code 段和 cs 关联」，运行时不产生任何机器码，也不会改 CS。

**4.** 一个字等于多少字节？8086 为什么是这个数？
**答**：2 字节 = 16 位。因为 8086 的数据总线是 16 位，一次能并行传输 16 位。

**5.** 某内存单元地址为 `FFFFFH`，这是 8086 内存地址空间的最后一个单元吗？
**答**：是。8086 地址空间是 `00000H`~`FFFFFH`，共 `100000H` = 1048576 个单元，正好 1MB。

**6.** CPU 从内存读数据时，三种总线各自的作用是什么？
**答**：地址总线送目标地址；控制总线发读信号；数据总线把数据送回 CPU。

**7.** 显存被映射在内存地址空间里有什么实际意义？
**答**：程序可以像写普通内存一样用 `mov` 向显存地址写数据，显卡会自动把它显示到屏幕上。这是汇编课里输出彩色字符的常用手段（如 `B8000H` 处的彩色文本显存）。

**8.** 判断：存储器里的数据 `03`，如果 CPU 把它当指令执行，它一定是「加 3」的意思。
**答**：错。`03` 只是 1 字节的二进制值，作为操作数时它是数字 3；作为指令的一部分时它的含义取决于它处在指令的哪个位置（8086 中 `03` 出现在指令首字节位置时是 `ADD r16, r/m16` 的操作码）。**离开上下文，单个字节没有含义。**

**9.** 地址总线 32 根的 CPU，最大寻址空间是多少？
**答**：`2^32 = 4294967296` 字节 = 4 GB。

**10.** 为什么说「内存地址空间」是逻辑概念？
**答**：因为同一个逻辑地址空间里映射了物理上完全不同的器件（内存条、显存、BIOS ROM）。CPU 不区分它们，只按地址访问；具体由芯片组把地址译码、选通对应器件。
