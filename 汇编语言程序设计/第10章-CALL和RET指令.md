## 10.1 ret和retf

**`ret` 和 `retf` 都是「用栈中的数据修改 IP（或 CS 和 IP），从而实现转移」的指令。**

### ret：段内近转移

**执行过程（相当于 `pop IP`）：**

```
   ① IP ← SS:[SP]        ; 从栈顶取一个字作为新的 IP
   ② SP ← SP + 2         ; 栈顶指针上移（栈收缩）
```

**机器码：`C3`（1 字节）。**

### retf：段间远转移

**执行过程（相当于 `pop IP` + `pop CS`）：**

```
   ① IP ← SS:[SP]        ; 先弹 IP
   ② SP ← SP + 2
   ③ CS ← SS:[SP]        ; 再弹 CS
   ④ SP ← SP + 2
```

**机器码：`CB`（1 字节）。**

**对照表（必背）：**

| 指令 | 完整名称 | 弹栈顺序 | 修改的寄存器 | 机器码 | 转移类型 |
|---|---|---|---|---|---|
| `ret` | return near | 只弹 **IP** | **IP** | `C3` | 段内近转移 |
| `retf` | return far | 先弹 **IP**，再弹 **CS** | **CS 和 IP** | `CB` | 段间远转移 |

> **重点**：**「ret 弹一个、retf 弹两个；retf 先弹 IP 再弹 CS」**——`ret` 多一个字母 `f`（far），就多弹一个 CS。**这个「先 IP 后 CS」的顺序和 `call far ptr` 压栈的顺序（先压 CS、后压 IP）正好相反，所以一对 `call`/`ret` 才能正确配合。**

**栈的变化示意（设初始 SP = 0100H）：**

```
   ret 的执行：                       retf 的执行：
   
   栈（SS 段）                        栈（SS 段）
   ┌──────────┐ 高地址                ┌──────────┐ 高地址
   │          │                       │          │
   ├──────────┤ ← SP=00FEH            ├──────────┤
   │  新的 IP  │                       │  新的 CS  │ ← SP+2
   ├──────────┤ ← SP=0100H（原）       ├──────────┤
   │          │                       │  新的 IP  │ ← SP=00FEH
   └──────────┘ 低地址                 └──────────┘ 低地址
                                       ↑ SP=0100H（原）
   执行后：SP = 0100H
            IP = 栈顶的字               执行后：SP = 0102H
                                        IP = 第一个字，CS = 第二个字
```

> **注意**：`pop IP`、`pop CS` 并不是合法的 8086 指令（CS 不能作 `pop` 的目的），这里只是用它们**描述 `ret`/`retf` 的执行效果**，方便理解。

## 10.2 call指令

**`call` 是调用子程序的指令，它做两件事：**

```
   ① 将当前 IP（或 CS 和 IP）压入栈   ← 「记住回来的路」
   ② 转移到目标地址                    ← 「跳过去执行」
```

**`call` 的 5 种形式（本章核心，务必默写）：**

| 形式 | 压栈内容 | 转移方式 | 机器码 |
|---|---|---|---|
| `call 标号` | **IP** | 段内近转移（依据 16 位位移） | `E8` + 16 位位移 |
| `call far ptr 标号` | **CS，再 IP** | 段间远转移（指令中给绝对地址） | `9A` + 偏移 + 段 |
| `call 16位reg` | **IP** | 段内转移（IP = 寄存器值） | `FF /2` |
| `call word ptr 内存` | **IP** | 段内转移（IP = 内存中的字） | `FF /2` |
| `call dword ptr 内存` | **CS，再 IP** | 段间转移（IP/CS = 内存中的双字） | `FF /3` |

**配套使用的返回指令：**

| call 形式 | 应该用哪个返回 |
|---|---|
| `call 标号`、`call 16位reg`、`call word ptr 内存` | **`ret`**（段内，弹 1 个字） |
| `call far ptr 标号`、`call dword ptr 内存` | **`retf`**（段间，弹 2 个字） |

**压栈顺序的细节（必考）：**

**`call far ptr` 和 `call dword ptr` 都是「先压 CS、后压 IP」**，所以执行完 call 后：

```
   栈顶（SP）      →  返回处的偏移（IP）   ← 最后压入的
   SP + 2          →  返回处的段（CS）     ← 先压入的
```

**而 `retf` 正好「先弹 IP、后弹 CS」——顺序严丝合缝。**

> **重点**：**记忆口诀：「call 压栈反着来（先 CS 后 IP），ret 弹栈顺着走（先 IP 后 CS）。」** 因为栈是后进先出的，要让 IP 先出，就必须让 IP 后进。

## 10.3 依据位移进行转移的call指令

**格式：`call 标号`，等价于：**

```
   push IP          ; 把 call 指令后第一个字节的偏移压栈
   jmp near ptr 标号 ; 段内近转移
```

**位移的计算公式和 `jmp near ptr` 完全一样：**

```
   位移 = 标号处的偏移地址 − call 指令后第一个字节的偏移地址
```

**示例：**

```asm
assume cs:code
code segment
start:  mov ax, 0           ; B8 00 00        偏移 0，长 3
        call s              ; E8 07 00        偏移 3，长 3
        mov bx, ax          ; 89 C3           偏移 6，长 2
        mov ax, 4c00h       ; B8 00 4C        偏移 8，长 3
        int 21h             ; CD 21           偏移 11，长 2
    s:  add ax, ax          ; 03 C0           偏移 13 = 000DH
        ret                 ; C3
code ends
end start
```

**位移计算：**

```
   位移 = 标号 s 的偏移 − call 指令后第一个字节的偏移
        = 13 − 6
        = 7 = 0007H
```

**机器码应是 `E8 07 00`。**

**验证各指令长度：**

| 指令 | 起始偏移 | 长度 | 累计 |
|---|---|---|---|
| `mov ax, 0` | 0 | 3 | 3 |
| `call s` | 3 | **3** | 6 |
| `mov bx, ax` | 6 | 2 | 8 |
| `mov ax, 4c00h` | 8 | 3 | 11 |
| `int 21h` | 11 | 2 | 13 |
| `s: add ax, ax` | **13** | 2 | 15 |
| `ret` | 15 | 1 | 16 |

> **重点**：`call 标号` 是 **3 字节**（`E8` + 16 位位移），比 `jmp near ptr` 长不了，但**多了一次压栈**。压进去的返回地址是**「call 指令后第一个字节」的偏移**——也就是 `call` 指令起始偏移 + 3。

**栈的变化（设 SP 初始为 0100H）：**

```
   执行 call s 之前：              执行 call s 之后：
   ┌──────────┐                   ┌──────────┐
   │          │                   │          │
   ├──────────┤ ← SP=0100H        ├──────────┤ ← SP=00FEH
   │          │                   │  0006H   │ ← 返回地址（IP）
   └──────────┘                   └──────────┘
                                  （SP 减少 2，压入返回地址）
```

## 10.4 转移的目的地址在指令中的call指令

**格式：`call far ptr 标号`，实现段间转移，等价于：**

```
   push CS
   push IP
   jmp far ptr 标号
```

**机器码 5 字节：`9A` + 2 字节偏移 + 2 字节段。**

**示例：**

```asm
assume cs:code
code segment
start:  mov ax, 0                   ; 偏移 0，长 3
        call far ptr s              ; 9A 00 01 00 10   偏移 3，长 5
        mov bx, ax                  ; 偏移 8，长 2
        mov ax, 4c00h               ; 偏移 10，长 3
        int 21h                     ; 偏移 13，长 2
    s:  add ax, ax
        retf
code ends
end start
```

**机器码分解：**

```
   9A    00 01    00 10
   ↑     └──┬──┘  └──┬──┘
 操作码  目的 IP   目的 CS
        0100H      1000H
```

| 字节 | 内容 | 含义 |
|---|---|---|
| 1 | `9A` | 远调用操作码 |
| 2~3 | `00 01` | **新的 IP = 0100H**（小端序） |
| 4~5 | `00 10` | **新的 CS = 1000H**（小端序） |

**注意：返回地址是 0008H（call 指令后第一个字节的偏移），不是 0003H。** 这一点和「位移转移」的 call 一致——**压栈的永远是「下一条指令」的地址**。

**栈的变化：**

```
   执行 call far ptr s 之后：
   ┌──────────┐ 高地址
   │  1000H   │ ← CS（先压入，在栈的深处）
   ├──────────┤
   │  0008H   │ ← IP（后压入，在栈顶）
   └──────────┘ ← SP（降低了 4）
```

**所以子程序末尾必须用 `retf`：先弹出 IP（0008H），再弹出 CS（1000H），才能正确返回。**

## 10.5 转移地址在寄存器中的call指令

**格式：`call 16位reg`，等价于：**

```
   push IP
   jmp 16位reg
```

**机器码：`FF /2`，例如 `call ax` = `FF D0`（2 字节）。**

```asm
assume cs:code
code segment
start:  mov ax, offset sub1     ; ★ 把子程序入口的偏移装入 AX
        call ax                 ; FF D0：压入返回地址，IP ← (AX)
        mov ax, 4c00h
        int 21h
sub1:   inc ax
        ret
code ends
end start
```

**执行过程：**

```
   ① mov ax, offset sub1   汇编期求出 sub1 的偏移，装入 AX
   ② call ax               把「call ax 之后那条指令」的偏移压栈，
                           然后 IP ← (AX)，跳到 sub1
   ③ 执行 sub1 的代码
   ④ ret                   从栈顶弹出返回地址给 IP，回到 call 之后继续执行
```

**这是「函数指针」的雏形**——调用哪个子程序在运行时由寄存器的值决定。

## 10.6 转移地址在内存中的call指令

**两种形式：**

| 形式 | 压栈内容 | 转移 | 机器码 |
|---|---|---|---|
| `call word ptr 内存单元地址` | **IP** | 段内（IP = 内存中的字） | `FF /2` |
| `call dword ptr 内存单元地址` | **CS，再 IP** | 段间（低字→IP，高字→CS） | `FF /3` |

**例：同时演示段内调用与段间调用**

```asm
assume cs:code, ds:data
data segment
    dw offset near_sub          ; 偏移 0：段内子程序入口（字）
    dw offset far_sub           ; 偏移 2：段间子程序入口的偏移
    dw seg far_sub              ; 偏移 4：段间子程序入口的段地址
data ends
code segment
start:
    mov ax, data
    mov ds, ax
    mov bx, 0

    call word ptr [bx]          ; ★ 段内调用：push IP; IP ← [bx]
    call dword ptr [bx+2]       ; ★ 段间调用：push CS; push IP; IP ← [bx+2], CS ← [bx+4]

    mov ax, 4c00h
    int 21h

near_sub:
    mov cx, 1
    ret                         ; 段内返回：只弹 IP

far_sub:
    mov dx, 2
    retf                        ; ★ 段间返回：先弹 IP，再弹 CS
code ends
end start
```

**运行结果**：`CX = 1`、`DX = 2`，最后程序正常返回 DOS。

**内存中双字的排布（`call dword ptr [bx+2]`）：**

```
   偏移:   2        3        4        5
         ┌────────┬────────┬────────┬────────┐
   data: │ 偏移低字节│ 偏移高字节│ 段低字节 │ 段高字节 │
         └────────┴────────┴────────┴────────┘
          └──── 低字 → IP ────┘└──── 高字 → CS ────┘
```

> **重点**：**`call dword ptr 内存` 与 `jmp dword ptr 内存`、中断向量表的结构完全一致——「低字给 IP、高字给 CS」。** 记住这个统一规律，第 12 章的中断向量表就不用另记了。

## 10.7 call和ret的配合使用

**`call` 和 `ret` 是天生的一对：`call` 压栈、`ret` 弹栈，栈就自然平衡了。**

**标准骨架：**

```asm
assume cs:code
code segment
main:                       ; 主程序
    mov ax, 1
    mov cx, 3
    call sub1               ; 调用子程序
    mov bx, ax              ; 用子程序的返回值
    mov ax, 4c00h
    int 21h
sub1:                       ; 子程序
    add ax, ax
    loop sub1
    ret                     ; ★ 返回（弹回 call 之后的地址）
code ends
end main
```

**执行轨迹（重点理解 `loop sub1` 循环的目标）：**

| 步骤 | 指令 | AX | CX | 栈 |
|---|---|---|---|---|
| ① | `mov ax, 1` | 1 | — | 空 |
| ② | `mov cx, 3` | 1 | 3 | 空 |
| ③ | `call sub1` | 1 | 3 | 压入「`mov bx, ax` 的偏移」 |
| ④ | `add ax, ax` | 2 | 3 | 同上 |
| ⑤ | `loop sub1` | 2 | 2 → 跳回 ④ | 同上 |
| ⑥ | `add ax, ax` | 4 | 2 | 同上 |
| ⑦ | `loop sub1` | 4 | 1 → 跳回 ④ | 同上 |
| ⑧ | `add ax, ax` | 8 | 1 | 同上 |
| ⑨ | `loop sub1` | 8 | 0 → 不跳 | 同上 |
| ⑩ | `ret` | 8 | 0 | **弹出返回地址，回到 `mov bx, ax`** |

**运行结果**：`AX = 8`，`BX = 8`。逻辑就是 `1 × 2³ = 8`。

**注意 `loop sub1` 的目标是 `sub1` 处的 `add ax, ax`，而不是 `call sub1`。** 这正是子程序内部可以有自己的循环、`ret` 只执行一次的原因。

> **重点**：**`call`/`ret` 的正确配合依赖「栈平衡」。** 如果子程序内部 `push` 了东西却没有 `pop`，`ret` 弹出来的就不是返回地址，程序立刻跑飞。**「有 push 必有 pop，且逆序配对」是写子程序的第一纪律。**

## 10.8 mul指令

**`mul` 是乘法指令。格式：`mul 乘数`。两个相乘的数位数必须相同。**

### 情形一：两个 8 位数相乘

```
   一个乘数：AL（固定）
   另一个  ：8 位（reg8 或 mem8）
   
   结果：16 位 → AX
```

```asm
mul bl              ; AL × BL，结果在 AX
mul byte ptr [bx]   ; AL × DS:[bx] 处的字节，结果在 AX
```

### 情形二：两个 16 位数相乘

```
   一个乘数：AX（固定）
   另一个  ：16 位（reg16 或 mem16）
   
   结果：32 位 → DX:AX（DX 存高 16 位，AX 存低 16 位）
```

```asm
mul bx              ; AX × BX，结果在 DX:AX
mul word ptr [bx]   ; AX × DS:[bx] 处的字，结果在 DX:AX
```

### 总结表（必背）

| 乘数位数 | 隐含的被乘数 | 结果存放 | 结果位数 | 溢出判断 |
|---|---|---|---|---|
| 8 位 | **AL** | **AX** | 16 位 | 结果 > FFH 则 `CF=OF=1`（AH ≠ 0） |
| 16 位 | **AX** | **DX:AX** | 32 位 | 结果 > FFFFH 则 `CF=OF=1`（DX ≠ 0） |

**`mul` 与 `div` 的对称关系：**

| 运算 | 8 位形式 | 16 位形式 |
|---|---|---|
| `mul` | `AL × r/m8 → AX` | `AX × r/m16 → DX:AX` |
| `div` | `AX ÷ r/m8 → AL(商), AH(余)` | `DX:AX ÷ r/m16 → AX(商), DX(余)` |

> **重点**：**`mul` 的结果位宽翻倍、`div` 的被除数位宽翻倍**——这两个正好互为逆运算。所以**一次 `mul` 之后紧跟一次 `div`（用同样的操作数），就能还原原来的值**（这正是第 8 章「一条奇怪的程序」的原理）。

**标志位的影响（第 11 章会细讲）：**

| 标志位 | `mul` 的影响 |
|---|---|
| **CF、OF** | **结果的高半部分非 0 → CF=1、OF=1**；否则 CF=0、OF=0 |
| SF、ZF、AF、PF | **未定义**（不要依赖） |

**常用场合：把 8 位乘法升级成 16 位运算。**

```asm
; 计算 BX × 10（常数乘法，用 mul 实现）
mov ax, bx
mov cx, 10
mul cx              ; ★ 用 mul cx 代替 10 次 add（DX 为高 16 位）
```

**完整例子：计算 200 × 300，结果（32 位）存入内存。**

```asm
assume cs:code, ds:data
data segment
    a    dw 200             ; 被乘数
    b    dw 300             ; 乘数
    prod dd 0               ; 4 字节存放 32 位结果
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    mov ax, a               ; AX = 200
    mul b                   ; ★ 16 位乘法：AX × b = 200 × 300 = 60000 = EA60H
                            ; 结果在 DX:AX，DX = 0，AX = EA60H
    mov word ptr prod, ax   ; 存低 16 位
    mov word ptr prod+2, dx ; 存高 16 位

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：`200 × 300 = 60000`，`60000 = 0EA60H`，所以 `prod` 的低字存 `EA60H`、高字存 `0000H`。

> **★ 为什么用标号 `a`/`b`/`prod` 而不是 `[0]`/`[2]`/`[4]`？** **MASM 把 `[数字]` 当常量**：`mov ax, [0]` 会被汇编成 `mov ax, 0`（不报错但结果错），`mov [4], ax` 会直接报 `error A2001: immediate operand not allowed`。**用标号是最稳妥的写法**；一定要按偏移写时必须加段前缀（`mov ax, ds:[0]`、`mov ds:[4], ax`）。

## 10.9 模块化程序设计

**子程序（subroutine）是完成特定功能、可以被重复调用的代码块。**

**为什么要用子程序？**

| 好处 | 说明 |
|---|---|
| **代码复用** | 一段功能只写一次，多处 `call` 调用 |
| **结构清晰** | 主程序只表达「做什么」，细节封装进子程序 |
| **便于调试** | 单个子程序可独立测试，出错范围小 |
| **便于分工** | 多人协作时按子程序划分任务 |
| **便于修改** | 功能变更只改子程序一处 |

**子程序的接口三要素（写子程序必须先想清楚这三条）：**

```
   ┌─────────────────────────────────────────┐
   │  子程序名：sub1                          │
   │  ① 入口参数：调用者要传进来什么？          │
   │  ② 功能    ：它做什么？（含副作用说明）     │
   │  ③ 出口参数：返回时把结果放在哪里？         │
   └─────────────────────────────────────────┘
```

**例：**

```asm
; =====================================================
; 子程序名：to_upper
; ① 入口参数：BX = 待转换字符串的首地址，CX = 字符串长度
; ② 功能    ：把字符串中的小写字母全部转换为大写字母
; ③ 出口参数：无（直接在原地址上修改）
; 说明      ：本子程序不破坏 AX、BX、CX 之外的寄存器
; =====================================================
```
```asm
to_upper:
    push ax                 ; ★ 保存本子程序会用到的寄存器
    push si
    mov si, 0
s:  mov al, [bx+si]
    cmp al, 'a'
    jb  next                ; 小于 'a'，不是小写字母
    cmp al, 'z'
    ja  next                ; 大于 'z'，不是小写字母
    and al, 11011111b       ; ★ 小写 → 大写：第 5 位清零
    mov [bx+si], al
next:
    inc si
    loop s
    pop si                  ; ★ 逆序恢复
    pop ax
    ret
```

> **重点**：**子程序的第一条纪律是「保持栈平衡」（有 push 必有 pop）；第二条纪律是「不破坏调用者依赖的寄存器」。** 一个功能正确但会偷偷改掉 CX、BX 的子程序，在实际项目里是灾难。

## 10.10 ★ 参数和结果传递的问题 ★

**子程序和调用者之间要交换数据，有三种方式：**

| 方式 | 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **① 寄存器传递** | 参数放寄存器，结果也放寄存器 | 最快、最简单 | 寄存器数量有限（8086 只有 4 个通用寄存器） | 参数少（1~3 个） |
| **② 内存（共享变量）传递** | 参数和结果都放在约定的内存单元 | 容量大，能传批量数据 | 需要额外的内存约定，可重入性差 | 参数多或有全局状态 |
| **③ 栈传递** | 调用前 `push` 参数，子程序用 `[bp+偏移]` 取 | **最通用、最灵活，支持批量数据** | 写法稍繁琐，要小心栈平衡 | 参数多、需要递归 |

> **★ 教材延伸**：方式③（用栈传递参数）在教材王爽《汇编语言》（第 4 版）里另有一篇专题**「附注 4 用栈传递参数」**（教材第 333 页），把「参数为什么从右往左压」「`ret n` 怎么自动清栈」「用栈传参和用寄存器传参的本质区别」讲得更细。**本节 10.10 方式三 + 10.11 批量数据的传递看完后，去翻附注 4 会有第二次收获**；再往后接[第 18 章](第18章-从8086到IA-32（拓展）.md) 18.6 节的 cdecl/stdcall 调用约定，你会发现**高级语言函数的参数传递规则，就是这一套东西的标准化版本**。

### 方式一：用寄存器传递

**最简单直接的例子：**

```asm
; -----------------------------------------------------
; 子程序：计算 (AX + BX) 的 3 倍，结果放 AX
; 入口参数：AX、BX
; 出口参数：AX
; -----------------------------------------------------
calc:
    add ax, bx
    mov cx, 3
    mul cx              ; AX × 3 → DX:AX，低位在 AX
    ret
```

**调用：**

```asm
    mov ax, 10
    mov bx, 20
    call calc           ; 调用后 AX = (10+20)×3 = 90
```

### 方式二：用内存单元（共享变量）传递

```asm
assume cs:code, ds:data
data segment
    pa   dw 10              ; 参数 1
    pb   dw 20              ; 参数 2
    pres dw 0               ; 结果
data ends
code segment
start:
    mov ax, data
    mov ds, ax
    call calc
    mov bx, pres            ; BX = 结果 = 90
    mov ax, 4c00h
    int 21h
; -----------------------------------------------------
; 子程序：计算 pa + pb 的 3 倍，结果存 pres
; 入口参数：无（从约定的内存单元读）
; 出口参数：无（写到约定的内存单元）
; ★ 用标号访问内存，不能用 [0]/[2]/[4]（MASM 会当常量）
; -----------------------------------------------------
calc:
    push ax
    push bx
    mov ax, pa
    add ax, pb
    mov bx, 3
    mul bx
    mov pres, ax
    pop bx
    pop ax
    ret
code ends
end start
```

**运行结果**：`(10 + 20) × 3 = 90`，所以 `pres` = `90`，主程序中 `BX = 90`。

### 方式三：用栈传递（最通用）

**调用者在 `call` 之前 `push` 参数；子程序用 `bp` 访问栈中的参数。**

**关键：`[bp+偏移]` 默认段是 SS，正好用来访问栈。**

```asm
    mov ax, 10
    push ax             ; ★ 先压参数
    mov ax, 20
    push ax             ; ★ 再压参数
    call calc           ; 然后 call（call 会再压返回地址）
```

**调用后栈的布局：**

```
   ┌──────────────┐ 高地址
   │   参数 1 = 10 │ ← [bp+6]
   ├──────────────┤
   │   参数 2 = 20 │ ← [bp+4]
   ├──────────────┤
   │   返回地址    │ ← [bp+2]  ← 靠近栈顶的那一端是返回地址
   ├──────────────┤
   │  旧 BP 的值  │ ← [bp]（子程序开头 push bp 后，bp 指向这里）
   └──────────────┘ ← SP、BP 低地址
```

**子程序的标准写法（栈传参模板，务必背下来）：**

```asm
; -----------------------------------------------------
; 子程序：计算两个参数之和的 3 倍，结果放 AX
; 入口参数：栈中 —— [bp+4] = 第一个参数，[bp+6] = 第二个参数
; 出口参数：AX
; -----------------------------------------------------
calc:
    push bp             ; ★ ① 保存调用者的 BP
    mov bp, sp          ; ★ ② 让 BP 指向栈顶（此时 [bp+2] 是返回地址）

    push bx             ; 保存本子程序要用的其他寄存器

    mov ax, [bp+4]      ; ★ ③ 取参数：+2 是返回地址，所以第一个参数在 +4
    add ax, [bp+6]      ; ★ 第二个参数在 +6
    mov bx, 3
    mul bx

    pop bx              ; 逆序恢复
    pop bp              ; ★ ④ 恢复调用者的 BP
    ret 4               ; ★ ⑤ 返回并「顺便」把 4 字节参数弹出栈
code ends
```

> **重点**：**栈传参的三个要点**：
> ① **`push bp` + `mov bp, sp`** 是固定开头，目的是用一个不动的基准（BP）去访问栈里的参数；
> ② **偏移从 `+4` 开始**（`+0` 是旧 BP，`+2` 是返回地址，`+4` 才是第一个参数）；
> ③ **`ret n`**（如 `ret 4`）在返回的同时把 n 字节参数弹出栈，由**被调用者**负责清理参数——这就是高级语言里 `stdcall` 约定做的事（第 18 章详述）。**如果不写 `ret n`，就要由调用者自己 `add sp, 4` 来平衡栈。**

## 10.11 批量数据的传递

**要传一批数据（如一个字符串）时，不能把每个字节都 `push` 进栈（太浪费）。标准做法是传「首地址 + 长度」。**

**三种常用套路：**

| 套路 | 传什么 | 子程序怎么取 |
|---|---|---|
| **寄存器传首地址 + 长度** | `BX` = 首地址，`CX` = 长度 | `mov al, [bx+si]` + `loop` |
| **内存中放「地址表」** | 内存单元存首地址和长度 | 先从内存读地址和长度，再访问 |
| **栈传首地址 + 长度** | `push` 首地址、`push` 长度 | `mov bx, [bp+4]`、`mov cx, [bp+6]` |

**典型例子：字符串转大写（批量数据传递的标准写法）**

```asm
assume cs:code, ds:data
data segment
    db 'hello, world!', 0       ; 待处理字符串（以 0 结尾）
    db 13, 10, '$'              ; 换行 + DOS 显示字符串的结束符 '$'
data ends
code segment
start:
    mov ax, data
    mov ds, ax

    mov bx, 0                   ; ★ BX = 字符串首地址（偏移 0）
    mov cx, 13                  ; ★ CX = 字符串长度
    call to_upper               ; 调用子程序：把字符串转大写

    mov dx, 0                   ; ★ 用 DOS 9 号功能显示字符串
    mov ah, 9
    int 21h

    mov ax, 4c00h
    int 21h

; =====================================================
; 子程序：to_upper
; ① 入口参数：BX = 字符串首地址，CX = 字符串长度
; ② 功能    ：把字符串中的小写字母改成大写
; ③ 出口参数：无（就地修改）
; =====================================================
to_upper:
    push ax                     ; ★ 保存本子程序会破坏的寄存器
    push si
    mov si, 0
s:  mov al, [bx+si]
    cmp al, 'a'
    jb  next                    ; 比 'a' 小 → 不是小写字母
    cmp al, 'z'
    ja  next                    ; 比 'z' 大 → 不是小写字母
    and al, 11011111b           ; ★ 小写转大写：第 5 位清零
    mov [bx+si], al
next:
    inc si
    loop s
    pop si                      ; ★ 逆序恢复
    pop ax
    ret
code ends
end start
```

**运行结果**：屏幕输出 `HELLO, WORLD!`，然后换行返回 DOS。

**关键点：**

| 要点 | 说明 |
|---|---|
| **参数只有一个「首地址」** | 不管字符串多长，都只传一个偏移 |
| **长度单独传** | 常用 `CX`（因为 `loop` 正好用 CX 计数） |
| **子程序内用 `[bx+si]` 遍历** | `bx` = 首地址，`si` = 递增的下标 |
| **必须保护用到的寄存器** | 本子程序用了 `AX`、`SI`，所以开头 `push`、结尾 `pop` |

> **重点**：**「首地址 + 长度」是批量数据传递的万能模式。** 高级语言里的 `void f(char *s, int len)` 编译成汇编后，本质上就是把首地址和长度放进寄存器（或栈）传给子程序。**看懂了这一节，就看懂了「指针 + 长度」这对参数的由来。**

## 10.12 寄存器冲突的问题

**问题场景：主程序用一个寄存器保存重要数据，调用子程序后，这个寄存器的值被子程序改掉了。**

```asm
assume cs:code
code segment
start:
    mov cx, 5               ; ★ 主程序要用 CX 做别的事
loop1:
    mov bx, 0
    call sub1               ; ★ 子程序内部也用了 CX！
    loop loop1              ; → CX 被子程序改掉，主循环次数完全错了
    mov ax, 4c00h
    int 21h

sub1:
    mov cx, 100             ; ★ 子程序用 CX 做自己的循环计数
    mov ax, 0
s:  inc ax
    loop s
    ret
code ends
end start
```

**这就是「寄存器冲突」：`CX` 是一个全局稀缺资源，主程序和子程序都想要。**

### 解决办法：子程序开头保存、结尾恢复

**标准模板：**

```asm
sub1:
    push cx                 ; ★ ① 进入子程序先保存会用到的寄存器
    push ax
                            ; ② 子程序主体可以随意使用 CX、AX
    mov cx, 100
    mov ax, 0
s:  inc ax
    loop s

    pop ax                  ; ★ ③ 退出前逆序恢复
    pop cx
    ret                     ; ④ 返回
```

**两条铁律：**

| 铁律 | 说明 |
|---|---|
| **有 push 必有 pop** | 否则 `ret` 弹出的不是返回地址，程序跑飞 |
| **pop 的顺序必须与 push 相反** | 栈是后进先出：`push cx` / `push ax` 必须对应 `pop ax` / `pop cx` |

**哪些寄存器需要保护？**

| 寄存器 | 是否需要保护 | 说明 |
|---|---|---|
| 子程序**用到的**通用寄存器（`AX`/`BX`/`CX`/`DX`/`SI`/`DI`/`BP`） | **需要** | 除非它本身就是出口参数 |
| 段寄存器 `DS`/`ES` | **如果改了就一定要恢复** | 主程序可能正在用自己设的 DS |
| 作为**出口参数**的寄存器 | **不要保护** | 结果就是要通过它返回 |
| `CS`、`IP` | 由 `call`/`ret` 自动处理 | 无需手工干预 |
| 标志寄存器 | 一般不用保护 | 除非调用者依赖标志位（可用 `pushf`/`popf`，见第 11 章） |

**规范的子程序写法（完整示范）：**

```asm
; =====================================================
; 子程序：str_len
; ① 入口参数：BX = 字符串首地址（以 0 结尾）
; ② 功能    ：求字符串长度（不含结尾的 0）
; ③ 出口参数：CX = 字符串长度
; 说明      ：本子程序只破坏 CX（出口参数），不破坏 AX、BX、DX、SI、DI
; =====================================================
str_len:
    push ax                     ; 保存内部临时用到的 AX
    push si
    mov si, 0
s:  mov al, [bx+si]
    cmp al, 0
    je  done                    ; 遇到 0 结束
    inc si
    jmp s                       ; ★ 不能用 loop（CX 还没算出来）
done:
    mov cx, si                  ; 长度就是下标
    pop si
    pop ax
    ret
```

**运行结果**：调用后 `CX` 就是字符串长度。**注意这里不能用 `loop`**——因为 `CX` 是输出结果，循环计数还没着落；用 `cmp`/`je`/`jmp` 更安全。

> **重点**：**「子程序不破坏调用者的现场」是模块化设计的基本契约。** 在高级语言里，编译器自动为每个函数生成「保存/恢复寄存器」的代码（这叫做**函数序言 prologue 和函数尾声 epilogue**）；写汇编要手工完成。**第 18 章讲 `cdecl`/`stdcall` 调用约定时，你会看到现代编译器生成的正是这一节的代码。**

## 实验十 编写子程序

**教材实验十要求编写三个子程序，它们是「子程序设计」的经典练习，也是考试常考的题型。**

### 子程序一：`show_str`——在指定位置显示字符串

```
; ① 入口参数：DH = 行号（0~24），DL = 列号（0~79），
;             CL = 颜色属性，DS:SI = 字符串首地址（以 0 结尾）
; ② 功能    ：在屏幕的指定位置显示字符串
; ③ 出口参数：无
```

**核心思路**：显存位于 `B8000H`（第 25 行）或 `B800H:0000`，**每个字符占 2 字节**（1 字节 ASCII + 1 字节属性）。屏幕一行 80 列，共 25 行。

```
   显存偏移 = (行号 × 80 + 列号) × 2
```

```asm
assume cs:code
code segment
start:
    mov dh, 8                   ; 第 8 行
    mov dl, 3                   ; 第 3 列
    mov cl, 2                   ; 颜色：绿色
    mov ax, data
    mov ds, ax
    mov si, 0                   ; DS:SI 指向字符串
    call show_str

    mov ax, 4c00h
    int 21h

; =====================================================
; 子程序：show_str
; ① 入口参数：DH=行号，DL=列号，CL=颜色，DS:SI=字符串首地址
; ② 功能    ：在屏幕指定位置显示以 0 结尾的字符串
; ③ 出口参数：无
; =====================================================
show_str:
    push ax
    push bx
    push cx
    push dx
    push es
    push si
    push di

    ; ① 计算显存偏移 = (行号×80 + 列号) × 2 → 放入 DI
    mov ax, 0
    mov al, 160                 ; 80 列 × 2 字节 = 一行 160 字节
    mul dh                      ; AX = 行号 × 160
    mov di, ax
    mov ax, 0
    mov al, dl
    add ax, ax                  ; AX = 列号 × 2
    add di, ax                  ; DI = 总偏移

    ; ② ES 指向显存段
    mov ax, 0b800h
    mov es, ax

    ; ③ 逐字符写入
    mov bl, cl                  ; BL 保存颜色属性（CX 会用到）
s:  mov al, [si]                ; 从 DS:SI 取一个字符
    mov ah, bl                  ; 属性字节
    cmp al, 0
    je  done                    ; 遇到 0 结束
    mov es:[di], ax             ; ★ 一次写入 2 字节：字符 + 属性
    add di, 2                   ; 下一个字符位置
    inc si
    jmp s
done:
    pop di
    pop si
    pop es
    pop dx
    pop cx
    pop bx
    pop ax
    ret

data segment
    db 'Welcome to masm!', 0
data ends
code ends
end start
```

**运行结果**：屏幕第 8 行第 4 列起显示绿色的 `Welcome to masm!`。

### 子程序二：`divdw`——解决除法溢出

```
; ① 入口参数：DX = 被除数高 16 位，AX = 被除数低 16 位，CX = 除数
; ② 功能    ：进行不会产生溢出的除法运算（被除数 32 位、除数 16 位、商 32 位）
; ③ 出口参数：DX = 商的高 16 位，AX = 商的低 16 位，CX = 余数
; 公式      ：int(H / N) × 65536 + int(rem(H / N) × 65536 + L) / N
```

```asm
; =====================================================
; 子程序：divdw
; 入口：DX:AX = 被除数（32 位），CX = 除数（16 位）
; 出口：DX:AX = 商（32 位），CX = 余数
; =====================================================
divdw:
    push bx                     ; ★ ① 保护 BX（本子程序要用它中转）
    push ax                     ; ★ ② 保存被除数的低 16 位（后面还要用）
                                ;    ★ 注意压栈顺序：bx 先、ax 后，
                                ;      所以弹出时要 ax 先、bx 后（逆序）

    mov ax, dx                  ; ③ 把被除数的高 16 位取到 AX
    mov dx, 0                   ;    清高 16 位，准备做 16 位除法
    div cx                      ; ④ 高 16 位 ÷ 除数 → AX = 高半商，DX = 余数

    mov bx, ax                  ; ⑤ 暂存高半商（它就是最终结果的高 16 位）

    pop ax                      ; ⑥ 恢复被除数的低 16 位到 AX（栈顶正是它）
                                ;    此时 DX 里正是上一步的余数，
                                ;    所以 DX:AX = 余数:低 16 位 = 新的 32 位被除数
    div cx                      ; ⑦ (余数:低 16 位) ÷ 除数 → AX = 低半商，DX = 最终余数

    mov cx, dx                  ; ⑧ 最终余数 → CX
    mov dx, bx                  ; ⑨ 高半商 → DX（配合 AX 得到完整的 32 位商）
    pop bx                      ; ⑩ 恢复 BX
    ret
```

**注意 `push ax` / `pop ax` 的用法：** 这里的栈被临时用来「暂存被除数的低 16 位」——先进后出的顺序正好让 `pop ax` 取回正确的那一个值。**这是 `push`/`pop` 作为「临时存储」的经典用法**，也说明栈不只是用来传参和保存现场的。

**运行结果**：把 32 位被除数除以 16 位除数，得到 32 位商和 16 位余数，**不会触发除法溢出**。

> **重点**：**`divdw` 体现的核心技巧是「分两步除」**——先用高 16 位除，把余数作为下一次除法的高位，再除低 16 位。**这是所有「大数除法」库函数的通用算法**，务必理解。

### 子程序三：`dtoc`——数值显示

```
; ① 入口参数：AX = 待显示的数（0 ~ 65535），DS:SI = 存放结果的缓冲区首地址
; ② 功能    ：把数值转换成十进制字符串，写入缓冲区
; ③ 出口参数：无
```

**核心思路：反复除以 10，余数就是最低位数字，倒序得到十进制串。**

```asm
; =====================================================
; 子程序：dtoc
; 入口：AX = 数值，DS:SI = 缓冲区首地址
; 出口：缓冲区中是以 0 结尾的十进制字符串
; =====================================================
dtoc:
    push ax
    push bx
    push cx
    push dx
    push si

    mov bx, 0                   ; BX 记录已产生的字符个数（倒序）
    mov cx, 10                  ; 除数 = 10
s:  mov dx, 0                   ; ★ 高 16 位清 0
    div cx                      ; DX:AX ÷ 10 → 商在 AX，余数在 DX
    add dl, 30h                 ; ★ 余数 + 30H 变成 '0'~'9'
    mov [si+bx], dl             ; 存进缓冲区（此时是低位在前）
    inc bx                      ; 计数加 1
    cmp ax, 0
    jne s                       ; 商不为 0 就继续

    ; 此时缓冲区里是倒序的，要反转
    mov byte ptr [si+bx], 0     ; 补上结尾的 0（字符串终止符）
    ; ---- 反转：DI 指向最后一个字符，SI 向后、DI 向前，两两交换到相遇 ----
    mov di, si
    mov ax, bx
    dec ax
    add di, ax                  ; DI = 缓冲区最后一个字符的地址
rev:
    cmp si, di                  ; ★ 地址比较必须用无符号转移指令 jae
    jae revdone                 ;    用 jge（有符号）在跨段/高地址时会判错
    mov al, [si]
    mov ah, [di]
    mov [si], ah                ; 左右交换
    mov [di], al
    inc si
    dec di
    jmp rev
revdone:

    pop si
    pop dx
    pop cx
    pop bx
    pop ax
    ret
```

**运行结果**：`AX = 12345` 时——
- **不做反转**时，缓冲区里是 `'5','4','3','2','1',0`（**低位在前**，这是 `div` 反复取余的天然顺序）；
- **补上上面那段反转**后，才是 `'1','2','3','4','5',0`。

> **重点**：**`div` 法取数字天然得到「低位在前」的倒序串，必须再反转一次才是人能读的顺序。** 这一点非常容易漏——只写循环不写反转，输出就是反的。反转的标准写法是「双指针相向交换」，循环条件是 `cmp si, di` + `jae`（**地址比较是无符号的，用 `jge` 是错的**）。

**关键点**：`div cx` 前**必须 `mov dx, 0`**（第 8 章的重点）；余数加 `30H` 是把数值 `0~9` 变成字符 `'0'~'9'`（ASCII 码复习：`'0' = 30H`）。

## 典型例题

**例 10.1**（题型：ret / retf 的执行过程）
设 `(SP) = 0100H`，栈中的数据如下：`SS:[00FEH] = 1234H`，`SS:[0100H] = 5678H`，`SS:[0102H] = 9ABCH`。
分别执行 `ret` 和 `retf`（执行前总是指向这个栈状态），IP、CS、SP 各变成多少？
**解**：
- **`ret`**：只弹一个字。
  - `IP ← SS:[SP] = SS:[0100H] = 5678H`
  - `SP ← 0100H + 2 = 0102H`
  - CS 不变。
- **`retf`**：弹两个字。
  - `IP ← SS:[SP] = SS:[0100H] = 5678H`，`SP ← 0102H`
  - `CS ← SS:[SP] = SS:[0102H] = 9ABCH`，`SP ← 0104H`
**答案**：`ret` → `IP = 5678H`、`SP = 0102H`、CS 不变；`retf` → `IP = 5678H`、`CS = 9ABCH`、`SP = 0104H`。

**例 10.2**（题型：call 标号的位移与机器码）
下面的程序中，`call s` 的机器码是什么？
```asm
assume cs:code
code segment
start:  mov ax, 0           ; 偏移 0
        mov bx, 0           ; 偏移 3
        call s              ; 偏移 6
        mov ax, 4c00h       ; 偏移 9
        int 21h             ; 偏移 12
        db 100 dup (0)      ; 偏移 14 ~ 113
    s:  add ax, 1           ; 偏移 114
        ret
code ends
end start
```
**解**：
- `mov ax, 0` 长 3 → 偏移 0~2
- `mov bx, 0` 长 3 → 偏移 3~5
- `call s` 长 **3** → 偏移 6~8，**call 后第一个字节的偏移 = 9**
- `mov ax, 4c00h` 长 3 → 偏移 9~11
- `int 21h` 长 2 → 偏移 12~13
- `db 100 dup (0)` 长 100 → 偏移 14~113
- `s:` 的偏移 = **114**
- **位移 = 114 − 9 = 105 = 0069H**
**答案**：机器码 `E8 69 00`（`E8` + 小端序的 16 位位移）。

**例 10.3**（题型：call far ptr 机器码与栈分析）
执行下面程序的 `call far ptr s` 之后，栈顶两个字的内容分别是什么？
```asm
assume cs:code
code segment
start:  mov ax, 0                   ; 偏移 0
        call far ptr s              ; 偏移 3
        mov bx, ax                  ; 偏移 8
        mov ax, 4c00h               ; 偏移 10
        int 21h                     ; 偏移 13
    s:  add ax, 1
        retf
code ends
end start
```
（设 `CS = 1000H`、调用前 `SP = 0100H`）
**解**：
- `call far ptr s` 长 **5** 字节，起始偏移 3 → 结束偏移 7，**下一条指令（`mov bx, ax`）的偏移 = 8**。
- `call far ptr` 的压栈顺序是 **先压 CS、再压 IP**：
  - `SP = 0100H − 2 = 00FEH`，`SS:[00FEH] ← CS = 1000H`
  - `SP = 00FEH − 2 = 00FCH`，`SS:[00FCH] ← IP = 0008H`
- 所以栈顶（`SS:[00FCH]`）是 **0008H**（返回的偏移），其上方（`SS:[00FEH]`）是 **1000H**（返回的段）。
**答案**：`SS:[00FCH] = 0008H`（IP）、`SS:[00FEH] = 1000H`（CS），`SP = 00FCH`。

**例 10.4**（题型：mul 计算与结果存放）
执行下面程序后，DX 和 AX 各是多少？
```asm
mov ax, 1000h
mov bx, 1000h
mul bx
```
**解**：
- `mul bx` 是 16 位乘法：`AX × BX → DX:AX`。
- `1000H = 4096`（十进制），`4096 × 4096 = 16777216`（十进制）。
- `16777216 = 1000000H`（十六进制）。
- 32 位结果的低 16 位放 AX，高 16 位放 DX。
- `1000000H` 的低 16 位是 `0000H`，高 16 位是 `0100H`。
**答案**：`AX = 0000H`，`DX = 0100H`。

**例 10.5**（题型：栈传参的偏移计算）
某子程序用栈接收两个参数，开头是 `push bp` / `mov bp, sp`。调用前调用者按 `push 参数1`、`push 参数2` 的顺序压栈。问：子程序里访问「参数 1」用 `[bp+?]`？
**解**：
- 执行 `push bp` 后，栈顶是**旧 BP 的值**；`mov bp, sp` 让 `bp` 指向此处。所以 `[bp+0]` = 旧 BP。
- 接着是 `call` 压入的**返回地址**（2 字节），所以 `[bp+2]` = 返回地址。
- 再往上是**最后压入的参数**，即「参数 2」，在 `[bp+4]`。
- 再往上是「参数 1」，在 `[bp+6]`。
**答案**：参数 1 用 `[bp+6]`，参数 2 用 `[bp+4]`。
**关键**：**「后压入的参数离 BP 更近」**——因为栈是后进先出，后压的在上（低地址）。

**例 10.6**（题型：寄存器冲突的诊断与修复）
下面程序希望主循环执行 5 次，但实际执行次数不对。找出原因并修复。
```asm
assume cs:code
code segment
start:
    mov cx, 5
loop1:
    mov bx, 0
    call sub1
    loop loop1
    mov ax, 4c00h
    int 21h
sub1:
    mov cx, 100
    mov ax, 0
s:  inc ax
    loop s
    ret
code ends
end start
```
**解**：
- 主程序用 `CX = 5` 控制外层循环。
- 子程序 `sub1` 内部也用了 `CX`（`mov cx, 100`），返回时 `CX` 已经是 0（循环结束）。
- 于是主程序的 `loop loop1` 执行时，`CX` 从 0 减成 `FFFFH`（≠ 0）→ **又跳回去**。
- 第二次进入 `sub1`，`mov cx, 100` 又把 `CX` 设成 100，循环完又变 0，主程序 `loop` 又减成 `FFFFH`……
- **所以不是「变成 65535 次」，而是彻底死循环**——`CX` 每次都被子程序重新写成 100 再耗成 0，主循环永远等不到 `CX` 变成 0 的那一刻。程序卡死，只能重启 DOSBox。
- **这是典型的寄存器冲突。**
**修复**：在子程序开头保存、结尾恢复（有 push 必有 pop，逆序配对）：
```asm
sub1:
    push cx                 ; ★ 保存调用者的 CX
    push ax
    mov cx, 100
    mov ax, 0
s:  inc ax
    loop s
    pop ax                  ; ★ 逆序恢复
    pop cx
    ret
```
**答案**：子程序破坏了 `CX`；修复办法是子程序开头 `push cx`（及用到的其他寄存器）、结尾逆序 `pop`。

**例 10.7**（题型：编写子程序——首地址+长度的批量处理）
编写子程序 `count_char`：入口 `BX` = 字符串首地址、`CX` = 长度、`DL` = 待统计的字符；出口 `AX` = 该字符出现的次数。要求不破坏 `BX`、`CX`、`DX`。
**解**：
```asm
; =====================================================
; 子程序：count_char
; ① 入口参数：BX = 字符串首地址，CX = 长度，DL = 待统计字符
; ② 功能    ：统计字符串中指定字符的个数
; ③ 出口参数：AX = 出现次数
; 说明      ：不破坏 BX、CX、DX、SI
; =====================================================
count_char:
    push bx                 ; 保存（虽然不改，但养成习惯）
    push cx
    push dx
    push si

    mov ax, 0               ; AX 作计数器
    mov si, 0
s:  mov dh, [bx+si]         ; ★ 用 DH 临时存取的字符（DX 已保存）
    cmp dh, dl              ; 和待统计字符比较
    jne next
    inc ax                  ; 相等则计数加 1
next:
    inc si
    loop s

    pop si
    pop dx
    pop cx
    pop bx
    ret
```
**调用示例**：
```asm
    mov bx, 0               ; 字符串在 data 段偏移 0
    mov cx, 10              ; 长度 10
    mov dl, 'a'             ; 统计字母 'a'
    call count_char         ; 返回后 AX = 'a' 的个数
```
**答案**：见上面的子程序。**关键点**：① 用 `[bx+si]` 遍历（首地址 + 递增下标）；② `loop` 用 `CX` 计数（正好是入口参数）；③ 开头 `push` 保存全部会用到的寄存器、结尾逆序 `pop`。

## 易错点提醒

1. **错**：分不清 `ret` 和 `retf`。**对**：**`ret` 只弹 IP（段内，`C3`）；`retf` 弹 IP 再弹 CS（段间，`CB`）**。与 `call` 配对时——`call 标号` 配 `ret`，`call far ptr` 配 `retf`。
2. **错**：以为 `ret` 弹栈的顺序是「先 CS 后 IP」。**对**：**`retf` 是「先弹 IP、再弹 CS」**（因为 `call far ptr` 是「先压 CS、后压 IP」，栈后进先出）。
3. **错**：以为 `call 标号` 压入的是 call 指令**自己**的偏移。**对**：压入的是 **call 指令后第一个字节**的偏移（即「下一条指令」的地址），也就是 `call` 起始偏移 + 3。
4. **错**：算 `call 标号` 的位移时忘了减 call 自身的长度。**对**：**位移 = 标号偏移 − call 后第一个字节的偏移**，公式与 `jmp near ptr` 完全相同。
5. **错**：`call 标号` 写成 2 字节。**对**：`call 标号` 是 **3 字节**（`E8` + 16 位位移）；`jmp short` 才是 2 字节。**指令长度算错，位移就全错。**
6. **错**：`call dword ptr 内存` 和 `call word ptr 内存` 混用返回指令。**对**：**`call dword ptr 内存` 是段间调用，必须用 `retf` 返回**；`call word ptr 内存` 是段内调用，用 `ret`。
7. **错**：子程序里 `push` 了但忘了 `pop`。**对**：**栈不平衡会让 `ret` 弹错地址，程序立刻跑飞**。铁律：有 push 必有 pop，且**逆序配对**。
8. **错**：`pop` 的顺序和 `push` 相同（`push cx` / `push ax` 后面写 `pop cx` / `pop ax`）。**对**：必须**逆序**（`pop ax` / `pop cx`），否则两个寄存器的值会互换。
9. **错**：用 `mul` 后去看 `DX`（8 位乘法）。**对**：**8 位乘法（`mul r/m8`）的结果只在 AX 里**；只有 16 位乘法结果才在 `DX:AX`。
10. **错**：以为 `mul` 会影响 `ZF`、`SF`。**对**：**`mul` 只影响 `CF` 和 `OF`**（结果高半部分非 0 则两者置 1），其余标志位未定义。
11. **错**：把「用栈传参」的偏移算成 `[bp+0]` 或 `[bp+2]`。**对**：`+0` 是旧 BP、`+2` 是返回地址，**第一个参数从 `+4` 开始**（如果先压的是第一个参数，则它在 `[bp+6]`，后压的在 `[bp+4]`）。
12. **错**：子程序用了 `ES` 或 `DS` 却不恢复。**对**：**如果子程序改了段寄存器，返回前必须恢复**，否则调用者后续的内存访问全错。标准做法也是 `push es` / `pop es`。
13. **错**：子程序内部用 `loop` 时，忘了 `CX` 可能正是调用者要的结果。**对**：若 `CX` 是出口参数（如求字符串长度），**不能一路上用 `loop`**，应改用 `cmp` + `jne` + `jmp`。
14. **错**：以为「入口参数多就只能用栈」。**对**：三种方式各有适用场景——**参数少用寄存器、参数多或要递归用栈、有全局状态用内存**。考试常问「三种传递方式的优缺点」。

## 本章小结

- **`ret`**：`IP ← SS:[SP]`，`SP ← SP+2`（弹 1 个字，`C3`）；**`retf`**：先弹 IP 再弹 CS（弹 2 个字，`CB`）。
- **`call` 做两件事：压栈（记录返回地址）+ 转移。** 压栈的永远是「下一条指令」的地址。
- **`call` 的 5 种形式**：`call 标号`（压 IP，`E8`+16 位位移）、`call far ptr 标号`（压 CS 再压 IP，`9A`+偏移+段）、`call 16位reg`（压 IP，`FF /2`）、`call word ptr 内存`（压 IP，`FF /2`）、`call dword ptr 内存`（压 CS 再压 IP，`FF /3`）。
- **配对规则**：段内调用（`call 标号`/`call 16位reg`/`call word ptr 内存`）用 **`ret`**；段间调用（`call far ptr`/`call dword ptr 内存`）用 **`retf`**。
- **`call 标号` 的位移公式**：`位移 = 标号偏移 − call 指令后第一个字节的偏移`。**`call 标号` 是 3 字节指令。**
- **`mul`**：8 位乘 → `AL × r/m8 → AX`；16 位乘 → `AX × r/m16 → DX:AX`。**`mul` 只影响 `CF` 和 `OF`。**
- **`mul` 位宽翻倍、`div` 被除数位宽翻倍**——互为逆运算。
- **参数传递三方式**：① 寄存器（快，参数少）；② 内存/共享变量（容量大）；③ **栈（最通用，支持批量与递归）**。
- **栈传参模板**：`push bp` / `mov bp, sp` → 参数在 `[bp+4]`、`[bp+6]`…… → `pop bp` / `ret n`（由被调用者清理参数）。
- **批量数据传递的万能模式：首地址 + 长度**（`BX` = 首地址、`CX` = 长度、`[bx+si]` 遍历）。
- **寄存器冲突的解法**：子程序开头 `push` 保存会用到的寄存器，结尾**逆序** `pop` 恢复。**有 push 必有 pop，栈必须平衡。**

> **一句话记住本章**：**`call` = 压返回地址 + 转移，`ret` = 弹回地址；段内用 `ret`、段间用 `retf`；`call 标号` 是 3 字节、位移照样用「标号 − 下一条指令」；参数少用寄存器、参数多用栈（`[bp+4]` 起）、批量数据传「首地址 + 长度」；子程序进出场必须「push 保存、逆序 pop 恢复」。**

## 自测题

**1.** 写出 `ret` 和 `retf` 的执行过程。
**答**：`ret`：`IP ← SS:[SP]`，`SP ← SP+2`（只弹 IP，机器码 `C3`）。`retf`：`IP ← SS:[SP]`，`SP ← SP+2`；`CS ← SS:[SP]`，`SP ← SP+2`（先弹 IP 再弹 CS，机器码 `CB`）。

**2.** `call` 指令做哪两件事？压入栈的地址是「call 指令本身的地址」还是别的？
**答**：① 把当前 IP（或 CS 和 IP）压栈；② 转移到目标地址。压入的是 **call 指令后第一个字节**的偏移，即「下一条指令」的地址。

**3.** 写出 `call` 的 5 种形式，并指出各自压栈的内容。
**答**：① `call 标号`——压 **IP**；② `call far ptr 标号`——压 **CS，再压 IP**；③ `call 16位reg`——压 **IP**；④ `call word ptr 内存`——压 **IP**；⑤ `call dword ptr 内存`——压 **CS，再压 IP**。

**4.** `call 标号` 的机器码长度是多少？位移怎么算？
**答**：**3 字节**（`E8` + 16 位位移）。位移 = `标号处的偏移 − call 指令后第一个字节的偏移`。

**5.** `call far ptr s` 的机器码是 `9A 00 01 00 10`，各字节是什么含义？
**答**：`9A` 是远调用操作码；`00 01` 是小端序存放的新 IP = `0100H`；`00 10` 是小端序存放的新 CS = `1000H`。

**6.** 段内调用应该用 `ret` 还是 `retf` 返回？段间调用呢？
**答**：段内调用（`call 标号`、`call 16位reg`、`call word ptr 内存`）用 **`ret`**；段间调用（`call far ptr`、`call dword ptr 内存`）用 **`retf`**。

**7.** 执行 `mov ax, 1000h` / `mov bx, 1000h` / `mul bx` 后，DX、AX 各是多少？
**解**：`1000H × 1000H = 1000000H`（十进制 16777216）。低 16 位 `0000H` → AX，高 16 位 `0100H` → DX。
**答**：`AX = 0000H`，`DX = 0100H`。

**8.** `mul` 影响哪些标志位？8 位乘法时怎么判断结果溢出？
**答**：只影响 **`CF` 和 `OF`**（其余标志位未定义）。8 位乘法结果在 AX 中，若 **`AH ≠ 0`**（即结果 > FFH）则 `CF=OF=1`，表示有进位/溢出；否则 `CF=OF=0`。

**9.** 用栈传递参数时，子程序开头为什么必须写 `push bp` / `mov bp, sp`？
**答**：因为 `SP` 在子程序执行过程中会因 `push`/`pop` 而不断变化，不能用来稳定地定位参数。`mov bp, sp` 用一个不动的基准 `BP` 指向栈帧起点，于是参数位置固定为 `[bp+4]`、`[bp+6]`……

**10.** 栈传参时，第一个参数为什么在 `[bp+6]` 而不是 `[bp+4]`？（设调用顺序为 `push 参数1`、`push 参数2`、`call`）
**答**：`[bp+0]` 是旧 BP、`[bp+2]` 是 `call` 压入的返回地址、`[bp+4]` 是**最后压入的参数 2**、`[bp+6]` 才是**先压入的参数 1**。栈是后进先出，后压的离 BP 更近。

**11.** 子程序返回时为什么必须保证栈平衡？
**答**：因为 `ret` 从栈顶取数据作为 IP。如果子程序内 `push` 了东西没 `pop`，栈顶就不是返回地址，`ret` 会跳到错误的地址，程序跑飞。

**12.** 写出子程序保护寄存器的标准模板。
**答**：
```asm
sub1:
    push cx             ; 保存会用到的寄存器
    push si
    ; ...（子程序主体）
    pop si              ; 逆序恢复
    pop cx
    ret
```

**13.** 批量数据（如字符串）传递的标准做法是什么？为什么不用把每个字节都 `push` 进栈？
**答**：标准做法是传**「首地址 + 长度」**（如 `BX` = 首地址、`CX` = 长度），子程序内用 `[bx+si]` 遍历。若逐个 `push`，参数多时会大量占用栈空间、写法冗长、效率低，而且栈深度不可控。
