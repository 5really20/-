## 15.1 接口芯片和端口

**CPU 之外的所有设备都叫外设（显示器、键盘、硬盘、网卡……）。**

**CPU 不能直接控制外设——它通过「接口芯片」与外界打交道。**

**层次关系：**

```
   ┌─────────┐
   │   CPU   │
   └────┬────┘
        │  地址总线 / 数据总线 / 控制总线
   ┌────┴─────────────────────────────────┐
   │              总线                     │
   └────┬──────────────┬──────────────┬────┘
        │              │              │
   ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
   │ 接口芯片 │    │ 接口芯片 │    │ 接口芯片 │
   │(显卡)    │    │(键盘接口)│    │(硬盘接口)│
   │ ┌─────┐ │    │ ┌─────┐ │    │ ┌─────┐ │
   │ │端口0│ │    │ │端口…│ │    │ │端口…│ │
   │ │端口1│ │    │ └─────┘ │    │ └─────┘ │
   │ │ ……  │ │    └────┬────┘    └────┬────┘
   │ └─────┘ │         │              │
   └────┬────┘    ┌────┴────┐    ┌────┴────┐
        │         │  键盘    │    │  硬盘    │
   ┌────┴────┐    └─────────┘    └─────────┘
   │  显示器  │
   └─────────┘
```

**核心思想（三句话）：**

```
   ① 各种接口芯片中都有一组「寄存器」
   ② CPU 把这些寄存器当作「端口」来访问（用 in / out）
   ③ 向端口写入数据 = 向外设发出命令或传送数据
      从端口读出数据 = 获得外设的状态或数据
```

**典型例子：**

| 接口芯片 | 端口 | 作用 |
|---|---|---|
| 显卡 | `B800H` 段开始的一段内存（显存） | 写显存 = 在屏幕上显示字符 |
| 键盘接口 | **`60H`** | 读 `60H` = 取得刚按下/松开的键的扫描码 |
| CMOS 芯片 | **`70H`（地址）/ `71H`（数据）** | 读写时间与系统配置（第 14 章） |
| 8259A 中断控制器 | `20H` / `21H` | 管理可屏蔽中断 |
| 定时器/计数器 8253 | `40H ~ 43H` | 定时、发声 |

> **重点**：**「CPU 通过端口访问接口芯片的寄存器，从而控制外设」——这是整个计算机 I/O 体系的基本模型。** 第 14 章的 CMOS（`70H`/`71H`）就是最典型的例子：**两个端口，控制一块芯片。** 本章的键盘（`60H`）同理。

## 15.2 外中断信息

**外中断：由 CPU 外部的事件引发的中断。**

**外中断源举例：**

```
   · 键盘按下或松开（第 15.3 节详细讲）
   · 硬盘读写完成
   · 网卡收到数据包
   · 定时器时间到
   · 打印机完成打印
```

**外中断分为两类（这是本章最重要的分类）：**

### 一、可屏蔽中断（Maskable Interrupt）

**特点：CPU 可以选择「响应」或「不响应」。**

```
   ★ 通过 CPU 的 INTR 引脚进入
   ★ 受标志寄存器中的 IF（Interrupt Flag，bit9）控制：
        IF = 1  →  CPU 响应可屏蔽中断
        IF = 0  →  CPU 不响应可屏蔽中断（「屏蔽」掉了）
```

**控制 `IF` 的两条指令：**

| 指令 | 作用 | 机器码 | 记忆 |
|---|---|---|---|
| **`sti`** | Set IF：`IF = 1`，**允许**可屏蔽中断 | `FB` | **st**i = **st**art / 开启 |
| **`cli`** | Clear IF：`IF = 0`，**禁止**可屏蔽中断 | `FA` | **cl**i = **cl**ear / 关闭 |

**为什么要「关中断」？**

**当程序正在修改关键数据（或者正在安装自己的中断例程）时，如果被中断打断，可能造成数据不一致。这时就暂时 `cli` 关掉可屏蔽中断，做完再 `sti` 打开。**

**注意：第 12 章讲过，中断过程会自动把 `IF` 清 0**——所以进入任何中断处理程序时，可屏蔽中断都是被禁止的（防止中断嵌套），`iret` 时再从栈中恢复原来的 `IF`。

### 二、不可屏蔽中断（Non-Maskable Interrupt，NMI）

**特点：CPU 必须响应，程序员无法禁止。**

```
   ★ 通过 CPU 的 NMI 引脚进入
   ★ 不受 IF 影响（cli 也挡不住）
   ★ 中断类型码固定为 2
```

**为什么需要「不可屏蔽」？**

**因为它用于报告「最紧急的硬件故障」：**

| NMI 触发源 | 说明 |
|---|---|
| 内存奇偶校验错 | RAM 中的数据出错（硬件故障） |
| I/O 通道校验错 | 数据传输出错 |
| 电源故障 | 掉电预警 |

**这些情况必须立刻处理（比如趁电量还没耗尽赶紧保存数据），不能因为程序关了中断就「当没发生」。**

### 外中断与内中断的对比（复习 + 对比）

| 对比项 | 内中断 | 外中断 |
|---|---|---|
| 中断源 | **CPU 内部** | **CPU 外部** |
| 例子 | 除法错误(0)、单步(1)、`into`(4)、`int n` | 键盘(`int 9`)、时钟(`int 8`)、硬盘 |
| 类型码来源 | 指令本身或 CPU 内部逻辑 | **中断控制器（8259A）提供**（NMI 固定为 2） |
| 能否屏蔽 | 不能（程序主动触发） | **可屏蔽中断能被 `cli` 禁止** |
| 处理过程 | **都是中断过程 6 步**（第 12 章） | **完全相同** |

> **重点**：**不管是内中断还是外中断，CPU 拿到类型码之后的处理过程完全一样**——都是「`pushf` → 清 `TF`/`IF` → `push CS` → `push IP` → 查向量表跳转」。**区别只在于「类型码是怎么来的」。** 所以第 12 章的中断过程是「总纲」，本章只是补上「外中断的类型码从哪来」。

## 15.3 PC机键盘的处理过程

**键盘是 PC 上最基本的外设，它的处理过程是理解外中断的绝佳实例。**

### 第一步：键盘内部的扫描

```
   · 键盘上每一个键相当于一个开关
   · 键盘内部有一个芯片，不断扫描每个键的开关状态
   · 按下一个键 → 开关接通 → 芯片产生一个「扫描码」（通码，Make Code）
   · 松开一个键 → 开关断开 → 芯片产生另一个「扫描码」（断码，Break Code）
```

**通码与断码的关系（必背）：**

```
   ★ 断码 = 通码 + 80H
   ★ 也就是「扫描码的最高位置 1」
```

**例子：**

| 键 | 通码（按下） | 断码（松开） |
|---|---|---|
| `g` | `22H` | **`A2H`**（`22H + 80H`） |
| `Esc` | `01H` | **`81H`** |
| `a` | `1EH` | `9EH` |
| `Shift` | `2AH` | `AAH` |
| `Enter` | `1CH` | `9CH` |

**所以判断「是按下还是松开」，只需看扫描码的最高位：**

```
   最高位 = 0  →  按下（通码）
   最高位 = 1  →  松开（断码）
```

### 第二步：扫描码送入 60H 端口

```
   ★ 扫描码被送到主板上键盘接口芯片的一个寄存器中，
     该寄存器的端口地址为 60H。
```

**所以：`in al, 60h` 就能读到刚发生的按键动作的扫描码。**

### 第三步：触发 9 号中断

```
   ★ 键盘输入到达 60H 端口后，键盘接口芯片向 CPU 发出中断请求
     （这是一次可屏蔽中断，通过 INTR 引脚）
   ★ CPU 响应后，通过中断控制器得到中断类型码 9
   ★ 于是转去执行 9 号中断处理程序（由 BIOS 提供）
```

### 第四步：BIOS 的 int 9 中断例程处理

**BIOS 提供的 `int 9` 例程做三件事：**

```
   ① 读出 60H 端口中的扫描码
   
   ② 如果是「字符键」（字母、数字、符号……）的扫描码：
        → 把「扫描码」和它对应的「字符码（ASCII）」送入【键盘缓冲区】
   
   ③ 如果是「控制键」（Ctrl、Shift、Alt）或「切换键」（CapsLock、NumLock、
      ScrollLock、Insert）的扫描码：
        → 把它转变为「状态字节」，写入内存中的【状态字节单元】
```

**键盘缓冲区（Keyboard Buffer）：**

```
   ★ BIOS 在内存中建立的一个【环形缓冲区】
   ★ 可以存 15 个键盘输入
   ★ 每个键盘输入占 2 字节：
        ┌──────────────┬──────────────┐
        │   字符码      │   扫描码      │
        │  （低字节）   │  （高字节）   │
        └──────────────┴──────────────┘
          = AL 的内容      = AH 的内容
          （ASCII 码）    （扫描码）

   ★ 用 int 16h 取键后：AL = 字符码、AH = 扫描码
   ★ 低字节是字符码、高字节是扫描码 —— 别记反（第 17 章会反复用到）
   ★ 有些键没有字符码（如功能键 F1、方向键），此时低字节为 0，
     必须靠高字节的扫描码才能区分按的是哪个键
   ★ int 16h 例程（第 17 章）就是从键盘缓冲区里取键盘输入的
```

**示意图（环形缓冲区，读指针追上写指针表示空）：**

```
      键盘缓冲区（15 个单元，每个 2 字节）
   ┌──────┬──────┬──────┬──────┬─────┬──────┐
   │扫描码│扫描码│扫描码│      │     │      │
   │字符码│字符码│字符码│ 空   │ 空  │ 空   │
   └──────┴──────┴──────┴──────┴─────┴──────┘
     ↑                    ↑
   读指针               写指针
   （int 16h 从这里取）  （int 9 往这里放）
   
   ★ 缓冲区满（存了 15 个）时，再按键就会「丢键」（还会响一声蜂鸣）
```

**状态字节单元：**

```
   ★ 记录控制键和切换键的当前状态（按位表示）
   ★ 例如：CapsLock 是否锁定、Shift 是否按下、Insert 是否处于插入态
   ★ 这些状态由 int 9 例程维护和更新
```

> **重点**：**记住这个链路：「按键 → 键盘芯片产生扫描码 → 送到 `60H` 端口 → 触发 `int 9` → BIOS 例程把扫描码/字符码放进键盘缓冲区 → 程序用 `int 16h` 从缓冲区取按键」。** 理解了它，你就理解了「为什么按键不会丢」——**因为有缓冲区。** 也理解了第 17 章「字符串输入」该怎么写。

## 15.4 编写int 9中断例程

**教材的目标：自己写一个 `int 9` 中断例程，实现「按下 `Esc` 键后改变屏幕颜色」。**

**核心代码（例程主体）：**

```asm
; ===== 新的 int 9 中断例程 =====
int9:
    push ax                     ; ★ 保护现场
    push bx
    push cx
    push es

    in al, 60h                  ; ★ 读 60H 端口，取得扫描码

    ; ★★★ 关键：调用原来的 int 9 例程 ★★★
    pushf                       ; 模拟 int 指令：先把标志寄存器压栈
    call dword ptr cs:[200h]    ; 再远调用原例程（地址存在 CS:200H 处）

    cmp al, 1                   ; ★ Esc 键的通码是 01H
    jne int9ret                 ; 不是 Esc → 直接返回

    ; ===== 是 Esc：改变屏幕颜色 =====
    mov ax, 0b800h
    mov es, ax
    mov bx, 1                   ; 从第一个字符的属性字节开始
    mov cx, 2000                ; 80 × 25 = 2000 个显示位置
s:
    inc byte ptr es:[bx]        ; ★ 属性字节 +1（颜色循环变化）
    add bx, 2                   ; 跳过一个显示位置（字符+属性=2字节）
    loop s

int9ret:
    pop es                      ; ★ 恢复现场（逆序）
    pop cx
    pop bx
    pop ax
    iret                        ; ★ 用 iret 返回
int9end:
    nop
```

### ★★ 为什么必须调用原来的 int 9 例程？★★

**这是本节最重要的一句话：**

```
   如果你写的 int 9 例程「不调用原来的例程」，那么：
   
   ① 扫描码不会被送入键盘缓冲区
   ② 其他程序（包括 DOS）就再也收不到键盘输入了
   ③ 结果：整个系统的键盘「失灵」——你敲什么都没反应
```

**图示对比：**

```
   【正确做法：调用原例程】
   按键 → 60H → 我们的 int9 ──调用──► BIOS 的 int9 ──► 键盘缓冲区
                     │                                    ▲
                     └── 顺便做点自己的事（改颜色）        │
                                              DOS/程序用 int 16h 取键 ✓

   【错误做法：不调用原例程】
   按键 → 60H → 我们的 int9 ──► 做自己的事，然后就 iret 了
                     ✗ 键盘缓冲区永远是空的
                     ✗ int 16h 永远读不到键
                     ✗ 全系统键盘失灵
```

**怎么调用原例程？——先把原入口地址保存起来。**

**在 15.5 的安装程序里，我们把原来的 `int 9` 入口地址存到 `0000:0200`（偏移）和 `0000:0202`（段地址）：**

```asm
    ; ===== 保存原来的 int 9 中断向量到 0:200 =====
    mov ax, 0
    mov es, ax
    push es:[9*4]               ; 取出原 int 9 的入口偏移
    pop  es:[200h]              ; 存到 0:200
    push es:[9*4+2]             ; 取出原 int 9 的入口段地址
    pop  es:[202h]              ; 存到 0:202
```

**然后在新例程里用一行代码调用它：**

```asm
    pushf
    call dword ptr cs:[200h]
```

**这两行代码的含义（必须理解）：**

| 代码 | 作用 |
|---|---|
| `pushf` | **模拟 `int` 指令的动作之一**：把标志寄存器压栈 |
| `call dword ptr cs:[200h]` | **远调用**：从 `CS:200H` 处取一个双字（4 字节）作为「段:偏移」入口地址 |
| `dword ptr` | 声明取的是**双字**（低字 = 偏移，高字 = 段地址）——第 10 章讲过的「`call dword ptr 内存`」形式 |
| `cs:[200h]` | **段前缀**：因为 `0:200` 是「绝对地址」，而我们的例程运行时 `CS = 0`，所以 `cs:200H` 就是 `0:200H` |

**为什么 `call` 之前要 `pushf`？**

**因为 `iret` 会弹出 `FLAGS`。原来的 `int 9` 例程末尾是一条 `iret`，它期望栈顶有 `FLAGS`。我们是用 `call` 而不是 `int` 进入的，`call` 不会自动压 `FLAGS`——所以必须手工 `pushf` 补上，否则原例程的 `iret` 会弹出错误的值，导致标志寄存器错乱。**

**这就是「用 `pushf` + `call far` 模拟一次 `int` 调用」的技巧。**

> **重点**：**「`pushf` + `call dword ptr` = 手工模拟 `int` 指令」——这个技巧叫「中断链（Interrupt Chaining）」。** 它让你能在自己的例程里「借用」系统原有的功能。**记住这个模式：装中断例程时，先保存原向量，在自己的例程里调用它，再做自己的事，最后 `iret`。** 这样既扩展了功能，又不破坏系统。

## 15.5 安装新的int 9中断例程

**完整程序（可直接汇编运行）：**

```asm
assume cs:code
stack segment
    db 128 dup (0)              ; ★ 给中断例程准备一个栈空间
                                ;    （因为中断可能在任何时候发生，
                                ;     原来的 SS:SP 可能指向不可用的位置）
stack ends

code segment
start:
    ; ===== 第一步：设置自己的栈 =====
    mov ax, stack
    mov ss, ax
    mov sp, 128                 ; ★ SS 和 SP 必须紧挨着设置

    ; ===== 第二步：把新例程安装到 0:204 =====
    push cs
    pop  ds                     ; DS = CS（源在代码段里）
    mov ax, 0
    mov es, ax                  ; ES = 0（目的是 0:204）
    mov si, offset int9
    mov di, 204h                ; ★ 从 204H 开始（200H~203H 要存原向量）
    mov cx, offset int9end - offset int9
    cld
    rep movsb

    ; ===== 第三步：保存原来的 int 9 中断向量到 0:200 =====
    mov ax, 0
    mov es, ax
    push es:[9*4]               ; 原入口偏移
    pop  es:[200h]              ; → 存到 0:200
    push es:[9*4+2]             ; 原入口段地址
    pop  es:[202h]              ; → 存到 0:202

    ; ===== 第四步：设置新向量，让 int 9 指向 0:204 =====
    cli                         ; ★ 关中断：改向量期间避免被键盘中断打断
    mov word ptr es:[9*4], 204h     ; ★ 新入口偏移 = 0204H
    mov word ptr es:[9*4+2], 0      ; ★ 新入口段地址 = 0000H
    sti                         ; ★ 开中断

    ; ===== 第五步：返回 DOS =====
    mov ax, 4c00h
    int 21h

; ===== 新的 int 9 中断例程 =====
int9:
    push ax                     ; 保护现场
    push bx
    push cx
    push es

    in al, 60h                  ; 读扫描码

    pushf                       ; ★ 模拟 int 调用
    call dword ptr cs:[200h]    ; ★ 调用原来的 int 9 例程（不能省！）

    cmp al, 1                   ; Esc 键的通码是 01H
    jne int9ret

    ; ===== 按了 Esc：改变屏幕颜色 =====
    mov ax, 0b800h
    mov es, ax
    mov bx, 1
    mov cx, 2000
s:
    inc byte ptr es:[bx]        ; 属性字节 +1
    add bx, 2
    loop s

int9ret:
    pop es                      ; 恢复现场（逆序）
    pop cx
    pop bx
    pop ax
    iret                        ; ★ 用 iret 返回
int9end:
    nop
code ends
end start
```

**运行结果：**

```
   程序返回 DOS 后，键盘依然正常工作（因为原例程被调用了）。
   此时每按一次 Esc 键，屏幕上的颜色就变化一次（属性字节 +1 的效果）。
   按其他键则无任何可见变化，但按键照常被系统接收。
```

**程序结构总结（五步法）：**

| 步骤 | 做什么 | 关键代码 |
|---|---|---|
| ① 设栈 | 给自己的中断例程准备栈 | `mov ax,stack` / `mov ss,ax` / `mov sp,128` |
| ② 安装 | 把例程搬到 `0:204` | `rep movsb`，`di = 204h` |
| ③ 保存原向量 | 原 `int 9` 入口存到 `0:200` | `push es:[9*4]` / `pop es:[200h]` |
| ④ 改向量 | `int 9` 指向 `0:204` | `cli` + `mov word ptr es:[9*4],204h` + `sti` |
| ⑤ 例程体 | 保护现场 → 读 `60H` → **调用原例程** → 自己的处理 → 恢复 → `iret` | `pushf` + `call dword ptr cs:[200h]` |

**几个细节的解释：**

**① 为什么例程要装在 `0:204` 而不是 `0:200`？**

```
   0:200 ~ 0:203  ← 用来存「原 int 9 的入口地址」（4 字节）
   0:204 ~        ← 装我们的新例程
   
   这样安排后，例程里可以用 cs:[200h] 方便地调用原例程
   （因为例程运行时 CS = 0，cs:200h 就是 0:200h）
```

**② 为什么改向量时要 `cli` / `sti`？**

```
   改 9 号向量需要两条指令（先写偏移、再写段地址）。
   如果在这两条指令之间来了键盘中断，CPU 会从「偏移已改、段未改」
   的半个向量跳过去 → 跳到错误的地方 → 系统崩溃。
   
   cli 关掉可屏蔽中断（键盘中断是可屏蔽的），就杜绝了这个窗口。
```

**③ 为什么例程里要重新设栈？**

```
   中断可能在任何程序执行时发生，此时 SS:SP 指向的可能是
   「即将被覆盖」或「空间不足」的区域。
   给中断例程准备一个独立的栈，能避免把数据压到别人的栈里造成破坏。
   （严格来说应该在例程入口处切换 SS:SP，本例简化为在程序开始处设置好。）
```

**④ 为什么 `in al,60h` 读到的 `AL` 在调用原例程后还有效？**

```
   因为 BIOS 的 int 9 例程内部会保护现场（push ax / pop ax），
   所以调用返回后 AL 中仍是刚才读出的扫描码。
   
   ★ 但依赖这一点是有风险的（不属于公开接口约定）。
     更稳妥的写法是先把扫描码存到别的寄存器：
         in al, 60h
         mov ah, al          ; 备份到 AH
         pushf
         call dword ptr cs:[200h]
         cmp ah, 1           ; 用备份判断
```

> **重点**：**「保存原向量 → 调用原向量 → 做自己的事」这个模式，是所有「中断挂钩（Hooking）」程序的标准骨架。** 无论是键盘增强工具、鼠标驱动、还是系统监控软件，内部都是这个结构。**考试如果让你「编写一个 `int 9` 例程实现某某功能」，把这五步写全（尤其是 `pushf` + `call dword ptr cs:[200h]`）就是满分答案。**

## 典型例题

**例 15.1**（题型：通码与断码）
某键被按下时产生的扫描码是 `1EH`，请问松开时产生的扫描码是多少？如果读 `60H` 端口得到 `9EH`，说明发生了什么？如何用一条指令判断「是按下还是松开」？
**解**：
- **断码 = 通码 + `80H`**：`1EH + 80H = 9EH`。
- 读到 `9EH` 说明**这个键被松开了**（`9EH = 1EH` 的最高位置 1）。
- **判断方法**：检查扫描码的最高位。
```asm
    in al, 60h
    test al, 80h            ; 测试最高位
    jz  pressed             ; 最高位 = 0 → 按下
    ; 否则 → 松开
```
**答案**：`9EH`；说明该键被松开；用 `test al, 80h` + `jz`/`jnz` 判断最高位。

**例 15.2**（题型：可屏蔽与不可屏蔽中断）
判断下列说法是否正确并说明理由：
（1）执行 `cli` 后，键盘中断不会被响应。
（2）执行 `cli` 后，内存奇偶校验错引起的中断不会被响应。
（3）中断过程中 `IF` 被自动清 0。
**解**：
- （1）**正确**——键盘中断通过 `INTR` 引脚进入，属于**可屏蔽中断**，`IF = 0` 时 CPU 不响应。
- （2）**错误**——内存奇偶校验错通过 `NMI` 引脚进入，属于**不可屏蔽中断**，**不受 `IF` 影响**，`cli` 挡不住它。
- （3）**正确**——中断过程第 ③ 步就是 `TF = 0`、`IF = 0`，目的是防止中断嵌套（避免中断处理程序自己又被同类中断打断）。**`iret` 时会从栈中恢复原来的 `IF`。**
**答案**：正确、错误、正确。

**例 15.3**（题型：`int 9` 例程的必要操作）
为什么改写 `int 9` 中断例程后，必须在新例程里调用原来的 `int 9` 例程？如果忘了会怎样？
**解**：
- **原因**：BIOS 的 `int 9` 例程负责核心工作——**读出 `60H` 端口的扫描码，把它和对应的字符码送入内存中的键盘缓冲区**（以及维护状态字节）。
- **如果不调用原例程**：扫描码永远不会进入键盘缓冲区 → **所有通过 `int 16h` 读键盘的程序（包括 DOS 命令行本身）都收不到任何按键** → **整个系统的键盘「失灵」**。
- **调用方法**：先保存原向量，再用 `pushf` + `call dword ptr cs:[200h]` 调用。
**答案**：见上。**关键**：新例程只是「附加功能」，不能取代原例程的职责。

**例 15.4**（题型：调用原中断例程的代码含义）
解释下面三行代码的作用，并说明为什么 `call` 之前必须有 `pushf`。
```asm
pushf
call dword ptr cs:[200h]
```
**解**：
- **`pushf`**：把标志寄存器压栈，**模拟 `int` 指令的压栈动作**。
- **`call dword ptr cs:[200h]`**：**远调用**——从 `CS:200H` 处取出一个双字（低字为偏移、高字为段地址）作为目标入口，调用原来的 `int 9` 例程。`dword ptr` 声明取双字，`cs:` 是段前缀（例程运行时 `CS = 0`，所以 `cs:200h` 就是 `0:200h`）。
- **`pushf` 不能省的原因**：原例程末尾是 **`iret`，它会弹出 `FLAGS`**。我们用 `call`（而不是 `int`）进入原例程，`call` **不会自动压 `FLAGS`**。如果不手工补上，`iret` 就会从栈里弹出错误的值送进标志寄存器，**导致标志位错乱、程序行为异常**。
**答案**：见上。**`pushf` + `call far` 合起来等价于手工模拟一条 `int` 指令。**

**例 15.5**（题型：显存属性操作）
在 `int 9` 例程中按下 `Esc` 后改变屏幕颜色，代码是 `mov bx,1` / `mov cx,2000` / `inc byte ptr es:[bx]` / `add bx,2` / `loop s`。请解释 `bx` 为什么从 1 开始、为什么每次加 2、`cx` 为什么是 2000。
**解**：
- **显存每个显示位置占 2 字节**：低字节是字符的 ASCII 码，**高字节（偏移为奇数）是属性字节**。
- **`bx` 从 1 开始**：`1` 是第一个显示位置的**属性字节**偏移（字符在 `0`，属性在 `1`）。
- **每次 `add bx, 2`**：跳过一个完整的显示位置（2 字节），**始终落在属性字节上**。
- **`cx = 2000`**：屏幕 25 行 × 80 列 = **2000 个显示位置**，正好把整屏的属性都改一遍。
- **`inc byte ptr es:[bx]`**：属性值 +1，颜色就往后移一档，**所以每按一次 `Esc` 屏幕颜色就变化一次**。`byte ptr` 声明只改 1 字节，**否则会连带改掉下一个字符**。
**答案**：见上。

**例 15.6**（题型：判断代码正确性）
下面的 `int 9` 例程有什么错误？会导致什么后果？
```asm
int9:
    in al, 60h
    cmp al, 1
    jne ok
    ; ……改变颜色的代码……
ok:
    iret
```
**解**：
- **错误一：没有保护现场。** 例程修改了 `AL`，而中断是**异步**发生的——调用者的 `AX` 可能正在存放重要数据，会被破坏。
- **错误二：★★ 没有调用原来的 `int 9` 例程 ★★。** 这会导致扫描码永远不进入键盘缓冲区，**整个系统键盘失灵**（所有用 `int 16h` 的程序都收不到按键）。
- **错误三：没有考虑按键的「松开」。** `Esc` 的断码是 `81H`，`cmp al, 1` 只匹配按下；这本身不算错（只在按下时改颜色是合理的），但如果要求「按下和松开都响应」，就必须用 `test al, 80h` 判断最高位。
- **错误四：安装时还需要 `cli`/`sti` 保护改向量的过程**（这属于安装代码，不在例程体内）。
**答案**：主要错误是「没保护现场」和「没调用原例程」；后果是**破坏调用者寄存器状态 + 全系统键盘失灵**。正确写法见 15.5 的完整程序。

## 易错点提醒

1. **错**：以为 `cli` 能禁止一切中断。**对**：**`cli` 只能禁止「可屏蔽中断」**（清 `IF`）。**不可屏蔽中断（NMI，类型码固定为 2）不受 `IF` 影响**，`cli` 挡不住。
2. **错**：把不可屏蔽中断的类型码记成别的数。**对**：**不可屏蔽中断的类型码固定为 2**（不是 1；1 是单步中断，0 是除法错误）。
3. **错**：把「断码 = 通码 − `80H`」记反。**对**：**断码 = 通码 + `80H`**，也就是**最高位置 1**。例：`g` 键通码 `22H`、断码 `A2H`。**判断按下/松开就看最高位（`test al,80h`）。**
4. **错**：以为扫描码可以直接当 ASCII 用。**对**：**扫描码是「哪个键」的编号，不是字符编码。** 例如 `g` 键的扫描码是 `22H`，而它的 ASCII 码是 `67H`。**扫描码与 ASCII 的对应关系由 BIOS 的 `int 9` 例程完成转换并存入键盘缓冲区。**
5. **错**：以为键盘按键直接进入程序，没有中间环节。**对**：**中间有「键盘缓冲区」**（BIOS 在内存中建立的环形缓冲区，存 15 个按键，每个 2 字节：**低字节字符码 + 高字节扫描码**）。**程序通过 `int 16h` 从缓冲区取键**——这就是为什么快速敲键不会丢（除非缓冲区满）。
6. **错**：★★ **改写 `int 9` 后不调用原来的例程** ★★。**对**：**必须调用！** 否则扫描码不会进入键盘缓冲区，**整个系统的键盘会失灵**。这是本章最容易犯、后果最严重的错误。
7. **错**：调用原例程时忘了 `pushf`。**对**：**原例程末尾是 `iret`，它会弹出 `FLAGS`**。用 `call` 进入不会自动压 `FLAGS`，**必须手工 `pushf` 补上**，否则标志寄存器被弹出错误的值。
8. **错**：调用原例程时写 `call [200h]` 或 `call word ptr cs:[200h]`。**对**：原例程入口是「段:偏移」共 4 字节，**必须用 `call dword ptr cs:[200h]`（远调用）**。写成 `word ptr` 就变成近调用了，`CS` 不会更新，跳到错误的段里。
9. **错**：安装新例程时忘了 `cli` / `sti`。**对**：**改中断向量需要两条指令（先改偏移、再改段），中间若有中断到来，CPU 会从「半个向量」跳转，导致系统崩溃。** 所以要用 `cli` 关中断、改完再 `sti`。
10. **错**：新例程装到 `0:200` 而原向量也存到 `0:200`，互相覆盖。**对**：**要错开！** 标准做法是：**原向量存 `0:200~0:203`，新例程装 `0:204` 起**。这样例程里用 `cs:[200h]` 就能方便地调用原例程。
11. **错**：以为键盘中断是「不可屏蔽」的。**对**：**键盘中断通过 `INTR` 引脚进入，是可屏蔽中断**（类型码 9）。**所以程序里 `cli` 之后敲键盘没反应是正常的。**
12. **错**：`int 9` 例程里改显存时忘了 `byte ptr`。**对**：**`inc byte ptr es:[bx]`** —— 属性是 1 字节，**不写 `byte ptr` 会按字操作，把下一个字符也一起改掉**。
13. **错**：中断例程里用 `ret` 返回。**对**：**必须用 `iret`**（弹 `IP`、`CS`、`FLAGS` 三个字）。这是第 12、13 章反复强调的铁律。

## 本章小结

- **CPU 不能直接控制外设，它通过「接口芯片」来间接控制**：**接口芯片内部的寄存器就是「端口」，CPU 用 `in`/`out` 访问端口，从而控制外设。**
- **外中断分两类**：
  - **可屏蔽中断**：通过 `INTR` 引脚进入，**受标志寄存器 `IF` 控制**。**`sti` 让 `IF=1`（允许），`cli` 让 `IF=0`（禁止）**。键盘中断属于此类。
  - **不可屏蔽中断（NMI）**：通过 `NMI` 引脚进入，**不受 `IF` 影响**，**类型码固定为 2**；用于内存校验错、电源故障等紧急情况。
- **内中断与外中断的处理过程完全相同（中断过程 6 步）**，区别只在于「中断类型码从哪来」：外中断由中断控制器（8259A）提供。
- **★★ 键盘处理链路：按键 → 键盘芯片产生扫描码 → 送到 `60H` 端口 → 触发 `int 9` → BIOS 例程把扫描码和字符码送入键盘缓冲区 → 程序用 `int 16h` 取键。★★**
- **通码 / 断码**：`断码 = 通码 + 80H`（最高位置 1）；**最高位为 0 表示按下，为 1 表示松开**。例：`Esc` 通码 `01H`、断码 `81H`。
- **键盘缓冲区**：BIOS 建立的**环形缓冲区**，存 **15** 个按键，**每个按键占 2 字节**（**低字节 = 字符码、高字节 = 扫描码**）。
- **★★★ 改写 `int 9` 后必须调用原来的例程**，否则扫描码进不了键盘缓冲区，**全系统键盘失灵**。调用方式：**先保存原向量到 `0:200`，再在例程里 `pushf` + `call dword ptr cs:[200h]`**。★★★
- **`pushf` + `call far ptr` = 手工模拟一条 `int` 指令**（`pushf` 是为了让原例程末尾的 `iret` 有正确的 `FLAGS` 可弹）。
- **安装新 `int 9` 例程五步法**：① 设置自己的栈；② `rep movsb` 把例程搬到 `0:204`；③ 保存原向量到 `0:200`；④ **`cli`** 改向量（`es:[9*4] = 204h`、`es:[9*4+2] = 0`）**`sti`**；⑤ 例程体按「保护现场 → 读 `60H` → 调用原例程 → 自己的处理 → 逆序恢复 → `iret`」编写。

> **一句话记住本章**：**「外中断分两种——可屏蔽的看 `IF`（`sti`/`cli`），不可屏蔽的（类型码 2）挡不住」；键盘走「扫描码 → `60H` → `int 9` → 键盘缓冲区 → `int 16h`」这条路，断码 = 通码 + `80H`；自己写 `int 9` 时，「保护现场 + `pushf` + `call dword ptr cs:[200h]` 调用原例程 + `iret`」三件事一件都不能少。**

## 自测题

**1.** CPU 如何控制外设？端口在其中扮演什么角色？
**答**：**CPU 通过「接口芯片」间接控制外设**。各种接口芯片内部都有一组寄存器，**CPU 把这些寄存器当作「端口」用 `in`/`out` 来访问**——向端口写数据等于向外设发命令或传数据，从端口读数据等于取得外设的状态或数据。

**2.** 外中断分为哪两类？各自的特点是什么？
**答**：**可屏蔽中断**——通过 `INTR` 引脚进入，**受 `IF` 控制**，`IF=1` 响应、`IF=0` 不响应，程序员可用 `sti`/`cli` 开关；**不可屏蔽中断（NMI）**——通过 `NMI` 引脚进入，**不受 `IF` 影响，CPU 必须响应**，**中断类型码固定为 2**，用于内存校验错、电源故障等紧急情况。

**3.** `sti` 和 `cli` 的作用是什么？机器码是什么？
**答**：**`sti`（`FB`）：置 `IF = 1`，允许可屏蔽中断；`cli`（`FA`）：清 `IF = 0`，禁止可屏蔽中断。**

**4.** 不可屏蔽中断的类型码是多少？它通常用于报告什么？
**答**：类型码固定为 **2**。通常用于报告**最紧急的硬件故障**：内存奇偶校验错、I/O 通道校验错、电源故障（掉电预警）等。

**5.** 什么是通码和断码？它们之间是什么关系？举例说明。
**答**：**通码（Make Code）是按下键时键盘芯片产生的扫描码；断码（Break Code）是松开键时产生的扫描码。** 关系是：**断码 = 通码 + `80H`**（把通码的最高位置 1）。例如 `g` 键通码 `22H`、断码 `A2H`；`Esc` 键通码 `01H`、断码 `81H`。

**6.** 键盘的扫描码送到哪个端口？读到扫描码后如何判断是按下还是松开？
**答**：送到 **`60H`** 端口（用 `in al, 60h` 读取）。**判断方法是看扫描码的最高位**：最高位为 0 是按下（通码），为 1 是松开（断码）。可用 `test al, 80h` + `jz`/`jnz` 判断。

**7.** 描述从「按下键盘上的 `a` 键」到「程序用 `int 16h` 读到该键」的完整过程。
**答**：① 键盘内部芯片扫描到 `a` 键接通，产生扫描码（通码 `1EH`）；② 扫描码被送到主板键盘接口芯片的 `60H` 端口；③ 键盘接口向 CPU 发出可屏蔽中断请求（`INTR`）；④ CPU 响应，取得类型码 9，执行中断过程跳转到 `int 9` 例程；⑤ **BIOS 的 `int 9` 例程读出 `60H` 中的扫描码，把它和对应的字符码 `61H`（`'a'`）一起送入键盘缓冲区**；⑥ 程序执行 `int 16h`，从键盘缓冲区取出这个按键。

**8.** 键盘缓冲区是什么？能存多少个按键？每个按键占几个字节？
**答**：**键盘缓冲区是 BIOS 在内存中建立的一个环形缓冲区**，用于暂存键盘输入。**可以存 15 个键盘输入**，**每个键盘输入占 2 个字节**——**低字节存字符码（ASCII，取键后放在 `AL`）、高字节存扫描码（取键后放在 `AH`）**。**别记反**：**低字节是字符码、高字节是扫描码**（用 `int 16h` 取键后 `AL` = 字符码、`AH` = 扫描码）。对于没有字符码的键（功能键、方向键），低字节为 0，只能靠高字节的扫描码区分。

**9.** 改写 `int 9` 中断例程后，为什么必须调用原来的 `int 9` 例程？
**答**：**因为原例程负责把扫描码和字符码送入键盘缓冲区**。如果新例程不调用它，扫描码就永远不会进入键盘缓冲区，**所有用 `int 16h` 读取键盘的程序（包括 DOS 本身）都收不到任何按键**，结果是**整个系统的键盘失灵**。

**10.** 解释 `pushf` / `call dword ptr cs:[200h]` 这两条指令的作用。为什么 `pushf` 不能省？
**答**：这两条指令**合起来模拟一条 `int` 指令**：`pushf` 压入标志寄存器，`call dword ptr cs:[200h]` 从 `CS:200H` 取出一个双字（偏移 + 段地址）作远调用，进入原来的 `int 9` 例程。**`pushf` 不能省，因为原例程末尾是 `iret`，它会弹出 `FLAGS`**——用 `call` 进入不会自动压 `FLAGS`，不补上的话 `iret` 会弹出错误的值，导致标志寄存器错乱。

**11.** 为什么 `call dword ptr cs:[200h]` 中必须写 `dword ptr`？写成 `word ptr` 会怎样？
**答**：**因为中断例程的入口地址是「段:偏移」共 4 字节**，`dword ptr` 表示取双字（低字为偏移、高字为段地址），构成一次**远调用**。**若写成 `word ptr`，就变成近调用**——只取偏移、不更新 `CS`，于是会跳到「当前代码段 + 该偏移」处，**而不是原例程真正的地址**，必然跳到错误的地方。

**12.** 安装新的 `int 9` 例程时，为什么改中断向量要用 `cli` 和 `sti` 包起来？
**答**：**因为改写一个 4 字节的中断向量需要两条指令（先写偏移、再写段地址）。** 如果在这两条指令之间来了键盘中断，CPU 会从「**新的偏移 + 旧的段地址**」这个「半个向量」处跳转，跳到完全错误的地方，**导致系统崩溃**。用 `cli` 暂时关掉可屏蔽中断（键盘中断属于可屏蔽中断），改完再 `sti`，就消除了这个危险窗口。

**13.** 在 `int 9` 例程里把例程代码装在 `0:204`、原向量存在 `0:200`，这样安排有什么好处？
**答**：**好处是让例程内部能方便地调用原例程。** 例程运行时 `CS = 0`，所以原来存在 `0000:0200` 的双字入口地址可以直接用 **`cs:[200h]`** 访问，不需要额外保存段地址；同时两者不重叠（`0:200~0:203` 存地址，`0:204` 起放代码）。

**14.** 为什么中断例程里通常要准备一个独立的栈？
**答**：**因为中断可能在任何程序执行时发生**，此时 `SS:SP` 指向的可能是「空间不足」或「即将被覆盖」的区域。**给中断例程准备独立的栈，可以避免把数据压到别的程序的栈里造成破坏**。（严格的做法是在例程入口处切换 `SS:SP` 并在返回前恢复。）
