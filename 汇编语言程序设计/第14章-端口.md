## 14.1 端口的读写

**端口（Port）：CPU 与外部设备通信的「窗口」。**

**和内存一样，CPU 对端口也有「读」和「写」两种操作，但用的是专门的指令 `in` / `out`。**

**端口的数量：**

```
   端口地址范围：0 ~ 65535（共 65536 = 64K 个端口）
```

**为什么是 64K 个端口？因为端口地址用 16 位表示（`0000H ~ FFFFH`），与内存的「段内 64KB」是同一个宽度。**

**`in` / `out` 指令的用法（只有这 4 种形式，务必记牢）：**

| 指令 | 数据宽度 | 端口号范围 | 说明 |
|---|---|---|---|
| `in al, 端口号` | 8 位 | `00H ~ FFH` | 从端口读 1 字节到 `AL` |
| `in ax, 端口号` | 16 位 | `00H ~ FFH` | 从端口读 1 个字到 `AX` |
| `in al, dx` | 8 位 | `0000H ~ FFFFH` | 端口号放在 `DX` 里 |
| `in ax, dx` | 16 位 | `0000H ~ FFFFH` | 端口号放在 `DX` 里 |
| `out 端口号, al` | 8 位 | `00H ~ FFH` | 把 `AL` 写到端口 |
| `out 端口号, ax` | 16 位 | `00H ~ FFH` | 把 `AX` 写到端口 |
| `out dx, al` | 8 位 | `0000H ~ FFFFH` | 端口号放在 `DX` 里 |
| `out dx, ax` | 16 位 | `0000H ~ FFFFH` | 端口号放在 `DX` 里 |

**两条硬性规定（最容易出错的地方）：**

```
   ★ 规定一：端口号在 0000H ~ FFFFH 之间，用 DX 存放；
             在 00H ~ FFH 之间，可以直接写在指令里。
   ★★ 规定二：端口读写的数据只能放在 AL（8 位）或 AX（16 位）中！
             不能用 BL、CX、SI 等其他寄存器！
```

**非法写法示例：**

| 非法写法 | 违反的规定 | 正确写法 |
|---|---|---|
| `in al, 200h` | 端口号 > `FFH` 不能直接写 | `mov dx, 200h` / `in al, dx` |
| `out 60h, bl` | 数据只能用 `AL`/`AX` | `mov al, bl` / `out 60h, al` |
| `in bx, 60h` | 数据只能用 `AL`/`AX` | `in ax, 60h` 或 `in al, 60h` |
| `out dx, bx` | 数据只能用 `AL`/`AX` | `mov ax, bx` / `out dx, ax` |

**端口读写的示意：**

```
       CPU                                外部设备
   ┌──────────┐                        ┌────────────┐
   │   AL/AX  │◄──── in  ──────────────│            │
   │          │                        │   端口 n    │
   │          │───── out ─────────────►│            │
   └──────────┘                        └────────────┘
       地址总线送出端口号（0 ~ 65535），
       数据总线传送 8 位或 16 位数据
```

> **重点**：**为什么数据只能用 `AL`/`AX`？因为 CPU 与端口之间的数据通路是硬件专门设计的——8086 的 I/O 指令只编码了「累加器」一种数据寄存器。** 这是硬件层面的限制，不是汇编器的规定，所以「先把值搬到 `AL`/`AX` 再 `out`」是唯一的办法。

**完整例子：读 CMOS RAM 的 2 号单元（分钟）。**

```asm
assume cs:code
code segment
start:
    mov al, 2               ; 要访问的 CMOS RAM 单元地址（2 号单元 = 分）
    out 70h, al             ; ★ 先把单元地址送到 70h 端口（地址端口）
    in  al, 71h             ; ★ 再从 71h 端口读出该单元的内容（数据端口）
                            ;    此时 AL = 分的 BCD 码

    mov ax, 4c00h
    int 21h
code ends
end start
```

**这段代码体现了 CMOS RAM 的「先给地址、再读数据」访问方式——下面 14.2 会详细解释。**

## 14.2 CMOS RAM芯片

**CMOS RAM 是主板上的一块可读写的存储器芯片。**

**它的两个特点（都很重要）：**

| 特点 | 说明 |
|---|---|
| **由电池供电** | 关机后内容不丢失（这就是为什么电脑拔掉电源后时间还在走） |
| **容量小、用途专一** | 只存**时间信息**和**系统配置信息**（内存大小、硬盘参数、启动顺序等） |

**CMOS RAM 的两个端口（必背）：**

```
   ★ 70H 端口：地址端口 —— 用来「指出要访问哪个单元」
   ★ 71H 端口：数据端口 —— 用来「读出或写入该单元的内容」
```

**访问流程（固定的两步）：**

```
   第一步：把要访问的单元地址写入 70H 端口
   第二步：从 71H 端口读出数据（或向 71H 端口写入数据）
```

**示意：**

```
      CPU                                   CMOS RAM
   ┌────────┐        out 70h, al        ┌──────────────┐
   │   AL   │──────────────────────────►│ 地址寄存器    │
   ├────────┤                           │      │        │
   │        │        in al, 71h         │      ▼        │
   │   AL   │◄──────────────────────────│  ┌─────────┐  │
   └────────┘                           │  │ 单元 0  │  │
                                        │  │ 单元 1  │  │
                                        │  │  ……     │  │
                                        │  │ 单元 7FH│  │
                                        │  └─────────┘  │
                                        └──────────────┘
   先把地址送进 70H，再通过 71H 读写数据 —— 这叫「端口间接寻址」
```

**为什么要用「两个端口」这种方式？**

**真正的原因是：CMOS 芯片只有一组 8 位数据线，却要承担「传地址」和「传数据」两种任务，必须有办法区分这两类字节。芯片用「端口号」来区分——写到 `70H` 的字节被当作「要访问哪个单元」，读写 `71H` 的字节被当作「该单元的内容」。**

> **⚠ 注意：不要理解成「因为地址装不下」。** `0 ~ 7FH` 这 128 个单元地址只需要 **7 位**，一个 8 位端口完全装得下。**所以这里根本不是位宽不够的问题，而是「一根数据线两用、靠端口号分流」的设计。**
>
> **这种「地址端口 + 数据端口」的模式在外设芯片里非常常见**（8259 中断控制器、8255 并行接口都是这个套路）——**芯片内部有一组寄存器，先写地址选中它，再读写数据。**

**访问流程（固定的两步）：**

```
   第一步：把要访问的单元地址写入 70H 端口
   第二步：从 71H 端口读出数据（或向 71H 端口写入数据）
```

**示意：**

```
   ┌────────┐                          ┌───────────────┐
   │   AL   │   out 70h, al   ────────►│   地址寄存器  │
   ├────────┤                          │       │       │
   │        │   in al, 71h    ◄────────│       ▼       │
   │   AL   │                          │  ┌─────────┐  │
   └────────┘                          │  │ 单元 0  │  │
                                       │  │ 单元 1  │  │
                                       │  │   ……   │  │
                                       │  │ 单元 7FH│  │
                                       │  └─────────┘  │
                                       └───────────────┘
   先把地址送进 70H，再通过 71H 读写数据 —— 这叫「端口间接寻址」
```

**CMOS RAM 中时间信息的存放单元（必须记住）：**

| 单元地址 | 存放内容 | 单元地址 | 存放内容 |
|---|---|---|---|
| `0` | **秒** | `7` | **日** |
| `2` | **分** | `8` | **月** |
| `4` | **时** | `9` | **年** |
| `1` | 秒报警 | `3` | 分报警 |
| `5` | 时报警 | `6` | 星期 |

**注意：这些时间值都以「BCD 码」的形式存放！**

**什么是 BCD 码（Binary-Coded Decimal，二-十进制编码）？**

```
   ★ 用 4 位二进制表示 1 位十进制数字（0~9）
   
   例如：十进制 26
       十位 2 → 0010B
       个位 6 → 0110B
       合起来 → 0010 0110B = 26H
   
   ★ 所以 BCD 码 26H 表示的是十进制数 26，不是十六进制数 26H（=38）！
```

**BCD 码与真值的对照：**

| 十进制数 | BCD 码（十六进制写法） | 若当成普通十六进制数 |
|---|---|---|
| 9 | `09H` | 9 |
| 10 | `10H` | 16 |
| 26 | `26H` | 38 |
| 59 | `59H` | 89 |
| 99 | `99H` | 153 |

**这就是为什么读出来的时间值不能直接当数字用，也不能直接送去显示——必须先转换。**

> **重点**：**「先向 70H 送地址、再从 71H 读数据」这个两步流程，不仅是 CMOS 的访问方式，也是很多外设芯片的通用模式（如 8259 中断控制器、8255 并行接口）。** 记住这个套路，以后看硬件手册就不会陌生。

## 14.3 shl和shr指令

**`shl`（Shift Logical Left，逻辑左移）和 `shr`（Shift Logical Right，逻辑右移）是移位指令。**

**`shl` 的规则：**

```
   ★ 把各位向左移，最高位移入 CF，最低位补 0
   
   移位前：  ┌─┬─┬─┬─┬─┬─┬─┬─┐
             │1│0│1│1│0│0│1│0│   = 0B2H
             └─┴─┴─┴─┴─┴─┴─┴─┘
              ▲               ▲
           最高位           最低位
              │
              └──► CF = 1
   
   左移 1 位：┌─┬─┬─┬─┬─┬─┬─┬─┐  ┌─┐
             │0│1│1│0│0│1│0│0│  │1│ ← CF
             └─┴─┴─┴─┴─┴─┴─┴─┘  └─┘
                                 最高位移进 CF
              最低位补 0
   
   结果：0110 0100B = 64H，CF = 1
```

**`shr` 的规则：**

```
   ★ 把各位向右移，最低位移入 CF，最高位补 0
   
   移位前：  1011 0010B = 0B2H
   
   右移 1 位：
             ┌─┐  ┌─┬─┬─┬─┬─┬─┬─┬─┐
        CF ──┘    │0│1│0│1│1│0│0│1│
             = 0  └─┴─┴─┴─┴─┴─┴─┴─┘
                    最高位补 0
                    最低位 0 移进 CF → CF = 0
   
   结果：0101 1001B = 59H，CF = 0
```

**指令格式（8086 的规定）：**

| 格式 | 说明 |
|---|---|
| `shl al, 1` | **移位 1 位，可以直接写 1** |
| `shr al, 1` | 同上 |
| `shl al, cl` | **移位位数 > 1 时，必须放进 `CL`** |
| `shr al, cl` | 同上 |

**★ 8086 的限制：8086 只支持「移 1 位」和「移 `CL` 位」，不支持 `shl al, 4` 这种立即数写法！**

```asm
    ; ✗ 8086 上非法（后来的 80186 及以后才支持）
    shl al, 4

    ; ✓ 正确写法
    mov cl, 4
    shl al, cl
```

**对标志位的影响：**

| 标志位 | 影响 |
|---|---|
| **`CF`** | **最后移出的一位**（`shl` 移出最高位，`shr` 移出最低位） |
| **`SF`** | 按移位后的结果设置（结果最高位） |
| **`ZF`** | 按移位后的结果设置（结果是否为 0） |
| **`PF`** | 按移位后的结果设置（低 8 位中 1 的个数） |
| **`OF`** | **只在移位 1 位时有意义**：若移位后符号位改变则 `OF=1`（`shl` 时是「最高位与 CF 不同」，`shr` 时是「原最高位为 1」） |
| `AF` | 未定义 |

**移位与乘除法的关系（非常实用）：**

```
   ★ 左移 1 位 = 乘 2（前提：不溢出）
   ★ 右移 1 位 = 除以 2（无符号数，向下取整）
```

| 指令 | 效果 | 例子（`AL = 05H`） |
|---|---|---|
| `shl al, 1` | `AL × 2` | `AL = 0AH` |
| `shr al, 1` | `AL ÷ 2` | `AL = 02H`（`05H ÷ 2 = 2 余 1`，`CF = 1`） |

**`shl` / `shr` 与 `mul` / `div` 的对比：**

| 对比项 | `shl` / `shr` | `mul` / `div` |
|---|---|---|
| 速度 | **快**（1 个时钟周期级别） | 慢（几十个时钟周期） |
| 适用场景 | **乘以/除以 2 的幂** | 一般乘除法 |
| 位数限制 | 只能做 2 的幂次 | 任意 |
| 溢出处理 | 只设置 `CF`/`OF` 标志，**结果照样截断** | 16 位乘法结果放 `DX:AX` |

> **重点**：**编译器优化时最常用的技巧之一就是「把乘 2 换成 `shl`」。** 例如 C 语言里的 `x * 8` 会被编译成 `shl ax, 1` 执行三次（或 `mov cl,3` + `shl ax,cl`）。**理解这一点，你就理解了「为什么位运算是快的」。**

**拆 BCD 码的经典用法（为 14.4 做准备）：**

**假设 `AL` 里是一个 BCD 码（如 `26H`，表示十进制的 26），要把它拆成十位和个位：**

```asm
    mov al, 26h             ; AL = 0010 0110B（BCD 码，表示十进制 26）
    mov ah, al              ; 复制一份到 AH

    ; ===== 取十位：把高 4 位移到低 4 位 =====
    mov cl, 4
    shr ah, cl              ; AH = 0000 0010B = 2（十位）
                            ; ★ 用 shr 而不是 shl，因为要把高位移下来

    ; ===== 取个位：把高 4 位清零 =====
    and al, 00001111b       ; AL = 0000 0110B = 6（个位）
                            ; ★ 用 and 屏蔽高 4 位

    ; ===== 转成 ASCII 码（才能显示） =====
    add ah, 30h             ; 2 → 32H = '2'
    add al, 30h             ; 6 → 36H = '6'
```

**为什么 `add 30H` 就能变成 ASCII？**

```
   ASCII 码中： '0' = 30H，'1' = 31H，'2' = 32H，…… '9' = 39H
   
   数字 n 的 ASCII 码 = 30H + n
   
   因为 ASCII 表把 '0'~'9' 连续排列，从 30H 开始。
```

| 数字（真值） | + `30H` | ASCII 字符 |
|---|---|---|
| 0 | `30H` | `'0'` |
| 2 | `32H` | `'2'` |
| 6 | `36H` | `'6'` |
| 9 | `39H` | `'9'` |

## 14.4 CMOS RAM中存储的时间信息

**目标：从 CMOS RAM 读出一个时间单元（如年），把它以「两位数字」的形式显示在屏幕上。**

**需要经过三个阶段：**

```
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │ ① 从 CMOS RAM │   │ ② BCD 码拆成  │   │ ③ 转 ASCII   │
   │    读出 BCD 码 │──►│   十位和个位   │──►│   并写显存    │
   │  (如 26H)     │   │  (2 和 6)     │   │ ('2' 和 '6') │
   └──────────────┘   └──────────────┘   └──────────────┘
```

**完整程序：在屏幕第 12 行第 40 列显示当前年份的后两位。**

```asm
assume cs:code
code segment
start:
    ; ===== ① 从 CMOS RAM 的 9 号单元读出年份 =====
    mov al, 9
    out 70h, al                 ; ★ 先把单元地址 9 送到 70H 端口
    in  al, 71h                 ; ★ 再从 71H 端口读出数据
                                ;    此时 AL = 年的 BCD 码（如 26H 表示 2026 年）

    ; ===== ② 把 BCD 码拆成十位和个位 =====
    mov ah, al                  ; 把 BCD 码复制一份到 AH
    mov cl, 4
    shr ah, cl                  ; ★ AH 右移 4 位 → AH = 十位（如 2）
    and al, 00001111b            ; ★ AL 与 00001111B → AL = 个位（如 6）

    ; ===== ③ 转成 ASCII 码 =====
    add ah, 30h                 ; 十位 → ASCII（2 + 30H = 32H = '2'）
    add al, 30h                 ; 个位 → ASCII（6 + 30H = 36H = '6'）

    ; ===== ④ 显示到屏幕第 12 行第 40 列 =====
    mov bx, 0b800h
    mov es, bx                  ; ★ ES 指向显存
    mov di, 160*12 + 40*2       ; ★ 第 12 行第 40 列
    mov byte ptr es:[di], ah    ; 写十位字符
    mov byte ptr es:[di+1], 2   ; 写属性：黑底绿字
    mov byte ptr es:[di+2], al  ; 写个位字符
    mov byte ptr es:[di+3], 2   ; 写属性

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：屏幕第 12 行第 40 列显示两个绿色数字，如 `26`（表示 2026 年）。

**内存/显存布局示意：**

```
   ES:DI ──► ┌────────┬────────┬────────┬────────┐
             │  '2'   │  02H   │  '6'   │  02H   │
             │ (32H)  │ (属性) │ (36H)  │ (属性) │
             └────────┴────────┴────────┴────────┘
             ES:[di]  ES:[di+1] ES:[di+2] ES:[di+3]
             
             十位字符            个位字符
             每个字符占 2 字节（字符 + 属性），所以相邻字符偏移 +2
```

**如果把时间信息做成「显示当前时间」的完整程序（时:分:秒）：**

> **★ 先说清屏幕位置**：第 12 行、从第 40 列开始显示 `HH:MM:SS` 共 8 个字符。
> 显存偏移 = `行 × 160 + 列 × 2`（每字符 2 字节：ASCII + 属性）。
> 第 12 行 = `160 × 12 = 1920`；于是：
>
> | 显示内容 | 列 | 显存偏移 | 算式 |
> |---|---|---|---|
> | 时的十位 | 40 | **2000** | `1920 + 40×2` |
> | 时的个位 | 41 | 2002 | 偏移 +2 |
> | `:` | 44 | **2008** | `1920 + 44×2` |
> | 分的十位 | 46 | **2012** | `1920 + 46×2` |
> | `:` | 50 | **2020** | `1920 + 50×2` |
> | 秒的十位 | 52 | **2024** | `1920 + 52×2` |

```asm
assume cs:code
code segment
start:
    mov ax, 0b800h
    mov es, ax                  ; ★ ES 指向显存，主程序设一次

    ; ===== 显示"时"（CMOS 4 号单元） =====
    mov al, 4
    out 70h, al                 ; 先送单元地址到 70h
    in  al, 71h                 ; 再从 71h 读数据
    mov di, 160*12+40*2         ; ★★ 关键：调用前必须设 DI = 显存偏移
    call show_bcd

    ; ===== 显示":"分隔符 =====
    mov byte ptr es:[160*12+44*2], ':'
    mov byte ptr es:[160*12+44*2+1], 2      ; 属性 2 = 黑底绿字

    ; ===== 显示"分"（CMOS 2 号单元） =====
    mov al, 2
    out 70h, al
    in  al, 71h
    mov di, 160*12+46*2         ; ★★ 换位置：重新设 DI
    call show_bcd

    ; ===== 显示":"分隔符 =====
    mov byte ptr es:[160*12+50*2], ':'
    mov byte ptr es:[160*12+50*2+1], 2

    ; ===== 显示"秒"（CMOS 0 号单元） =====
    mov al, 0
    out 70h, al
    in  al, 71h
    mov di, 160*12+52*2         ; ★★ 换位置：重新设 DI
    call show_bcd

    mov ax, 4c00h
    int 21h

; ===== 子程序：把 AL 中的 BCD 码显示在显存 ES:DI 处 =====
; 入口参数：AL = BCD 码，DI = 显存偏移（★ 必须由调用者在 call 之前设置）
; 说明：子程序会占用 ES，但主程序本来就只用 ES 指向显存，所以无需保护
show_bcd:
    push ax
    push bx
    push cx

    mov ah, al                  ; 复制一份 BCD 码
    mov cl, 4
    shr ah, cl                  ; AH = 十位（高 4 位移下来）
    and al, 00001111b           ; AL = 个位（屏蔽高 4 位）

    add ah, 30h                 ; 数字 + 30H = 对应 ASCII
    add al, 30h

    mov bx, 0b800h
    mov es, bx                  ; 保证 ES 指向显存（子程序自足）
    mov byte ptr es:[di], ah    ; 写十位字符
    mov byte ptr es:[di+1], 2   ; 写十位属性
    mov byte ptr es:[di+2], al  ; 写个位字符
    mov byte ptr es:[di+3], 2   ; 写个位属性

    pop cx
    pop bx
    pop ax
    ret
code ends
end start
```

**运行结果**：屏幕第 12 行第 40 列起显示形如 `14:35:07` 的时间（具体数值取决于运行时刻）。

> **★ 这个程序最容易写错的地方就是 `DI`**：`show_bcd` 用 `ES:[DI]` 和 `ES:[DI+2]` 定位，**如果调用前不设 `DI`，三次调用就会写到同一个未定义的地址上**，屏幕上什么也看不到（或看到一堆乱码）。**规矩：凡是「入口参数」里写了某个寄存器，`call` 之前就必须给它赋值——这是子程序题的第一号扣分点。** 这里三次调用前各写了一条 `mov di, 160*12+XX*2`，就是这个道理。

> **重点**：**这段「读 CMOS → 拆 BCD → 转 ASCII → 写显存」的四步流程，是本章所有题目的统一套路。** 考试里如果让你「读取 CMOS RAM 的某单元并显示」，把这四步写出来就基本满分。**唯一需要留心的细节是：`shr` 用来取高位（把高 4 位移下来），`and` 用来取低位（屏蔽高 4 位）——这两个操作不能写反。**

## 典型例题

**例 14.1**（题型：`in`/`out` 指令的合法性判断）
判断下面各条指令是否正确，错误的说明原因并改正。
（1）`in al, 60h`　（2）`out 60h, bl`　（3）`in al, 200h`　（4）`out dx, ax`　（5）`in bx, 80h`
**解**：
- （1）**正确**——端口号 `60H ≤ FFH` 可以直接写，数据用 `AL`。
- （2）**错误**——数据只能用 `AL`/`AX`，不能用 `BL`。改正：`mov al, bl` / `out 60h, al`。
- （3）**错误**——端口号 `200H > FFH`，不能直接写在指令里。改正：`mov dx, 200h` / `in al, dx`。
- （4）**正确**——端口号在 `DX` 里，数据是 `AX`。
- （5）**错误**——数据只能用 `AL`/`AX`，不能用 `BX`。改正：`in ax, 80h` 或 `in al, 80h`。
**答案**：正确、错误、错误、正确、错误。

**例 14.2**（题型：CMOS RAM 的访问）
写出「读出 CMOS RAM 的 4 号单元（小时）内容并存入 `AH`」的代码。
**解**：
```asm
    mov al, 4               ; ★ 第一步：把单元地址送到 70H 端口
    out 70h, al
    in  al, 71h             ; ★ 第二步：从 71H 端口读出数据
    mov ah, al              ; 保存到 AH
```
**答案**：见上。**关键**：**必须先把地址送到 `70H`，才能从 `71H` 读到对应单元的内容**——顺序不能颠倒，也不能只做第二步。

**例 14.3**（题型：`shl`/`shr` 的移位结果与标志位）
`AL = 0B2H = 1011 0010B`。分别执行 `shl al, 1` 和 `shr al, 1` 后，`AL` 和 `CF` 各是多少？
**解**：
- **`shl al, 1`**：各位左移，最高位 `1` 移入 `CF`，最低位补 0。
  `1011 0010B → 0110 0100B = 64H`，**`CF = 1`**。
- **`shr al, 1`**：各位右移，最低位 `0` 移入 `CF`，最高位补 0。
  `1011 0010B → 0101 1001B = 59H`，**`CF = 0`**。

**答案**：`shl` → `AL = 64H`、`CF = 1`；`shr` → `AL = 59H`、`CF = 0`。
**验证**：`0B2H = 178`。`178 × 2 = 356`，`356 mod 256 = 100 = 64H` ✓（乘 2 溢出被截断，`CF` 记录了移出的 1）。`178 ÷ 2 = 89 = 59H` ✓。

**例 14.4**（题型：BCD 码拆解）
`AL = 59H`（BCD 码，表示十进制 59）。写出把它拆成十位和个位并转成 ASCII 码的代码。
**解**：
```asm
    mov al, 59h                 ; AL = 0101 1001B（BCD 码 59）
    mov ah, al                  ; 复制到 AH
    mov cl, 4
    shr ah, cl                  ; ★ AH = 0000 0101B = 5（十位）
    and al, 00001111b            ; ★ AL = 0000 1001B = 9（个位）

    add ah, 30h                 ; AH = 5 + 30H = 35H = '5'
    add al, 30h                 ; AL = 9 + 30H = 39H = '9'
```
**答案**：`AH = 35H`（字符 `'5'`）、`AL = 39H`（字符 `'9'`）。
**关键**：**取高位用 `shr`（把高 4 位移到低位），取低位用 `and 00001111B`（屏蔽高 4 位）——两者不能互换。**

**例 14.5**（题型：BCD 码与真值的区别）
CMOS RAM 的 9 号单元读出的值是 `26H`。它表示的年份是多少？如果把它当成无符号数直接送给显示程序，会显示什么数字？
**解**：
- **`26H` 是 BCD 码**：高 4 位 `0010B = 2` 是十位，低 4 位 `0110B = 6` 是个位。
  **所以它表示十进制数 26**（即 2026 年）。
- **如果当普通无符号数处理**：`26H = 2×16 + 6 = 38`，会显示 `38`——**完全错误**。
**答案**：表示 26；若按普通十六进制处理会错误地显示 38。
**关键**：**BCD 码 `26H` ≠ 数值 `26H`。这就是必须做 `shr` + `and` + `add 30H` 三步转换的原因。**

**例 14.6**（题型：综合编程）
编程：读取 CMOS RAM 的 0 号单元（秒），把它显示在屏幕第 20 行第 10 列。
**解**：
```asm
assume cs:code
code segment
start:
    ; ===== ① 读 CMOS RAM 的 0 号单元 =====
    mov al, 0
    out 70h, al
    in  al, 71h                 ; AL = 秒的 BCD 码

    ; ===== ② 拆成十位和个位 =====
    mov ah, al
    mov cl, 4
    shr ah, cl                  ; AH = 十位
    and al, 00001111b            ; AL = 个位

    ; ===== ③ 转 ASCII =====
    add ah, 30h
    add al, 30h

    ; ===== ④ 显示到屏幕第 20 行第 10 列 =====
    mov bx, 0b800h
    mov es, bx
    mov di, 160*20 + 10*2       ; ★ 第 20 行第 10 列
    mov byte ptr es:[di], ah
    mov byte ptr es:[di+1], 2
    mov byte ptr es:[di+2], al
    mov byte ptr es:[di+3], 2

    mov ax, 4c00h
    int 21h
code ends
end start
```
**运行结果**：屏幕第 20 行第 10 列显示当前秒数的两位绿色数字（如 `07`）。
**答案**：见上。**关键**：显存偏移公式 `行 × 160 + 列 × 2`；**写字符后必须紧跟写属性字节**。

## 易错点提醒

1. **错**：写 `in al, 200h`。**对**：**端口号超过 `FFH` 时必须先送进 `DX`**，再写成 `in al, dx`。端口号 `00H~FFH` 才能直接写在指令里。
2. **错**：写 `out 60h, bl` 或 `in bx, 60h`。**对**：**端口读写的数据只能用 `AL`（8 位）或 `AX`（16 位）**，这是硬件规定，其他寄存器一律不行。
3. **错**：以为 `out 70h, al` 是「把数据写到 CMOS 的某个单元」。**对**：**`70H` 是「地址端口」，送进去的是「要访问哪个单元」的地址**；真正的数据要经 **`71H`** 端口读写。**两步缺一不可，顺序不能颠倒。**
4. **错**：读 CMOS 时只写 `in al, 71h`，忘了先 `out 70h, al`。**对**：**必须先指定单元地址**，否则读到的是「上一次访问过的单元」的内容（CMOS 芯片会保留地址寄存器的值）——这种 bug 极难排查。
5. **错**：把 BCD 码当成普通二进制数直接用。**对**：**BCD 码 4 位表示 1 位十进制数**。BCD `26H` 表示 26，而普通十六进制 `26H` 表示 38。**读出的时间值必须转换。**
6. **错**：拆 BCD 码时把 `shr` 和 `and` 用反。**对**：**取十位用 `shr ah, cl`（`cl = 4`，把高 4 位移下来）；取个位用 `and al, 00001111b`（屏蔽高 4 位）。**
7. **错**：写 `shl al, 4`。**对**：**8086 只支持 `shl al, 1` 和 `shl al, cl` 两种形式**，移位位数大于 1 时必须放进 `CL`。`shl al, 4` 是 80186 及以后才支持的写法。
8. **错**：以为 `shl` 溢出会像 `mul` 一样保留高位结果。**对**：**`shl` 把移出的最高位送进 `CF`，但结果本身被截断（只保留 8 位或 16 位）**。`0B2H shl 1 = 64H`（不是 `164H`），**高位信息只在 `CF` 里保留 1 位**。
9. **错**：以为 `add 30h` 是「加十六进制 30」。**对**：**`30H` 就是 ASCII 码 `'0'`**。因为 `'0'~'9'` 在 ASCII 表中连续排列（`30H~39H`），所以「数字 + `30H` = 该数字的 ASCII 码」。**这是数字转字符的标准技巧。**
10. **错**：写显存时忘了字符占 2 字节。**对**：**每个显示位置 2 字节（字符 + 属性）**，所以相邻字符的偏移相差 **2**：`es:[di]` 和 `es:[di+2]`，属性分别在 `di+1`、`di+3`。
11. **错**：写显存属性时忘了 `byte ptr`。**对**：**`mov byte ptr es:[di+1], 2`** —— 属性是 1 字节，**必须用 `byte ptr` 声明**，否则会按字写入，覆盖下一个字符。
12. **错**：在 8086 上用 `shr ah, 4` 直接写立即数。**对**：**必须先 `mov cl, 4`，再 `shr ah, cl`**（同第 7 条）。

## 本章小结

- **端口是 CPU 与外部设备通信的窗口，共 65536 个（地址 `0000H~FFFFH`）**；用 `in` / `out` 读写。
- **★ 两条硬规定：① 端口号 > `FFH` 时必须放在 `DX` 里；② 数据只能是 `AL`（8 位）或 `AX`（16 位）。★**
- **CMOS RAM**：主板上的小容量可读写芯片，**有电池供电，关机不丢**；存**时间信息**和**系统配置信息**。
- **★★ CMOS 的两个端口：`70H` 是地址端口、`71H` 是数据端口。访问流程：先 `out 70h, 单元地址`，再 `in al, 71h` 读数据（或 `out 71h, al` 写数据）。★★**
- **CMOS 时间单元**：`0` 秒、`2` 分、`4` 时、`7` 日、`8` 月、`9` 年；**都以 BCD 码存放**。
- **BCD 码**：4 位二进制表示 1 位十进制数（`26H` 表示 26，不是 38）。
- **`shl` 逻辑左移 / `shr` 逻辑右移**：**移出位进 `CF`，另一端补 0**；**左移 1 位 = ×2，右移 1 位 = ÷2**。
- **8086 的移位位数只有两种写法：`1` 或 `CL`**（`shl al, 4` 非法）。
- **拆 BCD 码的标准套路**：`mov ah, al` → `mov cl, 4` → **`shr ah, cl`（取十位）** → **`and al, 00001111b`（取个位）** → **`add ah/al, 30h`（转 ASCII）**。
- **数字转 ASCII 的原理**：`'0'~'9'` 的 ASCII 码是 `30H~39H`，所以「数字值 + `30H` = 对应字符」。

> **一句话记住本章**：**「端口就是设备的内存」——用 `in`/`out` 读写，数据只能走 `AL`/`AX`，端口号大了要放 `DX`；CMOS 的 `70H` 给地址、`71H` 传数据，时间以 BCD 码存放，读出来要「`shr` 取十位、`and` 取个位、`add 30H` 变字符」才能显示。**

## 自测题

**1.** 端口是什么？8086 有多少个端口？
**答**：**端口是 CPU 与外部设备通信的窗口**，CPU 通过读写端口来控制外设、获取外设状态。**8086 有 65536 个端口（地址 `0000H ~ FFFFH`）。**

**2.** `in` 和 `out` 指令的数据只能放在哪两个寄存器中？为什么？
**答**：只能是 **`AL`（8 位）或 `AX`（16 位）**。**这是 8086 硬件层面的规定**——I/O 指令只编码了「累加器」这一种数据寄存器，不是汇编器的限制。

**3.** 什么情况下端口号必须用 `DX` 存放？举例说明。
**答**：**当端口号超过 `FFH`（即大于 255）时必须用 `DX`**。例如要访问 `200H` 端口，不能写 `in al, 200h`，必须写成：
```asm
mov dx, 200h
in  al, dx
```
端口号在 `00H~FFH` 之间时可以直接写在指令里（如 `in al, 60h`）。

**4.** CMOS RAM 有什么特点？它保存哪两类信息？
**答**：CMOS RAM 是主板上的一块**小容量可读写存储器芯片，由电池供电，关机后内容不丢失**。它保存**时间信息**和**系统配置信息**（内存大小、硬盘参数、启动顺序等）。

**5.** CMOS RAM 用哪两个端口访问？各自的角色是什么？写出访问 4 号单元的完整代码。
**答**：用 **`70H`（地址端口）** 和 **`71H`（数据端口）**。**`70H` 用来指出要访问哪个单元，`71H` 用来读写该单元的内容。**
```asm
mov al, 4
out 70h, al         ; 先送单元地址到 70H
in  al, 71h         ; 再从 71H 读数据
```

**6.** CMOS RAM 中存放秒、分、时、日、月、年的单元地址分别是什么？
**答**：**秒 `0`、分 `2`、时 `4`、日 `7`、月 `8`、年 `9`。**

**7.** 什么是 BCD 码？BCD 码 `59H` 表示十进制多少？如果当成普通十六进制数是多少？
**答**：**BCD 码是用 4 位二进制表示 1 位十进制数字的编码方式。** BCD 码 `59H` 表示**十进制 59**；若当成普通十六进制数是 `5×16+9 = 89`。

**8.** `shl` 和 `shr` 的规则分别是什么？移出的位到哪里去了？
**答**：**`shl`（逻辑左移）：各位左移，最低位补 0，最高位移入 `CF`。`shr`（逻辑右移）：各位右移，最高位补 0，最低位移入 `CF`。** 移出的位**进入进位标志 `CF`**。

**9.** 在 8086 上，`shl al, 1` 和 `shl al, cl` 哪个合法？`shl al, 4` 合法吗？为什么？
**答**：`shl al, 1` 和 `shl al, cl` **都合法**。**`shl al, 4` 在 8086 上不合法**——8086 只支持「移 1 位」和「移 `CL` 位」两种编码（立即数移位是 80186 及以后才加入的）。**要移 4 位必须写成 `mov cl, 4` / `shl al, cl`。**

**10.** `AL = 0B2H`，执行 `shr al, 1` 后 `AL` 和 `CF` 各是多少？这个操作相当于什么运算？
**答**：`0B2H = 1011 0010B` 右移一位得 `0101 1001B = 59H`，最低位移入 `CF`，所以 **`AL = 59H`、`CF = 0`**。**相当于 `AL ÷ 2`**（`178 ÷ 2 = 89`，余数为 0 正好对应 `CF = 0`）。

**11.** `AL = 26H`（BCD 码），写出把它拆成十位、个位并转成 ASCII 码的代码，说明结果。
**答**：
```asm
mov ah, al                  ; AH = 26H
mov cl, 4
shr ah, cl                  ; AH = 02H（十位）
and al, 00001111b           ; AL = 06H（个位）
add ah, 30h                 ; AH = 32H = '2'
add al, 30h                 ; AL = 36H = '6'
```
**结果**：`AH = 32H`（字符 `'2'`）、`AL = 36H`（字符 `'6'`）。

**12.** 为什么数字加 `30H` 就变成了对应的 ASCII 字符？请举例。
**答**：因为 **ASCII 码表中字符 `'0' ~ '9'` 是连续排列的，从 `30H` 到 `39H`**。所以「数字值 + `30H`」就等于该数字对应字符的 ASCII 码。例如：`0 + 30H = 30H = '0'`；`5 + 30H = 35H = '5'`；`9 + 30H = 39H = '9'`。

**13.** 在屏幕第 20 行第 10 列写一个字符及其属性，显存偏移怎么算？属性字节写在哪里？
**答**：显存段地址 `B800H`，**偏移 = `20 × 160 + 10 × 2 = 3200 + 20 = 3220`**（因为每行 80 字符 × 2 字节 = 160 字节/行）。**字符写在 `ES:[3220]`，属性写在 `ES:[3221]`**（属性必须用 `mov byte ptr` 声明为 1 字节）。
