## 3.1 内存中字的存储

**在内存中，一个字（16 位）占两个连续字节：低地址单元存低字节，高地址单元存高字节。**

例：把 `2000H` 存入起始地址为 `20000H` 的内存。

```
   内存地址        内容
   20001H    ┌──────────────┐
             │     20H      │  ← 高地址存高字节
   20000H    ├──────────────┤
             │     00H      │  ← 低地址存低字节
             └──────────────┘
```

**这台机器叫「小端序（Little Endian）」**：低位字节放在低地址。

> **重点**：一个字在内存里占 2 个单元，我们说「字单元」时约定用**它的起始地址（低地址）**来指代。上面的字单元地址是 `20000H`。

| 写法 | 含义 |
|---|---|
| 字节单元 `20000H` | 内容为 `00H`，1 字节 |
| 字单元 `20000H` | 内容为 `2000H`，2 字节（`20000H` 和 `20001H`） |

## 3.2 DS和[address]

**DS（Data Segment）是数据段寄存器，`[address]` 用 DS 作为段地址，表示「物理地址 = (DS)×16 + address」处的一个内存单元。**

```asm
mov ax, ds:[0]     ; 不是「把 0 送进 ax」！是把 (DS)×16+0 处的字送进 ax
```

例如 `(DS) = 2000H`，`mov ax, ds:[0]` 读的是物理地址 `20000H` 处的**一个字**。

> **⚠ 警告：`[数字]` 在 DEBUG 和 MASM 里含义完全不同（必须看！）**
>
> 上面写成 `ds:[0]` 而不是 `[0]`，这不是多余——**这是本课程最容易踩的坑**：
>
> | 环境 | 写 `mov ax, [0]` 会怎样 |
> |---|---|
> | **DEBUG**（用 `a` 命令输入指令） | `[0]` 被当作**内存单元**，读 `DS:0` 处的字 ✓ |
> | **MASM**（写进 `.asm` 源程序） | **`[0]` 被当作常量 `0`，等价于 `mov ax, 0`！** ✗ |
>
> **MASM 实测证据**（`ml /c /Fl` 看列表文件里的机器码）：
>
> ```
>    0000  B8 0000          mov ax, [0]        ← 生成的机器码就是 mov ax, 0 ！！！
>    0003  8B 1E 0000       mov bx, ds:[0]     ← 加了段前缀，这才是取内存
> ```
>
> **★ 最危险的地方：MASM 对源操作数位置的 `[0]` 不报错**，只是静默地把它当成立即数 0——你得到一个「能跑但结果是 0」的程序，查半天查不出错。
>
> 而作为**目的**操作数时它会报错：
>
> ```
>    mov [6], ax        → error A2001: immediate operand not allowed
> ```
>
> **★ 结论：在 MASM 源程序里访问「固定偏移」的内存，一律加段前缀（或换成标号寻址）：**
>
> ```asm
> mov ax, ds:[0]      ; ✓ 源操作数：加 ds: 才是访问内存
> mov ds:[6], ax      ; ✓ 目的操作数：不加 ds: 直接报错
> mov bx, offset a    ; ✓✓ 更好的做法：用标号，可读性最好
> mov ax, [bx]
> ```
>
> **原因**：王爽教材大量在 DEBUG 下演示（那里 `[0]` 就是内存），而作业要求写 MASM 源程序。**两套语法不一样，切换时必须加 `ds:`。**

### 关键限制：不能把立即数直接送进段寄存器

```asm
mov ds, 1000h      ; × 非法指令！8086 不支持把立即数直接送入段寄存器
```

**为什么非法**：8086 的指令编码里，段寄存器作为目的操作数时只支持 `reg → sreg` 和 `mem → sreg` 两种形式，没有「立即数 → sreg」这种编码。这是硬件设计决定的，不是汇编器的问题。

**正确写法（必须绕一圈）**：

```asm
mov ax, 1000h      ; 先把立即数送到通用寄存器
mov ds, ax         ; 再从通用寄存器送到 DS
```

> **重点**：这个「绕一圈」的写法在后面的每个程序里都会出现，`mov ax, data` + `mov ds, ax` 是标准套路，**必须形成肌肉记忆**。

## 3.3 字的传送

**读一个字时，CPU 会从指定地址开始连续取两个字节，低地址处的字节作为低 8 位。**

例：内存状态如下

```
   地址        内容
   20001H      20H
   20000H      00H
```

执行 `(DS) = 2000H`，`mov ax, ds:[0]` 后：

- `AL = (20000H) = 00H`
- `AH = (20001H) = 20H`
- 所以 `AX = 2000H`

**写回时同理**：

```asm
mov ax, 1234h
mov ds:[0], ax     ; 把这一个字写入 DS:0
                   ; ★ 注意必须是 ds:[0]，写成 mov [0],ax 会报
                   ;   error A2001: immediate operand not allowed
```

执行后：

```
   地址        内容
   20001H      12H    ← 高字节
   20000H      34H    ← 低字节
```

> **重点**：`mov ds:[0], ax` 是**字**传送，写 2 个字节；`mov byte ptr ds:[0], al` 才是字节传送。加不加 `byte ptr` / `word ptr` 会在第 8 章详细讲。

## 3.4 mov、add、sub指令

**这三条指令的操作数规则相同：两个操作数位数必须一致，且不能同时是内存单元。**

| 指令 | 目的操作数 | 源操作数 | 例子 |
|---|---|---|---|
| `mov` | reg / sreg / mem | reg / sreg / mem / idata | `mov ax, bx` |
| `add` | reg / mem | reg / mem / idata | `add ax, 8` |
| `sub` | reg / mem | reg / mem / idata | `sub bx, 1` |

**常见错误对照表**：

| 错误写法 | 为什么错 | 正确写法 |
|---|---|---|
| `mov ax, bl` | 位数不一致（16 位 ← 8 位） | `mov al, bl` 或 `mov ax, bx` |
| `mov ds, 1000h` | 立即数不能直接送段寄存器 | `mov ax, 1000h` / `mov ds, ax` |
| `mov ds:[0], ds:[1]` | 两个内存单元不能直接传送 | `mov ax, ds:[1]` / `mov ds:[0], ax` |
| `add ds:[0], ds:[1]` | 同上 | 借助寄存器中转 |

**内存单元的写法**：`ds:[0]`、`[bx]`、`[bx+si]` 等。**注意 `mov ax,[0]` 在 Debug 和 MASM 中含义不同**（第 5 章 5.4 节详述，本节上面的警告块已给出实测证据）。

## 3.5 数据段

**DS 指向的那段内存就是「数据段」——这同样是逻辑概念。**

当我们说「定义了一个数据段」时，实际做的是：

1. 在程序里用 `dw`/`db` 等伪指令**声明**数据；
2. 运行时用 `mov ax, data` + `mov ds, ax` 让 **DS 指向数据所在的位置**。

```asm
assume ds:data

data segment
    dw 1234h, 5678h, 9ABCh    ; 定义 3 个字
data ends

code segment
start:
    mov ax, data              ; 取 data 段的段地址
    mov ds, ax                ; DS 指向数据段
    mov bx, 0
    mov ax, [bx]              ; AX = 1234H（data 段的第 1 个字）
    mov bx, 2
    mov cx, [bx]              ; CX = 5678H
code ends
```

> **重点**：`assume ds:data` 只是告诉汇编器「后面用 `[bx]` 时按 data 段的相对地址算」，**它不会真的设置 DS**。真正设置 DS 的是 `mov ds, ax` 两条指令。

## 3.6 栈

**栈（Stack）是一种「后进先出（LIFO，Last In First Out）」的存储空间。**

生活类比：**一叠盘子**。你只能从最上面放盘子、也只能从最上面拿盘子。最后放上去的那个，最先被拿走。

| 操作名 | 动作 | 对应指令 |
|---|---|---|
| 入栈（Push） | 把数据放到栈顶 | `push` |
| 出栈（Pop） | 从栈顶取出数据 | `pop` |

栈的两个基本属性：

- **栈顶是变化的**：每入栈/出栈一次，栈顶就移动一次；
- **只能操作栈顶**：不能直接访问栈中间的元素。

## 3.7 CPU提供的栈机制

**8086 用 `SS:SP` 定位栈顶：`(SS)×16 + (SP)` 就是当前栈顶的物理地址。SS 是栈段寄存器，SP 是栈指针。**

**8086 的栈是「从高地址向低地址生长」的**：

```
      栈段 SS:SP
   ┌──────────────┐ ← 栈底（高地址）
   │              │
   ├──────────────┤ ← SP 指向当前栈顶
   │   push 的数据 │
   └──────────────┘ ← 低地址
           ↓ 每 push 一次，SP 减小
```

### push ax 的执行过程（两步）

```
   ① (SP) = (SP) − 2          ; 栈顶向低地址方向移动 2 字节
   ② ((SS)×16 + (SP)) = (AX)  ; 把 AX 的内容送入新的栈顶处
```

**注意顺序：先移指针，再存数据。**

### pop ax 的执行过程（两步）

```
   ① (AX) = ((SS)×16 + (SP))  ; 先把栈顶处的数据读入 AX
   ② (SP) = (SP) + 2          ; 栈顶向高地址方向移回 2 字节
```

**注意顺序：先读数据，再移指针。**

### 完整演示

初始状态：`(SS) = 1000H`，`(SP) = 0010H`，`(AX) = 1234H`。

```
   push ax 之前
   10010H ┌──────────────┐ ← SP = 0010H
          │              │
```

执行 `push ax`：

```
   ① SP = 0010H − 2 = 000EH
   ② (1000H×16 + 000EH) = (1000EH) ← 1234H，低字节 34H 在 1000EH，高字节 12H 在 1000FH

   10010H ┌──────────────┐
          │              │
   1000FH ├──────────────┤
          │     12H      │ ← 高字节
   1000EH ├──────────────┤
          │     34H      │ ← 低字节
          └──────────────┘ ← SP = 000EH
```

执行 `pop ax`（假设 AX 已被改掉）：

```
   ① AX = (1000EH) = 1234H
   ② SP = 000EH + 2 = 0010H
```

> **重点**：**push 是「先减 SP 后写内存」，pop 是「先读内存后加 SP」**。这个顺序决定了 `push`/`pop` 的配对性，也是第 10 章 `call`/`ret` 的基础。

## 3.8 栈顶超界的问题

**8086 不检查栈是否溢出：栈空时继续 pop 会读到栈外的数据，栈满时继续 push 会覆盖栈外的数据。**

这是 8086 栈机制的**最大缺陷**——它没有任何保护机制。

```
   ① 栈空时 pop：SP 越过了栈底，读到了别的数据
   
   栈段上限 1000FH ┌──────────────┐ ← 栈底（原本的空栈顶）
                   │   别人的数据   │  ← pop 会读到这里！
   栈段下限 10000H ├──────────────┤
                   │              │
                   └──────────────┘
   
   ② 栈满时 push：SP 越过了栈底，覆盖了别人的数据
   
   栈段上限 1000FH ┌──────────────┐ ← 栈底（栈已满）
                   │  push 覆盖这里 │  ← 冲掉了别的程序的数据
                   └──────────────┘
```

**两种超界的后果**：

| 情形 | 后果 |
|---|---|
| 栈空时 `pop` | 读到不属于本栈的数据，结果不可预测（可能是别的程序/系统数据） |
| 栈满时 `push` | 覆盖栈外的数据（可能是别的程序的代码或数据），导致程序崩溃或系统异常 |

> **重点**：正因为 8086 不检查，**程序员必须自己保证 push/pop 配对、栈空间够用**。后面 80286+ 的保护模式（第 18 章）才加入了「段界限」检查来自动捕获这类错误——这是《操作系统》里「栈溢出攻击」的物理根源。

## 3.9 push、pop指令

**`push` 和 `pop` 的操作数可以是寄存器、段寄存器和内存单元，但不能是立即数。**

```asm
push ax            ; 寄存器入栈
push ds            ; 段寄存器入栈
push ds:[0]        ; 内存单元入栈（字）★ 必须加 ds:，写 push [0] 报 A2001
pop bx             ; 出栈到寄存器
pop es             ; 出栈到段寄存器
pop ds:[2]         ; 出栈到内存单元 ★ 同理必须加 ds:
```

**非法写法**：

```asm
push 1234h         ; × 不能 push 立即数
pop cs             ; × CS 不能作为 pop 的目的（可 push cs，但不能 pop cs）
```

**常见 push/pop 序列与 SP 变化**：

| 指令序列 | SP 变化 | 效果 |
|---|---|---|
| `push ax` | −2 | 压入 1 个字 |
| `push ax` / `push bx` | −4 | 压入 2 个字 |
| `push ax` / `pop bx` | 不变 | 栈平衡，但 `BX = 原 AX` |
| `push ax` / `push bx` / `pop bx` / `pop ax` | 不变 | **顺序相反**才能还原 |

> **重点**：**push 的顺序和 pop 的顺序必须相反**。先 push 的必须后 pop，否则值会交换。
>
> ```asm
> push ax        ; 先压 AX
> push bx        ; 后压 BX
> ...
> pop bx         ; 先弹 BX  ✓
> pop ax         ; 后弹 AX  ✓
> ```
> 如果写成 `pop ax` 再 `pop bx`，就会把 BX 的值给 AX、AX 的值给 BX——这是个隐蔽的 bug，第 10 章讲子程序时会专门强调。

## 3.10 栈段

**SS 指向的那段内存就是「栈段」——依然是逻辑概念。**

只要设置好 `SS` 和 `SP`，任意一段内存都能当栈用：

```asm
mov ax, 1000h
mov ss, ax          ; SS = 1000H
mov sp, 0010h       ; SP = 0010H → 栈顶在 10010H
```

这就定义了一个栈段：物理地址 `10000H` ~ `1000FH` 之间（栈向低地址生长，所以可用空间在 `10000H` ~ `1000FH`）。

**在源程序中声明栈段的完整写法**（第 6 章会细讲）：

```asm
stack segment
    dw 0,0,0,0,0,0,0,0       ; 预留 16 字节栈空间
stack ends

code segment
start:
    mov ax, stack
    mov ss, ax
    mov sp, 10h              ; 栈顶指向栈段末尾（高地址端）
code ends
```

> **重点**：**`SP` 要指向栈空间的「高地址端 + 1」**，因为栈是向低地址生长的，第一次 push 会先减 2 再写。

## 典型例题

**例 3.1**（题型：内存布局）
把 `0ABCDH` 存入起始地址为 `1000:0` 的内存单元，请画出该处 2 个字节的内容。
**解**：
- `0ABCDH` 的高字节是 `ABH`，低字节是 `CDH`。
- 按规定：**低地址存低字节**，所以 `1000:0` 处存 `CDH`，`1000:1` 处存 `ABH`。
```
   1000:1  ┌──────────┐
           │   ABH    │  ← 高字节放高地址
   1000:0  ├──────────┤
           │   CDH    │  ← 低字节放低地址
           └──────────┘
```
**答案**：`1000:0` 处是 `CDH`，`1000:1` 处是 `ABH`。

**例 3.2**（题型：push/pop 与 SP 变化）
初始 `(SS)=2000H`，`(SP)=0100H`，`(AX)=1122H`，`(BX)=3344H`。依次执行 `push ax`、`push bx`、`pop ax`、`pop bx`，求最终 SP、AX、BX 的值，并画出每一步的栈内容。
**解**：
```
① push ax：SP = 0100H − 2 = 00FEH；(200FEH)=22H，(200FFH)=11H
   （低字节 22H 在低地址 200FEH，高字节 11H 在 200FFH）

② push bx：SP = 00FEH − 2 = 00FCH；(200FCH)=44H，(200FDH)=33H

③ pop ax：先读 (200FCH) 处的字 = 3344H → AX = 3344H；再 SP = 00FCH + 2 = 00FEH
   为什么 AX 变成了 BX 原来的值：因为「后进先出」，最后 push 的 BX 最先被 pop 出来。

④ pop bx：读 (200FEH) 处的字 = 1122H → BX = 1122H；再 SP = 00FEH + 2 = 0100H
```
**答案**：`SP = 0100H`（回到初始值），`AX = 3344H`，`BX = 1122H`。**AX 和 BX 的值被交换了**——这就是 push/pop 顺序不配对造成的经典错误。

**例 3.3**（题型：DS 设置）
下面这段代码有什么错误？怎么改？
```asm
mov ds, 2000h
mov ax, ds:[0]
```
**解**：
- 错误在第 1 行：**8086 不允许把立即数直接送入段寄存器**，`mov ds, 2000h` 无法汇编。
- 原因：8086 指令编码中，段寄存器作目的操作数时只支持从寄存器或内存单元传送，没有「立即数 → 段寄存器」的编码形式。
- 改法：借助一个通用寄存器中转。
```asm
mov ax, 2000h        ; 立即数先送到通用寄存器
mov ds, ax           ; 再从通用寄存器送到 DS
mov ax, ds:[0]       ; 现在读的是 2000H×16+0 = 20000H 处的字
                     ; ★ 必须写 ds:[0]；写 mov ax,[0] 会被 MASM 当成 mov ax,0
```
**答案**：必须用 `mov ax, 2000h` + `mov ds, ax` 两步。

**例 3.4**（题型：读数写数）
内存状态如下，`(DS)=1000H`。执行 `mov ax, ds:[2]` 和 `mov ds:[0], ax` 后，内存变成什么样？
```
   10003H: 11H
   10002H: 22H
   10001H: 33H
   10000H: 44H
```
**解**：
1. `mov ax, ds:[2]`：读 `(DS)×16+2 = 10002H` 处的一个字。低字节取 `10002H` = `22H`，高字节取 `10003H` = `11H`，所以 `AX = 1122H`。
2. `mov ds:[0], ax`：把 `1122H` 写到 `10000H` 处的字单元。低字节 `22H` 放 `10000H`，高字节 `11H` 放 `10001H`。
```
   10003H: 11H   （不变）
   10002H: 22H   （不变）
   10001H: 11H   ← 被写入
   10000H: 22H   ← 被写入
```
**答案**：`AX = 1122H`；`10000H` 变成 `22H`，`10001H` 变成 `11H`。

**例 3.5**（题型：栈适用性判断）
初始 `(SS)=3000H`，`(SP)=0000H`。执行 `push ax` 后栈顶在哪里？会不会有问题？
**解**：
- `push ax`：`SP = 0000H − 2 = FFFEH`（16 位减法回绕）。
- 新的栈顶物理地址 = `3000H × 16 + FFFEH = 30000H + FFFEH = 3FFFEH`。
- **有问题**：`SP` 从 `0000H` 减到 `FFFEH`，栈顶从 `30000H` 一下子跳到了 `3FFFEH`——跳到了**栈段的另一端**，越过了整个 64KB 段。
- 这是因为 `SP` 是 16 位寄存器，`0000H − 2` 会回绕成 `FFFEH`。**栈的初始 SP 绝不能是 `0000H`**，应该设成栈空间末尾（如 `0010H`）。
**答案**：`SP = FFFEH`，栈顶在 `3FFFEH`；会越界，栈初始 SP 不能为 `0000H`。

**例 3.6**（题型：综合题——用栈交换数据）
不用 `xchg`，用栈把 `(AX)=1111H`、`(BX)=2222H` 的值交换。
**解**：
```asm
push ax        ; 栈：[1111H]，SP 减 2
push bx        ; 栈：[1111H, 2222H]，栈顶是 2222H，SP 再减 2
pop  ax        ; AX = 2222H（后进先出），SP 加 2
pop  bx        ; BX = 1111H，SP 加 2
```
为什么能交换：栈是后进先出，最后压入的 `BX` 值先被弹出给 `AX`，于是两者互换。
**答案**：
```asm
push ax
push bx
pop  ax
pop  bx
```
执行后 `AX = 2222H`，`BX = 1111H`，`SP` 恢复原值。

**例 3.7**（题型：栈溢出的判断）
设 `(SS)=8000H`，`(SP)=0004H`。连续执行 3 次 `push ax` 会不会超界？
**解**：
- 栈顶初始 `8000H×16+0004H = 80004H`。
- 第 1 次 push 后 `SP = 0002H`，栈顶 `80002H`，占用 `80002H`~`80003H`。
- 第 2 次 push 后 `SP = 0000H`，栈顶 `80000H`，占用 `80000H`~`80001H`。
- 第 3 次 push 后 `SP = FFFEH`，栈顶回绕到 `8FFFEH`——**严重超界**，因为 `SP` 从 `0000H` 减 2 变成了 `FFFEH`。
- 可用栈空间只有 `0004H` 字节 = 4 字节 = 2 个字，第 3 个 push 一定越界。
**答案**：会超界。栈空间只够 2 个字，且第 3 次 push 会让 `SP` 回绕到 `FFFEH`。

## 易错点提醒

1. **错**：写 `mov ds, 1000h`。**对**：立即数不能直接送段寄存器，必须 `mov ax,1000h` + `mov ds,ax` 两步。这个「绕一圈」是 8086 的硬件限制。
2. **错**：认为 `mov ds:[0], ax` 只写 1 个字节。**对**：`ax` 是 16 位，所以 `mov ds:[0], ax` 写**一个字 = 2 字节**；要写 1 字节得用 `mov byte ptr ds:[0], al`。
3. **错**：搞反 push 的两步顺序，以为「先存数据再减 SP」。**对**：`push ax` 是 **`(SP)=(SP)−2` 然后写内存**；`pop ax` 是 **先读内存再 `(SP)=(SP)+2`**。顺序错了画图就全错。
4. **错**：push 和 pop 的顺序写成一样。**对**：**必须相反**（先 push 的后 pop）。`push ax`/`push bx` 之后要 `pop bx`/`pop ax`，否则两个值互换。
5. **错**：认为 8086 会检测栈溢出并报错。**对**：8086 **完全不检查栈是否超界**，栈空时 pop 会读到垃圾、栈满时 push 会覆盖别的数据。保护模式（80286+）才有段界限检查。
6. **错**：把栈画成向高地址生长。**对**：8086 的栈**向低地址生长**，`push` 使 `SP` **减小**，`pop` 使 `SP` **增大**。
7. **错**：把栈的初始 `SP` 设成 `0000H`。**对**：`0000H − 2` 会回绕成 `FFFEH`，栈顶直接跳到段的另一端。`SP` 应设为栈空间末尾（高地址端）。
8. **错**：以为 `push 1234h` 可以。**对**：`push`/`pop` **不能操作立即数**，只能操作寄存器、段寄存器和内存单元。
9. **错**：以为 `pop cs` 合法。**对**：可以 `push cs`，但**不能 `pop cs`**（和不能 `mov cs` 同理）。
10. **错**：在 MASM 源程序里写 `mov ax, [0]` 或 `mov [6], ax` 想访问固定偏移的内存。**对**：**MASM 把 `[数字]` 当常量**——作源操作数时静默变成 `mov ax, 0`（机器码 `B8 0000`），作目的操作数时直接报 `error A2001: immediate operand not allowed`。**必须加段前缀 `ds:[0]`**（或改用标号寻址）。**注意这是 MASM 与 DEBUG 的语法差异，不是指令本身的差异**（第 5 章 5.4 节、本章 3.2 节的警告块有实测证据）。

## 本章小结

- 一个字在内存中占 2 个连续字节：**低地址存低字节、高地址存高字节**（小端序）。
- **`DS` 是数据段寄存器**，`[address]` 默认用 DS 作段地址，物理地址 = `(DS)×16 + address`。
- **`mov ds, 立即数` 非法**，必须经通用寄存器中转。
- **栈是后进先出（LIFO）的存储空间**，8086 用 **`SS:SP`** 定位栈顶，栈**向低地址生长**。
- **`push ax`：`(SP)=(SP)−2`，然后写内存；`pop ax`：先读内存，然后 `(SP)=(SP)+2`。**
- 8086 **不检查栈超界**：栈空 pop 读到垃圾，栈满 push 覆盖别人。
- **push 与 pop 的顺序必须相反**。
- 「数据段」「栈段」都是逻辑概念：让 DS / SS 指向哪段内存，哪段就是数据段 / 栈段。

> **一句话记住本章**：**内存按字节编号、按字存取要记住低字节在低地址；栈是「先移指针后存数、先取数后移指针」的后进先出空间，SP 永远指向栈顶。**

## 自测题

**1.** 字 `1234H` 存在 `20000H` 开始的内存里，`20000H` 和 `20001H` 各是什么？
**答**：`20000H` 是 `34H`（低字节），`20001H` 是 `12H`（高字节）。

**2.** 为什么 `mov ds, 1000h` 是非法的？写出正确写法。
**答**：8086 指令系统没有「立即数 → 段寄存器」的编码形式。正确写法：`mov ax,1000h` / `mov ds,ax`。

**3.** 写出 `push ax` 的两步执行过程。
**答**：① `(SP) = (SP) − 2`；② `((SS)×16+(SP)) = (AX)`。

**4.** 写出 `pop ax` 的两步执行过程。
**答**：① `(AX) = ((SS)×16+(SP))`；② `(SP) = (SP) + 2`。

**5.** 初始 `(SP)=0010H`，执行 `push ax`、`push bx`、`pop cx`、`pop dx` 后 SP 是多少？
**答**：`push` 两次减 4，`pop` 两次加 4，回到 `0010H`。

**6.** 栈是向高地址还是低地址生长？`push` 让 SP 变大还是变小？
**答**：向低地址（向下）生长；`push` 让 SP **减小** 2。

**7.** 8086 在栈溢出时会怎样？
**答**：不会做任何检查。栈空时 `pop` 读栈外数据，栈满时 `push` 覆盖栈外数据，都由程序员自己负责。

**8.** 判断：`mov ds:[0], ds:[1]` 是合法指令。
**答**：错。两个内存单元之间不能直接传送，必须借助寄存器中转，如 `mov ax, ds:[1]` + `mov ds:[0], ax`。（另外注意：写成 `mov [0], [1]` 时 MASM 会先报 `A2001: immediate operand not allowed`，因为 `[数字]` 被当成了常量。）

**9.** `(SS)=1000H`，`(SP)=0020H`，栈顶的物理地址是多少？这段栈可用多少字节（假设栈段长 64KB）？
**答**：栈顶 = `1000H×16 + 0020H = 10020H`。可用空间从 `10000H` 到 `1001FH`，共 **`0020H` = 32 字节**。
**为什么不是 33 字节**：`push` 是「**先减 SP，再写内存**」，第一次 `push` 把 `SP` 减到 `001EH` 后写 `1001EH`、`1001FH`；连续 16 次 `push` 后 `SP = 0000H`，写的是 `10000H ~ 1001FH`。**`10020H` 是空栈时 `SP` 指的位置，任何一次 `push` 都不会写它**——所以可用字节数 = `0020H − 0 = 32`，不是「末地址 − 首地址 + 1 = 21H」。（把「末 − 首 + 1」误用到栈顶指针值上，是这道题最经典的错法。）

**10.** 下面代码执行后 AX、BX 各是多少？
```asm
mov ax, 1111h
mov bx, 2222h
push ax
push bx
pop ax
pop bx
```
**答**：`AX = 2222H`，`BX = 1111H`（值被交换，因为 pop 顺序应与 push 顺序相反）。
