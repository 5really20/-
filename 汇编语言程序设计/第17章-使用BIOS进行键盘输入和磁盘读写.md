## 17.1 int 9中断例程对键盘输入的处理

**第 15 章已经讲过键盘处理的前半段，这里补全「进入缓冲区」之后的细节。**

**完整链条（复习 + 细化）：**

```
   ① 按键 → 键盘芯片产生扫描码
   ② 扫描码送到 60H 端口
   ③ 键盘接口向 CPU 发出可屏蔽中断请求
   ④ CPU 响应，得到类型码 9，执行 BIOS 的 int 9 中断例程
   ⑤ ★ int 9 例程处理：
        · 一般按键（字符键）→ 把「字符码」和「扫描码」送入【键盘缓冲区】
        · 控制键 / 切换键   → 转变为状态字节，写入内存中的【状态字节单元】
```

**键盘缓冲区的结构（本节的要点）：**

```
   ★ 环形缓冲区
   ★ 可以存放 15 个按键
   ★ 每个按键占 2 个字节
```

**每个按键的 2 字节布局（这个顺序很重要）：**

| 字节位置 | 存放内容 | 对应 `int 16h` 的返回寄存器 |
|---|---|---|
| **低字节** | **字符码（ASCII）** | **`AL`** |
| **高字节** | **扫描码** | **`AH`** |

**为什么是这个顺序？**

```
   因为 int 16h 读键盘时，就是把缓冲区里的这 2 个字节「一次读进 AX」：
   
        mov ax, [缓冲区里的字]
        → AL = 字符码（低字节）
        → AH = 扫描码（高字节）
   
   ★ 一次内存读取就同时得到了「字符码」和「扫描码」—— 这就是为什么
     低字节放字符码、高字节放扫描码。
```

**举例：按下 `a` 键**

```
   'a' 的扫描码 = 1EH    'a' 的字符码 = 61H
   
   送进缓冲区的一个字：  高字节 1EH  |  低字节 61H
                        └────┬────┘   └────┬────┘
                          扫描码        字符码
   
   程序用 int 16h 读出来：AH = 1EH（扫描码）、AL = 61H（字符码）
```

**缓冲区满会怎样？**

```
   ★ 已经存了 15 个按键时，再按键：
        · 新的按键【被丢弃】
        · 同时主机箱上的小喇叭会【响一声】（BIOS 的提示）
   ★ 这就是「输入太快会丢键」的原因。
```

**键盘缓冲区在内存中的位置（补充知识，真实 BIOS 数据区布局）：**

| 地址 | 内容 |
|---|---|
| `0040:001A` | 缓冲区**头指针**（`int 16h` 从这里取键） |
| `0040:001C` | 缓冲区**尾指针**（`int 9` 往这里放键） |
| `0040:001E ~ 0040:003D` | **键盘缓冲区本体**（16 个字 = 32 字节） |
| `0040:0017` | **状态字节**（Shift / Ctrl / Alt / CapsLock 等） |

> **重点**：**`int 9` 是「生产者」，`int 16h` 是「消费者」，键盘缓冲区是它们之间的「队列」——这是操作系统里最经典的「生产者-消费者」模型。** 理解了这个模型，你就理解了为什么「按键不会丢」（有缓冲）、为什么「太快会丢」（缓冲满）、以及为什么要用 `int 16h` 而不是直接读 `60H` 端口（**直接读 `60H` 会绕过 BIOS 的处理，拿不到字符码，而且会和 BIOS 抢数据**）。

## 17.2 使用int 16h中断例程读取键盘缓冲区

**`int 16h` 是 BIOS 提供的键盘服务中断，用 `AH` 指定功能号。**

| `AH` | 功能 | 入口 | 出口 |
|---|---|---|---|
| **`0`** | **从键盘缓冲区读一个按键，并删除它** | 无 | `AL` = 字符码，`AH` = 扫描码 |
| **`1`** | **读一个按键，但不删除** | 无 | **`ZF = 0`**：有键，`AL` = 字符码、`AH` = 扫描码<br>**`ZF = 1`**：缓冲区空 |
| **`2`** | 读状态字节 | 无 | `AL` = 状态字节（Shift/Ctrl/Alt 等） |

**★ 0 号功能的关键特性：如果缓冲区为空，它会「等待」——程序会停在 `int 16h` 这一句，直到用户按下某个键。**

| 功能号 | 缓冲区空时的行为 | 适用场景 |
|---|---|---|
| `AH = 0` | **阻塞等待**（一直等到有键为止） | 「按任意键继续」、必须读到一个字符 |
| `AH = 1` | **立即返回**，`ZF = 1` | 「检测是否有键按下」（不阻塞，可以边等待边做别的事） |

**例一：最简单的「按任意键继续」。**

```asm
    mov ah, 0
    int 16h                 ; ★ 程序停在这里，直到用户按下一个键
    ; 按下后：AL = 字符码，AH = 扫描码
```

**例二：用 1 号功能做「不阻塞的按键检测」。**

**下面的程序在等待按键的同时不断改变屏幕颜色——如果按键了就退出。**

```asm
assume cs:code
code segment
start:
    mov ax, 0b800h
    mov es, ax
    mov bx, 1                   ; 指向第一个属性字节

wait_key:
    mov ah, 1
    int 16h                     ; ★ 1 号功能：检测有无按键（不删除）
    jnz  key_pressed            ; ★ ZF = 0 → 有键，跳出循环

    inc byte ptr es:[bx]        ; 没有键：继续改变颜色
    add bx, 2
    cmp bx, 4000                ; 4000 = 2000 个位置 × 2 字节
    jb  wait_key
    mov bx, 1
    jmp short wait_key

key_pressed:
    mov ah, 0
    int 16h                     ; ★ 0 号功能：把那个键真正读走（删除）

    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果**：屏幕颜色不断变化；按下任意键后，程序立即退出。

**注意 `jnz` 在这里的含义：**

```
   int 16h 的 1 号功能用 ZF 表示结果：
        ZF = 0（NZ）→  缓冲区里有按键
        ZF = 1（Z） →  缓冲区是空的
   
   ★ 所以 jnz key_pressed 的意思是「有键就跳出去」。
   ★ 这是全书里少数几个「用标志位而不是用寄存器做返回值」的接口 —— 要特别记住！
```

**★ 用 1 号功能检测到按键后，一般还要用 0 号功能把它读走：**

```
   1 号功能只「看」不「拿」——它不删除缓冲区里的按键。
   如果只用 1 号功能检测而不读走，那个键会一直留在缓冲区里，
   下一轮检测又会发现「有键」→ 造成死循环或重复处理。
```

> **重点**：**`int 16h` 的 0 号和 1 号功能是一对搭档：1 号「看」，0 号「拿」。** 只「看」不「拿」是初学者最常犯的错误之一。**另外注意：`int 16h` 的返回值里 `AL` 是字符码、`AH` 是扫描码**——**要判断「按的是哪个功能键」（如 `F1`、方向键），必须看 `AH`（扫描码），因为功能键的字符码通常是 0。**

## 17.3 字符串的输入

**最基本的字符串输入程序要具备三个功能：**

```
   ① 在输入的同时显示这个字符串
   ② 一般在输入回车符后，字符串输入结束
   ③ 能删除已经输入的字符（退格键）
```

**要用到的技术（都是前面学过的）：**

| 技术 | 来源 |
|---|---|
| `int 16h` 读键盘 | 17.2 |
| 显存直接写字符 | 第 12 章 |
| **用「字符栈」保存已输入的字符** | 第 3 章（栈的思想） |
| **用「直接定址表」根据功能号调度子程序** | **第 16 章** |
| 数据标号 + 索引访问 | 第 16 章 |

**为什么要用「字符栈」？**

```
   因为要支持退格删除 —— 删除操作永远是「删掉最后输入的那个字符」，
   这正是「后进先出」，所以用栈最自然：
   
   输入 'a' → 入栈          显示 "a"
   输入 'b' → 入栈          显示 "ab"
   按退格   → 出栈 'b'      显示 "a"
   输入 'c' → 入栈          显示 "ac"
```

**需要用到的扫描码（`AH` 返回值）：**

| 按键 | 名称 | 扫描码 | 字符码 |
|---|---|---|---|
| `Enter` | 回车 | **`1CH`** | `0DH` |
| `Backspace` | 退格 | **`0EH`** | `08H` |
| `Esc` | 退出 | `01H` | `1BH` |
| 方向键 ↑ | | `48H` | `00H` |
| 方向键 ← | | `4BH` | `00H` |

**★★ 关键判断技巧：区分「可打印字符」和「控制键」★★**

```
   ★ 如果 AL（字符码）< 20H，说明这个键不是「可打印字符」，
     而是控制键或功能键 —— 这时要去检查 AH（扫描码）。
   
   ★ 例如按回车：AL = 0DH < 20H → 不是可打印字符 → 检查 AH = 1CH → 是回车
   ★ 例如按 'a'：AL = 61H ≥ 20H → 可打印字符 → 直接显示
```

**完整程序（可直接汇编运行）：**

```asm
assume cs:code, ds:data
data segment
    buf db 33 dup (0)           ; ★ 字符栈：存放已输入的字符（33 = 32 个字符 + 1 个结束标记 0）
    top dw 0                    ; ★ 栈顶指针（= 已输入的字符个数）
data ends

code segment
start:
    mov ax, data
    mov ds, ax
    call getstr                 ; 接收一行字符串输入

    mov ax, 4c00h
    int 21h

; ===== 子程序 getstr：接收字符串输入 =====
getstr:
    push ax
getstrs:
    mov ah, 0
    int 16h                     ; ★ 读一个键（缓冲区空则等待）
                                ;   返回：AL = 字符码，AH = 扫描码

    cmp al, 20h
    jb  nochar                  ; ★ AL < 20H → 不是可打印字符，转去判断控制键

    ; ===== 可打印字符：入栈 + 显示 =====
    mov ah, 0
    call charstack              ; 功能号 0：把 AL 中的字符入栈
    mov ah, 2
    call charstack              ; 功能号 2：重新显示整个字符串
    jmp short getstrs

nochar:
    cmp ah, 0eh                 ; ★ 退格键的扫描码是 0EH
    je  backspace
    cmp ah, 1ch                 ; ★ 回车键的扫描码是 1CH
    je  entert                  ; ★ 注意标号不能叫 enter（MASM 保留字）
    jmp short getstrs           ; 其他控制键：忽略，继续读

backspace:
    mov ah, 1
    call charstack              ; 功能号 1：从栈中弹出最后一个字符
    mov ah, 2
    call charstack              ; 重新显示（少了一个字符）
    jmp short getstrs

entert:                         ; ★ 标号叫 entert 而不是 enter —— 见下面的警告块
    mov al, 0                   ; ★ 准备在字符串末尾补一个 0 作为结束标记
    mov ah, 0
    call charstack              ; ★★ 功能号 0（charpush）：把 0 真正压入 buf 末尾
                                ;    —— 注意这里必须是 0，不能写 2！
    mov ah, 2
    call charstack              ; 功能号 2（charshow）：重新显示（0 显示为空白）
    pop ax
    ret

; ===== 子程序 charstack：字符栈操作（用直接定址表调度）=====
; 入口参数：AH = 功能号（0 = 入栈，1 = 出栈，2 = 显示），AL = 入栈的字符
;           AH = 1（出栈）时，出口参数 AL = 被弹出的字符
; ★ 注意：AX 是入口/出口参数，所以这里【不保护 AX】
charstack:
    jmp short charstart
    table dw charpush, charpop, charshow        ; ★ 第 16 章的直接定址表
charstart:
    push bx
    push cx
    push dx
    push di
    push es

    cmp ah, 2
    ja  sret                    ; ★ 功能号越界保护
    mov bl, ah
    mov bh, 0
    add bx, bx                  ; ★ dw 表：偏移 = 功能号 × 2
    call word ptr table[bx]     ; ★ 查表调用

sret:
    pop es
    pop di
    pop dx
    pop cx
    pop bx
    ret

; ===== 功能 0：入栈 =====
charpush:
    mov bx, top
    cmp bx, 32                  ; ★ 栈满保护（最多 32 个字符）
    jae cpret
    mov buf[bx], al             ; ★ 数据标号 + 索引（第 16 章）
    inc word ptr top
    ret

; ===== 功能 1：出栈 =====
charpop:
    cmp word ptr top, 0
    je  cpret                   ; 栈空，什么也不做
    dec word ptr top
    mov bx, top
    mov al, buf[bx]
cpret:
    ret

; ===== 功能 2：显示 =====
charshow:
    mov bx, 0b800h
    mov es, bx
    mov di, 160*12 + 40*2       ; ★ 从第 12 行第 40 列开始显示
    mov cx, 0
showloop:
    cmp cx, top
    jae showret                 ; 显示完 top 个字符就结束
    mov bx, cx
    mov al, buf[bx]
    mov es:[di], al             ; 写字符
    mov byte ptr es:[di+1], 2   ; 写属性：黑底绿字
    add di, 2
    inc cx
    jmp short showloop
showret:
    mov byte ptr es:[di], ' '   ; ★ 补一个空格，擦掉退格后残留的字符
    mov byte ptr es:[di+1], 2
    ret
code ends
end start
```

**运行结果：**

```
   程序运行后，你可以在屏幕上【看到自己输入的每一个字符】：
   
   输入 a b c        →  屏幕第 12 行显示：abc
   按退格键           →  屏幕显示：ab
   输入 d e           →  屏幕显示：abde
   按回车             →  输入结束，程序返回 DOS（字符串已存在 buf 中）
```

> **★★ 两个本机 MASM 6.11 实测出来的坑（都踩过，务必记住）★★**
>
> **坑一：回车分支里必须用功能号 0，不能用功能号 2。**
> 很多同学（和不少网上的版本）会写成 `mov al, 0` + `mov ah, 2` + `call charstack`，以为「调用显示功能，顺便就把 0 存进去了」。**错。** 查一下 `charstack` 的表就明白：
>
> | 功能号 | 子程序 | 它做什么 | 会不会把 `AL` 写进 `buf` |
> |---|---|---|---|
> | `0` | `charpush` | `mov buf[bx], al` + `inc top` | **会** |
> | `1` | `charpop` | `dec top` + 读出字符 | 不会（反而读 `AL`） |
> | `2` | `charshow` | 只把 `buf[0..top-1]` 写到显存，末尾补空格 | **不会**（`AL` 根本没用上） |
>
> 所以 **`mov ah, 2` 之后 `buf` 里一个字节都没多**，字符串末尾**没有 `0` 结束标记**——后面若用 `mov al, buf[bx]` 逐字符处理，就会一直读下去读到垃圾。**正确写法是 `mov ah, 0`（`charpush`）先把 `0` 压进去，再 `mov ah, 2` 刷新一次显示。** 程序里那两条 `call charstack` 就是这个意思。
>
> **坑二：标号不能叫 `enter`。**
> **`ENTER` 是 MASM 的保留字**（它是 80186 引入的「建立堆栈帧」指令，MASM 6.x 认识它）。把标号写成 `enter:` 会报：
> ```
> getstr.asm(31): error A2085: instruction or register not accepted in current CPU mode
> ```
> 注意这条错误信息**看起来像「CPU 型号不对」，其实只是名字撞了保留字**，非常容易误判。**本程序里改名为 `entert` 即可**（本机实测：改名后 `exit=0` 汇编通过）。
> **同类必须避开的标号名**：`c`（语言说明符，报 `A2008: syntax error : c`，第 16 章已讲）、`enter`、以及指令助记符本身（`mov`、`add`、`push`…）和寄存器名（`ax`、`ds`…）。**起标号名的安全做法：用 `s1`、`next`、`done`、`entert` 这类明显不是指令/寄存器的词。**

**程序结构总结：**

```
   getstr（主循环）
     ├── int 16h 读键
     ├── AL ≥ 20H  → 可打印字符 → charstack(入栈) + charstack(显示)
     └── AL < 20H  → 控制键 → 看 AH：
                   ├── 0EH（退格）→ charstack(出栈) + charstack(显示)
                   ├── 1CH（回车）→ 补 0，结束
                   └── 其他      → 忽略，继续读
   
   charstack（字符栈操作，用查表调度）
     ├── 功能 0：charpush  入栈
     ├── 功能 1：charpop   出栈
     └── 功能 2：charshow  显示
```

> **重点**：**这个程序是第 12~16 章技术的集大成：`int 16h` 读键（17.2）+ 显存直接写（12）+ 栈的思想（3）+ 直接定址表（16）+ 数据标号索引（16）+ 子程序与参数传递（10）。** 考试里如果出「写一个带退格的输入程序」，把上面这个结构写出来就够了。**三个必须注意的细节：① 用 `AL < 20H` 区分可打印字符与控制键；② 退格和回车要判 `AH`（扫描码）而不是 `AL`；③ 显示时要多写一个空格，否则退格后原来的字符会残留在屏幕上。**

## 17.4 应用int 13h中断例程对磁盘进行读写

**磁盘是计算机的主要外存储器，`int 13h` 是 BIOS 提供的磁盘服务中断。**

### 磁盘的物理结构

**磁盘的表面被划分成许多同心圆，每个同心圆叫一个「磁道（Track）」；磁道又被划分成若干段，每段叫一个「扇区（Sector）」。**

```
            磁盘表面（俯视）
        ╭─────────────────────────╮
        │   ╭─────────────────╮   │
        │  │  ╭───────────╮   │  │
        │  │ │  ╭─────╮   │  │  │
        │  │ │ │ ╭─╮ │   │  │  │
        │  │ │ │ │ │ │   │  │  │
        │  │ │ │ ╰─╯ │   │  │  │
        │  │ │ ╰─────╯   │  │  │
        │  │ ╰───────────╯  │  │
        │   ╰─────────────────╯   │
        ╰─────────────────────────╯
          └── 每一圈 = 一个磁道
              └─ 每段 = 一个扇区（512 字节）
```

**三个基本参数（CHS 寻址）：**

| 参数 | 英文 | 含义 |
|---|---|---|
| **面** | Side / Head | 磁盘有**两个面**（正面和反面），用**磁头号**区分 |
| **磁道** | Track / Cylinder | 每个面上的同心圆数量（软盘 80 个） |
| **扇区** | Sector | 每个磁道上划分的段数（软盘 18 个） |

**★ 一个扇区固定 512 字节（这是硬件规定，必须记住）。**

**3.5 英寸软盘的容量计算：**

```
   2 面 × 80 磁道 × 18 扇区 × 512 字节
   = 2 × 80 × 18 × 512
   = 1 474 560 字节
   = 1440 KB
   ≈ 1.44 MB
```

### int 13h 的常用功能

| `AH` | 功能 | 说明 |
|---|---|---|
| **`0`** | **复位磁盘系统** | 重新校准磁头 |
| **`1`** | 读磁盘状态 | 返回上次操作的状态 |
| **`2`** | **读扇区** | 从磁盘读数据到内存 |
| **`3`** | **写扇区** | 从内存写数据到磁盘 |
| `4` | 校验扇区 | |
| `5` | 格式化磁道 | **危险，不要随便用** |

**读扇区（`AH = 2`）的入口参数（必须背下来）：**

| 寄存器 | 含义 |
|---|---|
| **`AH`** | **`2`**（功能号：读扇区） |
| **`AL`** | **要读的扇区数** |
| **`CH`** | **磁道号**（柱面号） |
| **`CL`** | **扇区号（从 1 开始编号！）** |
| **`DH`** | **磁头号**（面号，从 0 开始） |
| **`DL`** | **驱动器号**：`0` = 软驱 A，`1` = 软驱 B，**`80H` = 硬盘** |
| **`ES:BX`** | **数据要读到哪里**（缓冲区地址） |

**出口参数：**

| 标志/寄存器 | 含义 |
|---|---|
| **`CF`** | **`CF = 0` 表示操作成功；`CF = 1` 表示失败** |
| `AH` | 失败时的错误码 |

**★ 注意扇区号从 1 开始，磁头号和磁道号从 0 开始——这个「不统一」最容易出错。**

**写扇区（`AH = 3`）的入口参数与读扇区完全相同，只是数据从 `ES:BX` 处写到磁盘。**

**例一：读 A 盘 0 面 0 道 1 扇区（引导扇区）到内存 `0:200`。**

```asm
assume cs:code
code segment
start:
    mov ax, 0
    mov es, ax
    mov bx, 200h                ; ★ ES:BX = 0000:0200（数据缓冲区）

    mov al, 1                   ; ★ 读 1 个扇区
    mov ch, 0                   ; ★ 0 磁道
    mov cl, 1                   ; ★ 1 扇区（扇区号从 1 开始！）
    mov dh, 0                   ; ★ 0 面
    mov dl, 0                   ; ★ 驱动器 A（硬盘要用 80H）
    mov ah, 2                   ; ★ 功能号 2：读扇区
    int 13h

    jc  error                   ; ★ CF = 1 → 读失败
    ; CF = 0 → 读取成功，数据已在 0:200

    mov ax, 4c00h
    int 21h
error:
    ; 出错处理
    mov ax, 4c00h
    int 21h
code ends
end start
```

**这段代码的关键点：**

| 要点 | 说明 |
|---|---|
| `mov bx, 200h` | `0:200` 是安全空间（第 5 章），不会覆盖系统数据 |
| `mov cl, 1` | **扇区号从 1 开始**，所以第一个扇区是 1 而不是 0 |
| `mov dl, 0` | 软驱 A。**如果读硬盘要写 `80H`** |
| `jc error` | **`CF` 是唯一的成功/失败指示**，不能不看 |
| 寄存器顺序 | `AH` 最后设（因为 `mov al,1` 不影响 `AH`，但写代码时先设 `AL` 再设 `AH` 更清晰） |

**例二：完整程序——读引导扇区并把前 32 字节显示在屏幕上。**

```asm
assume cs:code
code segment
start:
    ; ===== 第一步：读 A 盘 0 面 0 道 1 扇区 到 0:200 =====
    mov ax, 0
    mov es, ax
    mov bx, 200h
    mov al, 1
    mov ch, 0
    mov cl, 1
    mov dh, 0
    mov dl, 0
    mov ah, 2
    int 13h
    jc  readerr

    ; ===== 第二步：把 0:200 处的前 32 字节显示到屏幕第 12 行 =====
    mov ax, 0
    mov ds, ax                  ; ★ DS:SI → 0:200
    mov si, 200h

    mov ax, 0b800h
    mov es, ax
    mov di, 160*12              ; ★ 从第 12 行第 0 列开始

    mov cx, 32                  ; 显示 32 个字节
show:
    mov al, [si]
    cmp al, 20h
    jae printable               ; 可打印字符（≥ 20H）原样显示
    mov al, '.'                 ; ★ 不可打印字符统一显示成 '.'
printable:
    mov es:[di], al
    mov byte ptr es:[di+1], 2   ; 属性：黑底绿字
    add di, 2
    inc si
    loop show

    mov ax, 4c00h
    int 21h

readerr:
    ; ===== 读盘失败：显示提示 =====
    mov ax, 0b800h
    mov es, ax
    mov di, 160*12 + 30*2
    mov al, 'E'
    mov es:[di], al
    mov byte ptr es:[di+1], 4   ; 红色
    mov ax, 4c00h
    int 21h
code ends
end start
```

**运行结果：**

```
   如果 A 盘存在且能读：屏幕第 12 行显示引导扇区前 32 字节的内容
        （前 3 字节通常是 EB xx 90（跳转指令），第 4~11 字节是厂商名，
          中间会出现一些被替换成 '.' 的不可打印字节）
   
   如果读盘失败（如没有软驱 / DOSBox 未挂载 A 盘）：第 12 行显示红色的 'E'
```

> **重点**：**在 DOSBox 等模拟环境下，`A` 盘通常需要先挂载镜像（`MOUNT A <路径>`）才能读；没有挂载时 `int 13h` 会返回 `CF = 1`。** 这也正是必须检查 `CF` 的原因——**磁盘操作是最容易失败的操作之一**（无盘、坏道、扇区号越界……）。

**★ 写扇区极其危险：**

```
   ★ AH = 3 会把 ES:BX 处的数据【覆盖】到磁盘上指定的扇区。
   ★ 如果扇区号、磁道号写错，可能覆盖掉引导扇区或文件系统数据，
     导致磁盘内容损坏。
   ★ 练习时务必：
        · 用软盘镜像做实验（DOSBox 里挂载一个 img 文件）
        · 读写之前先确认「面 / 道 / 扇区」三个数字
        · 先在纸上把参数写清楚再敲代码
```

**读扇区与写扇区的对比：**

| 对比项 | `AH = 2`（读扇区） | `AH = 3`（写扇区） |
|---|---|---|
| 数据流向 | 磁盘 → `ES:BX` | `ES:BX` → 磁盘 |
| 入口参数 | **完全相同** | **完全相同** |
| 危险性 | 低（只读） | **高（会覆盖磁盘数据）** |
| 用途 | 读引导扇区、读文件内容 | 写引导扇区、保存数据 |

## 典型例题

**例 17.1**（题型：键盘缓冲区）
按下 `a` 键（扫描码 `1EH`、字符码 `61H`）后，键盘缓冲区里新增的那 2 个字节分别是什么？程序用 `int 16h` 的 0 号功能读出来时，`AL` 和 `AH` 各是什么？
**解**：
- 缓冲区中每个按键占 2 字节：**低字节存字符码、高字节存扫描码**。
  - 低字节 = **`61H`**（`'a'` 的 ASCII）
  - 高字节 = **`1EH`**（扫描码）
- 用 0 号功能读出后：**`AL = 61H`（字符码）、`AH = 1EH`（扫描码）**。
**答案**：低字节 `61H`、高字节 `1EH`；`AL = 61H`、`AH = 1EH`。
**关键**：**这个顺序使 `int 16h` 可以用一次内存读取（读一个字到 `AX`）同时得到字符码和扫描码。**

**例 17.2**（题型：`int 16h` 功能号选择）
分别说明下面两种情况该用 `int 16h` 的哪个功能号，并写出代码：
（1）程序要等用户按一个键才继续。
（2）程序要一边做其他事一边检测用户有没有按键。
**解**：
- （1）用 **`AH = 0`**——缓冲区为空时会**阻塞等待**：
```asm
    mov ah, 0
    int 16h                 ; 程序停在这里直到有键
```
- （2）用 **`AH = 1`**——**立即返回**，用 `ZF` 表示有无按键：
```asm
    mov ah, 1
    int 16h
    jnz key_pressed         ; ZF = 0 → 有键
    ; ZF = 1 → 无键，继续做别的事
```
**答案**：见上。
**关键**：**1 号功能只「看」不「拿」——检测到有键后还要用 0 号功能把键读走，否则它会一直留在缓冲区里。**

**例 17.3**（题型：`int 16h` 的 `ZF` 语义）
下面代码有什么问题？
```asm
wait:
    mov ah, 1
    int 16h
    jz  wait                ; ZF = 1 就继续等
    ; 有键了，继续往下执行
```
**解**：
- **`jz wait` 的逻辑是对的**（`ZF = 1` 表示缓冲区空 → 继续等待）。
- **问题在于：只用了 1 号功能检测，没有用 0 号功能把按键读走。** 所以那个按键**永远留在键盘缓冲区里**，后面任何用到 `int 16h` 的代码（包括 DOS 命令行）都会立刻读到这个「陈旧的键」——**造成按键重复响应或程序行为异常**。
- **正确写法**：检测到有键后再读走。
```asm
wait:
    mov ah, 1
    int 16h
    jz  wait
    mov ah, 0
    int 16h                 ; ★ 把键读走
```
**答案**：缺少「用 0 号功能读走按键」这一步，会导致按键残留、被后续代码重复读取。

**例 17.4**（题型：区分可打印字符与控制键）
`int 16h` 返回 `AL = 0DH`、`AH = 1CH`。这是什么键？为什么判断时要先看 `AL` 再看 `AH`？
**解**：
- **`AH = 1CH` 是回车键（`Enter`）的扫描码**，`AL = 0DH` 是回车符 `CR` 的字符码。所以这是**回车键**。
- **判断顺序的道理**：**所有控制键和功能键的字符码都在 `20H` 以下**（`CR = 0DH`、退格 `BS = 08H`、`Esc = 1BH`，方向键和功能键的字符码甚至是 `00H`）。所以**先用 `cmp al, 20h` / `jb` 排除掉可打印字符**，剩下的再去看 `AH`（扫描码）具体是哪个控制键——**这样只需比较少数几种控制键，而不是把几百个可打印字符都过一遍**。
**答案**：回车键；因为「`AL < 20H`」能一次性筛出所有非可打印字符，是效率最高、最不易漏判的方法。

**例 17.5**（题型：软盘容量计算）
一张 3.5 英寸软盘有 2 面、每面 80 磁道、每磁道 18 扇区。请计算它的容量（以 KB 和 MB 为单位）。
**解**：
```
   扇区总数 = 2 面 × 80 磁道 × 18 扇区 = 2880 个扇区
   每个扇区 = 512 字节
   
   总容量 = 2880 × 512 = 1 474 560 字节
          = 1 474 560 ÷ 1024 = 1440 KB
          = 1440 ÷ 1024 ≈ 1.41 MB（按 1MB = 1024KB 算）
          ≈ 1.44 MB（按 1MB = 1000KB 的厂商标称法算）
```
**答案**：**1440 KB ≈ 1.44 MB**。

**例 17.6**（题型：`int 13h` 参数设置）
写出「把 A 盘 0 面 1 道 3 扇区开始的 2 个扇区读到内存 `2000:0000` 处」的代码。
**解**：
```asm
    mov ax, 2000h
    mov es, ax                  ; ★ ES = 2000H
    mov bx, 0                   ; ★ BX = 0 → ES:BX = 2000:0000

    mov al, 2                   ; ★ 读 2 个扇区
    mov ch, 1                   ; ★ 磁道号 1
    mov cl, 3                   ; ★ 扇区号 3（从 1 开始编号）
    mov dh, 0                   ; ★ 磁头号（面号）0
    mov dl, 0                   ; ★ 驱动器 A（硬盘用 80H）
    mov ah, 2                   ; ★ 功能号 2：读扇区
    int 13h

    jc  error                   ; ★ CF = 1 表示失败
```
**答案**：见上。**关键**：① `ES:BX` 是**两个寄存器**共同给出的缓冲区地址；② **扇区号从 1 开始**，磁道号和磁头号从 0 开始；③ **必须检查 `CF`**。

**例 17.7**（题型：综合编程）
用 `int 13h` 写一个程序：把内存 `0:200` 处的一个 512 字节的扇区数据写到 A 盘的 0 面 0 道 2 扇区。要求有错误处理。
**解**：
```asm
assume cs:code
code segment
start:
    mov ax, 0
    mov es, ax
    mov bx, 200h                ; ★ ES:BX = 0000:0200（数据源）

    mov al, 1                   ; 写 1 个扇区
    mov ch, 0                   ; 0 磁道
    mov cl, 2                   ; ★ 2 扇区（不能写 1 扇区，那是引导扇区！）
    mov dh, 0                   ; 0 面
    mov dl, 0                   ; 驱动器 A
    mov ah, 3                   ; ★ 功能号 3：写扇区
    int 13h

    jc  werr                    ; ★ CF = 1 → 写失败

    mov ax, 4c00h
    int 21h

werr:
    ; ===== 写失败：在屏幕第 12 行显示红色 'E' =====
    mov ax, 0b800h
    mov es, ax
    mov di, 160*12 + 40*2
    mov byte ptr es:[di], 'E'
    mov byte ptr es:[di+1], 4
    mov ax, 4c00h
    int 21h
code ends
end start
```

**答案**：见上。
**关键**：① **绝对不能写 1 扇区**（0 面 0 道 1 扇区是引导扇区，写坏会导致磁盘无法启动）；② 写扇区的入口参数与读扇区**完全相同**，只是功能号改成 3、数据流向相反；③ **仍然必须检查 `CF`**。

## 易错点提醒

1. **错**：以为 `int 9` 和 `int 16h` 是同一件事。**对**：**`int 9` 是「往键盘缓冲区里放」（生产者），`int 16h` 是「从键盘缓冲区里取」（消费者）。** 它们是**不同角色**，通过缓冲区协作。
2. **错**：`int 16h` 的返回寄存器记反。**对**：**`AL` = 字符码（ASCII）、`AH` = 扫描码。** 要判断功能键（`F1`、方向键等）**必须看 `AH`**，因为它们的字符码通常是 `00H`。
3. **错**：以为 `int 16h` 的 1 号功能会「取走」按键。**对**：**1 号功能只「看」不「拿」**——它不删除缓冲区里的按键。**检测到有键后必须再用 0 号功能把它读走**，否则按键会残留在缓冲区，被后续代码重复读取。
4. **错**：忘了 `int 16h` 的 1 号功能是用 **`ZF`** 而不是某个寄存器返回「有无按键」的。**对**：**`ZF = 0` 表示有键（用 `jnz`）、`ZF = 1` 表示无键（用 `jz`）。** 这是少数用标志位做返回值的接口。
5. **错**：用 `int 16h` 的 0 号功能做「不阻塞检测」。**对**：**0 号功能在缓冲区为空时会阻塞等待**，程序会「卡住」。**要边干活边检测就用 1 号功能。**
6. **错**：想直接读 `60H` 端口来获取按键。**对**：**`60H` 里只有扫描码，没有字符码**；而且直接读会**绕过 BIOS 的处理，与 BIOS 抢数据**。**正确做法是用 `int 16h`。**
7. **错**：判断控制键时只看 `AL`。**对**：**回车、退格、方向键、功能键的字符码都可能为 `0` 或很小的值，必须看 `AH`（扫描码）才能区分。** 标准套路是：先 `cmp al,20h` / `jb` 筛掉可打印字符，再看 `AH`。
8. **错**：退格键的扫描码记成 `08H`。**对**：**退格键的扫描码是 `0EH`**（`08H` 是它的**字符码** `BS`）；**回车的扫描码是 `1CH`**（`0DH` 是字符码 `CR`）。**判断时要比较 `AH`，所以用 `0EH` 和 `1CH`。**
9. **错**：字符串输入程序退格后不擦屏。**对**：**退格后必须重新绘制，并且在最后一个字符之后补一个空格**，否则原来那个字符会残留在屏幕上（看起来「退格没生效」）。
10. **错**：把 `int 13h` 的**扇区号从 0 开始**数。**对**：**磁道号（`CH`）和磁头号（`DH`）从 0 开始，但扇区号（`CL`）从 1 开始！** 这「三缺一」的不统一是最经典的错误来源。
11. **错**：读硬盘时 `DL` 也写 0。**对**：**软驱 A 是 `DL = 0`、软驱 B 是 `DL = 1`、硬盘是 `DL = 80H`。** 写错了会读错设备或直接失败。
12. **错**：忘了检查 `int 13h` 的 `CF`。**对**：**`CF = 0` 表示成功、`CF = 1` 表示失败**——磁盘操作很容易失败（无盘、未挂载镜像、扇区越界、坏道）。**不检查 `CF` 就会把「失败后留下的垃圾数据」当成有效数据使用。**
13. **错**：`ES:BX` 只设了 `BX` 不设 `ES`。**对**：**缓冲区地址由 `ES:BX` 两个寄存器共同给出**，只设一个就会把数据写到别的内存区域（可能覆盖系统数据）。**另外 `ES` 不能直接送立即数**，要用通用寄存器中转。
14. **错**：以为「写扇区」和「读扇区」的参数不一样。**对**：**`AH = 3`（写）与 `AH = 2`（读）的入口参数完全相同**，只有功能号不同、数据流向相反。**唯一的例外是必须格外小心扇区号——不要写到引导扇区。**
15. **错**：在真机上随意做写扇区实验。**对**：**写扇区会覆盖磁盘上的原有数据，写错扇区可能损坏引导扇区或文件系统。** 实验时应在 DOSBox 中**挂载一个软盘镜像文件**来操作。

## 本章小结

- **键盘处理链路**：按键 → 扫描码 → `60H` 端口 → `int 9` 中断 → **BIOS 例程把「字符码 + 扫描码」送入键盘缓冲区** → 程序用 **`int 16h`** 取键。
- **键盘缓冲区**：**环形、可存 15 个按键、每个按键 2 字节（低字节字符码、高字节扫描码）**；满时丢键并响一声。
- **`int 9` 是生产者、`int 16h` 是消费者**——经典的「生产者-消费者」模型。
- **`int 16h` 三个常用功能**：
  - **`AH = 0`**：读一个键并删除；**缓冲区空则阻塞等待**；返回 **`AL` = 字符码、`AH` = 扫描码**。
  - **`AH = 1`**：读一个键但**不删除**；**`ZF = 0` 有键、`ZF = 1` 无键**；立即返回（不阻塞）。
  - **`AH = 2`**：读状态字节（Shift/Ctrl/Alt 等）。
- **★ 1 号功能只「看」不「拿」——检测到有键后必须用 0 号功能读走，否则按键残留在缓冲区。★**
- **字符串输入程序三要素**：**边输入边显示、回车结束、退格删除**；用**字符栈**保存已输入字符（后进先出正好匹配退格）。
- **区分可打印字符与控制键的判断技巧**：**`AL < 20H` → 不是可打印字符 → 再看 `AH`（扫描码）**。常用扫描码：**退格 `0EH`、回车 `1CH`**；字符码：退格 `08H`、回车 `0DH`。
- **退格后重绘时必须多写一个空格**，否则残留字符。
- **磁盘物理结构**：**面（磁头）/ 磁道 / 扇区**；**每个扇区 512 字节**；3.5 英寸软盘 = **2 面 × 80 磁道 × 18 扇区 × 512 字节 = 1440 KB ≈ 1.44 MB**。
- **`int 13h` 常用功能**：**`AH = 2` 读扇区、`AH = 3` 写扇区、`AH = 0` 复位磁盘**。
- **★★ 读/写扇区的入口参数（两者完全相同）：`AH` = 功能号、`AL` = 扇区数、`CH` = 磁道号、`CL` = 扇区号（从 1 开始！）、`DH` = 磁头号、`DL` = 驱动器号（`0` = A、`1` = B、`80H` = 硬盘）、`ES:BX` = 数据缓冲区。出口：`CF = 0` 成功、`CF = 1` 失败。★★**
- **写扇区（`AH = 3`）会覆盖磁盘数据，务必在镜像文件上做实验，绝不碰引导扇区。**

> **一句话记住本章**：**「`int 9` 写缓冲区、`int 16h` 读缓冲区，按键两字节（低字符码、高扫描码），`AH=0` 阻塞取走、`AH=1` 看而不取（`ZF` 表态）」；「磁盘 = 面 × 道 × 扇区 × 512 字节，`AH=2` 读、`AH=3` 写，参数全一样（`CH` 道、`CL` 扇区从 1 起、`DH` 面、`DL` 盘号、`ES:BX` 缓冲区），成功与否只看 `CF`」。**

## 自测题

**1.** 键盘缓冲区由谁写入、由谁读出？这体现了什么模型？
**答**：**由 BIOS 的 `int 9` 中断例程写入**（把按键的字符码和扫描码送进去），**由程序通过 `int 16h` 中断例程读出**。这体现了经典的「**生产者-消费者**」模型——`int 9` 是生产者、`int 16h` 是消费者、键盘缓冲区是它们之间的队列。

**2.** 键盘缓冲区能存多少个按键？每个按键占几个字节？各字节存放什么？
**答**：**能存 15 个按键**；**每个按键占 2 个字节**：**低字节存放字符码（ASCII）、高字节存放扫描码**。

**3.** 为什么键盘缓冲区里「低字节放字符码、高字节放扫描码」？这样安排有什么好处？
**答**：因为 **`int 16h` 读取时就是把缓冲区里的这 2 个字节一次读进 `AX`**——低字节进 `AL`、高字节进 `AH`。**这样一次内存读取就同时得到了字符码（`AL`）和扫描码（`AH`），不需要读两次或做位运算。**

**4.** `int 16h` 的 0 号、1 号、2 号功能各做什么？入口和出口参数是什么？
**答**：
- **0 号**：从缓冲区读一个按键并**删除**它；入口无；出口 `AL` = 字符码、`AH` = 扫描码；**缓冲区空时阻塞等待**。
- **1 号**：读一个按键但**不删除**；入口无；出口 **`ZF = 0` 表示有键**（`AL` = 字符码、`AH` = 扫描码）、**`ZF = 1` 表示无键**；**立即返回，不阻塞**。
- **2 号**：读状态字节；出口 `AL` = 状态字节（Shift/Ctrl/Alt/CapsLock 等状态）。

**5.** 为什么用 1 号功能检测到按键后还要用 0 号功能再读一次？
**答**：**因为 1 号功能只「看」不「拿」，不删除缓冲区里的按键。** 如果只用 1 号功能检测而不读走，那个按键会**永远留在缓冲区里**，导致下一轮检测仍然「有键」——**造成死循环，或者被后面任何调用 `int 16h` 的代码重复读到。**

**6.** `int 16h` 返回 `AH = 48H`、`AL = 00H`，这是什么键？为什么必须看 `AH`？
**答**：`AH = 48H` 是**方向键 ↑（上箭头）**的扫描码。**因为功能键和方向键的字符码通常是 `00H`**——如果只看 `AL`，所有方向键、功能键都会显示成「同一个键」，无法区分。**所以判断非字符键必须看 `AH`（扫描码）。**

**7.** 编写字符串输入程序时，如何区分「可打印字符」和「控制键」？说出判断代码和理由。
**答**：**用 `AL` 与 `20H` 比较**：
```asm
cmp al, 20h
jb  nochar          ; AL < 20H → 不是可打印字符
```
**理由**：**所有可打印字符（字母、数字、符号、空格）的 ASCII 码都 ≥ `20H`；而所有控制键（回车 `0DH`、退格 `08H`、`Esc` 1BH……）和功能键/方向键（字符码多为 `00H`）都 < `20H`。** 这样一条比较就能筛掉全部可打印字符，剩下的少数几种再去比较 `AH`。

**8.** 退格键和回车键的**扫描码**分别是多少？它们的**字符码**又分别是多少？
**答**：**退格键扫描码 `0EH`、字符码 `08H`（`BS`）；回车键扫描码 `1CH`、字符码 `0DH`（`CR`）。** 在字符串输入程序里判断按键类型时比较的是 `AH`，所以要用 `0EH` 和 `1CH`。

**9.** 字符串输入程序为什么用「字符栈」来保存已输入的字符？
**答**：**因为退格删除永远是「删掉最后输入的那个字符」，这正是「后进先出」，与栈的特性完全吻合。** 用栈保存后，退格只需要一次「出栈」，回车时的字符串也天然按输入顺序排列在栈里。

**10.** 字符串输入程序退格后重新显示时，为什么要在最后一个字符后面多写一个空格？
**答**：**因为重新显示时只重画了栈中剩余的字符，屏幕上原来那个被删掉的字符还在。** 在末尾补一个空格可以把它**擦掉**。**不补空格的话，屏幕看起来像「退格没生效」。**

**11.** 磁盘的三个基本物理参数是什么？一个扇区多少字节？
**答**：**面（Side，也叫磁头 Head）、磁道（Track，也叫柱面 Cylinder）、扇区（Sector）**；**一个扇区固定 512 字节。**

**12.** 计算 3.5 英寸软盘（2 面、80 磁道、18 扇区/道）的容量。
**解**：
```
   扇区总数 = 2 × 80 × 18 = 2880
   总容量   = 2880 × 512 = 1 474 560 字节
            = 1 474 560 ÷ 1024 = 1440 KB ≈ 1.44 MB
```
**答**：**1440 KB（约 1.44 MB）。**

**13.** 写出 `int 13h` 读扇区的入口参数，并说明哪些号从 0 开始、哪些从 1 开始。
**答**：**`AH` = 2（功能号）、`AL` = 扇区数、`CH` = 磁道号、`CL` = 扇区号、`DH` = 磁头号、`DL` = 驱动器号、`ES:BX` = 数据缓冲区地址。** 其中 **磁道号（`CH`）和磁头号（`DH`）从 0 开始，而扇区号（`CL`）从 1 开始**。出口用 **`CF`** 表示成功（0）或失败（1）。

**14.** 读扇区和写扇区的入口参数有什么区别？写扇区有什么风险？
**答**：**入口参数完全相同**——只有功能号不同（**读是 `AH = 2`、写是 `AH = 3`**），数据流向相反。**风险**：写扇区会用 `ES:BX` 处的数据**覆盖磁盘上原有内容**，如果磁道号/扇区号写错，可能**损坏引导扇区或文件系统数据**。所以实验应在 DOSBox 的软盘镜像上进行，**绝不能写 0 面 0 道 1 扇区（引导扇区）**。

**15.** 在 DOSBox 里运行读 A 盘的程序却总是失败，可能的原因是什么？程序上应该怎么处理？
**答**：**可能原因**：① **没有挂载 A 盘镜像**（DOSBox 中需先 `MOUNT A <镜像路径>`）；② 驱动器号写错（软驱 A 是 `DL = 0`，硬盘是 `80H`）；③ 扇区号写成 0（应从 1 开始）或超出范围；④ 磁道号/磁头号越界。**程序上必须检查 `int 13h` 的 `CF` 标志**（`jc error`），失败时给出提示，**而不是把失败后残留的缓冲区内容当成有效数据使用**。
