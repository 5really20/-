## 10.1 异常类和异常处理

### 10.1.1 异常和异常类

**异常（exception）是程序运行期间发生的、会中断正常流程的事件。** 异常不是语法错误：语法错误在程序运行前就被解释器拒绝，一行都执行不了；异常是程序跑起来之后，某一行执行不下去才发生的。

```python
# 语法错误：还没开始运行就报错，下面的 print 永远不会执行
# print("hello"      # SyntaxError: '(' was never closed
```

**异常发生时，Python 的处理流程是**：① 创建一个异常对象；② 沿着调用栈从内往外找能处理它的 `except`；③ 找到了就交给它处理，没找到就一路传到最外层，打印回溯信息并终止程序。

**所有异常都继承自 `BaseException`，日常打交道的是它的子类 `Exception`。** 这两者的分工是本节的第一个重点：

| 基类 | 直接子类（部分） | 该不该用 `except Exception` 捕获 |
|---|---|---|
| `BaseException` | `SystemExit`、`KeyboardInterrupt`、`GeneratorExit` | **不应该**，这三个表示"程序该退出了" |
| `Exception` | 其余全部业务异常 | **应该**，兜底就用它 |

```python
print(issubclass(KeyboardInterrupt, Exception))   # False  ← Ctrl+C 不是普通异常
print(issubclass(SystemExit, BaseException))      # True   ← sys.exit() 抛的是它
```

> **重点**：**兜底要写 `except Exception`，不要写裸 `except:`。** 裸 `except:` 等价于 `except BaseException:`，会把用户按 `Ctrl+C` 和 `sys.exit()` 一起吞掉，程序变得"杀不死"。

**常用异常类**（务必记住触发条件，读程序题直接考这个）：

| 异常类 | 触发条件 | 示例 |
|---|---|---|
| `ZeroDivisionError` | 除数为 0 | `1 / 0` |
| `ValueError` | 类型对但值不对 | `int("abc")` |
| `TypeError` | 类型不匹配 | `"a" + 1`、`len(1)` |
| `NameError` | 用了没定义的变量 | `print(undefined_var)` |
| `IndexError` | 序列下标越界 | `[1, 2][5]` |
| `KeyError` | 字典键不存在 | `{}["k"]` |
| `AttributeError` | 对象没有这个属性/方法 | `(1, 2).__setitem__` |
| `FileNotFoundError` | 文件不存在 | `open("no_such.txt")` |
| `ImportError` | 导入失败 | `import 不存在的模块` |

```python
try:
    1 / 0
except ZeroDivisionError as e:
    print(type(e).__name__, "|", e)     # ZeroDivisionError | division by zero
```

**实测的真实报错信息**（考试常要求你写出报错类型）：

```python
int("a")        # ValueError: invalid literal for int() with base 10: 'a'
[1, 2][5]       # IndexError: list index out of range
{}["k"]         # KeyError: 'k'
"a" + 1         # TypeError: can only concatenate str (not "int") to str
len(1)          # TypeError: object of type 'int' has no len()
open("no")      # FileNotFoundError: [Errno 2] No such file or directory: 'no'
```

**异常类的继承关系决定了 `except` 的匹配范围**——`except` 匹配的是"是不是这个类**或它的子类**"：

```python
print(issubclass(IndexError, LookupError))     # True   ← 所以 except LookupError 也能抓 IndexError
print(issubclass(KeyError, LookupError))       # True
print(issubclass(ZeroDivisionError, ArithmeticError))  # True
print(issubclass(FileNotFoundError, OSError))  # True
```

```
BaseException
├── SystemExit            ← 别捕获
├── KeyboardInterrupt     ← 别捕获
└── Exception
    ├── ArithmeticError ── ZeroDivisionError / OverflowError / FloatingPointError
    ├── LookupError ────── IndexError / KeyError
    ├── OSError ────────── FileNotFoundError / PermissionError / TimeoutError
    ├── ValueError
    ├── TypeError
    ├── NameError ──────── UnboundLocalError
    ├── AttributeError
    └── AssertionError
```

### 10.1.2 异常处理

**`try` 语句的完整形式有四个子句，执行顺序是固定的：**

```
try:     出问题的代码
except:  出了问题怎么办（可以写多个，从上往下匹配）
else:    try 里没出问题才执行
finally: 不管出没出问题都执行
```

**执行顺序实测**：

```python
def f(x):
    try:
        r = 10 / x
    except ZeroDivisionError as e:
        print("  except:", e)
        return "err"
    else:
        print("  else:", r)
        return r
    finally:
        print("  finally: 一定执行")

print(f(2))
#   else: 5.0
#   finally: 一定执行
# 5.0
print(f(0))
#   except: division by zero
#   finally: 一定执行
# err
```

> **重点**：**`else` 和 `finally` 的位置不能颠倒**，`else` 必须在所有 `except` 之后、`finally` 之前。`else` 的意义是"把**不该被 try 保护**的代码挪出去"——如果 `return r` 也写在 `try` 里，它的异常会被同一批 `except` 抓到，可能掩盖真正的 bug。

**`finally` 的三个用途**：① 释放资源（关文件、断连接）；② 无论成功失败都要记录的日志；③ 清理临时文件。但 `finally` 有个著名的坑：

```python
def m():
    try:
        return "try"
    finally:
        return "finally"     # ← finally 里的 return 会覆盖 try 里的 return

print(m())                   # finally
```

> **重点**：**不要在 `finally` 里写 `return`**。它会吞掉异常、覆盖返回值，是极难排查的 bug 来源。

**一个 `try` 配多个 `except` 时，从上往下匹配，第一个匹配上的生效**，所以子类必须写在父类前面：

```python
def g(x):
    try:
        return [1, 2][x] / 0
    except (IndexError, ZeroDivisionError) as e:   # 一个 except 抓多种异常，写成元组
        return f"捕获 {type(e).__name__}"
    except Exception as e:                          # 兜底必须放最后
        return f"兜底 {type(e).__name__}"

print(g(5), g(0))        # 捕获 IndexError 捕获 ZeroDivisionError
```

**`raise` 主动抛出异常**，用于"发现数据不合法时立刻终止"：

```python
def h(x):
    if x < 0:
        raise ValueError(f"不能为负：{x}")
    return x ** 0.5

try:
    h(-1)
except ValueError as e:
    print(type(e).__name__, e)     # ValueError 不能为负：-1
```

**`raise ... from e` 保留原始异常**（异常链），排错时能同时看到"表层原因"和"根本原因"：

```python
try:
    try:
        int("x")
    except ValueError as e:
        raise RuntimeError("转换失败") from e
except RuntimeError as e:
    print(e, "| cause:", type(e.__cause__).__name__)   # 转换失败 | cause: ValueError
```

**裸 `raise` 表示"重新抛出当前异常"**，常用于"记录日志后继续往上抛"：

```python
def k():
    try:
        return 1 / 0
    except ZeroDivisionError:
        print("E3 记录日志")
        raise                      # 不写异常对象，原样抛出

try:
    k()
except ZeroDivisionError as e:
    print(type(e).__name__)        # ZeroDivisionError
```

**自定义异常类**：继承 `Exception`（或它的子类），一般只写 `__init__` 和一个字符串消息。

```python
class AppError(Exception):
    """本项目所有异常的基类"""

class BalanceError(AppError):          # 继承自定义基类，便于统一捕获
    def __init__(self, balance, amount):
        super().__init__(f"余额不足：当前 {balance}，需要 {amount}")
        self.balance = balance         # 额外携带结构化数据
        self.amount = amount

try:
    raise BalanceError(50, 100)
except BalanceError as e:
    print(e, "|", e.balance, e.amount, "|", isinstance(e, AppError))
# 余额不足：当前 50，需要 100 | 50 100 | True
```

**自定义异常的四个规范**：① 类名以 `Error` 结尾；② 继承 `Exception` 而不是 `BaseException`；③ 先调 `super().__init__(消息)`；④ 项目里先定义一个 `AppError` 基类，所有自定义异常继承它，这样调用方可以 `except AppError` 一把抓。

**`with` 语句与异常**：上下文管理器的 `__exit__` 返回 **`True` 表示吞掉异常**，返回 `None`/`False` 表示继续往外抛。

```python
class Ctx:
    def __enter__(self):
        print("enter"); return self
    def __exit__(self, et, ev, tb):
        print("exit", et.__name__ if et else None)
        return True          # 吞掉异常

with Ctx():
    raise ValueError("被吞掉")
print("继续执行")
# enter
# exit ValueError
# 继续执行        ← 异常没往外传
```

**打印回溯信息**：`traceback.format_exc()` 返回字符串（适合写日志），`traceback.print_exc()` 直接打印。

```python
import traceback
try:
    1 / 0
except ZeroDivisionError:
    print(traceback.format_exc().splitlines()[-1])   # ZeroDivisionError: division by zero
```

### 10.1.3 断言语句

**`assert` 是"开发期的自检"，语法是 `assert 条件, 错误消息`**，条件为假时抛 `AssertionError`。

```python
def avg(nums):
    assert nums, "列表不能为空"          # 条件为假 → 抛 AssertionError("列表不能为空")
    return sum(nums) / len(nums)

print(avg([1, 2, 3]))     # 2.0

try:
    avg([])
except AssertionError as e:
    print(e)              # 列表不能为空
```

**`assert` 的三条使用规则**：

1. **它会被关掉。** 用 `python -O 脚本.py` 运行时，所有 `assert` 被跳过，`__debug__` 变成 `False`。所以**绝对不能用 `assert` 校验用户输入或做安全检查**——生产环境可能被优化掉。
2. **不要写 `assert` 的副作用。** `assert f()` 里如果 `f()` 有副作用，关掉断言后行为就变了。
3. **`assert 条件` 不带消息时，`str(e)` 是空串**：

```python
try:
    assert False
except AssertionError as e:
    print(repr(str(e)), type(e).__name__)    # '' AssertionError
```

| 场景 | 该用 `assert` | 该用 `raise` |
|---|---|---|
| 检查函数内部不变量 | ✅ | |
| 检查"绝不该发生"的分支 | ✅ | |
| 校验用户输入 / 文件内容 | | ✅ 必须 |
| 校验函数参数合法性 | | ✅ 必须（除非是内部函数） |

## 10.2 单元测试

**单元测试（unit test）是对"最小的可测单元"（通常是一个函数或一个方法）单独验证的代码。** 它的价值在于：改完代码跑一遍测试，就知道有没有把原来能用的功能改坏。

**Python 标准库自带 `unittest`**，用法固定为三步：① 写一个继承 `unittest.TestCase` 的类；② 每个测试写成一个**以 `test_` 开头**的方法；③ 用 `unittest.main()` 或 `TextTestRunner` 运行。

```python
import unittest

def add(a, b):
    return a + b

def div(a, b):
    if b == 0:
        raise ValueError("除数不能为 0")
    return a / b

class TestMath(unittest.TestCase):
    def setUp(self):                 # 每个测试方法执行前都会调用
        self.data = [1, 2, 3]

    def test_add(self):
        self.assertEqual(add(1, 2), 3)
        self.assertEqual(add(-1, 1), 0)

    def test_div(self):
        self.assertAlmostEqual(div(1, 3), 0.3333, places=4)   # 浮点比较要用它
        with self.assertRaises(ValueError):                    # 断言"这里应该抛异常"
            div(1, 0)

    def test_list(self):
        self.assertIn(2, self.data)
        self.assertEqual(len(self.data), 3)

    def test_skip(self):
        self.skipTest("演示跳过")

if __name__ == "__main__":
    unittest.main()
```

**运行结果实测**（`verbosity=2`）：

```python
res = unittest.TextTestRunner(stream=buf, verbosity=2).run(suite)
print(res.testsRun, len(res.failures), len(res.errors), len(res.skipped))
# 4 0 0 1        ← 4 个用例，0 失败，0 出错，1 跳过
print(res.wasSuccessful())      # True
```

**注意三个计数器的区别**：**`failures` 是断言失败**（结果不对），**`errors` 是代码出错**（比如被测函数抛了没预料到的异常），两者都要为 0 测试才算通过。

**`result.skipped` 里的元素是元组 `(test, reason)`，不是 TestCase 对象**——想拿名字要写 `t[0].id()`：

```python
print([t[0].id().split(".")[-1] for t in res.skipped])   # ['test_skip']
print(res.skipped[0][1])                                  # 演示跳过
```

**常用断言方法表**（`self.` 后面接这些）：

| 断言方法 | 通过条件 |
|---|---|
| `assertEqual(a, b)` / `assertNotEqual` | `a == b` / `a != b` |
| `assertTrue(x)` / `assertFalse(x)` | `bool(x)` 为真 / 为假 |
| `assertIsNone(x)` / `assertIsNotNone` | `x is None` / `x is not None` |
| `assertIn(a, b)` / `assertNotIn` | `a in b` / `a not in b` |
| `assertIsInstance(a, T)` | `isinstance(a, T)` |
| `assertAlmostEqual(a, b, places=7)` | 四舍五入到 `places` 位后相等（**浮点专用**） |
| `assertGreater(a, b)` / `assertLess` | `a > b` / `a < b` |
| `assertCountEqual(a, b)` | 两个序列元素相同（**忽略顺序**） |
| `assertRaises(E)` | 配合 `with`，断言块内抛 `E` |
| `assertWarns(W)` | 配合 `with`，断言块内发 `W` 警告 |

```python
self.assertAlmostEqual(0.1 + 0.2, 0.3, places=7)   # 通过
self.assertEqual(0.1 + 0.2, 0.3)                    # 失败！因为 0.30000000000000004 != 0.3
```

**断言失败时打印什么**（实测）：

```python
class T3(unittest.TestCase):
    def test_fail(self):
        self.assertEqual(add(1, 1), 3)

# 输出最后一行：AssertionError: 2 != 3
```

**`setUp` 和 `tearDown`**：`setUp` 在**每个** `test_` 方法前执行，`tearDown` 在**每个** `test_` 方法后执行（实测 4 个用例打印了 4 组 setUp/tearDown）。它们的用途是准备和清理测试环境（建临时文件、开数据库连接）。**正因为每个用例都重新 setUp，用例之间才不会互相污染**——所以**不要写出"依赖上一个用例留下的状态"的测试**。

> **关于执行顺序**：`unittest` **实际上按方法名的字母序执行**，不是按定义顺序。实测把用例定义成 `test_zebra` / `test_apple` / `test_mango` 的顺序，`TestLoader.getTestCaseNames()` 返回的是 **`['test_apple', 'test_mango', 'test_zebra']`**，实际执行顺序也相同（排序函数是 `TestLoader.sortTestMethodsUsing`，默认 `three_way_cmp`）。**但官方不保证这一点**，所以正确做法仍然是**让每个用例独立**，不要依赖任何执行顺序。

> **重点**：**测试方法名必须以 `test_` 开头**，否则 `unittest` 根本不会收集它，你会以为"测试通过"其实一个都没跑。

## 10.3 典型案例

### 10.3.1 自定义异常类

**需求**：写一个 `Account` 类，取款时金额为负抛 `ValueError`，余额不足抛自定义的 `BalanceError`，并携带当前余额供调用方使用。

```python
class AppError(Exception):
    """应用异常基类"""

class BalanceError(AppError):
    def __init__(self, balance, amount):
        super().__init__(f"余额不足：当前 {balance}，需要 {amount}")
        self.balance = balance
        self.amount = amount

class Account:
    def __init__(self, balance=0):
        self.balance = balance

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("取款金额必须为正数")
        if amount > self.balance:
            raise BalanceError(self.balance, amount)
        self.balance -= amount
        return self.balance

a = Account(100)
try:
    a.withdraw(500)
except BalanceError as e:
    print(e, "|", e.balance, e.amount)
# 余额不足：当前 100，需要 500 | 100 500
```

**设计要点**：① 消息在 `__init__` 里用 f-string 拼好，调用方直接 `print(e)` 就能看；② 额外属性（`balance`、`amount`）让调用方能写 `e.balance` 做判断，而不必去解析字符串；③ 两个异常分开，因为"金额为负"是调用方的错（`ValueError`），"余额不足"是业务状态（`BalanceError`）。

### 10.3.2 自定义测试类

**需求**：为 `is_prime(n)` 写测试，覆盖小数字、大数字、负数与边界。

```python
def is_prime(n):
    if n < 2:
        return False
    for i in range(2, int(n ** 0.5) + 1):
        if n % i == 0:
            return False
    return True

class TestPrime(unittest.TestCase):
    def test_small(self):
        self.assertTrue(is_prime(2))
        self.assertTrue(is_prime(3))
        self.assertFalse(is_prime(1))
        self.assertFalse(is_prime(4))

    def test_large(self):
        self.assertTrue(is_prime(97))
        self.assertFalse(is_prime(100))

    def test_negative(self):
        self.assertFalse(is_prime(-7))
        self.assertFalse(is_prime(0))
```

```python
# 运行结果：3 个用例全部通过
print(r.wasSuccessful(), r.testsRun, len(r.failures), len(r.errors))
# True 3 0 0
```

**给一个函数写测试的套路**（**测试用例的选取比数量更重要**）：

| 用例类别 | `is_prime` 的例子 | 为什么必须有 |
|---|---|---|
| 正常值 | 2、3、97 | 保证基本功能对 |
| 边界值 | 1、0、2 | 最容易写错的地方 |
| 非法值 | -7 | 负数循环一次都不进，容易误返回 `True` |
| 合数 | 4、100 | 保证"能识别出不是素数" |

**测试异常的分两种写法**，后者能进一步检查异常内容：

```python
# 写法一：只关心类型
with self.assertRaises(ValueError):
    a.withdraw(-5)

# 写法二：用 as cm 拿到异常对象，检查消息和属性
with self.assertRaises(BalanceError) as cm:
    a.withdraw(500)
self.assertEqual(cm.exception.balance, 100)
self.assertIn("余额不足", str(cm.exception))
```

## 典型例题

**例 10.1**（题型：读程序写结果 —— try/else/finally）

```python
def f(n):
    try:
        r = 100 // n
        print("A", r)
    except ZeroDivisionError:
        print("B")
    else:
        print("C")
    finally:
        print("D")
    return r

print("结果", f(5))
```

**解**：`f(5)` 中 `100 // 5 = 20`，`try` 块正常结束 → 打印 `A 20`；没出异常 → 执行 `else` → 打印 `C`；无论如何执行 `finally` → 打印 `D`；最后 `return r` 返回 20。注意 **`return r` 在 `try` 之外**，所以 `r` 必须能被访问到（这里能，因为 `r` 在 `try` 里赋值后仍在函数作用域内）。

**答案**：

```
A 20
C
D
结果 20
```

**例 10.2**（题型：读程序写结果 —— 异常的传播与捕获范围）

```python
try:
    try:
        print(1 / 0)
    except IndexError:
        print("内层捕获")
    finally:
        print("内层 finally")
except ZeroDivisionError:
    print("外层捕获")
```

**解**：内层 `try` 抛 `ZeroDivisionError`，但内层的 `except IndexError` **不匹配**（`ZeroDivisionError` 不是 `IndexError` 的子类），所以这个异常没被内层处理；`finally` 无条件执行 → 打印 `内层 finally`；异常继续往外抛，外层 `except ZeroDivisionError` 匹配上 → 打印 `外层捕获`。**这题的关键是 `finally` 不处理异常，只是"顺手执行"**。

**答案**：

```
内层 finally
外层捕获
```

**例 10.3**（题型：读程序写结果 —— finally 中的 return）

```python
def g():
    try:
        return 1
    finally:
        return 2

def h():
    try:
        raise ValueError("x")
    finally:
        print("清理完成")

print(g())
try:
    h()
except ValueError:
    print("抓到")
```

**解**：`g()` 的 `finally` 里有 `return 2`，**它覆盖了 `try` 的 `return 1`**，所以 `g()` 返回 2，而且 `try` 中抛出的异常也会被 `finally` 的 `return` 吞掉。`h()` 的 `finally` 只打印，异常继续往外抛，被外层 `except` 抓到。

**答案**：

```
2
清理完成
抓到
```

**例 10.4**（题型：编程题 —— 带重试的输入）

**题目**：写函数 `input_int(prompt, lo, hi)`，反复提示用户输入一个 `[lo, hi]` 范围内的整数，直到输入合法为止；输入非数字提示"不是整数"，超范围提示"超出范围"。为便于测试，用 `input` 的替身：把输入序列放在列表里逐个取。

**解**：用 `while True` + `try`/`except ValueError` 处理 `int()` 失败，用 `continue` 回到循环开头。

```python
def input_int(prompt, lo, hi, source):
    while True:
        s = next(source)                     # 代替 input(prompt)
        try:
            n = int(s)
        except ValueError:
            print(f"不是整数：{s}")
            continue
        if not (lo <= n <= hi):
            print(f"超出范围：{n}")
            continue
        return n

src = iter(["abc", "200", "50"])
print("得到", input_int("请输入：", 1, 100, src))
# 不是整数：abc
# 超出范围：200
# 得到 50
```

**答案**：输出三行诊断 + `得到 50`。**思路要点**：① `int(s)` 只保护这一句，`lo <= n <= hi` 的判断放在 `try` 外面（它不会抛 `ValueError`）；② 用 `continue` 而不是 `break`，`while True` 只在成功时 `return` 退出；③ 用 `next(iterator)` 注入输入序列，测试时不必真的敲键盘——这就是**可测试性设计**。

**例 10.5**（题型：编程题 —— 自定义异常 + 校验）

**题目**：定义异常 `ScoreError`，写函数 `grade(score)`：`score` 不是数字或不在 0~100 之间就抛 `ScoreError`（消息里带上非法值）；否则返回等级（≥90 优秀、≥80 良好、≥70 中等、≥60 及格、其余不及格）。

**解**：

```python
class ScoreError(Exception):
    def __init__(self, value, reason):
        super().__init__(f"成绩非法：{value!r}（{reason}）")
        self.value = value

def grade(score):
    if not isinstance(score, (int, float)) or isinstance(score, bool):
        raise ScoreError(score, "不是数字")
    if not (0 <= score <= 100):
        raise ScoreError(score, "不在 0~100 范围内")
    if score >= 90: return "优秀"
    if score >= 80: return "良好"
    if score >= 70: return "中等"
    if score >= 60: return "及格"
    return "不及格"

print(grade(92), grade(85), grade(70), grade(60), grade(59))
for bad in [-1, 101, "abc", True]:
    try:
        grade(bad)
    except ScoreError as e:
        print(e)
```

**答案**：

```
优秀 良好 中等 及格 不及格
成绩非法：-1（不在 0~100 范围内）
成绩非法：101（不在 0~100 范围内）
成绩非法：'abc'（不是数字）
成绩非法：True（不是数字）
```

**注意 `isinstance(score, bool)` 这一句**：`bool` 是 `int` 的子类，`isinstance(True, int)` 为 `True`，如果不排除，`grade(True)` 会被当成 1 分算成"不及格"而不是报错。消息里用 `{value!r}` 而不是 `{value}`，是为了让字符串带上引号，一眼看出 `'abc'` 是字符串。

**例 10.6**（题型：编程题 —— 为函数写单元测试）

**题目**：函数 `safe_div(a, b)` 要求：`b == 0` 抛 `ZeroDivisionError`；`a`/`b` 不是数字抛 `TypeError`；正常返回商。请写出它的实现和覆盖以上三种情况的 `unittest` 测试类。

**解**：

```python
import unittest

def safe_div(a, b):
    if not isinstance(a, (int, float)) or not isinstance(b, (int, float)):
        raise TypeError("参数必须是数字")
    if b == 0:
        raise ZeroDivisionError("除数不能为 0")
    return a / b

class TestSafeDiv(unittest.TestCase):
    def test_normal(self):
        self.assertEqual(safe_div(10, 2), 5)
        self.assertAlmostEqual(safe_div(1, 3), 0.333333, places=5)

    def test_zero(self):
        with self.assertRaises(ZeroDivisionError):
            safe_div(1, 0)

    def test_type(self):
        with self.assertRaises(TypeError):
            safe_div("1", 2)
        with self.assertRaises(TypeError):
            safe_div(1, None)

    def test_negative(self):
        self.assertEqual(safe_div(-10, 2), -5)
        self.assertEqual(safe_div(10, -2), -5)
```

**答案**：4 个测试方法全部通过，`testsRun = 4`、`failures = 0`、`errors = 0`。**思路要点**：① 正常值、异常值、边界值、负值各写一个 `test_` 方法，命名体现意图；② 浮点结果用 `assertAlmostEqual`；③ 异常用 `assertRaises`；④ **不要在一个 `test_` 方法里塞太多断言**——第一个失败后面的就不执行了，分开写定位更快。

## 易错点提醒

1. **`except` 子句顺序写反** → 错：`except Exception` 写在 `except ValueError` 前面，后者永远不执行。对：**从具体到宽泛**，子类在前、父类兜底在后。
2. **用裸 `except:` 兜底** → 错：`except:` 会把 `Ctrl+C`（`KeyboardInterrupt`）和 `sys.exit()`（`SystemExit`）也吞掉。对：写 `except Exception:`。
3. **在 `finally` 里 `return`** → 错：`return` 会覆盖 `try` 的返回值，还会吞掉正在传播的异常。对：`finally` 只做清理，不要写 `return`/`break`/`continue`。
4. **以为 `else` 是"出错了才执行"** → 错：`else` 恰恰是"**没出错**才执行"。对：记住 `else` 是"try 成功分支"，`except` 才是"失败分支"。
5. **`try` 块包得太大** → 错：把 20 行都塞进 `try`，一旦报错根本不知道哪一行出的问题，还可能被 `except` 掩盖真实 bug。对：**只把可能出错的那一两行放进 `try`**。
6. **用 `assert` 校验用户输入** → 错：`python -O` 会把 `assert` 全部跳过，校验失效。对：面向外部的校验一律用 `if ... raise ValueError(...)`。
7. **自定义异常忘了 `super().__init__()`** → 错：`str(e)` 变成空串，日志里什么都看不到。对：`super().__init__(消息字符串)` 必须调用。
8. **测试方法名没以 `test_` 开头** → 错：`unittest` 不会收集它，你以为测了其实没测。对：所有测试方法名一律 `test_` 开头，类名以 `Test` 开头。
9. **用 `assertEqual` 比较浮点数** → 错：`assertEqual(0.1 + 0.2, 0.3)` 必然失败。对：用 `assertAlmostEqual(a, b, places=7)`。
10. **把 `failures` 和 `errors` 当成一回事** → 错：`failures` 是断言不成立，`errors` 是被测代码抛了未预期的异常。对：两个都要为 0；看到 `errors` 先去看被测函数的实现，看到 `failures` 先看预期值写错没有。
11. **`except ... as e` 的 `e` 出了 `except` 块就没了** → 错：Python 3 在 `except` 块结束时会 `del e`，块外再用 `e` 会 `NameError`。对：需要留用就在块内赋值给别的变量（如 `err = e`）。
12. **`raise ValueError` 忘了加括号** → 错：`raise ValueError`（类本身）也能抛，但消息为空，且不会走你的 `__init__` 逻辑。对：统一写 `raise ValueError("消息")`。

## 本章小结

- 异常是**运行时**事件，语法错误是**运行前**就拒绝；异常继承自 `Exception`，而 `SystemExit`/`KeyboardInterrupt` 继承自 `BaseException`，不该被兜底捕获。
- `try`/`except`/`else`/`finally` 的执行顺序固定：`try` 出错走 `except`，没出错走 `else`，`finally` 永远最后执行。
- 多个 `except` **从具体到宽泛**匹配，兜底用 `except Exception:`，绝不用裸 `except:`。
- `raise` 主动抛出异常，`raise ... from e` 保留异常链，裸 `raise` 重新抛出；自定义异常要继承 `Exception` 并调 `super().__init__()`。
- `assert` 是开发期自检，会被 `python -O` 关掉，**不能用来校验外部输入**。
- `unittest` 用 `TestCase` + `test_` 开头的方法 + 断言方法组织测试；`setUp`/`tearDown` 每个用例各跑一次；浮点比较用 `assertAlmostEqual`，断言异常用 `assertRaises`。

> **一句话记住本章**：**能出错的地方用 `try` 只包那一两行、兜底写 `except Exception`、清理放 `finally`；能写测试的函数就用 `unittest` 钉住它的行为。**

**参考答案**

1. 顺序是 `try → except 或 else → finally`；**`else` 在 `try` 块没有发生异常时执行**，且必须在所有 `except` 之后、`finally` 之前。
2. 裸 `except:` 等价于 `except BaseException:`，会捕获 `KeyboardInterrupt`（Ctrl+C）和 `SystemExit`（`sys.exit()`），让程序无法正常中断；`except Exception:` 只捕获业务异常，把这两个放过去。
3. `A`（先执行 `print("A")`）、`B`（`raise` 后 `try` 中断，进入匹配的 `except`）、`D`（`finally` 无条件执行）。`else` **不执行**，因为出了异常。
4. 依次为 `ZeroDivisionError`、`ValueError`、`IndexError`、`KeyError`、`TypeError`。
5. `-O` 模式下所有 `assert` 被跳过，`__debug__` 为 `False`，这行断言**完全不执行**，`x` 为负数也不会报错。因此 `assert` **不能用于校验用户输入或做安全检查**，只能作为开发期的自检。
6. 因为调用方可以写 `except AppError:` 一次性捕获本项目所有自定义异常，而不必逐个列举；同时能通过 `except AppError` 把"自己的异常"和"标准库异常"区分开，避免误捕。
7. `failures` 是**断言不成立**（代码跑完了，结果和预期不符）；`errors` 是**被测代码抛出了未预期的异常**（代码根本没跑完）。两者都必须为 0 测试才算通过。
8. **1 个**（`test_a`）。`unittest` 只收集名字以 `test` 开头的方法；`check_b` 不是测试，`setUp` 是钩子方法不是测试。
9. 因为 `0.1 + 0.2` 的实际值是 `0.30000000000000004`，与 `0.3` 不相等，`assertEqual` 会失败。应改用 `self.assertAlmostEqual(0.1 + 0.2, 0.3, places=7)`。
10. 参考实现：
    ```python
    class ConvertError(Exception):
        def __init__(self, value):
            super().__init__(f"无法转换为整数：{value!r}")
            self.value = value

    def to_int(s):
        try:
            return int(s)
        except (ValueError, TypeError):
            raise ConvertError(s) from None

    print(to_int("42"))        # 42
    try:
        to_int("abc")
    except ConvertError as e:
        print(e)               # 无法转换为整数：'abc'
    ```
    要点：`int(s)` 可能抛 `ValueError`（字符串不是数字）也可能抛 `TypeError`（传了 `None`），所以两个都要抓；`from None` 表示不显示原始异常链，让报错更干净。
