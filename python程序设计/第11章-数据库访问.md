## 11.1 概述

**数据库（database）是按一定结构组织、存储和管理数据的仓库。** 用文件存数据有三个绕不过去的坎：

| 问题 | 用文件存 | 用数据库存 |
|---|---|---|
| 查找一条记录 | 从头读一遍，O(n) | 建索引，接近 O(log n) |
| 修改一条记录 | 整个文件重写 | 只改那一行 |
| 多个人同时改 | 后写的覆盖先写的 | 事务 + 锁，保证不出错 |
| 数据格式约束 | 靠代码自觉 | 表结构 + 约束，写错直接拒绝 |

**数据库分两大类**：

| 类别 | 数据模型 | 代表 | 适合存 |
|---|---|---|---|
| **关系型数据库（RDBMS）** | 二维表（行 + 列），表之间用外键关联 | SQLite、MySQL、PostgreSQL、SQL Server、Oracle | 结构固定、需要事务的数据（订单、成绩、账户） |
| **非关系型数据库（NoSQL）** | 文档 / 键值 / 图 | MongoDB、Redis、Neo4j | 结构多变、量大、读写频繁的数据（日志、爬虫结果） |

> **重点**：**关系型数据库用 SQL（结构化查询语言）操作，NoSQL 各家 API 不同。** 学好 SQL 和 DB-API 流程，换数据库时改的只是连接语句。

## 11.2 常用关系数据库访问

### 11.2.1 常用关系数据库简介

| 数据库 | 特点 | 典型场景 | Python 驱动 |
|---|---|---|---|
| **SQLite** | **单文件、零配置、无需服务器**，Python 标准库自带 | 学习、桌面程序、手机 App | `sqlite3`（内置） |
| **MySQL** | 开源、Web 应用最常用 | 网站后台 | `pymysql`、`mysql-connector-python` |
| **PostgreSQL** | 功能最强、支持复杂类型与地理数据 | 数据量大、要求高的系统 | `psycopg2` |
| **SQL Server** | 微软产品，与 .NET 生态结合好 | 企业内网系统 | `pyodbc`、`pymssql` |
| **Oracle** | 商业数据库，金融/电信常用 | 大型核心系统 | `cx_Oracle`、`oracledb` |

**本课程和实验统一用 SQLite**，理由是它**不需要安装服务器**，一个 `.db` 文件就是一个完整的数据库，非常适合上机。

```python
import sqlite3
print(sqlite3.sqlite_version)     # 3.53.1   ← SQLite 引擎版本
# 注意：sqlite3.version（模块版本）从 Python 3.12 起已弃用，Python 3.14 会移除，不要用
```

**SQLite 的五个"没有"要提前知道**：没有独立的服务器进程；没有用户名密码（文件权限即权限）；没有真正的并发写（写操作会锁整个库）；没有 `RIGHT JOIN`（老版本）；没有存储过程和复杂的权限体系。所以它**不适合做高并发网站**，但**极其适合学习和单机程序**。

### 11.2.2 Python DB-API 规范

**DB-API（Python Database API）是 Python 定义的数据库访问统一接口**，所有主流驱动都遵守它。这意味着**换数据库时，你的代码结构几乎不用改，只换驱动和连接语句**。

**六步标准流程**（必须背下来，实验报告和考试都要写）：

```
① 建立连接  conn = sqlite3.connect("数据源")
② 创建游标  cur = conn.cursor()
③ 执行 SQL  cur.execute("SQL 语句", 参数元组)
④ 取结果    cur.fetchone() / fetchmany(n) / fetchall()
⑤ 提交/回滚 conn.commit() / conn.rollback()
⑥ 关闭      cur.close(); conn.close()
```

**核心对象与方法的职责划分**：

| 对象/方法 | 作用 | 关键点 |
|---|---|---|
| `connect(...)` | 建立到数据库的连接 | SQLite 传文件名；MySQL 传 `host/user/password/database/charset` |
| `conn.cursor()` | 创建游标 | **SQL 都是通过游标执行的** |
| `conn.commit()` | 提交事务 | **增删改必须提交，否则不落盘** |
| `conn.rollback()` | 回滚事务 | 出错时撤销本次未提交的改动 |
| `conn.close()` | 关闭连接 | 必须关，否则文件被占用 |
| `cur.execute(sql, params)` | 执行一条 SQL | `params` 是元组或字典 |
| `cur.executemany(sql, seq)` | 执行同一条 SQL 多次 | 批量插入专用，**比循环快得多** |
| `cur.fetchone()` | 取下一行 | 取完返回 **`None`** |
| `cur.fetchmany(n)` | 取 n 行 | 返回列表 |
| `cur.fetchall()` | 取剩余全部 | 返回列表，**大表慎用** |
| `cur.rowcount` | 影响的行数 | `executemany` 后是总条数 |
| `cur.lastrowid` | 最后插入行的自增主键 | **`executemany` 后不可靠** |
| `cur.description` | 结果集的列信息 | 列名是 `d[0]` |

**参数化查询是安全底线**：`execute` 的第二个参数用**占位符**传值，**驱动会负责转义，绝不会被注入**。占位符写法**随驱动而异，换数据库时必须改**：

| 数据库 | 驱动 | 占位符 |
|---|---|---|
| SQLite | `sqlite3`（内置） | **`?`**（或命名占位符 `:name`） |
| MySQL | `pymysql` / `mysql-connector` | **`%s`** |
| PostgreSQL | `psycopg2` | **`%s`** |

⚠️ 最常见的错误是「在 MySQL 里也写 `?`」——`pymysql` 只认 `%s`，写 `?` 会直接报语法错误。

```python
evil = "x' OR '1'='1"

cur.execute(f"SELECT COUNT(*) FROM student WHERE name='{evil}'")
print(cur.fetchone()[0])          # 4      ← 拼接：条件被绕过，返回了全部 4 行！

cur.execute("SELECT COUNT(*) FROM student WHERE name=?", (evil,))
print(cur.fetchone()[0])          # 0      ← 参数化：老老实实当成一个普通字符串
```

> **重点**：**只要 SQL 里出现 `f"..."` 或 `+` 拼出来的用户输入，就是漏洞。** SQL 注入常年位居安全漏洞榜首，防范办法只有一条：**永远用占位符**。

### 11.2.3 典型案例——访问关系数据库

**需求**：用 `sqlite3` 建一个学生成绩库，完成建表、批量插入、条件查询、分组统计、事务回滚。

```python
import sqlite3

conn = sqlite3.connect("school.db")       # 文件不存在会自动创建
cur = conn.cursor()

# ① 建表：INTEGER PRIMARY KEY AUTOINCREMENT 让 id 自增
cur.execute("""
    CREATE TABLE IF NOT EXISTS student(
        id    INTEGER PRIMARY KEY AUTOINCREMENT,
        name  TEXT NOT NULL,
        score REAL,
        class TEXT)
""")

# ② 批量插入：用 ? 占位符，executemany 一次提交多条
cur.executemany("INSERT INTO student(name, score, class) VALUES(?, ?, ?)",
                [("张三", 92,   "计科2201"),
                 ("李四", 85.5, "计科2201"),
                 ("王五", 78,   "计科2202"),
                 ("赵六", 95,   "计科2202")])
conn.commit()
print(cur.rowcount, cur.lastrowid)     # 4 0    ← executemany 后 lastrowid 不可靠

# ③ 查询全部
cur.execute("SELECT * FROM student")
print(cur.fetchall())
# [(1, '张三', 92.0, '计科2201'), (2, '李四', 85.5, '计科2201'),
#  (3, '王五', 78.0, '计科2202'), (4, '赵六', 95.0, '计科2202')]
```

**`fetchone` 与 `fetchmany` 会"消费"游标**——取过的行不会再来一遍：

```python
cur.execute("SELECT * FROM student")
print(cur.fetchone())        # (1, '张三', 92.0, '计科2201')
print(cur.fetchmany(2))      # [(2, '李四', 85.5, '计科2201'), (3, '王五', 78.0, '计科2202')]

# 条件取完就返回 None
c = conn.execute("SELECT name FROM student WHERE score > 1000")
print(c.fetchone())          # None
```

**用 `sqlite3.Row` 让结果能按列名取值**（比记下标位置可靠得多）：

```python
conn.row_factory = sqlite3.Row
cur = conn.cursor()
cur.execute("SELECT id, name, score FROM student WHERE score >= ?", (85,))
rows = cur.fetchall()
print([tuple(r) for r in rows])       # [(1, '张三', 92.0), (2, '李四', 85.5), (4, '赵六', 95.0)]
print(rows[0]["name"], rows[0][0])    # 张三 1        ← 列名和下标都能用
print(rows[0].keys())                 # ['id', 'name', 'score']
```

**分组统计**（SQL 的聚合函数 + `GROUP BY`，比取回 Python 再算快得多）：

```python
cur.execute("""SELECT class, COUNT(*), ROUND(AVG(score), 2)
               FROM student GROUP BY class ORDER BY 3 DESC""")
print([tuple(r) for r in cur.fetchall()])
# [('计科2201', 2, 88.75), ('计科2202', 2, 86.5)]
```

**事务用 `with conn:` 管理**——块内正常结束自动 `commit`，抛异常自动 `rollback`：

```python
# 出异常 → 自动回滚
try:
    with conn:
        cur.execute("UPDATE student SET score = ? WHERE name = ?", (100, "王五"))
        raise RuntimeError("模拟出错")
except RuntimeError as e:
    print(e)                                   # 模拟出错

cur.execute("SELECT score FROM student WHERE name='王五'")
print(cur.fetchone()[0])                       # 78.0   ← 改动被回滚了

# 正常结束 → 自动提交
with conn:
    cur.execute("UPDATE student SET score = ? WHERE name = ?", (88, "王五"))
cur.execute("SELECT score FROM student WHERE name='王五'")
print(cur.fetchone()[0])                       # 88.0
```

**未提交的数据对其他连接不可见**（这是事务"隔离性"的直接体现）：

```python
conn2 = sqlite3.connect("school.db")
cur.execute("INSERT INTO student(name, score) VALUES('临时', 60)")
print(cur.execute("SELECT COUNT(*) FROM student").fetchone()[0])       # 5  ← 本连接看得见
print(conn2.execute("SELECT COUNT(*) FROM student").fetchone()[0])     # 4  ← 另一连接看不见
conn.commit()
print(conn2.execute("SELECT COUNT(*) FROM student").fetchone()[0])     # 5  ← 提交后才可见
```

**约束错误会被数据库直接拒绝**：

```python
cur.execute("INSERT INTO student(name, score) VALUES(NULL, 60)")
# sqlite3.IntegrityError: NOT NULL constraint failed: student.name

cur.execute("SELECT * FROM nosuch")
# sqlite3.OperationalError: no such table: nosuch
```

**一个实用的通用查询函数**（把结果直接变成字典列表，方便接 `json.dumps`）：

```python
def query_all(sql, params=()):
    c = conn.cursor()
    c.execute(sql, params)
    return [dict(r) for r in c.fetchall()]

print(query_all("SELECT name, score FROM student ORDER BY score DESC"))
# [{'name': '赵六', 'score': 95.0}, {'name': '张三', 'score': 92.0}, ...]
```

**内存数据库**：`sqlite3.connect(":memory:")` 建一个只存在于内存的库，程序退出即消失，**跑单元测试时特别有用**（不产生垃圾文件）：

```python
m = sqlite3.connect(":memory:")
m.execute("CREATE TABLE t(x)")
m.execute("INSERT INTO t VALUES(1)")
print(m.execute("SELECT * FROM t").fetchall())     # [(1,)]
```

**换到 MySQL 时要改的只有三处**（其余代码结构不变）：

```python
import pymysql
conn = pymysql.connect(host="localhost", user="root", password="123456",
                       database="school", charset="utf8mb4")   # ← ① 连接方式
cur = conn.cursor()
cur.execute("SELECT * FROM student WHERE score > %s", (85,))    # ← ② 占位符是 %s
# ③ 其余 execute / fetchall / commit / close 写法完全一样
```

## 11.3 非关系数据库访问

### 11.3.1 MongoDB

**MongoDB 是文档型数据库**，数据以 **BSON 文档**（本质是"带类型的 JSON"）存储，多条文档组成**集合（collection）**。对应关系如下：

| 关系型概念 | MongoDB 概念 | 说明 |
|---|---|---|
| 数据库 database | 数据库 database | 同名 |
| 表 table | **集合 collection** | 集合里的文档结构可以**互不相同** |
| 行 row | **文档 document** | 一个字典，自动带 `_id` 主键 |
| 列 column | **字段 field** | 可以嵌套字典和数组 |
| 主键 `PRIMARY KEY` | `_id` | 不指定时自动生成 `ObjectId` |

**它和关系型的取舍**：

| 维度 | 关系型（SQLite/MySQL） | MongoDB |
|---|---|---|
| 表结构 | 必须先定义，改动要迁移 | **无需预定义**，字段随时增减 |
| 关联查询 | `JOIN` 强大 | 弱，靠**内嵌文档**或多次查询 |
| 事务 | 完善 | 4.0 起支持，但不如关系型成熟 |
| 适合 | 结构稳定、要一致性 | 结构多变、量大、读多写少 |

**安装驱动与连接**（本机未安装 `pymongo`，以下代码在装好 MongoDB 服务后可直接运行）：

```python
# 命令行安装：pip install pymongo
from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017/")   # 默认端口 27017
db = client["school"]              # 数据库不存在会自动创建
col = db["student"]                # 集合不存在会自动创建
```

**基本操作对照表**（左边是 SQL 思路，右边是 MongoDB 写法）：

| 操作 | SQL | MongoDB |
|---|---|---|
| 插入一条 | `INSERT INTO student VALUES(...)` | `col.insert_one({...})` |
| 插入多条 | `INSERT ... ` 多次 | `col.insert_many([{...}, {...}])` |
| 查询一条 | `SELECT * WHERE name='张三'` | `col.find_one({"name": "张三"})` |
| 查询多条 | `SELECT * WHERE score>85` | `col.find({"score": {"$gt": 85}})` |
| 更新 | `UPDATE ... SET score=100` | `col.update_one({"name":"张三"}, {"$set":{"score":100}})` |
| 删除 | `DELETE FROM student WHERE ...` | `col.delete_one({"name":"张三"})` |
| 统计 | `SELECT COUNT(*)` | `col.count_documents({})` |
| 排序 | `ORDER BY score DESC` | `col.find().sort("score", -1)` |
| 限制条数 | `LIMIT 3` | `col.find().limit(3)` |

**查询比较符要用 `$` 开头的操作符**，这是与 SQL 差别最大的地方：

| SQL | MongoDB | 含义 |
|---|---|---|
| `>` | `{"$gt": 值}` | 大于 |
| `>=` | `{"$gte": 值}` | 大于等于 |
| `<` | `{"$lt": 值}` | 小于 |
| `=` | 直接写值 | 等于 |
| `!=` | `{"$ne": 值}` | 不等于 |
| `IN` | `{"$in": [值1, 值2]}` | 在列表中 |
| `AND` | `{"k1": v1, "k2": v2}` | 多字段写在一个字典里 |
| `OR` | `{"$or": [{...}, {...}]}` | 或 |

### 11.3.2 典型案例——访问 MongoDB

**需求**：把一个班的成绩存入 MongoDB，查出 85 分以上的人、按分数降序取前 2 名、更新一个人的分数。

```python
from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017/")
col = client["school"]["student"]

# 清空旧数据（演示用；正式环境不要随便调）
col.delete_many({})

# ① 批量插入：文档结构可以不一样（李四多了 city 字段）
col.insert_many([
    {"name": "张三", "score": 92,   "class": "计科2201"},
    {"name": "李四", "score": 85.5, "class": "计科2201", "city": "武汉"},
    {"name": "王五", "score": 78,   "class": "计科2202"},
    {"name": "赵六", "score": 95,   "class": "计科2202"},
])
print(col.count_documents({}))        # 4

# ② 条件查询：85 分以上
for d in col.find({"score": {"$gt": 85}}, {"_id": 0, "name": 1, "score": 1}):
    print(d["name"], d["score"])
# 张三 92
# 李四 85.5
# 赵六 95

# ③ 排序 + 取前 2 名
for d in col.find({}, {"_id": 0, "name": 1}).sort("score", -1).limit(2):
    print(d["name"])
# 赵六
# 张三

# ④ 更新：$set 只改指定字段，$inc 在原值上加
col.update_one({"name": "王五"}, {"$set": {"score": 88}})
col.update_one({"name": "王五"}, {"$inc": {"score": 2}})
print(col.find_one({"name": "王五"}, {"_id": 0})["score"])     # 90

# ⑤ 分组统计：聚合管道
pipe = [{"$group": {"_id": "$class", "avg": {"$avg": "$score"}, "n": {"$sum": 1}}},
        {"$sort": {"_id": 1}}]
print(list(col.aggregate(pipe)))
# [{'_id': '计科2201', 'avg': 88.75, 'n': 2}, {'_id': '计科2202', 'avg': 92.5, 'n': 2}]

client.close()
```

> **注意**：`{"_id": 0, "name": 1}` 叫**投影（projection）**，`1` 表示要这一列、`0` 表示不要，**除 `_id` 外不能混用 0 和 1**。另外 MongoDB 的 `_id` 是 `ObjectId` 对象，不是字符串，想按它查询要写 `ObjectId("...")`。

## 典型例题

**例 11.1**（题型：读程序写结果 —— 事务与提交）

```python
import sqlite3
conn = sqlite3.connect(":memory:")
cur = conn.cursor()
cur.execute("CREATE TABLE t(id INTEGER PRIMARY KEY, name TEXT)")
cur.execute("INSERT INTO t VALUES(1, 'a')")
print("A", cur.execute("SELECT COUNT(*) FROM t").fetchone()[0])
conn.rollback()
print("B", cur.execute("SELECT COUNT(*) FROM t").fetchone()[0])
conn.commit()
print("C", cur.execute("SELECT COUNT(*) FROM t").fetchone()[0])
```

**解**：`:memory:` 库从空开始。插入 1 行后，**在同一连接内立刻就能查到**（未提交的改动对本连接可见）→ `A` 打印 1。`conn.rollback()` **撤销自上次提交以来的所有改动**，所以 `B` 打印 0。`commit()` 之后没有新改动，`C` 仍是 0。

**答案**：

```
A 1
B 0
C 0
```

**例 11.2**（题型：读程序写结果 —— 游标的消费性）

```python
import sqlite3
conn = sqlite3.connect(":memory:")
cur = conn.cursor()
cur.execute("CREATE TABLE t(x)")
cur.executemany("INSERT INTO t VALUES(?)", [(i,) for i in range(1, 6)])
cur.execute("SELECT x FROM t ORDER BY x")
print(cur.fetchone())
print(cur.fetchmany(2))
print(cur.fetchall())
print(cur.fetchone())
```

**解**：`fetchone()` 取第 1 行 → `(1,)`；`fetchmany(2)` 取接下来的 2 行 → `[(2,), (3,)]`；`fetchall()` 取剩余全部 → `[(4,), (5,)]`；再 `fetchone()` 时游标已到末尾 → **`None`**。

**答案**：

```
(1,)
[(2,), (3,)]
[(4,), (5,)]
None
```

**例 11.3**（题型：编程题 —— 建库建表并批量插入）

**题目**：用 `sqlite3` 建一个 `books.db`，表 `book(id INTEGER PRIMARY KEY AUTOINCREMENT, title TEXT NOT NULL, price REAL, stock INTEGER)`，插入 4 本书，然后查出库存大于 0 的书按价格降序输出。

**解**：

```python
import sqlite3

conn = sqlite3.connect("books.db")
cur = conn.cursor()
cur.execute("""CREATE TABLE IF NOT EXISTS book(
                   id INTEGER PRIMARY KEY AUTOINCREMENT,
                   title TEXT NOT NULL, price REAL, stock INTEGER)""")

books = [("Python程序设计", 69.8, 12), ("数据结构", 45.0, 0),
         ("算法导论", 128.0, 3), ("C程序设计", 39.5, 8)]
cur.executemany("INSERT INTO book(title, price, stock) VALUES(?, ?, ?)", books)
conn.commit()

cur.execute("SELECT title, price FROM book WHERE stock > ? ORDER BY price DESC", (0,))
for title, price in cur.fetchall():
    print(f"{title:<16}{price:>8.2f}")
cur.close()
conn.close()
```

**答案**：

```
算法导论              128.00
Python程序设计         69.80
C程序设计              39.50
```

（每行都是 `f"{title:<16}{price:>8.2f}"` = **24 个字符**：标题补到 16 字符，价格右对齐占 8 字符。注意这是**按字符数**对齐的，中文占 2 列显示宽度，所以肉眼看着仍然不齐——见下方要点④。）

**思路要点**：① `CREATE TABLE IF NOT EXISTS` 让脚本可以重复运行；② 用 `executemany` 一次插入，比循环 `execute` 快很多；③ 查询条件 `stock > 0` 也**用占位符**，保持一致的习惯；④ `f"{title:<16}"` 对中文仍然对不齐（中文按 1 字符算但占 2 列），实际排版要改用英文或按显示宽度手工补齐。

**例 11.4**（题型：编程题 —— 防注入的参数化查询）

**题目**：写函数 `find_student(name, min_score)`，按姓名精确匹配且分数不低于 `min_score` 查询学生；要求**能安全处理任意用户输入**，并说明如果改成字符串拼接会有什么后果。

**解**：

```python
def find_student(name, min_score):
    cur.execute("SELECT id, name, score, class FROM student WHERE name = ? AND score >= ?",
                (name, min_score))
    return cur.fetchall()

# 恶意输入被当成普通字符串，查不到任何东西
print(find_student("x' OR '1'='1", 0))     # []
print(find_student("张三", 90))            # [(1, '张三', 92.0, '计科2201')]
```

**答案**：参数化查询返回 `[]`（因为库里没有叫这个名字的人），正常输入返回对应记录。**如果写成拼接**：

```python
sql = f"SELECT * FROM student WHERE name = '{name}' AND score >= {min_score}"
# name = "x' OR '1'='1" 时，SQL 变成：
# SELECT * FROM student WHERE name = 'x' OR '1'='1' AND score >= 0
# 由于 '1'='1' 恒真，条件被绕过，全部学生都被查出来
```

**后果**：轻则越权看到别人的数据，重则被 `'; DROP TABLE student; --` 直接删表。**结论：用户输入永远走占位符，一个例外都没有。**

**例 11.5**（题型：编程题 —— 用 with 管理事务）

**题目**：写函数 `transfer(from_id, to_id, amount)` 实现转账：从 `from_id` 扣 `amount`、给 `to_id` 加 `amount`，两步必须**要么都成功、要么都不做**；余额不足抛异常。

**解**：

```python
def transfer(from_id, to_id, amount):
    with conn:                                   # 正常结束自动 commit，抛异常自动 rollback
        cur.execute("SELECT balance FROM account WHERE id = ?", (from_id,))
        row = cur.fetchone()
        if row is None:
            raise ValueError(f"账号不存在：{from_id}")
        if row[0] < amount:
            raise ValueError(f"余额不足：{row[0]} < {amount}")
        cur.execute("UPDATE account SET balance = balance - ? WHERE id = ?", (amount, from_id))
        cur.execute("UPDATE account SET balance = balance + ? WHERE id = ?", (amount, to_id))
    return "转账成功"
```

**答案**：`with conn:` 保证了**原子性**——两条 `UPDATE` 之间任何一步失败，整个 `with` 块回滚，不会出现"钱扣了但没到账"。**思路要点**：① 先查余额再扣，别用 `balance = balance - ?` 硬扣（扣成负数也不知道）；② 判断失败时**抛异常**而不是 `return`，因为 `return` 会让 `with` 块正常结束从而提交；③ SQL 里 `balance = balance - ?` 是数据库端计算，避免了"读到 Python 再写回"的竞态。

**例 11.6**（题型：编程题 —— 查询结果转字典与 JSON）

**题目**：写函数 `students_to_json(class_name)`，查出指定班级的全部学生，返回 JSON 字符串（中文不转义）。

**解**：

```python
import json, sqlite3

def students_to_json(class_name):
    conn = sqlite3.connect("school.db")
    conn.row_factory = sqlite3.Row                    # 让结果支持按列名取值
    try:
        cur = conn.execute(
            "SELECT id, name, score, class FROM student WHERE class = ? ORDER BY score DESC",
            (class_name,))
        return json.dumps([dict(r) for r in cur.fetchall()], ensure_ascii=False)
    finally:
        conn.close()                                  # 无论如何都要关连接

print(students_to_json("计科2201"))
```

**答案**：

```json
[{"id": 1, "name": "张三", "score": 92.0, "class": "计科2201"},
 {"id": 2, "name": "李四", "score": 85.5, "class": "计科2201"}]
```

**思路要点**：① `row_factory = sqlite3.Row` 之后 `dict(r)` 直接把一行变成字典，不用手写字段名映射；② `ensure_ascii=False` 让中文原样输出（第9章讲过）；③ 用 `try/finally` 保证连接一定被关闭——`sqlite3` 的连接实现了上下文管理器，也可以写 `with sqlite3.connect(...) as conn:`，但**注意那个 `with` 只管事务不管关闭**，关闭仍需显式调用。

## 易错点提醒

1. **增删改之后忘了 `commit()`** → 错：程序退出时改动丢失，或者文件被锁住。对：每个写操作批次后调 `conn.commit()`，或者用 `with conn:` 包起来。
2. **用 f-string / `+` 拼接 SQL** → 错：SQL 注入，用户输入可以改掉整条语句。对：一律用 `?` 占位符 + 参数元组。
3. **占位符写成了字符串格式化** → 错：`execute("... WHERE name = '%s'" % name)` 仍然是注入。对：`execute("... WHERE name = ?", (name,))`——**注意参数元组末尾的逗号**，`(name)` 是字符串不是元组。
4. **`fetchone()` 取完还继续取** → 错：返回 `None`，再写 `row[0]` 就 `TypeError: 'NoneType' object is not subscriptable`。对：先判断 `if row is None`。
5. **以为 `executemany` 后 `lastrowid` 是最后一条的 id** → 错：实测返回 **0**。对：要拿自增 id 就循环 `execute` 逐条取，或插入后再 `SELECT last_insert_rowid()`。
6. **忘了 `conn.close()`** → 错：Windows 下文件被占用，删不掉、改不了。对：用 `try/finally` 或 `contextlib.closing` 保证关闭。
7. **在 `with conn:` 块里 `return`** → 错：`return` 会让块正常结束从而**提交**，你以为出错了其实数据已经写进去。对：块内失败一律 `raise`。
8. **用 `SELECT *` 后靠下标取值** → 错：表结构一改（加一列）下标全错位，还很难查。对：显式写列名，并用 `sqlite3.Row` 按列名取值。
9. **以为 `rollback()` 能撤销所有改动** → 错：它只撤销**上次 `commit()` 之后**的改动。对：想撤销已提交的数据只能写反向 SQL，所以要养成"小步提交"的习惯。
10. **MySQL 里也写 `?` 占位符** → 错：`pymysql` 用的是 `%s`。对：SQLite 用 `?` 或 `:name`，MySQL 用 `%s`，PostgreSQL 用 `%s`——**换驱动时检查占位符**。
11. **把数据库文件放进版本库** → 错：`.db` 是二进制文件，每次运行都变，会把仓库搞乱。对：加进 `.gitignore`，只提交建表和初始化数据的 SQL 脚本。
12. **用 SQLite 做高并发 Web 后台** → 错：SQLite 写操作会锁整个库，并发写会报 `database is locked`。对：并发场景换 MySQL/PostgreSQL。

## 本章小结

- 数据库解决文件的四个痛点：查找慢、修改难、并发冲突、缺少约束；**关系型用 SQL，NoSQL 各家 API 不同**。
- Python 通过 **DB-API** 统一访问数据库，六步流程是：**连接 → 游标 → 执行 → 取结果 → 提交/回滚 → 关闭**。
- `sqlite3` 是标准库自带、单文件零配置的关系数据库，**最适合学习和上机实验**；`:memory:` 可用于测试。
- **增删改必须 `commit()`**；`with conn:` 正常结束自动提交、出异常自动回滚，是管理事务的标准写法。
- **参数化查询（`?` 占位符）是防 SQL 注入的唯一正确做法**，字符串拼接 SQL 一律视为漏洞。
- `fetchone`/`fetchmany`/`fetchall` 会消费游标，取完再取返回 `None`；`row_factory = sqlite3.Row` 让结果支持按列名取值。
- MongoDB 用**集合 + 文档**替代表和行，查询用 `$gt`/`$in`/`$or` 等操作符，`insert_one`/`find`/`update_one`/`delete_one` 是四个基本操作。

> **一句话记住本章**：**连接、游标、执行、取结果、提交、关闭——六步走完；SQL 里的用户输入永远用 `?` 占位符，绝不用字符串拼。**

**参考答案**

1. ① `conn = 驱动.connect(...)` 建立连接；② `cur = conn.cursor()` 创建游标；③ `cur.execute(sql, params)` 执行 SQL；④ `cur.fetchone()/fetchmany(n)/fetchall()` 取结果；⑤ `conn.commit()` 或 `conn.rollback()` 提交/回滚；⑥ `cur.close(); conn.close()` 关闭。
2. SQLite 和 MySQL 是**关系型**（二维表 + SQL），适合结构固定、需要事务的数据；MongoDB 是**文档型**（集合 + 文档），适合结构多变、量大、读多写少的场景。SQLite 单文件零配置适合学习与单机程序，MySQL 适合 Web 后台，MongoDB 适合日志、爬虫结果等半结构化数据。
3. `execute` 执行一条 SQL（参数是一个元组），`executemany` 用同一 SQL 执行多次（参数是序列的序列）。批量插入 1000 条**必须用 `executemany`**，它一次往返就完成，比循环 `execute` 快一个数量级。
4. 直接用 `+` 拼接用户输入，存在 **SQL 注入**漏洞：输入 `x' OR '1'='1` 会让条件恒真、查出全部数据，输入 `'; DROP TABLE student; --` 甚至能删表。改法：`cur.execute("SELECT * FROM student WHERE name = ?", (name,))`。
5. 游标已经取完所有行（或结果集为空）时返回 `None`。直接取下标会抛 `TypeError: 'NoneType' object is not subscriptable`。使用前应先判断 `if row is None: ...`。
6. `commit()` 把本次事务的改动真正写入数据库；`rollback()` 撤销**上次提交之后**的所有改动。`with conn:` 块内抛异常时，`__exit__` 会调用 `rollback()`，本次改动全部作废；正常结束则自动 `commit()`。
7. 第一次打印 `1`（未提交的改动对本连接可见）；`rollback()` 撤销未提交的插入；第二次打印 `0`。
8. 让查询结果既能用下标取值，也能**按列名取值**（`row["name"]`），还支持 `dict(row)` 直接转字典。表结构变动时不必重新数下标，代码更健壮。
9. `col.find({"score": {"$gt": 85}})`，对应 SQL 的 `SELECT * FROM ... WHERE score > 85`。MongoDB 的比较运算符都以 `$` 开头：`$gt`/`$gte`/`$lt`/`$lte`/`$ne`/`$in`。
10. 参考实现：
    ```python
    import sqlite3
    conn = sqlite3.connect(":memory:")
    cur = conn.cursor()
    cur.execute("CREATE TABLE t(id INTEGER PRIMARY KEY, name TEXT)")
    cur.executemany("INSERT INTO t(name) VALUES(?)", [("a",), ("b",)])
    print(cur.execute("SELECT COUNT(*) FROM t").fetchone()[0])   # 2
    conn.close()
    ```
    要点：`id` 是自增主键，插入时只给 `name` 一列；`executemany` 的参数是 `[("a",), ("b",)]`，**每个元素的长度必须等于 SQL 里的占位符个数**（不是「必须写成元组」）。占位符是 1 个时，`["a", "b"]` 也能跑（单字符字符串长度正好是 1，两行都插入成功，`COUNT = 2`）；但元素是多字符字符串时就会报错：`["ab", "cd"]` → `sqlite3.ProgrammingError: Incorrect number of bindings supplied. The current statement uses 1, and there are 2 supplied.`。**所以规范写法仍是元组 `("a",)`——它对任何长度的数据都成立。**
