## 16.1 从"会写类"到"会设计类"

**第6章你已经会**：`class` 定义、`__init__`、实例属性与类属性、`self`、私有成员（名称改写）、`@classmethod`/`@staticmethod`、`@property`、`__str__`/`__repr__`、继承、`super()`、多态、抽象类、鸭子类型。

**本章补的是"设计层面"的东西**：

| 需求 | 第6章的写法 | 本章的写法 |
|---|---|---|
| 只存数据的类 | 手写 `__init__`/`__repr__`/`__eq__` | **`@dataclass`**（16.2） |
| 限制属性、省内存 | 做不到 | **`__slots__`**（16.3） |
| 一组固定取值 | 用 0/1/2 或字符串常量 | **`Enum`**（16.4） |
| 自定义可遍历对象 | 返回列表 | **迭代器协议**（16.5） |
| 管理资源（文件/锁/连接） | `try/finally` | **上下文管理器**（16.6） |
| 属性校验 | `@property` | **描述符**（16.7） |
| 对象像内置类型一样运算 | 写 `add()` 方法 | **魔术方法**（16.8） |
| 子类自动注册 | 手工维护列表 | **元类 / `__init_subclass__`**（16.9） |

**什么时候不该用类？**（**这是最容易被忽略的一节**）

- **只需要一个函数**：`def area(r): return 3.14*r*r` 就够了，别包成 `class Calculator`。
- **只是数据的容器**：用 `@dataclass` 或 `namedtuple`，不要手写一堆 getter/setter。
- **状态和行为强耦合时才用类**：比如"银行账户"（余额 + 存取款，且必须保证余额一致）。

> **重点**：**面向对象不是"把函数塞进类里"。** 一个只有 `__init__` 和一串 `get_xxx`/`set_xxx` 的类是**反模式**（贫血模型）——那还不如直接用字典或 `dataclass`。

## 16.2 数据类 dataclass

**问题**：一个只用来装数据的类，要手写一堆样板代码：

```python
class PointOld:
    def __init__(self, x, y=0):
        self.x, self.y = x, y
    def __repr__(self):
        return f"PointOld(x={self.x!r}, y={self.y!r})"
    def __eq__(self, other):
        return isinstance(other, PointOld) and (self.x, self.y) == (other.x, other.y)
```

**`@dataclass` 一行搞定**：

```python
from dataclasses import dataclass, field, asdict, replace

@dataclass
class Point:
    x: int
    y: int = 0
    tags: list = field(default_factory=list)     # ★ 可变默认值必须用 factory

print(Point(1, 2))              # Point(x=1, y=2, tags=[])
print(Point(1, 2) == Point(1, 2))   # True    ← 自动生成 __eq__
print(Point(1, 2) == Point(2, 1))   # False
print(Point(1))                 # Point(x=1, y=0, tags=[])   ← 自动生成默认值
print(asdict(Point(1, 2)))      # {'x': 1, 'y': 2, 'tags': []}
print(replace(Point(1, 2), y=99))   # Point(x=1, y=99, tags=[])
```

**`@dataclass` 自动生成哪些方法**：

| 方法 | 是否默认生成 | 说明 |
|---|---|---|
| `__init__` | ✅ | 按字段声明顺序作为参数 |
| `__repr__` | ✅ | 显示所有字段，调试极方便 |
| `__eq__` | ✅ | 按字段逐个比较 |
| `__hash__` | ❌ | 定义了 `__eq__` 后 `__hash__` 被设为 `None`（**不可哈希**） |
| `__lt__` 等 | ❌ | 需要 `order=True` |

**`field()` 的三个常用参数**：

| 参数 | 作用 | 例子 |
|---|---|---|
| `default_factory` | **可变默认值必须用它** | `field(default_factory=list)` |
| `default` | 不可变默认值 | `field(default=0)` |
| `repr=False` | 不在 `repr` 里显示（如密码） | `field(repr=False)` |
| `compare=False` | 不参与 `==` 比较 | `field(compare=False)` |

> **重点：为什么可变默认值必须用 `default_factory`？** 这与第5章 `def f(a=[])` 默认参数陷阱是**同一个坑**——默认值在**定义时只求值一次**，所有实例会共享同一个列表。实测：
> ```python
> a1, a2 = Point(1), Point(2)
> a1.tags.append("x")
> print(a1.tags, a2.tags)      # ['x'] []      ← factory 让每个实例拿到独立的列表
> ```
> 如果用 `tags: list = []`，`dataclass` 会**直接报错**：`ValueError: mutable default <class 'list'> for field tags is not allowed`——**它主动帮你挡住了这个坑**。

**三个常用变体**：

```python
# ① 不可变（相当于只读对象，可哈希、能当字典键、能放进 set）
from dataclasses import dataclass
@dataclass(frozen=True)
class FrozenPoint:
    x: int
    y: int

fp = FrozenPoint(1, 2)
print(hash(fp) is not None)     # True
try:
    fp.x = 5                    # 想改就报错
except Exception as e:
    print(type(e).__name__, e)  # FrozenInstanceError cannot assign to field 'x'

# ② 可排序
@dataclass(order=True)
class Score:
    name: str
    value: int

print([str(s) for s in sorted([Score("b", 2), Score("a", 1)])])
# ["Score(name='a', value=1)", "Score(name='b', value=2)"]

# ③ 继承：子类字段的默认值不能与父类非默认字段冲突
@dataclass
class Base:
    a: int
@dataclass
class Child(Base):
    b: int = 0                  # 有默认值的字段必须排在后面
```

> **易错**：`@dataclass(order=True)` 生成的比较是**按字段声明顺序逐个比较**的（先比 `name` 再比 `value`）。想按 `value` 排序应该调整字段顺序，或用 `sorted(key=lambda s: s.value)`。

**`dataclass` vs `namedtuple` vs 普通类**：

| 对比项 | `dataclass` | `namedtuple` | 普通类 |
|---|---|---|---|
| 可变 | ✅ 默认可变 | ❌ 不可变 | ✅ |
| 能加方法 | ✅ | 有限 | ✅ |
| 内存 | 中 | **小** | 大 |
| 能加新属性 | ✅ | ❌ | ✅ |
| 适合 | **绝大多数数据类** | 轻量只读记录 | 有复杂行为 |

## 16.3 __slots__

**默认情况下，每个实例都有一个 `__dict__` 字典来存属性**——灵活但费内存（一个空字典就占 64 字节以上）。**`__slots__` 用固定槽位替代字典**。

```python
class WithSlots:
    __slots__ = ("x", "y")              # 只允许这两个属性
    def __init__(self, x, y):
        self.x, self.y = x, y

class WithoutSlots:
    def __init__(self, x, y):
        self.x, self.y = x, y

w, wo = WithSlots(1, 2), WithoutSlots(1, 2)
print(hasattr(w, "__dict__"))       # False   ← 没有字典
print(hasattr(wo, "__dict__"))      # True

try:
    w.z = 3                          # 想加新属性
except AttributeError as e:
    print(type(e).__name__, e)       # AttributeError 'WithSlots' object has no attribute 'z'
```

**两个副作用**：

1. **不能再动态加属性**（这既是限制也是保护——能提前发现拼写错误，比如把 `self.name` 写成 `self.nmae`）。
2. **不能与 `__dict__` 共存**，也不能给实例单独挂属性。**类属性仍然可以加**：`WithSlots.z = 99` 是允许的（改的是类，不是实例）。

**注意两个坑**：

- **`__slots__` 里的名字不能与类属性重名**，否则报 `ValueError: 'x' in __slots__ conflicts with class variable`。
- **子类如果没定义 `__slots__`，会重新获得 `__dict__`**，省内存的效果就没了。

> **什么时候用？** 需要创建**几十万个对象**时（如坐标点、日志记录、图的节点）。普通业务代码**优先用 `dataclass`**，可读性比省那点内存重要。

## 16.4 枚举 Enum

**问题**：代码里到处是"魔法数字"，看不出含义还容易写错：

```python
if status == 1:        # 1 是什么？待付款？已发货？
    ...
```

**`Enum` 让取值有名字、有类型、有约束**：

```python
from enum import Enum, IntEnum, auto

class Color(Enum):
    RED = 1
    GREEN = 2
    BLUE = 3

print(Color.RED)                 # Color.RED
print(Color.RED.name, Color.RED.value)   # RED 1
print(Color(2))                  # Color.GREEN     ← 按值查
print(Color["BLUE"])             # Color.BLUE      ← 按名查
print([c.name for c in Color])   # ['RED', 'GREEN', 'BLUE']   ← 可遍历
print(Color.RED == Color.RED)    # True
print(Color.RED == 1)            # False    ← ★ 枚举成员不等于它的值！

try:
    Color.RED.value = 9          # 成员不可变
except AttributeError as e:
    print(type(e).__name__)      # AttributeError
```

**`Enum` vs `IntEnum`**：

| 对比项 | `Enum` | `IntEnum` |
|---|---|---|
| 能否与整数比较 | ❌ `Color.RED == 1` 是 `False` | ✅ `Weekday.MON == 1` 是 `True` |
| 能否参与算术 | ❌ | ✅ `Weekday.MON + 1` 得到 `2` |
| 类型安全 | **强**（推荐） | 弱（容易被当成普通整数） |
| 适合 | **绝大多数场景** | 需要与 C 库/旧代码的整数互操作时 |

```python
class Weekday(IntEnum):
    MON = 1
    TUE = 2

print(Weekday.MON == 1)      # True
print(Weekday.MON + 1)       # 2
```

**`auto()` 自动编号**：

```python
class Status(Enum):
    PENDING = auto()        # 1
    PAID = auto()           # 2
    SHIPPED = auto()        # 3

print([(s.name, s.value) for s in Status])   # [('PENDING', 1), ('PAID', 2), ('SHIPPED', 3)]
```

**枚举的三种实用写法**：

```python
# ① 用 @unique 强制值不重复（有重复会报错）
from enum import unique
@unique
class U(Enum):
    A = 1
    B = 2

# ② 中文描述：用 __str__ 或自定义属性
class Order(Enum):
    PENDING = (1, "待付款")
    PAID = (2, "已付款")
    def __init__(self, code, label):
        self.code = code
        self.label = label

print(Order.PAID.label)      # 已付款

# ③ 用 @property 加派生属性
class Size(Enum):
    S = 1
    M = 2
    L = 3
    @property
    def score(self):
        return self.value * 10
print(Size.L.score)          # 30
```

> **重点**：**枚举成员在模块内是单例**——`Color.RED is Color.RED` 永远是 `True`，所以可以放心用 `is` 比较。而且**枚举能防住"拼写错误"**：写 `Color.REDD` 会立刻 `AttributeError`，而写字符串 `"redd"` 只会静默地走进 else 分支。

## 16.5 迭代器协议

**任何实现了 `__iter__` 和 `__next__` 的对象都可以被 `for` 遍历。** 这两个方法就是**迭代器协议（iterator protocol）**。

```python
class CountDown:
    """倒计时：3 → 2 → 1"""
    def __init__(self, n):
        self.n = n
    def __iter__(self):          # 返回迭代器本身
        return self
    def __next__(self):          # 返回下一个值，没值了抛 StopIteration
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1

print(list(CountDown(3)))                    # [3, 2, 1]
print([x for x in CountDown(4)])             # [4, 3, 2, 1]
print(hasattr(CountDown(3), "__iter__"),
      hasattr(CountDown(3), "__next__"))     # True True
print(next(iter(CountDown(2))))              # 2
```

**斐波那契迭代器**（无限序列的有限截取）：

```python
class Fib:
    def __init__(self, n):
        self.n, self.a, self.b, self.i = n, 0, 1, 0
    def __iter__(self):
        return self
    def __next__(self):
        if self.i >= self.n:
            raise StopIteration
        self.i += 1
        self.a, self.b = self.b, self.a + self.b
        return self.a

print(list(Fib(8)))      # [1, 1, 2, 3, 5, 8, 13, 21]
```

**三个必须理解的点**：

1. **`StopIteration` 是 `for` 循环的终止信号**，不是错误。`for` 内部会捕获它并正常结束。
2. **迭代器是"一次性"的**（与第4章生成器表达式耗尽坑完全一样）——遍历完就空了，要重新遍历必须重新创建对象。
3. **`__iter__` 返回 `self` 表示"我既是可迭代对象也是迭代器"**。更规范的做法是让 `__iter__` 返回一个**新的迭代器对象**（这样对象本身可以被反复遍历）。**这与"可迭代对象（iterable）"和"迭代器（iterator）"的区别有关**：列表是**可迭代对象**（有 `__iter__` 但没有 `__next__`），`iter(列表)` 得到的才是**迭代器**（有 `__next__`）。

| 概念 | 需要实现 | 能否被 `for` 遍历 | 能否用 `next()` |
|---|---|---|---|
| 可迭代对象 Iterable | `__iter__` | ✅ | ❌ |
| 迭代器 Iterator | `__iter__` + `__next__` | ✅ | ✅ |

**更简单的写法：用生成器函数**（第4章学过，**能不用类就不用类**）：

```python
def count_down(n):
    while n > 0:
        yield n
        n -= 1

print(list(count_down(3)))      # [3, 2, 1]
```

> **对比**：迭代器类适合"**需要保存复杂状态、需要额外方法**"的场合；生成器函数适合"**就是走一遍序列**"。**能用 `yield` 解决就不要写类。**

## 16.6 上下文管理器协议

**上下文管理器（context manager）** 就是能用在 `with` 语句里的对象——它保证**无论是否发生异常，清理代码都会执行**（第9章的 `with open(...)` 用的就是它）。

**自己实现需要两个方法**：

```python
import time

class Timer:
    def __enter__(self):
        self.t0 = time.perf_counter()
        return self                      # as 后面拿到的就是它
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.t0
        print(f"耗时 {self.elapsed:.6f} 秒")
        return False                     # False/None = 不吞异常，继续往外抛

with Timer() as t:
    sum(range(10000))
# 耗时 0.000xxx 秒
```

**`__exit__` 的三个参数和返回值**（**必考**）：

| 参数/返回值 | 含义 |
|---|---|
| `exc_type` | 异常类型（正常退出时是 `None`） |
| `exc` | 异常实例 |
| `tb` | traceback 对象 |
| **返回 `True`** | **吞掉异常**，`with` 块外的代码继续执行 |
| 返回 `False`/`None` | 异常继续向外传播 |

```python
try:
    with Timer():
        raise ValueError("测试异常穿透")
except ValueError as e:
    print("异常穿透:", e)        # 异常穿透: 测试异常穿透
```

**第二种写法：`@contextmanager` 装饰生成器**（**代码更短，推荐**）：

```python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")          # yield 之前 = __enter__
    yield name                  # yield 的值就是 as 拿到的值
    print(f"</{name}>")         # yield 之后 = __exit__

with tag("div") as n:
    print("  内容", n)
# <div>
#   内容 div
# </div>
```

> **⚠️ `@contextmanager` 的坑**：`yield` 之后的清理代码**只有正常退出时才会执行**——如果 `with` 块里抛了异常，异常会在 `yield` 处重新抛出，**清理代码被跳过**。要保证清理一定执行，必须写成 `try/finally`：
> ```python
> @contextmanager
> def tag(name):
>     print(f"<{name}>")
>     try:
>         yield name
>     finally:
>         print(f"</{name}>")     # 无论是否异常都执行
> ```

**用 `contextlib.suppress` 吞异常**（比 `try/except/pass` 更清晰）：

```python
from contextlib import suppress
with suppress(FileNotFoundError):
    open("不存在的文件.txt")
print("继续执行 ✓")             # 继续执行 ✓
```

**标准库现成的上下文管理器**：`open()`、`threading.Lock()`、`contextlib.suppress`、`contextlib.redirect_stdout`、`decimal.localcontext()`、`unittest` 的 `assertRaises`。

## 16.7 描述符与 property

**描述符（descriptor）是"定义了 `__get__`/`__set__`/`__delete__` 的类"**。它定义了"**访问一个属性时到底发生什么**"——**`@property` 本身就是描述符的一个应用**，但描述符可以**复用**。

**问题**：用 `@property` 校验多个属性要写重复代码：

```python
class RectBad:
    def __init__(self, w, h):
        self._w, self._h = w, h
    @property
    def w(self): return self._w
    @w.setter
    def w(self, v):
        if v <= 0: raise ValueError("必须为正")
        self._w = v
    # height 还要再写一遍……
```

**用描述符一次写好、到处复用**：

```python
class Positive:
    """一个"必须为正数"的属性描述符"""
    def __set_name__(self, owner, name):     # 自动拿到属性名
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        if obj is None:                      # 通过类访问 → 返回描述符本身
            return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name} 必须为正数，收到 {value}")
        setattr(obj, self.name, value)

class Rect:
    width = Positive()                       # 复用！
    height = Positive()
    def __init__(self, w, h):
        self.width, self.height = w, h
    @property
    def area(self):
        return self.width * self.height

r = Rect(3, 4)
print(r.area)                    # 12
try:
    Rect(-1, 4)
except ValueError as e:
    print("描述符校验:", e)       # 描述符校验: _width 必须为正数，收到 -1
print(type(Rect.width).__name__)  # Positive   ← 通过类访问返回描述符本身
```

**三个方法的分工**：

| 方法 | 触发时机 | 说明 |
|---|---|---|
| `__set_name__(owner, name)` | **类定义时**自动调用一次 | 拿到属性名，避免手写字符串 |
| `__get__(obj, objtype)` | 读属性时 | `obj is None` 表示通过**类**访问 |
| `__set__(obj, value)` | 写属性时 | 校验写在这里 |
| `__delete__` | `del` 时 | 较少用 |

> **理解顺序**：**属性查找时，如果类属性是一个"数据描述符"（定义了 `__set__`），它会优先于实例的 `__dict__`**。这就是描述符能"拦截"赋值的原因。

**`cached_property`：算一次就缓存**（第5章 `lru_cache` 的实例属性版）：

```python
import functools

calls = {"n": 0}

class Heavy:
    @functools.cached_property
    def data(self):
        calls["n"] += 1
        return sum(range(1000))

h = Heavy()
print(h.data, h.data, "计算次数:", calls["n"])   # 499500 499500 计算次数: 1
print("data" in h.__dict__)                      # True  ← 结果存进了实例字典
```

> **注意**：`cached_property` 要求类**有 `__dict__`**（所以**不能和 `__slots__` 一起用**），而且缓存是**可变的**——改了依赖数据后缓存不会自动失效。

## 16.8 魔术方法进阶

**魔术方法（magic method / dunder method）** 让自定义对象用起来像内置类型。第6章讲过 `__str__`/`__repr__`/`__eq__`，这里补齐常用的四类。

**一个"钱"的完整例子**：

```python
class Money:
    def __init__(self, amount, currency="CNY"):
        self.amount, self.currency = amount, currency
    def __repr__(self):                  # 给开发者看：print([m]) 用它
        return f"Money({self.amount}, {self.currency!r})"
    def __str__(self):                   # 给用户看：print(m) 用它
        return f"{self.amount:.2f} {self.currency}"
    def __add__(self, other):            # m1 + m2
        if self.currency != other.currency:
            raise ValueError("币种不同")
        return Money(self.amount + other.amount, self.currency)
    def __radd__(self, other):           # 0 + m  → 让 sum() 能用
        if other == 0:
            return self
        return self.__add__(other)
    def __mul__(self, k):                # m * 2
        return Money(self.amount * k, self.currency)
    def __eq__(self, o):                 # m1 == m2
        return (self.amount, self.currency) == (o.amount, o.currency)
    def __hash__(self):                  # 定义了 __eq__ 就必须定义 __hash__
        return hash((self.amount, self.currency))
    def __bool__(self):                  # if m:
        return self.amount != 0
    def __len__(self):                   # len(m)
        return int(self.amount)
    def __getitem__(self, i):            # m[0]
        return (self.amount, self.currency)[i]

m = Money(10) + Money(2.5)
print(str(m))                                    # 12.50 CNY
print(repr(m))                                   # Money(12.5, 'CNY')
print(str(m * 2))                                # 25.00 CNY
print(str(sum([Money(1), Money(2), Money(3)])))  # 6.00 CNY   ← 靠 __radd__
print(Money(1) == Money(1), len({Money(1), Money(1), Money(2)}))   # True 2
print(bool(Money(0)), bool(Money(1)))            # False True
print(len(Money(7.8)), Money(5)[0], Money(5)[1]) # 7 5 CNY
```

**四类魔术方法速查**：

| 类别 | 方法 | 触发 |
|---|---|---|
| **字符串** | `__str__` / `__repr__` / `__format__` | `print()` / 容器内显示 / `f"{obj}"` |
| **算术** | `__add__` `__sub__` `__mul__` `__truediv__` `__floordiv__` `__mod__` `__pow__` | `+ - * / // % **` |
| **反向算术** | `__radd__` `__rsub__` `__rmul__` … | 左操作数不支持时（**`sum()` 靠 `__radd__`**） |
| **就地算术** | `__iadd__` `__imul__` … | `+=` `*=`（**列表的 `+=` 就是 `__iadd__`**） |
| **比较** | `__eq__` `__ne__` `__lt__` `__le__` `__gt__` `__ge__` | `== != < <= > >=` |
| **容器** | `__len__` `__getitem__` `__setitem__` `__delitem__` `__contains__` | `len()` `[]` `del` `in` |
| **可调用** | `__call__` | `obj(...)` |
| **布尔** | `__bool__` | `if obj:` |
| **哈希** | `__hash__` | `hash()`、字典键、`set` |
| **转换** | `__int__` `__float__` `__iter__` | `int(obj)` 等 |

**`@total_ordering`：只写两个比较方法，自动补全六个**：

```python
import functools

@functools.total_ordering
class Ver:
    def __init__(self, s):
        self.parts = tuple(int(x) for x in s.split("."))
    def __eq__(self, o): return self.parts == o.parts
    def __lt__(self, o): return self.parts < o.parts      # 只写 __eq__ 和 __lt__
    def __repr__(self): return "v" + ".".join(map(str, self.parts))

print(Ver("1.2.0") < Ver("1.10.0"), Ver("2.0") > Ver("1.9"), Ver("1.0") <= Ver("1.0"))
# True True True     ← > 和 <= 是自动生成的
```

> **注意**：**只写 `__eq__` 和 `__lt__`**（或 `__eq__` + `__gt__`），`total_ordering` 才能推导其余四个。**字符串比较 `"1.10.0" < "1.2.0"` 是错的**（按字符逐位比，`'1' < '2'`），所以版本号必须先转成整数元组。

**`__call__`：让实例像函数一样被调用**（第5章"函数是一等对象"的类版本）：

```python
class Multiplier:
    def __init__(self, k):
        self.k = k
    def __call__(self, x):
        return x * self.k

double = Multiplier(2)
print(double(5), double(10))      # 10 20
print(callable(double))           # True
```

## 16.9 元类与 __init_subclass__

**"类也是对象"**——`type` 是它们的类型。**元类（metaclass）就是"创建类的类"**。

```python
class Meta(type):
    def __new__(mcs, name, bases, ns):
        ns["created_by"] = "Meta"                 # 往类里注入属性
        return super().__new__(mcs, name, bases, ns)

class WithMeta(metaclass=Meta):
    pass

print(WithMeta.created_by)              # Meta
print(type(WithMeta).__name__)          # Meta     ← 类的类型是 Meta
print(type(WithMeta()).__name__)        # WithMeta ← 实例的类型仍是 WithMeta
```

**元类最实用的用途：子类自动注册**（**插件系统的基础**）：

```python
class RegistryMeta(type):
    registry = {}
    def __new__(mcs, name, bases, ns):
        cls = super().__new__(mcs, name, bases, ns)
        if name != "Base":                        # 跳过基类自己
            mcs.registry[name] = cls
        return cls

class Base(metaclass=RegistryMeta):
    pass

class A(Base): pass
class B(Base): pass

print(list(RegistryMeta.registry.keys()))       # ['A', 'B']
```

**但大多数情况下，`__init_subclass__` 更简单**（**Python 3.6+ 推荐**）：

```python
class Shape:
    _registry = {}

    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        if getattr(cls, "kind", None):
            Shape._registry[cls.kind] = cls

    @classmethod
    def create(cls, kind, *a):                   # 工厂方法
        return cls._registry[kind](*a)

class Sq(Shape):
    kind = "square"
    def __init__(self, s): self.s = s
    def area(self): return self.s ** 2

class Ci(Shape):
    kind = "circle"
    def __init__(self, r): self.r = r
    def area(self): return round(3.14159 * self.r ** 2, 2)

print(Shape.create("square", 3).area(), Shape.create("circle", 2).area())   # 9 12.57
print(list(Shape._registry.keys()))              # ['square', 'circle']
```

> **工程建议**：**99% 的场合不要写元类**。用 `__init_subclass__`、装饰器或 `__set_name__` 就能解决。元类的三个真实用途是：ORM 框架（Django Model 靠元类收集字段）、插件注册、单例/接口约束。**"如果你还在犹豫要不要用元类，那就是不该用。"**

## 16.10 三个常用设计模式

**设计模式（design pattern）是被反复验证过的"类与对象组织套路"。** 这里只讲最常用的三个。

### 单例模式（Singleton）

**需求**：全局只能有一个实例（配置对象、连接池、日志器）。

```python
class Singleton:
    _inst = None
    def __new__(cls, *a, **kw):          # 在"创建对象"这一步拦截
        if cls._inst is None:
            cls._inst = super().__new__(cls)
        return cls._inst

print(Singleton() is Singleton())        # True
```

> **注意**：`__new__` 只在**创建**时拦截，`__init__` **每次调用都会重新执行**。要避免重复初始化，在 `__init__` 里加 `if getattr(self, "_init", False): return` 之类的守卫。
>
> **更 Pythonic 的做法**：用一个**模块级变量**就是天然单例（模块只会被导入一次），根本不用写类。

### 工厂模式（Factory）

**需求**：根据参数决定创建哪个类，调用方不需要知道具体类名。

```python
class Shape:
    _registry = {}
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        if getattr(cls, "kind", None):
            Shape._registry[cls.kind] = cls
    @classmethod
    def create(cls, kind, *a):
        if kind not in cls._registry:
            raise ValueError(f"不支持的形状：{kind}")
        return cls._registry[kind](*a)
```

**好处**：**新增形状只要加一个子类，不用改工厂函数**（符合"开闭原则"）。这与第6章"用 `@classmethod` 做替代构造器"是同一类技巧。

### 观察者模式（Observer）

**需求**：一个对象状态变化时，自动通知所有关注它的对象（事件系统、GUI 回调、消息订阅）。

```python
class Subject:
    def __init__(self):
        self._obs = []
    def attach(self, fn):                # 订阅
        self._obs.append(fn)
    def notify(self, msg):               # 通知
        for fn in self._obs:
            fn(msg)

log = []
s = Subject()
s.attach(lambda m: log.append(f"邮件:{m}"))
s.attach(lambda m: log.append(f"短信:{m}"))
s.notify("订单已发货")
print(log)      # ['邮件:订单已发货', '短信:订单已发货']
```

**三个模式一句话总结**：

| 模式 | 解决什么 | 关键手法 |
|---|---|---|
| 单例 | 全局唯一实例 | 拦截 `__new__`，或直接用模块变量 |
| 工厂 | 创建逻辑与使用解耦 | 注册表 + `classmethod` |
| 观察者 | 一对多通知 | 存回调列表 + 遍历调用 |

> **提醒**：**不要为了用模式而用模式。** 一个 `if/elif` 能解决的事，套上工厂模式只会更难懂。

## 16.11 组合优于继承

**继承（inheritance）** 表达"**is-a**"（狗是动物）；**组合（composition）** 表达"**has-a**"（汽车有引擎）。

```python
class Engine:
    def start(self):
        return "引擎启动"

class Car:
    def __init__(self):
        self.engine = Engine()           # 组合：把引擎"装进"汽车
    def start(self):
        return f"汽车：{self.engine.start()}"

print(Car().start())     # 汽车：引擎启动
```

**为什么优先用组合？**（**这是设计原则，也是考试问答点**）

| 问题 | 继承的麻烦 | 组合的好处 |
|---|---|---|
| 耦合度 | 子类**依赖父类实现细节**，父类一改子类就崩 | 只依赖接口 |
| 灵活性 | 类定义时就定死了，运行时不能换 | **运行时可以替换**（`car.engine = ElectricEngine()`） |
| 层级爆炸 | "会飞的汽车"、"会游泳的汽车" → 多重继承地狱 | 想加能力就加一个部件 |
| 复用 | 单继承语言只能继承一个 | 想组合几个就几个 |

> **判断口诀**：**能说"A 是 B"就用继承，能说"A 有 B"就用组合。** 拿不准时**用组合**。

**协作式 `super()` 与 MRO**：

```python
class A2:
    def hi(self): return "A"

class B2(A2):
    def hi(self): return "B->" + super().hi()

class C2(A2):
    def hi(self): return "C->" + super().hi()

class D2(B2, C2):
    def hi(self): return "D->" + super().hi()

print(D2().hi())                             # D->B->C->A
print([c.__name__ for c in D2.__mro__])      # ['D2', 'B2', 'C2', 'A2', 'object']
```

**读法**：`D2` 的继承顺序是 `B2, C2`，所以先找 `B2.hi`，里面 `super()` 按 **MRO** 找到下一个是 `C2`（**不是 `A2`！**），`C2.hi` 再 `super()` 才到 `A2`。所以输出是 `D->B->C->A`。

> **重点**：**`super()` 不是"调用父类"，而是"按 MRO 调用下一个类"**。这就是"协作式多重继承"能工作的原因——每个类只负责加一点东西，然后交给链上的下一个。**但如果每个类都直接写 `A2.hi(self)` 而不是 `super().hi()`，多重继承就会重复执行或漏执行。**

**MRO 用 C3 线性化算法**，三条规则：① 子类优先于父类；② 多个父类按声明顺序；③ 单调性（不会出现矛盾的顺序）。**Python 会用这个算法检查继承是否合法**，冲突时报 `TypeError: Cannot create a consistent method resolution order (MRO)`。

## 16.12 抽象基类与 Protocol

**抽象基类（ABC）** 定义"必须实现哪些方法"，**不允许直接实例化**：

```python
import abc

class Repo(abc.ABC):
    @abc.abstractmethod
    def get(self, k): ...
    @abc.abstractmethod
    def put(self, k, v): ...
    def describe(self):                          # 可以有具体实现
        return f"{type(self).__name__} 有 {len(self)} 条"

class MemRepo(Repo):
    def __init__(self): self.d = {}
    def get(self, k): return self.d.get(k)
    def put(self, k, v): self.d[k] = v
    def __len__(self): return len(self.d)

mr = MemRepo(); mr.put("a", 1)
print(mr.get("a"), mr.describe())     # 1 MemRepo 有 1 条

try:
    Repo()
except TypeError as e:
    print(str(e)[:70])
    # Can't instantiate abstract class Repo without an implementation for ab
```

> **注意**：**抽象方法的检查发生在"实例化时"，不是"定义子类时"**。所以忘实现某个抽象方法，只有在 `MemRepo()` 那一刻才报错（**与 Java 的编译期检查不同**）。

**`typing.Protocol`：结构化子类型**（鸭子类型的"正式版"）：

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Quacker(Protocol):
    def quack(self) -> str: ...

class Duck:
    def quack(self): return "嘎嘎"

class Robot:
    def quack(self): return "滴滴"

print(isinstance(Duck(), Quacker), isinstance(Robot(), Quacker), isinstance(3, Quacker))
# True True False
```

| 对比项 | `abc.ABC` | `typing.Protocol` |
|---|---|---|
| 判定方式 | **名义子类型**：必须显式继承 | **结构化子类型**：有对应方法就算 |
| 需要继承吗 | ✅ 必须 | ❌ 不需要（隐式满足） |
| 检查时机 | 运行时（实例化时） | 静态检查器（mypy）+ `runtime_checkable` 时运行时可查 |
| 适合 | 框架内部接口 | **跨团队的松耦合接口** |

**区别一句话**：`ABC` 说"**你必须是这个家族的人**"，`Protocol` 说"**你只要会这一手就行**"。**后者更符合 Python 的鸭子类型哲学。**

## 16.13 拷贝协议

第4章讲过浅拷贝与深拷贝。**自定义类可以让 `copy` 模块按自己的规则拷贝**：

```python
import copy

class WithCopy:
    def __init__(self, d):
        self.d = list(d)
    def __copy__(self):                  # copy.copy() 调用它
        return WithCopy(self.d)          # 浅拷贝也把内部列表复制一份
    def __repr__(self):
        return f"WithCopy({self.d})"

wc = WithCopy([1, 2])
wc2 = copy.copy(wc)
wc2.d.append(3)
print(wc.d, wc2.d, wc is wc2)     # [1, 2] [1, 2, 3] False
```

**默认行为对比**：

```python
class Node:
    def __init__(self, val, child=None):
        self.val, self.child = val, child

n = Node(1, Node(2))
print(copy.copy(n).child is n.child)          # True   ← 浅拷贝共享子对象
print(copy.deepcopy(n).child is n.child)      # False  ← 深拷贝递归复制
```

| 方法 | 被谁调用 | 默认行为 |
|---|---|---|
| `__copy__` | `copy.copy(obj)` | 复制 `__dict__`，但**内部对象仍是共享的** |
| `__deepcopy__(memo)` | `copy.deepcopy(obj)` | 递归复制所有内部对象 |
| `__reduce__` | `pickle` / `copy` | 自定义序列化方式 |

> **提示**：**深拷贝要处理循环引用**（A 引用 B，B 又引用 A），`copy` 模块用 `memo` 字典记录已复制的对象来避免无限递归。自己实现 `__deepcopy__` 时**必须把 `memo` 传下去**。

## 16.14 singledispatch

**问题**：一个函数要按参数类型走不同分支，写成一长串 `isinstance`：

```python
def show_bad(x):
    if isinstance(x, int):
        return f"整数 {x}"
    elif isinstance(x, list):
        return f"列表长度 {len(x)}"
    elif isinstance(x, float):
        return f"浮点 {x}"
    return f"未知类型 {type(x).__name__}"
```

**`functools.singledispatch` 把它变成"函数版的多态"**：

```python
import functools

@functools.singledispatch
def show(x):
    return f"未知类型 {type(x).__name__}"        # 默认实现

@show.register(int)
def _(x): return f"整数 {x}"

@show.register(list)
def _(x): return f"列表长度 {len(x)}"

@show.register
def _(x: float): return f"浮点 {x}"              # 用类型注解注册

print(show(1), "|", show([1, 2]), "|", show(1.5), "|", show("s"))
# 整数 1 | 列表长度 2 | 浮点 1.5 | 未知类型 str
```

**好处**：① **新增类型只需加一个 `register`**，不用改原函数；② 可以按 MRO 自动找最匹配的实现（`bool` 会命中 `int` 的注册）；③ 第三方库能给你的函数"打补丁"注册新类型。

**什么时候用？** 处理**多种输入类型**的工具函数（如"把任意对象转成 JSON 友好的形式"）、**访问者模式**的轻量替代。

## 典型例题

**例 16.1**（题型：编程题 —— 用 dataclass 重构）

**题目**：把下面这个类用 `@dataclass` 改写，要求：`age` 默认 18、`courses` 是每个实例独立的空列表、对象可比较相等、`repr` 显示全部字段。

```python
class Student:
    def __init__(self, name, age=18, courses=None):
        self.name = name
        self.age = age
        self.courses = courses if courses is not None else []
    def __repr__(self):
        return f"Student({self.name!r}, {self.age}, {self.courses})"
    def __eq__(self, other):
        return (self.name, self.age, self.courses) == (other.name, other.age, other.courses)
```

**解**：

```python
from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    age: int = 18
    courses: list = field(default_factory=list)
```

**答案**：4 行替代原来 10 行。验证：

```python
s1, s2 = Student("张三"), Student("李四")
s1.courses.append("Python")
print(s1)                            # Student(name='张三', age=18, courses=['Python'])
print(s2)                            # Student(name='李四', age=18, courses=[])
print(Student("张三") == Student("张三"))   # True
print(Student("张三") == Student("李四"))   # False
```

**要点**：① **`field(default_factory=list)` 保证每个实例拿到独立的列表**（等价于原代码里 `courses=None` 的绕法，但更清晰）；② `__repr__` 和 `__eq__` 全部自动生成；③ **注意 `dataclass` 的字段顺序**——有默认值的字段必须排在无默认值字段之后。

**例 16.2**（题型：读程序写结果 —— 迭代器协议）

```python
class Seq:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n

s = Seq(3)
print(list(s))
print(list(s))
print(list(Seq(3)))
```

**解**：`Seq(3)` 的 `__next__` 每次把 `n` 减 1 后返回 `n`，所以依次返回 `2, 1, 0`，然后 `n <= 0` 抛 `StopIteration`。**关键在第二次 `list(s)`**：`s` 的 `n` 已经被减到 0 了，所以第二次遍历**一个元素都没有**，得到空列表。第三次用的是**新建的对象**，又得到 `[2, 1, 0]`。

**答案**：`[2, 1, 0]` / `[]` / `[2, 1, 0]`。**这就是"迭代器是一次性的"**——这与第4章生成器耗尽坑是同一个问题。**要让对象能被反复遍历，`__iter__` 应该返回一个全新的迭代器对象，而不是 `self`。**

**例 16.3**（题型：读程序写结果 —— 上下文管理器与异常）

```python
class CM:
    def __enter__(self):
        print("进入")
        return 42
    def __exit__(self, t, e, tb):
        print("退出", t.__name__ if t else None)
        return True

with CM() as v:
    print("值", v)
    raise ValueError("boom")
print("还在继续")
```

**解**：进入 `with` 先调用 `__enter__`，打印"进入"并返回 42，`as v` 拿到 42。块内打印"值 42"，然后抛 `ValueError`。异常触发 `__exit__`，`t` 是 `ValueError` 类型，打印"退出 ValueError"。**`__exit__` 返回 `True` 表示吞掉异常**，所以 `with` 块之后的代码继续执行，打印"还在继续"，程序不崩溃。

**答案**：
```
进入
值 42
退出 ValueError
还在继续
```
**要点**：**返回 `True` 是吞异常、返回 `False`/`None` 是继续往外抛**——这个区别是上下文管理器最常考的点。

**例 16.4**（题型：编程题 —— 用描述符做校验）

**题目**：写一个描述符 `Range`，限制属性值必须在 `[lo, hi]` 区间内；用它给 `class Score` 的 `value` 属性加上 0~100 的校验。

**解**：

```python
class Range:
    def __init__(self, lo, hi):
        self.lo, self.hi = lo, hi
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if not (self.lo <= value <= self.hi):
            raise ValueError(f"{self.name} 必须在 {self.lo}~{self.hi}，收到 {value}")
        setattr(obj, self.name, value)

class Score:
    value = Range(0, 100)
    def __init__(self, value):
        self.value = value
    def __repr__(self):
        return f"Score({self.value})"

print(Score(85))                     # Score(85)
print(Score(85).value)               # 85
try:
    Score(120)
except ValueError as e:
    print("校验:", e)                # 校验: _value 必须在 0~100，收到 120
```

**答案**：`Score(85)`、`85`、`校验: _value 必须在 0~100，收到 120`。**要点**：① **`__set_name__` 让描述符自动知道自己的属性名**（不用手写字符串，改名也不会漏）；② `__get__` 里 **`obj is None` 的分支必须写**，否则 `Score.value`（通过类访问）会报错；③ **描述符实例是类属性，被所有实例共享**——所以真正的值必须存在实例的 `_value` 里，不能存在描述符自己身上（那会变成"所有 Score 共用一个值"）。

**例 16.5**（题型：编程题 —— 单例 + 工厂）

**题目**：实现一个配置管理器 `Config`，要求全局只有一个实例，且能从字典批量更新配置；再实现一个日志工厂，按名字返回对应的 logger 单例。

**解**：

```python
class Config:
    _inst = None
    def __new__(cls):
        if cls._inst is None:
            cls._inst = super().__new__(cls)
            cls._inst._data = {}
            cls._inst._inited = True
        return cls._inst
    def update(self, d):
        self._data.update(d)
        return self
    def get(self, k, default=None):
        return self._data.get(k, default)
    def __repr__(self):
        return f"Config({self._data})"

c1, c2 = Config(), Config()
c1.update({"debug": True, "level": "INFO"})
print(c1 is c2)                      # True
print(c2.get("debug"), c2.get("level"))   # True INFO

class LoggerFactory:
    _loggers = {}
    @classmethod
    def get(cls, name):
        if name not in cls._loggers:
            cls._loggers[name] = f"<Logger {name}>"
        return cls._loggers[name]

print(LoggerFactory.get("db") is LoggerFactory.get("db"))    # True
print(list(LoggerFactory._loggers.keys()))                   # ['db']
```

**答案**：`True` / `True INFO` / `True` / `['db']`。**要点**：① **`__new__` 里同时初始化数据**（用 `_inited` 标记），否则 `Config()` 第二次调用会重置数据；② **`update` 返回 `self` 支持链式调用**；③ 工厂用**类变量字典**做缓存，天然实现"同名 logger 只建一次"。

**例 16.6**（题型：编程题 —— 观察者 + 元类注册）

**题目**：写一个简易事件系统：`EventBus` 支持 `on(事件名, 回调)` 和 `emit(事件名, 数据)`；再用 `__init_subclass__` 让所有 `Handler` 子类自动注册到全局表。

**解**：

```python
class EventBus:
    def __init__(self):
        self._handlers = {}
    def on(self, event, fn):
        self._handlers.setdefault(event, []).append(fn)
        return self
    def emit(self, event, data=None):
        for fn in self._handlers.get(event, []):
            fn(data)
        return self

bus = EventBus()
log = []
(bus.on("login", lambda d: log.append(f"记录登录 {d}"))
    .on("login", lambda d: log.append(f"发欢迎邮件 {d}"))
    .on("logout", lambda d: log.append(f"记录登出 {d}")))
bus.emit("login", "张三")
bus.emit("logout", "张三")
bus.emit("unknown")
print(log)
# ['记录登录 张三', '发欢迎邮件 张三', '记录登出 张三']

HANDLERS = {}
class Handler:
    def __init_subclass__(cls, **kw):
        super().__init_subclass__(**kw)
        HANDLERS[cls.__name__] = cls

class LoginHandler(Handler): pass
class LogoutHandler(Handler): pass
print(list(HANDLERS.keys()))         # ['LoginHandler', 'LogoutHandler']
```

**答案**：`['记录登录 张三', '发欢迎邮件 张三', '记录登出 张三']` 和 `['LoginHandler', 'LogoutHandler']`。**要点**：① **`setdefault(event, []).append(fn)` 一步完成"取列表或建列表"**（等价于第4章 `defaultdict(list)` 的写法）；② **`emit` 一个没有订阅者的事件不会报错**（`get(event, [])` 返回空列表）；③ **`on` 返回 `self` 支持链式调用**；④ `__init_subclass__` 是**定义子类时**自动执行的钩子，比元类简单得多。

## 易错点提醒

1. **`dataclass` 里给可变字段写 `= []`** → 错：直接报 `ValueError: mutable default <class 'list'> for field xxx is not allowed`。对：用 **`field(default_factory=list)`**。
2. **以为 `@dataclass` 生成的对象可哈希** → 错：定义了 `__eq__` 后 `__hash__` 被置为 `None`，放进 `set` 会报 `TypeError: unhashable type`。对：加 `frozen=True`，或自己定义 `__hash__`。
3. **`__slots__` 里的名字与类属性重名** → 错：`ValueError: 'x' in __slots__ conflicts with class variable`。对：改名字，或把默认值写进 `__init__`。
4. **子类定义了 `__slots__` 但父类没定义** → 错：**子类实例仍带 `__dict__`**（父类实例本来就有，子类实例继承了它），`w.b = 1` 照样能加新属性，省内存效果完全失效。对：**整条继承链都要定义 `__slots__`**（除了 `object`）——父类也定义后实例才真正没有 `__dict__`，此时 `o.b = 1` 报 `AttributeError: 'OnlySlots' object has no attribute 'b' and no __dict__ for setting new attributes`。
5. **用 `Enum` 成员和它的值比较** → 错：`Color.RED == 1` 是 **`False`**。对：比 `Color.RED.value == 1`，或改用 `IntEnum`。
6. **`__iter__` 返回 `self` 却以为对象能反复遍历** → 错：迭代器是**一次性**的，第二次 `list(obj)` 得到 `[]`。对：**`__iter__` 里返回一个全新的迭代器对象**，或用生成器函数。
7. **忘了在 `__next__` 里抛 `StopIteration`** → 错：`for` 循环永远不结束（死循环）。对：明确写终止条件并 `raise StopIteration`。
8. **`__exit__` 忘了返回值** → 错：返回 `None` 等价于 `False`，异常继续外抛（如果本意是吞掉异常就错了）。对：**吞异常显式 `return True`**。
9. **`@contextmanager` 的清理代码没放 `finally`** → 错：`with` 块内抛异常时，`yield` 之后的清理代码**被跳过**。对：写成 `try: yield ... finally: 清理`。
10. **描述符把值存在自己身上** → 错：描述符实例是**类属性、被所有实例共享**，`self.value = v` 会让所有对象共用一个值。对：**存到 `obj` 上**（`setattr(obj, "_" + name, v)`）。
11. **`__get__` 忘了处理 `obj is None`** → 错：通过类访问（`Score.value`）时 `obj` 是 `None`，会 `AttributeError`。对：**`if obj is None: return self`**。
12. **只重载了 `__eq__` 没重载 `__hash__`** → 错：对象变得不可哈希，不能当字典键。对：**两个一起定义**，且 `__hash__` 用的字段要和 `__eq__` 一致。
13. **以为 `super()` 就是"父类"** → 错：**`super()` 是按 MRO 找下一个类**，多重继承下可能是"兄弟类"。对：理解 `__mro__` 的输出顺序。
14. **`functools.total_ordering` 只写了一个方法** → 错：必须提供 `__eq__` **加上** `__lt__`（或 `__gt__` 等四个之一）。对：写 `__eq__` + `__lt__`。
15. **`cached_property` 与 `__slots__` 一起用** → 错：`cached_property` 需要往 `__dict__` 里写缓存，而 `__slots__` 没有 `__dict__`，报 `TypeError: No '__dict__' attribute`。对：二选一。
16. **动不动就写元类** → 错：元类会让代码难以理解和调试。对：**优先用 `__init_subclass__`、装饰器或 `__set_name__`**。

## 本章小结

- **`@dataclass` 消灭样板代码**：自动生成 `__init__`/`__repr__`/`__eq__`；**可变默认值必须用 `field(default_factory=list)`**（与第5章 `def f(a=[])` 是同一个坑，但 `dataclass` 会主动报错拦住你）；`frozen=True` 得到不可变且可哈希的对象；`order=True` 得到可排序对象。
- **`__slots__` 省内存、禁止动态加属性**；副作用是**不能有 `__dict__`**、**与 `cached_property` 不兼容**、**子类不写 `__slots__` 就失效**。
- **`Enum` 消灭魔法数字**：`Color.RED != 1`（**枚举成员不等于它的值**），可遍历、可按名/按值查找、成员是单例；需要与整数互操作时才用 `IntEnum`。
- **迭代器协议 = `__iter__` + `__next__` + `StopIteration`**；**迭代器是一次性的**（`__iter__` 返回 `self` 时对象只能遍历一遍）；能用生成器函数就别写类。
- **上下文管理器 = `__enter__` + `__exit__`**；**`__exit__` 返回 `True` 吞异常、返回 `False`/`None` 继续抛**；`@contextmanager` 写法更短，但**清理代码必须放 `try/finally`**。
- **描述符定义"访问属性时发生什么"**，`@property` 是它的一个应用；`__set_name__` 自动拿属性名，`__get__` 必须处理 `obj is None`，**值要存在实例上而不是描述符上**。
- **魔术方法让对象像内置类型**：`__add__`/`__radd__`（`sum()` 靠它）/`__eq__`+`__hash__`/`__bool__`/`__len__`/`__getitem__`/`__call__`；`@total_ordering` 只写 `__eq__` + `__lt__` 就能补齐六个比较。
- **"类也是对象"，元类是创建类的类**；但 **99% 的场合应该用 `__init_subclass__` 而不是元类**。
- **三个常用模式**：单例（`__new__` 拦截，或直接用模块变量）、工厂（注册表 + `classmethod`，加新类型不改旧代码）、观察者（回调列表 + 遍历通知）。
- **组合优于继承**：能说"is-a"才用继承，否则用组合；**`super()` 是按 MRO 调用下一个类，不是"调用父类"**。
- **`abc.ABC` 是名义子类型（必须继承），`typing.Protocol` 是结构化子类型（有方法就算）**——后者更符合 Python 的鸭子类型哲学。
- **`singledispatch` 是"函数版多态"**，用 `register` 按类型分派，替代一长串 `isinstance`。

> **一句话记住本章**：**数据用 `dataclass`、取值用 `Enum`、资源用上下文管理器、校验用描述符、能力用组合——元类留给框架作者，你只需要 `__init_subclass__`。**

**参考答案**

1. 自动生成 **`__init__`、`__repr__`、`__eq__`**。因为默认值在**定义类时只求值一次**，写 `= []` 会让所有实例共享同一个列表（与第5章 `def f(a=[])` 是同一个坑）；`default_factory=list` 让每个实例调用时新建一个列表。实际上 `dataclass` 遇到 `= []` 会**直接报错**拦住你。
2. ① **对象不可变**（赋值抛 `FrozenInstanceError`），可以放心当"值对象"用；② **可哈希**，能放进 `set`、能当字典键（普通 `dataclass` 因为定义了 `__eq__` 而 `__hash__` 为 `None`）。
3. ① **不能给实例动态添加属性**（写错属性名会立刻 `AttributeError`，这其实是保护）；② **实例没有 `__dict__`**，因此与 `cached_property`、`__dict__` 相关的功能不兼容。**子类不定义 `__slots__` 会重新获得 `__dict__`，省内存效果失效。**
4. **`False`**。`Enum` 成员是**独立的对象**，不等于它的值（这是 `Enum` 类型安全的体现）。需要与整数直接比较、参与算术（比如与 C 库或旧代码互操作）时才用 **`IntEnum`**。
5. 实现 **`__iter__`** 和 **`__next__`**。`for` 循环不断调用 `__next__`，当它抛出 **`StopIteration`** 时，`for` 捕获这个异常并**正常结束循环**（不是报错）。
6. 因为 `__iter__` 返回 `self` 时，**迭代状态（比如计数）就保存在对象自己身上**，遍历一遍后状态已经耗尽，第二次遍历立刻抛 `StopIteration`。改法：**让 `__iter__` 每次返回一个全新的迭代器对象**（可以另写一个迭代器类，或用生成器函数 `yield`）。
7. 返回 **`True` 表示"异常已被处理"，`with` 块之后的代码继续执行**；返回 **`None`/`False` 表示不处理，异常继续向外传播**（调用方能捕获到）。
8. 因为 `@contextmanager` 把生成器分成 `yield` 前后两段：`yield` 之后的代码相当于 `__exit__`。**如果 `with` 块里抛了异常，异常会在 `yield` 那一行重新抛出**，`yield` 后面的普通语句**根本执行不到**。放进 `try/finally` 的 `finally` 里才能保证一定执行。
9. 因为**通过类访问属性**（如 `Score.value`）时，`__get__` 收到的 `obj` 是 `None`（`objtype` 才是类）。如果不判断就 `getattr(obj, ...)`，会抛 `AttributeError`。正确做法是 `if obj is None: return self`。
10. 因为 `__hash__` 和 `__eq__` 必须**保持一致**：相等的对象必须有相同的哈希值，否则字典和 `set` 会失效（两个"相等"的对象被放进不同的桶）。Python 为了安全，一旦你定义了 `__eq__`，就把默认的 `__hash__` 设为 `None`，强制你显式决定。
11. **`super()` 不是"调用父类"，而是"按 MRO（方法解析顺序）调用下一个类"**。`D2(B2, C2)` 的 `__mro__` 是 **`[D2, B2, C2, A2, object]`**，所以 `B2.hi` 里的 `super().hi()` 调用的是 **`C2.hi`**，输出是 `D->B->C->A`。
12. **`abc.ABC` 是名义子类型**：必须**显式继承**才算，检查在**实例化时**（忘实现抽象方法 → `TypeError: Can't instantiate abstract class ...`）。**`typing.Protocol` 是结构化子类型**：只要**有对应的方法/属性**就算，不需要继承（配合 `@runtime_checkable` 可做 `isinstance` 检查，主要供 mypy 等静态检查器使用）。后者更符合鸭子类型。
13. **单例**：保证全局只有一个实例（配置、连接池）；**工厂**：把"创建哪个类"的决定集中起来，新增类型时不必改调用方（注册表 + `classmethod`）；**观察者**：一对多的通知机制，状态变化时自动通知所有订阅者（事件系统、GUI 回调）。
14. ```python
    from dataclasses import dataclass, field

    @dataclass
    class Student:
        name: str
        age: int = 18
        courses: list = field(default_factory=list)

    s1, s2 = Student("张三"), Student("李四")
    s1.courses.append("Python")
    print(s1)      # Student(name='张三', age=18, courses=['Python'])
    print(s2)      # Student(name='李四', age=18, courses=[])
    ```
