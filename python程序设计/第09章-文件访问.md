## 9.1 概述

**文件（file）是存储在外部介质上的数据集合**，按内容分为两类：

| 类型 | 内容 | 打开方式 | 典型格式 |
|---|---|---|---|
| **文本文件** | 字符（有编码） | `"r"` / `"w"` | `.txt` `.csv` `.json` `.py` |
| **二进制文件** | 字节（无编码） | `"rb"` / `"wb"` | `.jpg` `.png` `.exe` `.pkl` |

**编码（encoding）**：计算机只存字节，字符要先按规则转成字节。**UTF-8** 是国际通用编码（1 个汉字 3 字节）；**GBK** 是中文 Windows 的传统编码（1 个汉字 2 字节）。

```python
s = "中文测试"
print(len(s.encode("utf-8")), len(s.encode("gbk")))
# 12 8        ← 同一个字符串，UTF-8 是 12 字节，GBK 是 8 字节
print(s.encode("utf-8"))            # b'\xe4\xb8\xad\xe6\x96\x87\xe6\xb5\x8b\xe8\xaf\x95'
print(s.encode("gbk"))              # b'\xd6\xd0\xce\xc4\xb2\xe2\xca\xd4'
```

> **中文乱码的本质**：**用 A 编码写入、用 B 编码读取**。用 GBK 写的文件用 UTF-8 读，就会抛 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0: invalid start byte`；如果碰巧不报错，就会显示成 `ÖÐÎÄ²âÊÔ` 这样的乱码。
>
> **统一原则：自己的项目一律用 UTF-8**，并且**每次 `open()` 都显式写 `encoding="utf-8"`**。

**路径**：用 `os.path.join()` 拼接（第 7 章讲过），**绝对路径在 Windows 上要注意 `\` 是转义符**，要么写 `r"D:\data\a.txt"`，要么写 `"D:/data/a.txt"`。

## 9.2 文本文件访问

### 9.2.1 打开文件

**语法**：

```python
open(file, mode="r", buffering=-1, encoding=None, errors=None, newline=None)
```

| 参数 | 说明 |
|---|---|
| `file` | 文件名或路径（**字符串或 `pathlib.Path`**） |
| `mode` | 打开模式，默认 `"r"` |
| `encoding` | 编码，**文本模式必须显式指定** |
| `newline` | 换行处理，**CSV 必须写 `newline=""`** |
| `errors` | 编码错误处理策略（`"ignore"` / `"replace"`） |

**模式表（必背）**：

| 模式 | 含义 | 文件不存在 | 文件已存在 | 可否读 | 可否写 |
|---|---|---|---|---|---|
| `"r"` | **只读**（默认） | **报错** | 从头读 | ✅ | ❌ |
| `"w"` | **只写** | 创建 | **清空重写** | ❌ | ✅ |
| `"a"` | **追加** | 创建 | 在末尾追加 | ❌ | ✅ |
| `"x"` | **独占创建** | 创建 | **报错** | ❌ | ✅ |
| `"r+"` | 读写 | 报错 | **不清空**，指针在开头 | ✅ | ✅ |
| `"w+"` | 读写 | 创建 | **清空** | ✅ | ✅ |
| `"a+"` | 读写 | 创建 | 追加 | ✅ | ✅ |
| `"rb"` / `"wb"` | 二进制读/写 | —— | —— | —— | —— |

> **`"w"` 是"危险模式"**：只要打开就**立刻清空原文件**，哪怕你一个字都没写。**想保留原内容必须用 `"a"`。** 这是初学者最容易造成数据丢失的操作。

> **`+` 不等于"追加"**：很多人以为 `"r+"` 是追加，其实**`"r+"` 的写指针在文件开头，会覆盖前面的内容**。**追加只能靠 `"a"`**（`"a"` 模式下写指针永远在末尾，`seek` 也拉不回来）。

**`with` 上下文管理器（必须用）**：

```python
# ✅ 推荐：with 会自动关闭文件（即使中间抛异常）
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")

# ❌ 不推荐：忘记 close 会导致数据没落盘 / 文件句柄泄漏
f = open("a.txt", "w", encoding="utf-8")
f.write("第一行\n")
f.close()               # 必须记得，且异常时会跳过
```

> **为什么必须 `with`？** ① **自动 `close()`**，包括发生异常时；② 文件句柄是**有限资源**（Windows 默认同时打开约 512 个），泄漏会导致 `OSError: [Errno 24] Too many open files`；③ **缓冲区的数据只有在关闭时才保证写入磁盘**，不关文件可能"写了但文件是空的"。

### 9.2.2 文件操作

**四种读法对比（高频考点）**：

| 方法 | 返回 | 内存占用 | 适用场景 |
|---|---|---|---|
| `f.read()` | **整个文件的字符串** | 全部载入 | 小文件一次处理 |
| `f.read(n)` | 前 n 个**字符** | 只占 n | **大文件分块读** |
| `f.readline()` | **一行**（含 `\n`） | 一行 | 逐行处理、只读前几行 |
| `f.readlines()` | **每行组成的列表** | 全部载入 | 需要反复遍历 |
| `for line in f:` | 每次一行 | **一行** | **大文件首选** |

```python
# 先造一个测试文件
with open("demo.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n第二行\n第三行\n")

with open("demo.txt", encoding="utf-8") as f:
    print(repr(f.read(5)))              # '第一行\n第'   ← read(n) 的单位是"字符"
with open("demo.txt", encoding="utf-8") as f:
    print(f.readline().strip(), "|", f.readline().strip())
    # 第一行 | 第二行
with open("demo.txt", encoding="utf-8") as f:
    print(f.readlines())                # ['第一行\n', '第二行\n', '第三行\n']
with open("demo.txt", encoding="utf-8") as f:
    print([l.strip() for l in f])       # ['第一行', '第二行', '第三行']   ← 迭代
```

> **`readlines()` 与 `for line in f` 的区别**：`readlines()` **一次性把所有行读进内存**，10 万行的日志会占几百 MB；**`for line in f` 是惰性迭代，内存里始终只有一行**。**处理大文件一律用 `for line in f:`。**

> **每行末尾都带 `\n`**（最后一行可能没有）。**去掉它用 `line.rstrip("\n")` 或 `line.strip()`**。注意 `strip()` 会**同时去掉行首空格**，如果行首空格有意义（如代码文件）就用 `rstrip("\n")`。

**带行号遍历（实用模板）**：

```python
with open("demo.txt", encoding="utf-8") as f:
    for i, line in enumerate(f, 1):     # start=1 让行号从 1 开始
        print(i, line.rstrip())
# 1 第一行
# 2 第二行
# 3 第三行
```

**写入**：

```python
# write：写字符串，返回写入的字符数
with open("w1.txt", "w", encoding="utf-8") as f:
    n = f.write("Hello\n")
    print(n)                            # 6

# writelines：写字符串序列（注意：不会自动加换行！）
with open("w2.txt", "w", encoding="utf-8") as f:
    f.writelines(["x\n", "y\n"])
print(repr(open("w2.txt", encoding="utf-8").read()))    # 'x\ny\n'

# 危险示范：不加 \n 会全部挤在一行
with open("w3.txt", "w", encoding="utf-8") as f:
    f.writelines(["x", "y", "z"])
print(repr(open("w3.txt", encoding="utf-8").read()))    # 'xyz'
```

> **`writelines()` 不补换行**（这是名字的误导之处）。要写"每行一条"必须自己在每个元素后加 `\n`：`f.writelines(s + "\n" for s in lines)`。

**文件指针 `seek` 与 `tell`**：

| 方法 | 作用 |
|---|---|
| `f.tell()` | 返回当前指针位置 |
| `f.seek(offset, whence)` | 移动指针。`whence`：`0` 文件头（默认）、`1` 当前位置、`2` 文件尾 |
| `f.seek(0)` | **回到开头（重新读一遍的常用写法）** |

```python
# 先造一个"行尾就是 \n"的测试文件：必须用二进制模式写
# （Windows 上文本模式写会把 \n 自动变成 \r\n，见下面第二个坑）
with open("demo.txt", "wb") as f:
    f.write("第一行\n第二行\n第三行\n".encode("utf-8"))   # 30 字节

with open("demo.txt", "rb") as f:        # 二进制模式下 seek 才是精确字节定位
    f.seek(-4, 2)                        # 从文件尾往前 4 字节
    print(f.read().decode("utf-8"))      # 行\n
with open("demo.txt", encoding="utf-8") as f:
    f.readline()
    print(f.tell(), repr(f.readline()))  # 10 '第二行\n'
```

> **两个坑**：① **文本模式下 `seek` 只能跳到"字符边界"**，跳到多字节字符中间会报 `UnicodeDecodeError`。实测对 `"第一行\n第二行\n第三行\n"` 逐个位置试：`seek(0)` → `'第一行\n'`、`seek(3)` → `'一行\n'`、`seek(6)` → `'行\n'` **都能正常读**，而 `seek(1)` / `seek(2)` / `seek(4)` / `seek(5)` / `seek(7)` **全部报 `'utf-8' codec can't decode byte 0xac in position 0: invalid start byte`**——因为一个汉字占 3 字节，切在中间就把字符劈开了。**要按字节精确定位就全程用二进制模式，读出来再整体 decode。**
>
> ② **`\r\n` 会让字节数和你以为的不一样**：同一个字符串 `"第一行\n第二行\n第三行\n"`，**二进制模式写**是 **30 字节**（行尾 1 字节），**文本模式写**在 Windows 上是 **33 字节**（每行行尾变成 `\r\n` 两字节）。这时再 `seek(-4, 2)` 读到的是 `b'\xa1\x8c\r\n'`，`decode("utf-8")` 直接抛 **`UnicodeDecodeError: 'utf-8' codec can't decode byte 0xa1 in position 0: invalid start byte`**——**这不是 seek 的错，是文件内容和你以为的不一样**。
>
> 同理，**`tell()` 返回的是文件里的字节偏移，不是 `len(读到的字符串)`**：读到的 `'第一行\n'` 在内存里是 4 字符、10 字节，但在 33 字节那个文件里占了 **11 字节**（`第一行` 9 字节 + `\r\n` 2 字节），所以 `tell()` 打印 **11**；换成 30 字节那个文件才是 **10**。**看到 `tell()` 的数字对不上不要慌，先想想换行符。**

**常用文件方法汇总表**：

| 方法 | 作用 |
|---|---|
| `read(n)` / `readline()` / `readlines()` | 读全部 / 一行 / 所有行 |
| `write(s)` / `writelines(seq)` | 写字符串 / 写字符串序列 |
| `seek(pos)` / `tell()` | 移动指针 / 当前位置 |
| `flush()` | **强制把缓冲区写入磁盘** |
| `close()` | 关闭文件（`with` 自动调用） |
| `f.closed` | 是否已关闭（布尔属性） |
| `f.name` / `f.mode` | 文件名 / 打开模式 |

> **`flush()` 什么时候用？** 做**实时日志**时，程序还在跑但文件里看不到内容，就是因为数据还在缓冲区。`f.flush()` 强制落盘。**另一个办法是 `open(..., buffering=1)`（行缓冲）。**

**大文件分块读的标准写法**：

```python
with open("big.txt", "w", encoding="utf-8") as f:
    for i in range(1000):
        f.write(f"行{i}\n")

with open("big.txt", encoding="utf-8") as f:
    n = 0
    while True:
        chunk = f.read(100)             # 每次 100 个字符
        if not chunk:                   # 读到空串说明到底了
            break
        n += 1
print(n)                                # 49
```

> **`while True` + `read(n)` + `if not chunk: break`** 是分块读的固定套路。**注意判断条件是"空串"而不是"None"**——`read()` 在文件末尾返回 `''`。

## 9.3 二进制文件访问

**二进制模式（`"rb"`/`"wb"`）读写的对象是 `bytes`，不带编码、不能直接 `readline`。** 它适合：图片/音频、需要**精确定位字节**的场景、以及下面四种"序列化"工具。

**序列化（serialization）**：把内存中的对象（列表、字典、自定义类实例）**变成字节流**以便存盘或传输；反向过程叫**反序列化**。

| 工具 | 定位 | 能存什么 | 跨版本/跨语言 |
|---|---|---|---|
| **pickle** | 通用对象序列化 | **几乎所有 Python 对象** | ❌ 仅 Python，且不保证跨版本 |
| **struct** | 按格式打包**定长**数据 | 数字、定长字节串 | ✅ 与 C 语言互通 |
| **marshal** | Python 内部用的序列化 | 基本类型、代码对象 | ❌ **官方不建议持久化** |
| **shelve** | **持久化的字典** | 任意可 pickle 的对象 | ❌ 仅 Python |

### 9.3.1 使用 Pickle 模块读/写二进制文件

```python
import pickle

obj = {"a": [1, 2, 3], "b": (4, 5), "c": {6, 7}, "d": "中文"}

# 写
with open("data.pkl", "wb") as f:
    pickle.dump(obj, f)

# 读
with open("data.pkl", "rb") as f:
    back = pickle.load(f)
print(back["a"], back["b"], sorted(back["c"]), back["d"])
# [1, 2, 3] (4, 5) [6, 7] 中文

# 也可以直接转成 bytes（不落盘）
print(len(pickle.dumps(obj)))           # 65
print(pickle.loads(pickle.dumps([1, 2, 3])))    # [1, 2, 3]
print(pickle.dumps(42))                 # b'\x80\x04K*.'
```

| 函数 | 作用 |
|---|---|
| `pickle.dump(obj, f)` | 把对象写入**二进制文件** |
| `pickle.load(f)` | 从文件读回对象 |
| `pickle.dumps(obj)` | 转成 `bytes` |
| `pickle.loads(b)` | 从 `bytes` 还原 |

> **⚠️ 安全警告（必须知道）**：**`pickle.load()` 会执行字节流里的"构造指令"，加载不可信来源的 pkl 文件等于让对方在你的电脑上执行任意代码。** 只反序列化**自己生成的**文件。同理，**不要用 `pickle` 做网络传输格式**——跨语言通信用 JSON 或 Protobuf。

> **pickle 的两个限制**：① **只能被 Python 读**（Java/C++ 读不了）；② **Python 3.8 存的 pkl 用 Python 3.12 读可能失败**（版本不兼容），官方建议用 JSON 做长期存储。

### 9.3.2 使用 Struct 模块读/写二进制文件

**`struct` 按"格式字符串"把 Python 值打包成定长字节，或反过来解包。** 它是与 C 语言结构体互通的桥梁。

| 格式符 | C 类型 | 字节数 |
|---|---|---|
| `b` / `B` | signed/unsigned char | 1 |
| `h` / `H` | short | 2 |
| `i` / `I` | **int** | 4 |
| `l` / `q` | long / long long | 8 |
| `f` / `d` | **float / double** | 4 / 8 |
| `s` | 字节串（`4s` = 4 字节） | n |
| `?` | bool | 1 |

**字节序前缀**：`<` 小端（Windows/x86）、`>` 大端（**网络字节序**）、`=` 本机。

```python
import struct

packed = struct.pack("i", 1000)
print(packed, len(packed))              # b'\xe8\x03\x00\x00' 4
print(struct.unpack("i", packed))       # (1000,)      ← 注意返回元组

packed2 = struct.pack("i4sf", 1, b"abcd", 3.5)
print(len(packed2), struct.unpack("i4sf", packed2))
# 12 (1, b'abcd', 3.5)

print(struct.pack(">i", 1), struct.pack("<i", 1))
# b'\x00\x00\x00\x01' b'\x01\x00\x00\x00'    ← 字节序不同
print(struct.calcsize("i4sf"))          # 12

try:
    struct.unpack("i", b"ab")           # 长度不够
except struct.error as e:
    print(type(e).__name__, e)          # error unpack requires a buffer of 4 bytes
```

> **三个要点**：① **`unpack` 永远返回元组**，单个值要写 `struct.unpack("i", b)[0]`；② **字节数必须完全对上**，否则 `struct.error: unpack requires a buffer of 4 bytes`；③ **跨机器传输必须显式指定字节序**（网络协议统一用 `>` 大端），否则 Intel 和 ARM 机器读出来的数值会颠倒。

### 9.3.3 使用 Marshal 模块读/写二进制文件

**`marshal` 是 Python 内部用来序列化"代码对象"（`.pyc` 文件）的模块**，接口与 pickle 几乎一样。

```python
import marshal

with open("data.marshal", "wb") as f:
    marshal.dump([1, "中文", 3.5, (4, 5)], f)
with open("data.marshal", "rb") as f:
    print(marshal.load(f))              # [1, '中文', 3.5, (4, 5)]
print(len(marshal.dumps([1, "中文", 3.5])))     # 30
```

> **官方明确警告**：**`marshal` 的数据格式不保证跨 Python 版本兼容**，只用于 `.pyc` 这类"可随时重新生成"的中间文件。**持久化数据请用 pickle 或 JSON，不要用 marshal。** 它出现在教材里主要是为了完整性。

### 9.3.4 使用 Shelve 模块读/写二进制文件

**`shelve` 提供"持久化的字典"**：像用 dict 一样存取，数据自动落到磁盘文件（底层用 pickle）。

```python
import shelve

# 写（像字典一样用）
with shelve.open("mydb") as db:
    db["user"] = {"name": "张三", "age": 20}
    db["count"] = 5
    print(db["count"], db["user"]["name"], list(db.keys()))
    # 5 张三 ['user', 'count']
    db["count"] += 1                    # 读出来 → 改 → 写回去，可以

# 再打开（数据还在）
with shelve.open("mydb") as db:
    print(db["count"], list(db.keys())) # 6 ['user', 'count']
    print("user" in db)                 # True
    del db["count"]

with shelve.open("mydb") as db:
    print(list(db.keys()))              # ['user']
```

| 操作 | 写法 |
|---|---|
| 存 | `db["key"] = value` |
| 取 | `db["key"]` / `db.get("key", 默认值)` |
| 判断存在 | `"key" in db` |
| 删除 | `del db["key"]` |
| 键列表 | `list(db.keys())` |
| 遍历 | `for k in db:` |

> **四个坑**：① **`shelve.open()` 必须用 `with`**，否则可能不写回磁盘；② **`db["count"] += 1` 能用，但修改嵌套的列表/字典时可能不生效**——因为取出来的是**副本**，要写 `d = db["k"]; d.append(1); db["k"] = d`，或者 `shelve.open(..., writeback=True)`（**代价是内存占用高**）；③ **一个逻辑"库"实际会生成 3 个文件**——`mydb.bak`、`mydb.dat`、`mydb.dir`，**删库要把它们全删掉**（只删 `.dat` 会留下坏掉的索引）；④ 同样受 pickle 的安全限制。

## 9.4 典型案例

### 9.4.1 合并文件

**问题**：把同目录下多个文本文件按顺序合并成一个。

```python
import os

os.makedirs("parts", exist_ok=True)
for i in range(3):
    with open(f"parts/part{i}.txt", "w", encoding="utf-8") as f:
        f.write(f"文件{i}的内容\n")

# 方式一：逐个读进来写出去
files = [f"parts/part{i}.txt" for i in range(3)]
with open("merged.txt", "w", encoding="utf-8") as out:
    for fp in files:
        with open(fp, encoding="utf-8") as fin:
            out.write(fin.read())
print(repr(open("merged.txt", encoding="utf-8").read()))
# '文件0的内容\n文件1的内容\n文件2的内容\n'
```

**更实用的版本：合并目录下所有 `.txt`，并加上分隔标题，跳过编码错误的文件**

```python
import os

def merge_txt(src_dir, out_path, encoding="utf-8"):
    """把 src_dir 下所有 .txt 合并到 out_path"""
    names = sorted(n for n in os.listdir(src_dir) if n.endswith(".txt"))
    count = 0
    with open(out_path, "w", encoding=encoding) as out:
        for name in names:
            path = os.path.join(src_dir, name)
            out.write(f"===== {name} =====\n")
            try:
                with open(path, encoding=encoding) as fin:
                    out.write(fin.read())
            except UnicodeDecodeError:
                out.write("（该文件编码不是 UTF-8，已跳过）\n")
                continue
            out.write("\n")
            count += 1
    return count

print(merge_txt("parts", "all.txt"))            # 3
print(open("all.txt", encoding="utf-8").read()[:30])
# ===== part0.txt =====
# 文件0的内容
```

> **要点**：① **`sorted()` 保证合并顺序稳定**（`os.listdir` 的顺序依赖文件系统，不可靠）；② **写文件用 `"w"` 只打开一次**，在循环外打开——**在循环里反复 `open(..., "w")` 会把前面的内容全部清空**，这是合并文件最经典的错误；③ **捕获 `UnicodeDecodeError` 跳过坏文件**，让批处理不会因为一个文件而整体失败。

### 9.4.2 CSV 与 JSON 文件操作

#### CSV（逗号分隔值）

**CSV 的读写必须用 `csv` 模块，不要手工 `split(",")`**——因为字段里可能含逗号、引号、换行。

**写 CSV**：

```python
import csv

rows = [["姓名", "Python", "数学"], ["张三", "92", "88"], ["李四", "85", "90"]]
with open("scores.csv", "w", newline="", encoding="utf-8-sig") as f:
    csv.writer(f).writerows(rows)

print(repr(open("scores.csv", encoding="utf-8-sig").read()))
# '姓名,Python,数学\n张三,92,88\n李四,85,90\n'
```

**读 CSV**：

```python
import csv

# 方式一：reader → 每行是列表
with open("scores.csv", newline="", encoding="utf-8-sig") as f:
    rows = list(csv.reader(f))
print(rows)
# [['姓名', 'Python', '数学'], ['张三', '92', '88'], ['李四', '85', '90']]

# 方式二：DictReader → 每行是字典（推荐，用列名取值）
with open("scores.csv", newline="", encoding="utf-8-sig") as f:
    data = list(csv.DictReader(f))
print(data[0], data[0]["Python"])       # {'姓名': '张三', 'Python': '92', '数学': '88'} 92
print([x["姓名"] for x in data])        # ['张三', '李四']
```

| 写法 | 每行类型 | 取值方式 |
|---|---|---|
| `csv.reader(f)` | `list` | **靠下标** `row[1]` |
| `csv.DictReader(f)` | `dict` | **靠列名** `row["Python"]` ✅ |
| `csv.writer(f).writerow(r)` | —— | 写一行 |
| `csv.writer(f).writerows(rs)` | —— | 写多行 |
| `csv.DictWriter(f, fieldnames)` | —— | 按列名写 |

> **两个必写参数，缺一不可**：
>
> | 参数 | 不写的后果 |
> |---|---|
> | **`newline=""`** | Windows 上每行变成 `\r\r\n`（多一个回车），用 Excel 打开**每两行之间多一个空行** |
> | **`encoding="utf-8-sig"`** | 中文在 **Excel 里显示成乱码**（Excel 默认按 GBK 读，不认识无 BOM 的 UTF-8） |
>
> 实测对比（同一个 `writerow(["a","b"])`）：
>
> ```python
> # 不加 newline=""
> b'a,b\r\r\n'
> # 加了 newline=""
> b'a,b\r\n'
> ```
>
> **`utf-8-sig` 会写入 3 字节 BOM（`b'\xef\xbb\xbf'`）**，Excel 靠它识别编码。**但用普通 `utf-8` 读回来时会多出一个 `\ufeff` 字符**，所以读写要一致地用 `utf-8-sig`。

> **CSV 读出来的全是字符串**：`"92"` 不是 `92`。**要参与计算必须 `int()` / `float()` 转换**，这也是 CSV 处理最常见的 bug 来源。

#### JSON（JavaScript 对象表示法）

**JSON 是跨语言的数据交换格式**，语法与 Python 的字典/列表几乎一样，但有三点不同：

| Python | JSON | 说明 |
|---|---|---|
| `True` / `False` | `true` / `false` | **小写** |
| `None` | `null` | —— |
| `'单引号'` | `"双引号"` | **JSON 只认双引号** |
| 元组 `(1,2)` | 数组 `[1,2]` | 存进去变列表 |
| 键可以是任意可哈希对象 | 键**必须是字符串** | 数字键会变成字符串 |

```python
import json

data = {"姓名": "张三", "年龄": 20, "成绩": [92, 88], "备注": None, "已婚": False}

# 转字符串
print(json.dumps(data, ensure_ascii=False))
# {"姓名": "张三", "年龄": 20, "成绩": [92, 88], "备注": null, "已婚": false}

print(json.dumps(data))         # 默认 ensure_ascii=True → 中文变成 \uXXXX
# {"\u59d3\u540d": "\u5f20\u4e09", "\u5e74\u9f84": 20, ...}

print(json.dumps(data, ensure_ascii=False, indent=2).splitlines()[0])   # {

# 写文件
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
print(json.load(open("data.json", encoding="utf-8"))["成绩"])           # [92, 88]

# 从字符串解析
print(json.loads('[1, 2, {"a": 3}]'))       # [1, 2, {'a': 3}]

# JSON 只认双引号
try:
    json.loads("{'a': 1}")
except json.JSONDecodeError as e:
    print(type(e).__name__, e)
# JSONDecodeError Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```

| 函数 | 作用 |
|---|---|
| `json.dumps(obj, ensure_ascii=False, indent=2)` | 对象 → **JSON 字符串** |
| `json.dump(obj, f, ...)` | 对象 → **文件** |
| `json.loads(s)` | **字符串** → 对象 |
| `json.load(f)` | **文件** → 对象 |

> **`ensure_ascii=False` 是中文项目的必写参数**。默认 `True` 会把所有非 ASCII 字符转成 `\uXXXX` 转义——**文件能正常读回来，但人打开看不懂**，写配置文件、导出数据时必须关掉。
>
> **`indent=2` 让 JSON 带缩进、可读**；不加就是挤在一行。**代价是文件变大**，做机器传输时通常不加。

#### 综合案例：CSV 成绩统计与等级评定

```python
import csv

# 读入
with open("scores.csv", newline="", encoding="utf-8-sig") as f:
    rows = list(csv.DictReader(f))
sc = [(r["姓名"], int(r["Python"])) for r in rows]
print(sc)       # [('张三', 92), ('李四', 85)]

# 统计
avg = sum(s for _, s in sc) / len(sc)
print(round(avg, 2), max(sc, key=lambda x: x[1]), min(sc, key=lambda x: x[1]))
# 88.5 ('张三', 92) ('李四', 85)

# 按成绩降序并评定等级，写出新文件
def level(s):
    return "优秀" if s >= 90 else "良好" if s >= 80 else "及格" if s >= 60 else "不及格"

with open("out.csv", "w", newline="", encoding="utf-8-sig") as f:
    w = csv.writer(f)
    w.writerow(["姓名", "Python", "等级"])
    for name, s in sorted(sc, key=lambda x: -x[1]):
        w.writerow([name, s, level(s)])

print(repr(open("out.csv", encoding="utf-8-sig").read()))
# '姓名,Python,等级\n张三,92,优秀\n李四,85,良好\n'
```

> **要点**：① 用 `DictReader` 按**列名**取值，比下标可读且不怕列顺序变化；② **读出来立刻转 `int`** 并存成 `(姓名, 成绩)` 元组列表，后续排序统计都方便；③ **`sorted(key=lambda x: -x[1])`** 用负号实现降序；④ 等级用**链式条件表达式**一次写完；⑤ 写出时同样要 `newline=""` + `utf-8-sig`。

## 典型例题

**例 9.1**（题型：读程序写结果——打开模式）

```python
with open("t.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n第二行\n第三行\n")

with open("t.txt", encoding="utf-8") as f:
    print(repr(f.read(5)))
    print(f.tell())

with open("t.txt", "a", encoding="utf-8") as f:
    f.write("第四行\n")

with open("t.txt", "w", encoding="utf-8") as f:
    f.write("重写\n")

print(repr(open("t.txt", encoding="utf-8").read()))
print(open("t.txt", encoding="utf-8").read().count("\n"))
```

**解**：`read(5)` 读 **5 个字符**（不是字节）：`第一行\n第` → `'第一行\n第'`。`"a"` 是**追加**，在原内容后加第四行。`"w"` 是**清空重写**，前面所有内容都没了，只剩 `'重写\n'`（1 个换行）。

**答案**：

```
'第一行\n第'
14
'重写\n'
1
```

> **注意 `tell()` 的值**：文本模式下 `tell()` 返回的是一个**不透明的"位置标记"**（含解码器状态），**不要把它当成字节数**。上例中 `'第一行\n第'` 是 13 字节，但 `tell()` 给出 14。**要按字节精确定位请用二进制模式。**

**例 9.2**（题型：编程题——文件统计）

统计一个文本文件的行数、字符数、单词数（按空白切分）和非空行数。

```python
text = "Python is great\n\nIt is easy to learn\n   \nData analysis with Python\n"
with open("stat.txt", "w", encoding="utf-8") as f:
    f.write(text)

def stat_file(path):
    with open(path, encoding="utf-8") as f:
        content = f.read()
    lines = content.splitlines()
    return {
        "字符数": len(content),
        "行数": len(lines),
        "非空行数": sum(1 for l in lines if l.strip()),
        "单词数": len(content.split()),
    }

r = stat_file("stat.txt")
for k, v in r.items():
    print(f"{k}: {v}")
# 字符数: 67
# 行数: 5
# 非空行数: 3
# 单词数: 12
```

**解**：`splitlines()` 按换行切分**且不保留 `\n`**（比 `readlines()` 更干净），`"Python is great\n\nIt is easy to learn\n   \nData analysis with Python\n"` 得到 **5 行**（含一个空行和一个只含空格的"空白行"）。`content.split()` **不带参数时按任意空白切分并自动忽略连续空白**，所以 `"   "` 这种空白行不贡献单词，单词数 12。`sum(1 for l in lines if l.strip())` 统计非空行 → 3。

> **三个数字要分清**：**字符数 67** 包含所有换行符；**行数 5** 是 `splitlines()` 的结果；**非空行数 3** 是去掉空白行后的结果。**「行数」和「非空行数」不一样是考试常设的陷阱**——文件最后一行如果有换行符，`splitlines()` 不会多算一行，但 `readlines()` 同样不会，而 `content.split("\n")` **会**多出一个空串。

**例 9.6**（题型：编程题——用 pickle 与 shelve 做简易通讯录）

```python
import shelve

def add(db, name, phone):
    if name in db:
        return f"{name} 已存在"
    db[name] = phone
    return f"已添加 {name}"

def find(db, name):
    return db.get(name, "未找到该联系人")

def delete(db, name):
    if name in db:
        del db[name]
        return f"已删除 {name}"
    return "未找到该联系人"

with shelve.open("contacts") as db:
    print(add(db, "张三", "13812345678"))       # 已添加 张三
    print(add(db, "李四", "13900000000"))       # 已添加 李四
    print(add(db, "张三", "1"))                 # 张三 已存在
    print(find(db, "张三"))                     # 13812345678
    print(find(db, "王五"))                     # 未找到该联系人
    print(sorted(db.keys()))                    # ['张三', '李四']  ← 字典序

# 重新打开，数据仍在
with shelve.open("contacts") as db:
    print(len(db), find(db, "李四"))            # 2 13900000000
    print(delete(db, "李四"))                   # 已删除 李四
```

**例 9.7**（题型：编程题——struct 打包二进制记录）

把学生记录（学号 int + 姓名 8 字节 + 成绩 float）打包成定长二进制，再解包验证。

```python
import struct

# 格式：i（学号 4 字节）8s（姓名 8 字节）f（成绩 4 字节） = 16 字节
fmt = "<i8sf"
print(struct.calcsize(fmt))                 # 16

records = [(2022001, "张三", 92.5), (2022002, "李四", 85.0)]
with open("stu.dat", "wb") as f:
    for sid, name, score in records:
        f.write(struct.pack(fmt, sid, name.encode("utf-8"), score))

import os
print(os.path.getsize("stu.dat"))           # 32   ← 2 条 × 16 字节

with open("stu.dat", "rb") as f:
    while True:
        chunk = f.read(16)                  # 定长读取
        if not chunk:
            break
        sid, name, score = struct.unpack(fmt, chunk)
        print(sid, name.decode("utf-8").rstrip("\x00"), score)
# 2022001 张三 92.5
# 2022002 李四 85.0
```

**解**：`<` 表示小端字节序，`i` 是 4 字节整数，`8s` 是 8 字节定长字节串（**不足会补 `\x00`，所以解包后要 `rstrip("\x00")` 去掉**），`f` 是 4 字节浮点。**因为每条记录定长 16 字节，所以可以用 `f.read(16)` 循环定位，不需要分隔符**——这正是二进制定长格式的优点。

**答案**：见注释。

## 易错点提醒

1. **用了 `"w"` 却想保留原内容。**
   - 错在哪：`"w"` 一打开就**清空文件**，原数据全部丢失且无法恢复。
   - 正确做法：追加用 `"a"`；只在确实要覆盖时用 `"w"`。
2. **不用 `with`，忘记 `close()`。**
   - 错在哪：缓冲区的数据没落盘（文件可能是空的）、文件句柄泄漏，异常时更不会关闭。
   - 正确做法：一律 `with open(...) as f:`。
3. **`open()` 不写 `encoding`。**
   - 错在哪：会用系统默认编码（中文 Windows 是 GBK），换台机器或换系统就乱码。
   - 正确做法：**每次 `open()` 都显式写 `encoding="utf-8"`**。
4. **CSV 读写不加 `newline=""`。**
   - 错在哪：Windows 上每行结尾变成 `\r\r\n`（多一个回车），Excel 打开每两行之间多一个空行。
   - 正确做法：`open(path, "w", newline="", encoding="utf-8-sig")`。
5. **CSV 给 Excel 打开时用 `encoding="utf-8"`。**
   - 错在哪：Excel 默认按 GBK 解读，无 BOM 的 UTF-8 中文全是乱码。
   - 正确做法：写 CSV 用 `encoding="utf-8-sig"`（写入 3 字节 BOM）；**读的时候也要用 `utf-8-sig`**，否则会多出 `\ufeff` 字符。
6. **以为 CSV 读出来是数字。**
   - 错在哪：`csv` 模块读出的**每个字段都是字符串**，`"92" > "100"` 为 `True`，排序和比较全错。
   - 正确做法：读出来立刻 `int()` / `float()` 转换。
7. **手工用 `split(",")` 解析 CSV。**
   - 错在哪：字段里含逗号（`"张三,男"`）、含引号、含换行时会切错。
   - 正确做法：用 `csv.reader` / `csv.DictReader`。
8. **JSON 忘了 `ensure_ascii=False`。**
   - 错在哪：中文全部变成 `\u73ed\u7ea7` 这样的转义，文件人能读但看不懂。
   - 正确做法：`json.dump(data, f, ensure_ascii=False, indent=2)`。
9. **`json.loads()` 解析单引号字符串。**
   - 错在哪：`JSONDecodeError: Expecting property name enclosed in double quotes`——**JSON 规范只认双引号**，`{'a': 1}` 不是合法 JSON。
   - 正确做法：用双引号 `'{"a": 1}'`；如果手上是 Python 字典的字面量字符串，用 `ast.literal_eval()`。
10. **用 `pickle.load()` 加载来路不明的文件。**
    - 错在哪：pickle 反序列化会**执行字节流中的指令**，等于让攻击者在你电脑上运行代码。
    - 正确做法：只反序列化自己生成的文件；跨语言/跨版本存储用 JSON。
11. **循环里反复 `open(out, "w")`。**
    - 错在哪：每次打开都清空，最终文件里只剩最后一次写入的内容。
    - 正确做法：**输出文件在循环外打开一次**，循环内只 `write`。
12. **大文件用 `read()` 或 `readlines()`。**
    - 错在哪：整个文件装进内存。实测 1 万行的文本占 88890 字节，全读进来在内存里要 117838 字节；100 万行就会吃掉十几 GB。
    - 正确做法：`for line in f:` 逐行迭代，或 `while` + `read(块大小)` 分块读。

## 本章小结

- 文件分**文本文件**（有编码，`"r"`/`"w"`）和**二进制文件**（无编码，`"rb"`/`"wb"`）两类。
- **乱码的本质是"用 A 编码写、用 B 编码读"**；UTF-8 一个汉字 3 字节、GBK 2 字节；**自己的项目一律用 UTF-8 并显式写 `encoding`**。
- **模式表必背**：`r` 只读（不存在报错）、`w` 只写（**清空**）、`a` 追加、`x` 独占创建、`+` 加读写、`b` 二进制。**`"w"` 一打开就清空，最危险。**
- **必须用 `with open(...) as f:`**：自动关闭、异常也关闭、保证数据落盘。
- **四种读法**：`read()` 全读、`read(n)` 分块、`readline()` 一行、`readlines()` 全读成列表、**`for line in f:` 惰性迭代（大文件首选）**。每行末尾带 `\n`，用 `rstrip("\n")` 去掉。
- **`writelines()` 不会自动加换行**；`seek`/`tell` 在**文本模式下是不透明标记**，要精确按字节定位用二进制模式。
- **CSV 两个必写参数**：`newline=""`（否则 `\r\r\n`）、`encoding="utf-8-sig"`（否则 Excel 乱码）；`DictReader` 按列名取值更好用；**读出来全是字符串，要手动转换**。
- **JSON**：`dump`/`dumps` 与 `load`/`loads` 的区别是「文件」与「字符串」；**中文项目必写 `ensure_ascii=False`**；JSON 只认双引号，`True/False/None` 变成 `true/false/null`。
- **四种二进制工具**：**pickle** 万能但仅限 Python 且**有安全风险**；**struct** 按格式定长打包、与 C 互通、**必须指定字节序**；**marshal** 只用于 `.pyc`、**官方不建议持久化**；**shelve** 是"持久化字典"、**必须用 `with`**。

> **一句话记住本章**：`with open(路径, 模式, encoding="utf-8")` 三件套不能少；`"w"` 会清空、`"a"` 才追加；大文件用 `for line in f`；CSV 加 `newline=""` 和 `utf-8-sig`，JSON 加 `ensure_ascii=False`。

## 自测题

5. `"r+"` 和 `"a"` 都能在已有文件里写数据，它们的区别是什么？
6. 出现 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0` 说明什么？给出两种修复方法。
7. 读写 CSV 时 `newline=""` 和 `encoding="utf-8-sig"` 各解决什么问题？不写会怎样？

9. `json.dumps(data)` 和 `json.dumps(data, ensure_ascii=False)` 的输出有什么不同？为什么中文项目要用后者？
10. `json.loads("{'a': 1}")` 会怎样？为什么？
11. pickle、struct、marshal、shelve 四种工具各自的定位是什么？哪一个有明确的安全风险？
12. `struct.unpack("i", b"ab")` 会怎样？为什么？

**参考答案**

1. `"r"`：文件不存在**报 `FileNotFoundError`**，存在则从头读（只读）；`"w"`：不存在则**创建**，存在则**清空重写**（只写）；`"a"`：不存在则**创建**，存在则**在末尾追加**（只写，指针永远在末尾）；`"x"`：不存在则**创建**，**存在则报 `FileExistsError`**（独占创建）。
2. ① **自动 `close()`**，即使中间抛异常也会关闭，不会泄漏文件句柄；② **保证缓冲区的数据写入磁盘**，不关文件可能出现"写了但文件是空的"；③ 代码更简洁，不用在 `finally` 里写 `close()`。
3. `read()` 和 `readlines()` 会把**整个文件载入内存**；`readline()` 一次一行、内存里只有一行，但要自己写循环判断结束；**`for line in f` 也是惰性迭代，内存里始终只有一行，且语法最简洁**。处理 10 万行日志**必须用 `for line in f:`**（或 `while` + `read(块)` 分块读）。
4. 末尾带**换行符 `\n`**（Windows 上写出的文件是 `\r\n`，Python 文本模式读时会自动转成 `\n`；最后一行可能没有）。去掉用 `line.rstrip("\n")`。**`strip()` 会同时去掉行首和行尾的所有空白**（包括空格、制表符），而 **`rstrip("\n")` 只去掉末尾的换行**——处理代码、缩进敏感的文本时必须用后者。
5. `"r+"` 打开时**不清空文件，但写指针在开头**，直接 `write` 会**覆盖前面的内容**；`"a"` 打开时写指针**永远在文件末尾**（`seek` 也拉不回来），任何写入都是追加。**要追加只能用 `"a"`。**
6. 说明这个文件**不是 UTF-8 编码**（很可能是 GBK），第 0 个字节 `0xd6` 不是合法的 UTF-8 起始字节——GBK 的「中」正是 `0xd6 0xd0`。修复方法：① **用正确的编码打开**：`open(path, encoding="gbk")`；② **不确定编码时，先用 `"rb"` 读成 `bytes`，再逐个编码 `try: raw.decode(enc)` 试**，或者用 `chardet` 库自动检测。
7. **`newline=""`** 解决「换行被重复翻译」的问题：不加时 Windows 上 csv 写入的 `\r\n` 中的 `\n` 又被翻译成 `\r\n`，每行变成 `\r\r\n`，Excel 打开每两行之间多一个空行。**`encoding="utf-8-sig"`** 解决「Excel 中文乱码」的问题：它会写入 3 字节 BOM（`b'\xef\xbb\xbf'`），Excel 靠 BOM 识别出这是 UTF-8；不加时 Excel 按 GBK 解读，中文全是乱码。**注意读的时候也要用 `utf-8-sig`，否则第一个字段会多出 `\ufeff`。**
8. `csv.reader` 每行返回**列表**，只能靠**下标**取值（`row[1]`），列顺序一变就错；`csv.DictReader` 每行返回**字典**（用第一行作列名），可以靠**列名**取值（`row["Python"]`），可读性好且不怕列顺序变化。**推荐用 `DictReader`**，除非 CSV 没有表头或需要按位置处理。
9. `json.dumps(data)` 默认 `ensure_ascii=True`，会把所有非 ASCII 字符转成 `\uXXXX` 转义序列（`"班级"` → `"\u73ed\u7ea7"`）；加 `ensure_ascii=False` 则**保留中文原样**。两者都能被正确读回，但**前者人打开看不懂**，写配置文件、导出数据给同事看时必须用 `ensure_ascii=False`。
10. 会抛 **`json.JSONDecodeError: Expecting property name enclosed in double quotes`**。因为 **JSON 规范要求字符串（包括键名）必须用双引号**，单引号是 Python 的字面量语法而不是 JSON 语法。如果手上确实是一个 Python 字面量字符串，应该用 **`ast.literal_eval("{'a': 1}")`** 来解析（它比 `eval` 安全，只认字面量）。
11. **pickle**：通用对象序列化，能存几乎所有 Python 对象，但仅限 Python 且不保证跨版本兼容，**有安全风险**；**struct**：按格式字符串把数字和定长字节串打包成定长二进制，**与 C 语言互通**，必须显式指定字节序；**marshal**：Python 内部用于 `.pyc` 的序列化，**官方明确不建议用于持久化**；**shelve**：提供"持久化的字典"接口，底层用 pickle。**pickle 有明确的安全风险**：`pickle.load()` 会执行字节流中的构造指令，加载不可信文件等于执行任意代码。
12. 会抛 **`struct.error: unpack requires a buffer of 4 bytes`**。因为格式符 `"i"` 要求 **4 字节**的缓冲区，而 `b"ab"` 只有 2 字节。`struct` 是**定长**打包/解包，字节数必须与格式字符串算出的 `calcsize` **完全一致**，多了少了都会报错。
